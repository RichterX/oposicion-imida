# Mini-test - Bloque 05 - 5.3 Programacion orientada a objetos

Marca una opcion por pregunta.

## Preguntas

1. Que describe mejor la POO?
- A) Solo programar con funciones sueltas
- B) Modelar con objetos que encapsulan estado y comportamiento
- C) Evitar reutilizacion
- D) Prohibir herencia

2. Diferencia entre clase y objeto?
- A) No hay diferencia
- B) Clase es instancia y objeto es molde
- C) Clase define molde; objeto es instancia concreta
- D) Objeto solo existe en UML

3. Encapsulacion significa:
- A) Exponer todo internamente
- B) Ocultar estado interno tras interfaz controlada
- C) Eliminar metodos
- D) Evitar validaciones

4. Abstraccion en POO:
- A) Ignorar requisitos
- B) Copiar codigo
- C) Guardar logs
- D) Quedarse con lo esencial y ocultar detalles innecesarios

5. Herencia permite:
- A) Reutilizar y extender comportamiento de una clase base
- B) Evitar clases derivadas
- C) Sustituir composicion siempre
- D) Eliminar polimorfismo

6. Polimorfismo implica:
- A) Un metodo, una sola implementacion posible
- B) Mismo contrato con implementaciones distintas
- C) No usar interfaces
- D) Solo aplica a bases de datos

7. Diferencia clave entre composicion y herencia?
- A) Composicion: "tiene un"; herencia: "es un"
- B) Son identicas
- C) Herencia siempre mejor
- D) Composicion solo en frontend

8. Principio SRP indica:
- A) Una clase debe tener una sola razon de cambio
- B) Una clase debe hacerlo todo
- C) No usar metodos privados
- D) Nunca dividir clases

9. Bajo acoplamiento favorece:
- A) Dependencias fuertes
- B) Menor mantenibilidad
- C) Cambios mas seguros y pruebas mas faciles
- D) Mas duplicidad obligatoria

10. Alta cohesion significa:
- A) Responsabilidades dispersas sin relacion
- B) Responsabilidades relacionadas y enfocadas en cada clase
- C) Una sola clase para toda la app
- D) Evitar nombres descriptivos

---

## Plantilla de respuestas

1. B
2. C
3. B
4. D
5. A
6. B
7. A
8. A
9. C
10. B
