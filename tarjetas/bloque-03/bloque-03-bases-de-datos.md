# Tarjetas - Bloque 03 (Bases de datos)

Formato:
P: Pregunta
R: Respuesta

---

## 3.1 SQL

P: Que es SQL?
R: Lenguaje estandar para definir, consultar y manipular datos en bases de datos relacionales.

P: Que es una tabla en modelo relacional?
R: Estructura de filas y columnas que almacena una entidad.

P: Que diferencia hay entre clave primaria y clave foranea?
R: La primaria identifica un registro de forma unica; la foranea referencia la primaria de otra tabla.

## 3.2 PostgreSQL

P: Que es PostgreSQL?
R: Sistema gestor de bases de datos relacional de codigo abierto, robusto y extensible.

P: Que ventaja destaca en PostgreSQL para entornos exigentes?
R: Alto cumplimiento SQL, integridad y funcionalidades avanzadas.

P: Herramienta de consola habitual en PostgreSQL?
R: psql.

## 3.3 Oracle

P: Que es Oracle Database?
R: SGBD relacional empresarial orientado a alto rendimiento, escalabilidad y disponibilidad.

P: En que contextos suele usarse Oracle?
R: Entornos corporativos criticos con grandes volumenes y alta exigencia operativa.

P: Que lenguaje procedural se asocia a Oracle?
R: PL/SQL.

## 3.4 MySQL

P: Que es MySQL?
R: SGBD relacional muy extendido, especialmente en aplicaciones web.

P: Ventaja practica de MySQL en proyectos comunes?
R: Simplicidad operativa y amplio ecosistema.

P: Que comando SQL crea una base de datos?
R: CREATE DATABASE nombre;

## 3.5 PL/SQL

P: Que es PL/SQL?
R: Extension procedural de SQL en Oracle para programar logica en bloques, procedimientos y funciones.

P: Que aporta PL/SQL frente a SQL puro?
R: Variables, control de flujo, manejo de excepciones y reutilizacion de logica.

P: Que es un procedimiento almacenado?
R: Bloque de codigo guardado en la base de datos que ejecuta tareas definidas.

## 3.6 PostGIS

P: Que es PostGIS?
R: Extension espacial de PostgreSQL para almacenar y consultar datos geograficos.

P: Que tipo de datos agrega PostGIS?
R: Geometrias como puntos, lineas y poligonos.

P: Para que sirve una consulta espacial?
R: Para analizar relaciones geograficas, por ejemplo distancia o interseccion.

## Tarjetas de repaso transversal (Bases de datos)

P: Que principio evita duplicidad e inconsistencias?
R: Normalizacion y modelado correcto de relaciones.

P: Que debes definir antes de cargar datos masivamente?
R: Claves, restricciones, tipos de datos e indices.

P: Que diferencia hay entre integridad y rendimiento?
R: Integridad asegura datos correctos; rendimiento optimiza tiempos de consulta y operacion.

P: Que error frecuente complica mantenimiento?
R: Disenar tablas sin claves claras ni convenciones de nombres.

P: Objetivo final de una base de datos bien administrada?
R: Datos consistentes, seguros, consultables y utiles para toma de decisiones.
