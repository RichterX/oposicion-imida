# 🧭 1. ¿QUÉ ES PRINCE2?

**PRINCE2** es un método de gestión de proyectos.

El nombre procede históricamente de:

> **Projects IN Controlled Environments**

Su objetivo es proporcionar una estructura para:

```text
dirigir
+
gestionar
+
controlar
```

un proyecto desde su comienzo hasta su cierre.

PRINCE2 proporciona:

```text
principios
+
prácticas
+
procesos
+
roles/responsabilidades
+
controles
```

y debe adaptarse al contexto del proyecto.

# 🧠 3. PRINCE2 NO ES UNA METODOLOGÍA DE DESARROLLO

Esta distinción es importante.

PRINCE2 se ocupa principalmente de:

```text
gobierno
+
dirección
+
gestión
+
control
```

del proyecto.

No prescribe necesariamente:

```text
cómo programar
cómo diseñar una interfaz
qué lenguaje utilizar
cómo implementar una base de datos
```

Por eso puede utilizarse junto con:

```text
Scrum
Agile
Waterfall
Lean
otros enfoques de entrega
```

# 🎯 4. ¿QUÉ ES UN PROYECTO?

Un proyecto es una organización temporal creada para entregar uno o más productos de negocio de acuerdo con un Business Case acordado.

Características habituales:

```text
temporal
+
objetivo definido
+
productos concretos
+
recursos limitados
+
cambio
+
riesgo
```

Un proyecto tiene:

```text
inicio
+
desarrollo
+
cierre
```

No debe confundirse con:

```text
operación continua
```

---

# 🔄 5. PROYECTO VS OPERACIÓN

| Proyecto | Operación |
|---|---|
| Temporal | Continua |
| Produce un cambio/producto definido | Mantiene actividad habitual |
| Tiene comienzo y final | Puede ser indefinida |
| Gestiona un objetivo concreto | Gestiona actividad recurrente |

Ejemplo:

```text
PROYECTO
→ desarrollar una nueva aplicación

OPERACIÓN
→ mantener la aplicación funcionando
```

# ⭐ 7. LOS 7 PRINCIPIOS

Los principios son las bases que caracterizan un proyecto gestionado según PRINCE2.

Son:

```text
1. Asegurar la justificación continua del negocio
2. Aprender de la experiencia
3. Definir roles, responsabilidades y relaciones
4. Gestionar por excepción
5. Gestionar por etapas
6. Enfocarse en los productos
7. Adaptar al proyecto
```

En terminología inglesa:

```text
1. Ensure continued business justification
2. Learn from experience
3. Define roles, responsibilities and relationships
4. Manage by exception
5. Manage by stages
6. Focus on products
7. Tailor to suit the project
```

# 💰 8. PRINCIPIO 1 · JUSTIFICACIÓN CONTINUA DEL NEGOCIO

El proyecto debe seguir teniendo sentido desde el punto de vista empresarial.

La pregunta fundamental:

> ¿Sigue mereciendo la pena realizar este proyecto?

Debe evaluarse:

```text
coste
+
riesgo
+
beneficios
+
viabilidad
+
deseabilidad
```

Si el proyecto deja de estar justificado:

```text
puede detenerse
```

---

# 🧠 9. PRINCIPIO 2 · APRENDER DE LA EXPERIENCIA

PRINCE2 busca aprovechar:

```text
experiencias anteriores
+
experiencia actual
+
experiencia futura
```

Las lecciones deben:

```text
identificarse
+
registrarse
+
utilizarse
```

No tiene sentido descubrir una solución en un proyecto y perder ese conocimiento.

---

# 👥 10. PRINCIPIO 3 · ROLES, RESPONSABILIDADES Y RELACIONES

Todas las personas implicadas deben comprender:

```text
quién decide
+
quién ejecuta
+
quién responde
+
quién informa
```

PRINCE2 establece una estructura clara de responsabilidades.

---

# 🚦 11. PRINCIPIO 4 · GESTIONAR POR EXCEPCIÓN

Es uno de los conceptos más importantes.

La idea:

```text
delegar autoridad
+
definir tolerancias
+
intervenir cuando se exceden
```

En lugar de controlar cada detalle constantemente.

Ejemplo:

```text
Proyecto:
presupuesto tolerado ±10%

Mientras:
    desviación ≤ 10%
        ↓
    gestión dentro de la tolerancia

Si:
    desviación > 10%
        ↓
    excepción
        ↓
    escalar
```

---

# 📏 12. TOLERANCIAS

Las tolerancias permiten establecer límites para:

```text
tiempo
coste
calidad
alcance
beneficios
riesgo
```

# 🪜 13. PRINCIPIO 5 · GESTIONAR POR ETAPAS

Un proyecto grande se divide en:

```text
etapas de gestión
```

Cada etapa:

```text
se planifica
+
se controla
+
se revisa
```

Al terminar una etapa:

```text
evaluación
+
decisión
```

sobre continuar.

---

# 📦 14. PRINCIPIO 6 · ENFOCARSE EN LOS PRODUCTOS

PRINCE2 se centra en:

```text
qué debe entregarse
```

antes de centrarse en:

```text
cómo se realizará
```

Esto permite definir claramente:

```text
producto
+
calidad
+
criterios de aceptación
```

---

# 🧩 15. PRINCIPIO 7 · ADAPTAR AL PROYECTO

PRINCE2 no pretende aplicarse de forma rígida.

Debe adaptarse a:

```text
tamaño
+
complejidad
+
importancia
+
riesgo
+
contexto
+
organización
```

La adaptación no significa:

```text
eliminar PRINCE2
```

sino:

```text
ajustar su aplicación
```

al contexto.

```text

+
```


# 🚀 28. STARTING UP A PROJECT

Es el proceso previo a la iniciación formal del proyecto.

Busca determinar:

```text
¿merece la pena iniciar este proyecto?
```

Se comprueba que existen las condiciones necesarias para iniciar la planificación detallada.

---

# 🏛️ 29. DIRECTING A PROJECT

Es responsabilidad principalmente del:

```text
Project Board
```

El Project Board toma decisiones de alto nivel.

Entre otras:

```text
autorizar iniciación
autorizar proyecto
autorizar etapas
dar dirección
autorizar excepciones
autorizar cierre
```

---

# 🏗️ 30. INITIATING A PROJECT

Aquí se establecen las bases sólidas para gestionar el proyecto.

Se define:

```text
cómo se gestionará
+
cómo se controlará
+
cómo se medirán resultados
```

Se desarrolla el:

```text
Project Initiation Documentation
(PID)
```

# 🪜 34. MANAGING A STAGE BOUNDARY



# 🏁 35. CLOSING A PROJECT

El proyecto debe cerrarse de manera controlada.

```text

+
entrega aceptada
+
lecciones
+

+
```

El cierre no significa simplemente:


# 🧠 56. PRINCE2 VS SCRUM

| PRINCE2 | Scrum |
|---|---|
| Método de gestión de proyectos | Framework para productos/problemas complejos |
| Dirección y control del proyecto | Desarrollo iterativo e incremental |
| Business Case | Product Goal |
| Gestión por etapas | Sprints |
| Tolerancias | Adaptación continua |
| Project Board | Scrum Team |
| Project Manager | No existe equivalente directo |
| Puede combinarse con Agile | Puede utilizarse dentro de un proyecto PRINCE2 |

No hay que concluir:

```text
PRINCE2 = Waterfall
```

PRINCE2 7 puede adaptarse a diferentes enfoques de entrega, incluidos enfoques ágiles. citeturn0search5

---

# 🧠 57. PRINCE2 VS ITIL

| PRINCE2 | ITIL |
|---|---|
| Gestión de proyectos | Gestión de servicios |
| Proyecto temporal | Servicios y operaciones |
| Business Case | Valor del servicio |
| Project Board | Gobernanza del servicio |
| Etapas | Ciclo de gestión/adaptación |
| Productos del proyecto | Servicios/productos de servicio |

Pueden coexistir.

Ejemplo:

```text
PRINCE2
→ gestionar proyecto de implantación de CRM

ITIL
→ gestionar el servicio CRM una vez operativo
```
