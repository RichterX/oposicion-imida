# 🧭 1. ¿QUÉ ES ITIL?

**ITIL** significa:

> **Information Technology Infrastructure Library**

Es un marco de buenas prácticas para la **gestión de servicios de TI (ITSM, IT Service Management)**.

Su propósito es ayudar a las organizaciones a:

```text
planificar
   ↓
diseñar
   ↓
entregar
   ↓
soportar
   ↓
mejorar
servicios de TI
```

La idea fundamental no es simplemente:

> "Gestionar servidores y ordenadores."

Sino:

> **Gestionar servicios tecnológicos de manera que generen valor para consumidores, usuarios y otras partes interesadas.**

ITIL es un **marco de buenas prácticas**, no una norma certificable como ISO 20000.

---

# ⚠️ 2. ITIL 4 Y LA EVOLUCIÓN ACTUAL

Para este temario debemos distinguir dos cosas.

La versión tradicional de referencia en gran parte de la documentación de ITIL moderna es **ITIL 4**. Su modelo incluye:

```text
Sistema de Valor del Servicio
+
4 dimensiones
+
7 principios guía
+
Cadena de valor del servicio
+
prácticas
+
mejora continua
```

Actualmente PeopleCert también dispone de **ITIL Foundation (Version 5)**, que evoluciona el marco hacia la gestión de productos y servicios digitales y mantiene muchos conceptos estructurales heredados de ITIL 4. ITIL 4 continúa disponible durante la transición, con retirada planificada de sus módulos para finales de 2027. [PeopleCert]

> **Para esta oposición no debemos mezclar terminología de versiones sin comprobar qué versión exige el temario oficial.**
>
> En este capítulo se utiliza **ITIL 4 como marco principal**, y se señalarán las cuestiones en las que la evolución actual pueda generar confusión.

# 🧠 3. CONCEPTOS FUNDAMENTALES

Antes de estudiar el modelo hay que dominar el vocabulario.

---

## 3.1 Servicio

Un **servicio** es un medio para permitir la creación conjunta de valor al facilitar los resultados que los clientes quieren conseguir, sin que tengan que gestionar determinados costes y riesgos específicos.

La idea clave:

```text
Servicio
=
facilitar resultados
+
gestionar parte de costes/riesgos
```

---

## 3.2 Gestión de servicios

**Service Management** es el conjunto de capacidades organizativas especializadas para proporcionar valor mediante servicios.

No se limita a:

```text
servidores
redes
software
```

Incluye:

```text
personas
procesos
tecnología
proveedores
información
gestión
```

---

## 3.3 Valor

El objetivo último de ITIL es:

```text
crear valor
```

El valor no lo produce exclusivamente el proveedor.

Se:

```text
CO-CREA
```

entre proveedor, consumidor y otras partes interesadas.

---

# 👥 4. PROVEEDOR Y CONSUMIDOR

## Service Provider

Es la organización o parte de una organización que proporciona servicios.

## Service Consumer

Es quien recibe o consume el servicio.

Dentro del consumidor pueden distinguirse diferentes roles.

### Customer

Define los requisitos del servicio y es responsable de los resultados obtenidos mediante el consumo del servicio.

### User

Utiliza directamente el servicio.

### Sponsor

Autoriza el presupuesto para el consumo del servicio.

Un mismo individuo puede desempeñar varios roles.

---

# 🎯 5. OUTPUT VS OUTCOME

Una distinción muy importante:

## Output

Es un resultado tangible producido por una actividad.

Ejemplo:

```text
Se instala un nuevo servidor.
```

Output:

```text
servidor instalado
```

## Outcome

Es el resultado o efecto conseguido por el consumidor.

Ejemplo:

```text
Los usuarios pueden acceder
a la aplicación sin interrupciones.
```

Outcome:

```text
servicio disponible
+
objetivo empresarial conseguido
```

### Regla mental

```text
OUTPUT
→ qué producimos

OUTCOME
→ qué consigue el consumidor
```

---

# 💰 6. COSTES Y RIESGOS

El consumidor utiliza servicios para evitar gestionar directamente determinados:

```text
costes
```

y:

```text
riesgos
```

Esto no significa que desaparezcan.

El proveedor puede:

```text
asumir
+
gestionar
+
reducir
```

determinados costes y riesgos.

# ⚙️ 7. UTILITY Y WARRANTY

Dos conceptos clásicos de ITIL.

## Utility

Responde:

> **¿Qué hace el servicio?**

También se puede asociar con:

```text
fit for purpose
```

Es decir:

```text
adecuado para el propósito
```

---

## Warranty

Responde:

> **¿Cómo funciona el servicio?**

Se relaciona con:

```text
fit for use
```

Es decir:

```text
adecuado para el uso
```

La warranty puede incluir aspectos como:

```text
disponibilidad
capacidad
continuidad
seguridad
```

# 🏗️ 9. SISTEMA DE VALOR DEL SERVICIO

El **Service Value System (SVS)** explica cómo los distintos componentes y actividades de la organización trabajan conjuntamente para facilitar la creación de valor.

Sus componentes principales son:

```text
Principios guía
       +
Gobernanza
       +
Cadena de valor del servicio
       +
Prácticas
       +
Mejora continua
```

Todo ello está orientado a:

```text
OPPORTUNITY / DEMAND
        ↓
      VALUE
```

# 🧭 11. LOS 7 PRINCIPIOS GUÍA

Son una de las partes más preguntables de ITIL 4.

Los siete principios son:

```text
1. Focus on value
2. Start where you are
3. Progress iteratively with feedback
4. Collaborate and promote visibility
5. Think and work holistically
6. Keep it simple and practical
7. Optimize and automate
```

En español:

```text
1. Centrarse en el valor
2. Empezar donde estás
3. Progresar iterativamente con retroalimentación
4. Colaborar y promover la visibilidad
5. Pensar y trabajar holísticamente
6. Mantenerlo simple y práctico
7. Optimizar y automatizar
```

---

# ⭐ 12. PRINCIPIO 1 · CENTRARSE EN EL VALOR

Todo lo que hace la organización debería relacionarse con:

```text
valor para las partes interesadas
```

Pregunta mental:

> ¿Esto aporta valor?

---

# ⭐ 13. PRINCIPIO 2 · EMPEZAR DONDE ESTÁS

No hay que destruir automáticamente lo existente.

Primero:

```text
evaluar situación actual
```

Después:

```text
decidir qué conservar
+
qué mejorar
+
qué sustituir
```

---

# ⭐ 14. PRINCIPIO 3 · PROGRESAR ITERATIVAMENTE CON RETROALIMENTACIÓN

Evitar intentar resolver todo de una vez.

En su lugar:

```text
pequeño cambio
     ↓
feedback
     ↓
evaluación
     ↓
siguiente iteración
```

---

# ⭐ 15. PRINCIPIO 4 · COLABORAR Y PROMOVER LA VISIBILIDAD

La información debe ser visible para las personas adecuadas.

Evitar:

```text
silos
+
información oculta
+
decisiones aisladas
```

---

# ⭐ 16. PRINCIPIO 5 · PENSAR Y TRABAJAR HOLÍSTICAMENTE

No debemos optimizar un componente ignorando el resto.

Hay que considerar:

```text
personas
procesos
tecnología
proveedores
información
```

y sus relaciones.

---

# ⭐ 17. PRINCIPIO 6 · MANTENERLO SIMPLE Y PRÁCTICO

Si algo no aporta valor:

```text
eliminar complejidad innecesaria
```

No se trata de hacer:

```text
menos por sistema
```

sino:

```text
evitar trabajo inútil
```

---

# ⭐ 18. PRINCIPIO 7 · OPTIMIZAR Y AUTOMATIZAR

Primero:

```text
optimizar
```

Después:

```text
automatizar
```

Automatizar un proceso deficiente puede simplemente producir:

```text
un proceso deficiente más rápido
```

# 🛤️ 29. VALUE STREAM

Un **value stream** es una combinación específica de actividades y prácticas diseñada para crear valor.

Por ejemplo:

```text
Nueva aplicación
```

podría utilizar:

```text
PLAN
 ↓
ENGAGE
 ↓
DESIGN & TRANSITION
 ↓
OBTAIN/BUILD
 ↓
DELIVER & SUPPORT
 ↓
IMPROVE
```

Pero otro escenario puede seguir un camino diferente.

# 🧰 30. PRÁCTICAS

ITIL 4 sustituye la visión excesivamente centrada en "procesos" por una visión de **prácticas**.

Una práctica es:

> Un conjunto de recursos organizativos diseñados para realizar un trabajo o alcanzar un objetivo.

ITIL 4 agrupa las prácticas en:

```text

```

```text
14 prácticas de gestión general
17 prácticas de gestión de servicios
3 prácticas de gestión técnica
```

# 🚨 34. INCIDENTE

Un **incidente** es una interrupción no planificada de un servicio o una reducción de la calidad de un servicio.

Ejemplo:

```text
La aplicación deja de estar disponible.
```

Objetivo de Incident Management:

```text
restaurar el funcionamiento normal
lo antes posible
```

---

# 🧠 35. PROBLEMA

Un **problema** es una causa, o causa potencial, de uno o más incidentes.

Ejemplo:

```text
INCIDENTE
→ aplicación se cae

PROBLEMA
→ fallo recurrente en una dependencia
```

---

# 🔥 36. INCIDENTE VS PROBLEMA

| Incidente | Problema |
|---|---|
| Interrupción/reducción del servicio | Causa real o potencial |
| Busca restaurar servicio | Busca reducir/prevenir incidentes |
| Respuesta operativa | Análisis y gestión de causa |

### Frase para memorizar

```text
INCIDENTE
→ "haz que vuelva a funcionar"

PROBLEMA
→ "averigua por qué ocurre"
```

---

# 🎫 37. SERVICE REQUEST

Una **service request** es una petición de servicio predefinida iniciada por un usuario.

Ejemplos:

```text
solicitar acceso
pedir software autorizado
solicitar información
restablecimiento de una cuenta
```

No debe confundirse automáticamente con un incidente.

---

# 🖥️ 38. SERVICE DESK

El **Service Desk** actúa como punto de entrada y contacto entre proveedor y usuarios.

Puede gestionar:

```text
incidentes
peticiones
comunicación
información
```

---

# 📊 39. SERVICE LEVEL MANAGEMENT

Se ocupa de definir, documentar y gestionar objetivos basados en negocio para los niveles de servicio.

Concepto clave:

```text
SLA
```

Un **Service Level Agreement** es un acuerdo documentado entre proveedor de servicios y cliente que identifica servicios y objetivos acordados.

# 🔄 40. CONTINUAL IMPROVEMENT

La mejora continua busca garantizar que:

```text
productos
+
servicios
+
prácticas
```

se mejoran continuamente.

No es:

```text
"arreglar cosas cuando fallan"
```

sino una actividad permanente.

# 🧭 41. MODELO DE MEJORA CONTINUA

El modelo puede expresarse mediante preguntas:

```text
1. ¿Cuál es la visión?

2. ¿Dónde estamos ahora?

3. ¿Dónde queremos estar?

4. ¿Cómo llegamos allí?

5. Actuar

6. ¿Hemos llegado?

7. ¿Cómo mantenemos el impulso?
```

La formulación exacta puede variar según la representación utilizada, pero el concepto fundamental es:

```text
visión
 ↓
situación actual
 ↓
objetivo
 ↓
plan
 ↓
acción
 ↓
evaluación
 ↓
mejora
```

# 🏛️ 42. GOBERNANZA

La gobernanza garantiza que la organización:

```text

+

+

```

En el SVS:

```text
GOVERNANCE
```

es un componente fundamental.

```text
gestión operativa diaria
```

# ⚖️ 44. ITIL VS ISO 20000

| ITIL | ISO/IEC 20000 |
|---|---|
| Framework de buenas prácticas | Norma internacional |
| Orienta sobre cómo gestionar servicios | Define requisitos de un SMS |
| No es una norma certificable de organización | Puede utilizarse para certificación |
| Proporciona prácticas y modelos | Establece requisitos de conformidad |

---

# 🧩 45. ITIL VS SCRUM

También es importante para el bloque:

| ITIL | Scrum |
|---|---|
| Gestión de servicios | Marco ágil |
| Operación y mejora de servicios | Desarrollo/gestión iterativa del trabajo |
| ITSM | Agile |
| Valor de servicios | Entrega incremental y feedback |

No son necesariamente competidores.

Pueden coexistir.

---

**R:** Una petición de servicio predefinida iniciada por un usuario.

---

## Tarjeta 9

**P:** ¿Qué diferencia hay entre utility y warranty?

**R:** Utility indica qué hace el servicio y warranty cómo funciona y con qué garantías.

---

## Tarjeta 10

**P:** ¿Qué es un SLA?

**R:** Un acuerdo documentado entre proveedor y cliente que establece servicios y objetivos de nivel de servicio acordados.
