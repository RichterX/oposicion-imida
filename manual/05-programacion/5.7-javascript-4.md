# 1. INTRODUCCIÓN

Hasta ahora hemos trabajado principalmente con código síncrono:

```javascript
const resultado = sumar(2, 3);

console.log(resultado);
```

El código se ejecuta siguiendo un orden.

Pero una aplicación web necesita realizar tareas que no terminan inmediatamente:

```text
peticiones HTTP
temporizadores
lectura de archivos
eventos
operaciones del navegador
```

Aquí aparece la asincronía.

---

# 2. SINCRONÍA

En un modelo síncrono, las operaciones se ejecutan siguiendo el orden del programa.

Conceptualmente:

```text
A
↓
B
↓
C
↓
D
```

Una operación puede bloquear la continuación hasta que termina.

---

# 3. ASINCRONÍA

La asincronía permite iniciar determinadas operaciones y continuar ejecutando otras tareas mientras esperamos su resultado.

Conceptualmente:

```text
A
↓
iniciar operación
↓
B
↓
C
↓
resultado de operación
```

Esto es fundamental en aplicaciones web.

---

# 4. JAVASCRIPT Y SINGLE THREAD

Tradicionalmente se describe JavaScript del navegador como un lenguaje cuya ejecución de código JavaScript ocurre en un único hilo principal.

Esto significa que existe un:

```text
Call Stack
```

principal para ejecutar el código JavaScript.

Pero el navegador proporciona mecanismos adicionales para trabajar con tareas asíncronas.

---

# 5. CALL STACK

El **Call Stack** es la pila donde se gestionan las llamadas de funciones que están ejecutándose.

Ejemplo:

```javascript
function uno() {
    dos();
}

function dos() {
    console.log("Hola");
}

uno();
```

Conceptualmente:

```text
Call Stack

dos()
uno()
global
```

Cuando `dos()` termina, sale de la pila.

Después termina `uno()`.

---

# 6. LIFO

Una pila utiliza normalmente el principio:

```text
LIFO
```

que significa:

```text
Last In
First Out
```

Es decir:

```text
último en entrar
→ primero en salir
```

---

# 7. WEB APIS

El navegador proporciona APIs que pueden realizar determinadas operaciones fuera de la ejecución directa del código JavaScript del Call Stack.

Ejemplos:

```text
setTimeout
DOM events
Fetch
timers
otras APIs del navegador
```

Cuando una operación asíncrona termina, su callback o continuación puede quedar preparada para ser procesada posteriormente.

---

# 8. EVENT LOOP

El **Event Loop** coordina el trabajo entre:

```text
Call Stack
colas de tareas
microtask queue
```

Su objetivo simplificado es comprobar cuándo puede ejecutarse código pendiente.

---

# 9. CALLBACK QUEUE / TASK QUEUE

Las tareas pendientes pueden esperar en una cola.

Ejemplo conceptual:

```text
Task Queue

callback A
callback B
callback C
```

Cuando el Call Stack queda libre, el Event Loop puede permitir que una tarea pendiente pase a ejecutarse.

---

# 10. MICROTASK QUEUE

Existe una cola de microtareas.

Entre las fuentes habituales de microtasks encontramos:

```text
Promises
queueMicrotask()
```

Las microtasks tienen un tratamiento prioritario frente a las tareas normales cuando el motor llega al punto correspondiente del ciclo del Event Loop.

---

# 11. MODELO SIMPLIFICADO

Podemos imaginar:

```text
                  ┌───────────────┐
                  │   JavaScript  │
                  │  Call Stack   │
                  └───────┬───────┘
                          │
                          ↓
                    Event Loop
                    /         \
                   ↓           ↓
            Microtask Queue   Task Queue
                   │           │
                   └─────┬─────┘
                         ↓
                    Call Stack
```

El modelo real del navegador es más complejo, pero este esquema sirve para estudiar los conceptos fundamentales.

---

# 12. `setTimeout()`

Permite programar un callback para ejecutarse después de un tiempo mínimo especificado.

Ejemplo:

```javascript
setTimeout(() => {
    console.log("Hola");
}, 1000);
```

No significa:

```text
"ejecuta exactamente después de 1000 ms"
```

Significa, de forma simplificada:

```text
"no ejecutar antes de ese tiempo y poner el callback a disposición cuando corresponda"
```

---

# 13. TRAMPA CLÁSICA DE `setTimeout`

Consideremos:

```javascript
console.log("A");

setTimeout(() => {
    console.log("B");
}, 0);

console.log("C");
```

Resultado:

```text
A
C
B
```

¿Por qué?

Porque:

```text
setTimeout(..., 0)
```

no ejecuta inmediatamente el callback.

El callback queda pendiente para una tarea posterior.

---

# 14. PROMISES

Una Promise representa el resultado eventual de una operación asíncrona.

Puede encontrarse en estados como:

```text
pending
fulfilled
rejected
```

---

# 15. ESTADO `pending`

Una Promise recién creada puede encontrarse:

```text
pending
```

Esto significa que todavía no se ha resuelto ni rechazado.

---

# 16. ESTADO `fulfilled`

Si la operación termina correctamente:

```text
fulfilled
```

La Promise tiene un valor de cumplimiento.

---

# 17. ESTADO `rejected`

Si la operación falla:

```text
rejected
```

La Promise tiene un motivo/razón de rechazo.

---

# 18. TRANSICIONES DE ESTADO

Una Promise puede pasar:

```text
pending
   ↓
fulfilled
```

o:

```text
pending
   ↓
rejected
```

Una vez establecida:

```text
fulfilled
```

o:

```text
rejected
```

no vuelve a:

```text
pending
```

---

# 19. CREAR UNA PROMISE

Ejemplo:

```javascript
const promesa =
    new Promise(
        (resolve, reject) => {

            const correcto = true;

            if (correcto) {
                resolve("OK");
            } else {
                reject(
                    new Error("Error")
                );
            }
        }
    );
```

---

# 20. `resolve()`

Indica que la operación ha terminado correctamente.

```javascript
resolve(valor);
```

El valor puede ser recuperado por:

```text
then()
```

---

# 21. `reject()`

Indica que la operación ha fallado.

```javascript
reject(error);
```

El rechazo puede manejarse mediante:

```text
catch()
```

---

# 22. `then()`

Permite registrar qué hacer cuando la Promise se cumple.

Ejemplo:

```javascript
promesa.then(
    resultado => {
        console.log(resultado);
    }
);
```

---

# 23. `catch()`

Permite manejar un rechazo.

```javascript
promesa.catch(
    error => {
        console.error(error);
    }
);
```

---

# 24. `finally()`

Permite ejecutar código independientemente de si la Promise termina correctamente o con rechazo.

```javascript
promesa.finally(
    () => {
        console.log(
            "Finalizado"
        );
    }
);
```

Es útil para tareas de limpieza:

```text
ocultar spinner
cerrar recurso
restablecer estado
```

---

# 25. ENCADENAMIENTO DE PROMISES

Los métodos:

```text
then()
catch()
finally()
```

permiten construir cadenas.

Ejemplo:

```javascript
obtenerUsuario()
    .then(usuario => {
        return obtenerPedidos(
            usuario.id
        );
    })
    .then(pedidos => {
        console.log(pedidos);
    })
    .catch(error => {
        console.error(error);
    });
```

---

# 26. RETURN EN `then()`

Una característica importante:

```javascript
promise
    .then(valor => {
        return otraPromise();
    })
    .then(resultado => {
        ...
    });
```

El segundo `then()` recibe el resultado de la Promise devuelta por el primero.

Esto permite encadenar operaciones asíncronas.

---

# 27. THROW EN PROMISE CHAIN

Si dentro de un callback de `then()` se produce:

```javascript
throw new Error(
    "Error"
);
```

la Promise resultante de ese `then()` queda rechazada.

Por tanto, puede ser capturada por:

```javascript
.catch(...)
```

---

# 28. `Promise.resolve()`

Crea una Promise cumplida a partir de un valor.

Ejemplo:

```javascript
Promise.resolve(10);
```

---

# 29. `Promise.reject()`

Crea una Promise rechazada:

```javascript
Promise.reject(
    new Error("Error")
);
```

---

# 30. `Promise.all()`

Permite esperar a varias Promises.

Ejemplo:

```javascript
const resultado =
    await Promise.all([
        obtenerUsuarios(),
        obtenerProductos(),
        obtenerPedidos()
    ]);
```

Si todas se cumplen:

```text
resultado
→ array con sus valores
```

Si una se rechaza:

```text
Promise.all()
→ se rechaza
```

---

# 31. `Promise.all()` Y CONCURRENCIA

Consideremos:

```javascript
await Promise.all([
    tareaA(),
    tareaB(),
    tareaC()
]);
```

Las operaciones se inician antes de esperar conjuntamente sus resultados.

Es útil cuando:

```text
las tareas son independientes
```

y necesitamos todas para continuar.

---

# 32. `Promise.allSettled()`

Espera a que todas las Promises terminen, independientemente de si:

```text
fulfilled
```

o:

```text
rejected
```

Ejemplo:

```javascript
const resultados =
    await Promise.allSettled([
        tareaA(),
        tareaB(),
        tareaC()
    ]);
```

Cada resultado contiene información sobre su estado.

---

# 33. `Promise.race()`

Devuelve una Promise que adopta el estado de la primera Promise del conjunto que se establezca.

Ejemplo:

```javascript
const resultado =
    await Promise.race([
        tareaA(),
        tareaB()
    ]);
```

La primera que termine en:

```text
fulfilled
```

o:

```text
rejected
```

determina el resultado de la Promise devuelta.

---

# 34. `Promise.any()`

Espera hasta encontrar una Promise que se cumpla.

Ejemplo:

```javascript
const resultado =
    await Promise.any([
        servidorA(),
        servidorB(),
        servidorC()
    ]);
```

Si alguna se cumple:

```text
→ devuelve su valor
```

Si todas se rechazan:

```text
→ rechaza con AggregateError
```

---

# 35. 🧠 DIFERENCIAS ENTRE MÉTODOS

```text
Promise.all()
→ necesito todas
→ falla si una rechaza

Promise.allSettled()
→ quiero conocer el resultado de todas

Promise.race()
→ me interesa la primera que se establezca

Promise.any()
→ me interesa la primera que se cumpla
```

Esta tabla es carne de test.

---

# 36. MICROTASKS Y PROMISES

Los callbacks de:

```text
then()
catch()
finally()
```

se ejecutan mediante la cola de microtasks.

Por ello, una Promise resuelta puede ejecutarse antes que determinadas tareas normales pendientes.

---

# 37. EJEMPLO

```javascript
console.log("A");

setTimeout(() => {
    console.log("B");
}, 0);

Promise.resolve().then(() => {
    console.log("C");
});

console.log("D");
```

Resultado habitual:

```text
A
D
C
B
```

Porque:

```text
A
D
→ microtask Promise
C
→ task de setTimeout
B
```

---

# 38. `async`

Una función declarada como:

```javascript
async function obtenerDatos() {
    ...
}
```

siempre devuelve una Promise.

---

# 39. `async` Y RETURN

Ejemplo:

```javascript
async function obtenerNumero() {
    return 10;
}
```

No devuelve directamente:

```text
10
```

Devuelve una Promise cumplida con:

```text
10
```

Conceptualmente:

```javascript
Promise.resolve(10)
```

---

# 40. `await`

Permite esperar el resultado de una Promise dentro de una función `async`.

Ejemplo:

```javascript
async function obtenerDatos() {

    const respuesta =
        await fetch("/api/users");

    return respuesta;
}
```

---

# 41. `await` NO BLOQUEA TODO JAVASCRIPT

Esto es importante.

Cuando utilizamos:

```javascript
await
```

la función `async` queda suspendida hasta que la Promise se establece.

No significa que el hilo principal completo quede bloqueado esperando.

El resto de tareas del entorno puede continuar.

---

# 42. TRY / CATCH CON ASYNC

Podemos manejar errores:

```javascript
async function cargar() {

    try {

        const datos =
            await obtenerDatos();

        console.log(datos);

    } catch (error) {

        console.error(error);
    }
}
```

---

# 43. `finally` CON ASYNC

También:

```javascript
try {
    await cargarDatos();
} catch (error) {
    console.error(error);
} finally {
    ocultarSpinner();
}
```

---

# 44. ASYNC ARROW FUNCTION

También podemos escribir:

```javascript
const cargar =
    async () => {

        const datos =
            await obtenerDatos();

        return datos;
    };
```

---

# 45. FETCH API

`fetch()` permite realizar peticiones de red.

Ejemplo:

```javascript
const respuesta =
    await fetch(
        "/api/users"
    );
```

Devuelve una:

```text
Promise<Response>
```

---

# 46. RESPONSE

La respuesta HTTP está representada por:

```text
Response
```

Podemos consultar:

```text
status
ok
headers
url
```

entre otras propiedades.

---

# 47. `response.ok`

Indica si el estado HTTP se encuentra en el rango:

```text
200-299
```

Ejemplo:

```javascript
if (!response.ok) {
    throw new Error(
        "Error HTTP"
    );
}
```

### ⚠️ Trampa importante

`fetch()` no rechaza automáticamente la Promise simplemente porque el servidor responda con:

```text
404
500
```

Los errores HTTP deben comprobarse mediante propiedades como:

```text
response.ok
response.status
```

---

# 48. `response.status`

Permite obtener el código HTTP.

Ejemplo:

```javascript
console.log(
    response.status
);
```

Podría ser:

```text
200
404
500
```

---

# 49. LEER JSON

Si la respuesta contiene JSON:

```javascript
const datos =
    await response.json();
```

`response.json()` devuelve una Promise.

Por eso:

```javascript
const datos =
    await response.json();
```

---

# 50. `response.text()`

También podemos obtener texto:

```javascript
const texto =
    await response.text();
```

---

# 51. OTROS MÉTODOS DE RESPONSE

Según el contenido podemos utilizar:

```text
json()
text()
blob()
arrayBuffer()
formData()
```

No todos son apropiados para todos los tipos de respuesta.

---

# 52. GET

Una petición GET básica:

```javascript
const response =
    await fetch(
        "/api/users"
    );
```

El método predeterminado es:

```text
GET
```

---

# 53. POST

Podemos especificar:

```javascript
const response =
    await fetch(
        "/api/users",
        {
            method: "POST",
            headers: {
                "Content-Type":
                    "application/json"
            },
            body: JSON.stringify({
                nombre: "Pedro"
            })
        }
    );
```

---

# 54. HEADERS

Podemos enviar cabeceras:

```javascript
headers: {
    "Content-Type":
        "application/json",
    "Authorization":
        "Bearer token"
}
```

---

# 55. BODY

El body puede contener datos apropiados al tipo de petición.

Para JSON:

```javascript
body: JSON.stringify({
    nombre: "Pedro"
})
```

Es habitual utilizar:

```text
Content-Type: application/json
```

---

# 56. PETICIÓN COMPLETA

Ejemplo:

```javascript
async function crearUsuario() {

    const response =
        await fetch(
            "/api/users",
            {
                method: "POST",

                headers: {
                    "Content-Type":
                        "application/json"
                },

                body: JSON.stringify({
                    nombre: "Pedro",
                    activo: true
                })
            }
        );

    if (!response.ok) {
        throw new Error(
            `HTTP ${response.status}`
        );
    }

    return response.json();
}
```

---

# 57. ABORTCONTROLLER

Podemos cancelar determinadas operaciones de Fetch mediante:

```javascript
const controller =
    new AbortController();

fetch(
    "/api/users",
    {
        signal:
            controller.signal
    }
);
```

Posteriormente:

```javascript
controller.abort();
```

puede abortar la operación asociada.

---

# 58. TIMEOUT CON ABORTCONTROLLER

Una técnica habitual:

```javascript
const controller =
    new AbortController();

const timeout =
    setTimeout(
        () => controller.abort(),
        5000
    );

try {

    const response =
        await fetch(
            "/api/users",
            {
                signal:
                    controller.signal
            }
        );

} finally {

    clearTimeout(timeout);
}
```

# 59. CORS

CORS significa:

```text
Cross-Origin Resource Sharing
```

Es un mecanismo mediante el cual el navegador controla determinadas solicitudes entre orígenes diferentes.

Por ejemplo:

```text
frontend.example.com
        ↓
api.example.com
```

pueden considerarse orígenes diferentes.

---

# 60. ORIGIN

Un origen está determinado por:

```text
scheme
host
port
```

Por ejemplo:

```text
https://example.com
```

y:

```text
http://example.com
```

no tienen el mismo origen porque cambia el esquema.

---

# 61. CORS NO ES UNA REGLA DEL BACKEND ÚNICAMENTE

El navegador aplica restricciones relacionadas con CORS.

El servidor puede proporcionar cabeceras que indiquen qué orígenes están permitidos.

Ejemplo conceptual:

```text
Access-Control-Allow-Origin
```

---

# 62. PREFLIGHT

Determinadas solicitudes cross-origin pueden provocar una petición previa:

```text
OPTIONS
```

conocida como:

```text
preflight
```

Su objetivo es comprobar si la solicitud real está permitida.

---

# 63. CREDENTIALS

Fetch permite configurar credenciales mediante:

```javascript
credentials
```

Valores relevantes:

```text
omit
same-origin
include
```

Esto está relacionado con:

```text
cookies
autenticación
CORS
```
