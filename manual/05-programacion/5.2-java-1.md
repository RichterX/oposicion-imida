# 2. ¿QUÉ ES JAVA?

Java es un lenguaje compilado a **bytecode**, que normalmente se ejecuta sobre una **JVM (Java Virtual Machine)**.

El flujo conceptual es:

```text
Código fuente
    ↓
Compilador
    ↓
Bytecode
    ↓
JVM
    ↓
Sistema operativo
```

Esto permite que un mismo bytecode pueda ejecutarse en diferentes plataformas que dispongan de una JVM compatible.

Una de las ideas históricas asociadas a Java es:

```text
Write Once, Run Anywhere
```

---

# 3. JVM

JVM significa:

```text
Java Virtual Machine
```

Es el componente que ejecuta el bytecode.

Conceptualmente:

```text
programa Java
     ↓
  bytecode
     ↓
    JVM
     ↓
  ejecución
```

### 🧠 Para examen

Si preguntan:

> ¿Qué ejecuta el bytecode Java?

Respuesta:

```text
JVM
```

---

# 4. BYTECODE

El código fuente Java suele escribirse en:

```text
.java
```

Después de compilarlo se obtiene bytecode, normalmente en:

```text
.class
```

Ejemplo:

```text
Hola.java
   ↓
compilación
   ↓
Hola.class
```

---

# 5. `javac`

El compilador tradicional de Java es:

```text
javac
```

Ejemplo:

```bash
javac Hola.java
```

Esto puede generar:

```text
Hola.class
```

Después:

```bash
java Hola
```

ejecuta la clase mediante la JVM.

### 🧠 Regla

```text
javac
→ compila

java
→ ejecuta
```

---

# 6. JDK

JDK significa:

```text
Java Development Kit
```

Es el kit destinado al desarrollo Java.

Incluye herramientas necesarias para desarrollar y ejecutar aplicaciones Java, entre ellas el compilador y la JVM.

### 🧠 Regla

```text
JDK
→ desarrollar
```

---

# 7. JRE

JRE significa:

```text
Java Runtime Environment
```

Históricamente se utilizaba para proporcionar el entorno necesario para ejecutar aplicaciones Java.

### 🧠 Regla conceptual

```text
JRE
→ ejecutar
```

En Java moderno la distribución del JRE independiente ha cambiado, especialmente desde Java 9, por lo que conviene entender estos términos históricamente y no reducirlos a una fórmula rígida.

---

# 8. JVM VS JRE VS JDK

|---|---|
| JVM | Ejecuta bytecode |
| JRE | Entorno tradicional de ejecución |

# 12. `public`


es un modificador de acceso.

# 13. `main()`

El punto de entrada tradicional de una aplicación Java es:

```java
public static void main(String[] args)
```

Cuando ejecutamos una clase como aplicación, la JVM busca este método como punto de entrada.

---

# 14. DESCOMPONIENDO `main`

```java
public static void main(String[] args)
```

### `public`

Indica el acceso del método.

### `static`

El método pertenece a la clase y no requiere una instancia para ser invocado.

### `void`

No devuelve ningún valor.

### `main`

Es el nombre convencional del punto de entrada.

### `String[] args`

Es un array de cadenas que recibe los argumentos de línea de comandos.


La diferencia:

```text
println()
→ imprime y añade salto de línea
```

# 19. VARIABLES

# 20. TIPADO ESTÁTICO

Java utiliza tipado estático.

Por ejemplo:

```java
int edad = 35;
```

No podemos hacer:

```java
edad = "Pedro";
```

porque `edad` fue declarada como:

```text
int
```

y la cadena es:

```text
String
```

El compilador detectará la incompatibilidad.


Esta lista es importante para examen.

---

# 22. `byte`

```java

```

Características:


---

# 23. `short`

```java

```

Características:

```text
16 bits
```

Rango:

```text
-32.768 a 32.767
```

# 24. `int`

```java
int edad = 35;
```

Características:

```text

```

Rango:

```text
-2³¹ a 2³¹ - 1
```

Es decir:

```text
-2.147.483.648

2.147.483.647
```

Es el entero de uso general más habitual.

# 25. `long`

```java

```

# 26. `float`

---

# 27. `double`


# 28. `char`

Se utilizan:

```text

```

Mientras:

```java

```

# 29. `boolean`


# 30. `String`

# 42. COMPARACIÓN

# 43. `==` EN JAVA

Para tipos primitivos:

```java
a == b
```

compara valores.

Con referencias:

```java
objeto1 == objeto2
```

compara si ambas referencias representan el mismo objeto.

Para comparar contenido de objetos como `String` se utiliza normalmente:

```java
equals()
```

Ejemplo:

```java
String a = new String("Hola");
String b = new String("Hola");

a.equals(b)
```

produce:

```text
true
```

mientras:

```java
a == b
```

puede ser:

```text
false
```

porque son objetos diferentes.

# 44. OPERADORES LÓGICOS

Java utiliza:

```text
&&
||
!
```

Equivalencias:

```text
&& → AND
|| → OR
!  → NOT
```

Ejemplo:

```java
if (edad >= 18 && activo) {
    ...
}
```

---

# 45. CORTOCIRCUITO

`&&` y `||` utilizan evaluación de cortocircuito.

Ejemplo:

```java
if (objeto != null && objeto.estaActivo()) {
    ...
}
```

Si:

```text
objeto != null
```

es falso, la segunda condición no se evalúa.

---

# 46. `&` Y `|`

No debemos confundir:

```text
&&
||
```

con:

```text
&
|
```

En general:

```text
&& / ||
→ operadores lógicos con cortocircuito

& / |
→ operadores bit a bit y también pueden operar sobre booleanos sin cortocircuito
```

Para condiciones habituales:

```java
if (a && b)
```

es la forma esperada.

# 47. INCREMENTO Y DECREMENTO

Java dispone de:

```text
++
--
```

Ejemplo:

```java

contador++;
```

Ahora:

```text
contador = 1
```

---

# 48. PREFIJO VS POSTFIJO

```java
++i
```

incrementa antes de utilizar el valor de la expresión.

```java
i++
```

utiliza primero el valor actual y después incrementa.

Ejemplo:

```java
int a = 5;
int b = a++;
```

Resultado:

```text
a = 6
b = 5
```

En cambio:

```java
int a = 5;
int b = ++a;
```

produce:

```text
a = 6
b = 6
```

# 54. `switch`

Forma tradicional:

```java
switch (dia) {

    case 1:
        System.out.println("Lunes");
        break;

    case 2:
        System.out.println("Martes");
        break;

    default:
        System.out.println("Otro");
}
```

---

# 55. `break` EN `switch`

En el `switch` tradicional:

```java
break;
```

evita continuar ejecutando los siguientes casos.

Si se omite, puede producirse:

```text
fall-through
```

---

# 56. `default`

```java
default:
```

se utiliza cuando ningún `case` coincide.

Conceptualmente:

```text
switch
├── case
├── case
├── case
└── default
```

---

# 57. SWITCH MODERNO

Las versiones modernas de Java permiten:

```java
String resultado = switch (dia) {
    case 1 -> "Lunes";
    case 2 -> "Martes";
    default -> "Otro";
};
```

El operador:

```text
->
```

permite una sintaxis más compacta y evita el `break` tradicional en estos casos.
