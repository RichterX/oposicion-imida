# 1. INTRODUCCIÓN

En esta parte vamos a cubrir varias piezas del ecosistema estándar de Java que aparecen constantemente en código real y que pueden convertirse fácilmente en preguntas de oposición.

La estructura será:

```text
Cadenas
   ↓
Wrappers
   ↓
Autoboxing
   ↓
Fechas y horas
   ↓
Expresiones regulares
   ↓
Archivos / NIO
   ↓
Serialización
```

Aquí hay varias trampas clásicas:

```text
String es inmutable
StringBuilder es mutable
StringBuffer es mutable y sincronizado

int ≠ Integer

== ≠ equals()

LocalDate ≠ LocalDateTime

Period ≠ Duration

Path ≠ File

Pattern ≠ Matcher
```

# 2. `String`

`String` representa cadenas de caracteres.

Ejemplo:

```java
String nombre = "Pedro";
```

Es una clase de Java:

```text
java.lang.String
```

Por pertenecer a `java.lang`, no necesitamos importarla explícitamente.

---

# 3. STRING ES INMUTABLE

Una de las características fundamentales de `String`:

```text
es inmutable
```

Ejemplo:

```java
String texto = "Hola";

texto.toUpperCase();
```

La llamada no modifica el objeto original.

Para conservar el resultado:

```java
texto = texto.toUpperCase();
```

Conceptualmente:

```text
"Hola"
  ↓
toUpperCase()
  ↓
" HOLA "
```

se crea/obtiene otra cadena.

```java
String mensaje =
```

# 6. `length()`

Devuelve la longitud:

```java
String texto = "Hola";

int longitud = texto.length();
```

Resultado:

```text
4
```

### ⚠️ Trampa


En un array:

```java

```

es un campo.

# 8. `substring()`

```java
String texto = "Hola mundo";
```

# 12. `equals()` VS `equalsIgnoreCase()`

```java
"Hola".equals("Hola");
```

→ `true`

Mientras:

```java
"Hola".equals("hola");
```

→ `false`

Podemos ignorar mayúsculas/minúsculas:

```java
"Hola".equalsIgnoreCase("hola");
```

→ `true`

# 13. `trim()` VS `strip()`

`trim()` elimina determinados espacios de los extremos.

Java moderno proporciona:

```java
strip()
```

que utiliza una definición basada en espacios Unicode.

Ejemplo:

```java
String texto = "  Hola  ";

texto.trim();
texto.strip();
```

Ambos pueden eliminar espacios de los extremos en casos habituales, pero `strip()` es la alternativa moderna y más adecuada para Unicode.

# 17. STRING POOL

Java utiliza un mecanismo conocido como:

```text
String Pool
```

para determinadas cadenas literales.

Ejemplo:

```java
String a = "Hola";
String b = "Hola";
```

El runtime puede hacer que ambas referencias apunten a la misma instancia internada.

Por ello:

```java
a == b
```

puede ser:

```text
true
```

Pero no debemos utilizar `==` para comprobar igualdad lógica de cadenas.

La forma correcta:

```java
a.equals(b)
```

---

# 18. `new String()`

Si hacemos:

```java
String a = new String("Hola");
String b = new String("Hola");
```

estamos creando objetos distintos.

Por tanto:

```java
a == b
```

normalmente será:

```text
false
```

mientras:

```java
a.equals(b)
```

será:

```text
true
```

---

# 19. `intern()`

`intern()` permite obtener la representación canónica de una cadena en el pool de strings.

Ejemplo:

```java
String texto =
    new String("Hola");

String internado =
    texto.intern();
```

Esto puede hacer que la referencia obtenida corresponda a la cadena internada.

Para examen basta recordar:

```text
intern()
→ interacción con String Pool
```

# 20. `StringBuilder`

Cuando necesitamos construir/modificar cadenas repetidamente, podemos utilizar:

```java
StringBuilder
```

Ejemplo:

```java
StringBuilder sb =
    new StringBuilder();

sb.append("Hola");
sb.append(" ");
sb.append("Pedro");

String resultado =
    sb.toString();
```

# 21. STRINGBUILDER ES MUTABLE

A diferencia de `String`:

```text
String
→ inmutable

StringBuilder
→ mutable
```

Por eso es adecuado para concatenaciones repetidas.

# 27. `StringBuffer`

`StringBuffer` también es mutable.

La diferencia histórica importante:

```text
StringBuilder
→ no sincronizado

StringBuffer
→ sincronizado
```

Por tanto, `StringBuffer` está pensado para escenarios donde su sincronización interna sea relevante.

En código moderno de un único hilo:

```text
StringBuilder
```

suele ser la opción habitual.

# 30. ¿POR QUÉ EXISTEN LOS WRAPPERS?

Porque determinadas APIs trabajan con:

```text
objetos
```

en lugar de tipos primitivos.

Por ejemplo:

```java
List<Integer> numeros =
    new ArrayList<>();
```

No podemos utilizar directamente:

```java
List<int>
```

# 31. AUTOBOXING

Java puede convertir automáticamente:

```text
primitivo
→ wrapper
```

Ejemplo:

```java
Integer numero = 10;
```

Conceptualmente:

```text
int
 ↓
Integer
```

Esto es:

```text
autoboxing
```

---

# 32. UNBOXING

También puede ocurrir lo contrario:

```java
Integer numero = 10;

int valor = numero;
```

Conceptualmente:

```text
Integer
   ↓
 int
```

Esto es:

```text
unboxing
```

# 35. `Integer` Y `==`

Aquí aparece una trampa clásica:


Puede producir:


Pero:

```java
Integer a = 1000;
Integer b = 1000;
```

no debe asumirse como `true`.

### 🧠 Regla

Para comparar valores de wrappers:

```java
a.equals(b)
```

# 52. EXPRESIONES REGULARES

Las expresiones regulares permiten describir patrones de texto.

Ejemplo:

```text
\d+
```

representa una secuencia de uno o más dígitos.

Java proporciona:

```text

```

en:

```java

```

---

# 53. `Pattern`

`Pattern` representa una expresión regular compilada.

Ejemplo:

```java
Pattern patron =
    Pattern.compile("\\d+");
```

---

# 54. `Matcher`

`Matcher` permite aplicar un patrón sobre una secuencia de caracteres.

Ejemplo:

```java
Matcher matcher =
    patron.matcher("12345");
```

---

# 55. `matches()`

Comprueba si toda la entrada coincide con el patrón:

```java
boolean valido =
    matcher.matches();
```

---

# 56. `find()`

Busca la siguiente coincidencia dentro del texto:

```java
while (matcher.find()) {
    System.out.println(
        matcher.group()
    );
}
```

Diferencia:

```text
matches()
→ toda la entrada

find()
→ busca coincidencias dentro del texto
```

---

# 57. `group()`

Después de encontrar una coincidencia:

```java
matcher.group()
```

devuelve el texto correspondiente a la coincidencia actual.

---

# 58. GRUPOS CAPTURADOS


# 71. SERIALIZACIÓN

La serialización permite representar el estado de un objeto en una forma que pueda almacenarse o transmitirse.

Java proporciona tradicionalmente:

```java
Serializable
```

Ejemplo:

```java
class Persona
        implements Serializable {

    private String nombre;
}
```

---

# 72. `Serializable`

`Serializable` es una:

```text
interfaz marcador
```

No necesita implementar métodos.

Indica que una clase puede participar en el mecanismo de serialización estándar de Java.

---

# 73. `ObjectOutputStream`

Puede utilizarse para serializar objetos:

```java
ObjectOutputStream out =
    new ObjectOutputStream(
        new FileOutputStream("datos.ser")
    );

out.writeObject(persona);
```

---

# 74. `ObjectInputStream`

Para deserializar:

```java
ObjectInputStream in =
    new ObjectInputStream(
        new FileInputStream("datos.ser")
    );

Persona persona =
    (Persona) in.readObject();
```

---

# 75. `transient`

Un campo:

```java
transient
```

no participa en la serialización estándar de Java.

Ejemplo:

```java
private transient String password;
```

Esto permite excluir ese campo del mecanismo estándar.

### ⚠️ Importante

`transient` no es un mecanismo general de cifrado.

---

# 76. `serialVersionUID`

Una clase serializable puede declarar:

```java
private static final long serialVersionUID = 1L;
```

Se utiliza para controlar la compatibilidad de versiones durante la deserialización.

---

# 77. RIESGOS DE LA SERIALIZACIÓN

La deserialización de datos no confiables puede ser peligrosa.

Por eso, en aplicaciones modernas debemos evitar asumir:

```text
"Serializable = seguro"
```

La serialización nativa de Java tiene implicaciones de seguridad y compatibilidad que deben considerarse cuidadosamente.
