# 2. FORMULARIOS: VALIDACIÓN NATIVA

HTML permite realizar validaciones básicas sin necesidad de JavaScript.

Por ejemplo:

```html
<input
    type="email"
    required>
```

El navegador puede comprobar:

```text
campo obligatorio
formato de email
rangos
longitudes
patrones
```

según el tipo de control y sus atributos.

---

# 3. `min` Y `max`

Para determinados controles numéricos podemos indicar límites:

```html
<input
    type="number"
    min="18"
    max="100">
```

Esto establece:

```text
mínimo = 18
máximo = 100
```

---

# 4. `step`

El atributo:

```html
step
```

define el intervalo permitido entre valores.

Ejemplo:

```html
<input
    type="number"
    min="0"
    max="100"
    step="5">
```

Valores válidos podrían incluir:

```text
0
5
10
15
...
```

dependiendo del resto de restricciones.

---

# 5. `minlength` Y `maxlength`

Permiten establecer restricciones sobre la longitud de determinados campos de texto.

Ejemplo:

```html
<input
    type="text"
    minlength="3"
    maxlength="20">
```

---

# 6. `pattern`

Permite especificar una expresión regular para validar el valor de determinados controles de texto.

Ejemplo:

```html
<input
    type="text"
    pattern="[A-Za-z]{3,}">
```

El navegador puede utilizar este patrón durante la validación del formulario.

---

# 7. `autocomplete`

El atributo:

```html
autocomplete
```

permite indicar al navegador cómo debe tratar el autocompletado del campo.

Ejemplo:

```html
<input
    type="email"
    autocomplete="email">
```

Puede mejorar la experiencia de usuario y facilitar el rellenado de formularios.

---

# 8. `autofocus`

Permite indicar que un control debe recibir el foco inicialmente.

```html
<input
    type="text"
    autofocus>
```

Debe utilizarse con criterio, especialmente por cuestiones de accesibilidad y experiencia de usuario.

---

# 9. `novalidate`

El atributo:

```html
novalidate
```

puede utilizarse en un formulario para indicar que no se debe aplicar la validación nativa del navegador al enviarlo.

Ejemplo:

```html
<form
    action="/registro"
    method="post"
    novalidate>
```

---

# 10. `formnovalidate`

También existe:

```html
formnovalidate
```

que puede utilizarse en determinados controles de envío para evitar la validación nativa en ese envío concreto.

Ejemplo:

```html
<button
    type="submit"
    formnovalidate>
    Guardar
</button>
```

---

# 11. `form` COMO ATRIBUTO

Algunos controles pueden asociarse a un formulario mediante el atributo:

```html
form
```

Ejemplo:

```html
<form id="registro">
    ...
</form>

<input
    type="text"
    form="registro">
```

Esto permite asociar el control con un formulario concreto incluso cuando no está anidado directamente dentro de él.

---

# 12. `enctype`

El atributo:

```html
enctype
```

indica cómo se codifican los datos del formulario al enviarlos.

Valores importantes:

```text
application/x-www-form-urlencoded
multipart/form-data
text/plain
```

---

# 13. `application/x-www-form-urlencoded`

Es la codificación predeterminada habitual de los formularios.

Los datos se representan como pares:

```text
clave=valor
```

y se codifican para ser enviados.

---

# 14. `multipart/form-data`

Es especialmente importante cuando el formulario incluye archivos.

Ejemplo:

```html
<form
    action="/upload"
    method="post"
    enctype="multipart/form-data">

    <input
        type="file"
        name="archivo">

    <button type="submit">
        Subir
    </button>

</form>
```

### 🧠 Trampa de examen

```text
subir archivos
→ multipart/form-data
```

---

# 15. `accept`

En un campo de tipo archivo podemos indicar qué tipos de archivos se aceptan.

Ejemplo:

```html
<input
    type="file"
    accept="image/*">
```

Esto proporciona una indicación al navegador sobre los tipos de archivos permitidos.

No debe confundirse con una validación de seguridad en el servidor.

---

# 16. VALIDACIÓN CLIENTE VS SERVIDOR

La validación HTML ocurre en el:

```text
cliente / navegador
```

Pero nunca debemos confiar exclusivamente en ella.

La aplicación debe validar los datos también en el:

```text
servidor
```

porque el cliente puede ser manipulado.

### Regla fundamental

```text
Validación cliente
→ usabilidad

Validación servidor
→ seguridad e integridad
```

# 20. `<output>`


Ejemplo:


Representa:


aproximadamente en este ejemplo.

# 22. `<meter>`

Ejemplo:


```text

→ medida dentro de un rango
```

# 23. `<details>` Y `<summary>`

Ejemplo:

```html
    </p>
```

`summary` proporciona el título que puede activar la apertura/cierre.

# 24. `<dialog>`

```html
<dialog>
```

para representar una ventana de diálogo.


# 25. MULTIMEDIA: `<audio>`

Ya vimos la estructura básica:

```html
<audio controls>
    <source
        src="audio.mp3"
        type="audio/mpeg">
</audio>
```

Puede incluir:

```text
controls
autoplay
loop
muted
preload
```

según el comportamiento deseado y las políticas del navegador.

---

# 26. `autoplay`

Indica que el recurso multimedia debería comenzar automáticamente.

Sin embargo, los navegadores modernos pueden limitar la reproducción automática, especialmente cuando existe sonido.

Por tanto:

```text
autoplay
```

no garantiza que el navegador reproduzca automáticamente el contenido en todas las circunstancias.

---

# 27. `muted`

Permite iniciar un contenido multimedia sin sonido.

Ejemplo:

```html
<video
    autoplay
    muted>
</video>
```

Esto es relevante porque los navegadores suelen permitir determinados escenarios de reproducción automática silenciosa que pueden bloquear con sonido.

---

# 28. `loop`

Hace que el recurso vuelva a comenzar al finalizar.

```html
<video
    controls
    loop>
</video>
```

---

# 29. `preload`

Indica una preferencia sobre la precarga del contenido multimedia.

Valores habituales:

```text
none
metadata
auto
```

Conceptualmente:

```text
none
→ no precargar

metadata
→ precargar metadatos

auto
→ permitir mayor precarga
```

No es una garantía absoluta del comportamiento del navegador.

```html
        src="subtitulos-es.vtt"
```

```text
accesibilidad
subtítulos
```

# 31. FORMATO WEBVTT

El formato:

```text
WebVTT
```

puede utilizarse para pistas de texto asociadas a contenido multimedia.

Es habitual en subtítulos y otros tipos de pistas temporizadas.

---

# 32. `<picture>`

Permite proporcionar diferentes recursos de imagen según las condiciones.

Ejemplo:

```html
<picture>

    <source
        media="(min-width: 800px)"
        srcset="imagen-grande.jpg">

    <img
        src="imagen-pequena.jpg"
        alt="Paisaje">

</picture>
```

El elemento `img` actúa como recurso/fallback final.

---

# 33. `srcset`

Permite proporcionar diferentes versiones de una imagen.

Ejemplo:

```html
<img
    src="foto.jpg"
    srcset="
        foto-480.jpg 480w,
        foto-800.jpg 800w,
        foto-1200.jpg 1200w"
    alt="Paisaje">
```

El navegador puede seleccionar el recurso más adecuado según las condiciones.

---

# 34. `sizes`

Puede utilizarse junto con `srcset` para indicar al navegador el tamaño esperado de la imagen en diferentes condiciones de diseño.

Ejemplo:

```html
<img
    src="foto.jpg"
    srcset="
        foto-480.jpg 480w,
        foto-800.jpg 800w,
        foto-1200.jpg 1200w"
    sizes="
        (max-width: 600px) 480px,
        800px"
    alt="Paisaje">
```

Esto ayuda a realizar una selección eficiente del recurso.

---

# 35. `loading="lazy"`

Algunos recursos pueden cargarse de forma diferida.

Ejemplo:

```html
<img
    src="foto.jpg"
    loading="lazy"
    alt="Paisaje">
```

Esto puede mejorar el rendimiento al evitar cargar inmediatamente recursos que están fuera de la zona visible.

# 36. CANVAS

El elemento:

```html
<canvas>
```

proporciona una superficie de dibujo que puede manipularse normalmente mediante JavaScript.

Ejemplo:

```html
<canvas
    id="grafico"
    width="500"
    height="300">
</canvas>
```

Por sí mismo, `canvas` no contiene automáticamente un gráfico.

JavaScript se utiliza para dibujar.

---

# 37. CANVAS: MODELO

Conceptualmente:

```text
HTML
 ↓
<canvas>
 ↓
JavaScript
 ↓
dibujar píxeles / formas
```

Puede utilizarse para:

```text
gráficos

visualizaciones
animaciones
edición gráfica
```

---

# 38. CANVAS VS SVG

Esta diferencia es importante.

### Canvas

```text
superficie de dibujo
```

Los gráficos se representan mediante operaciones de dibujo.

### SVG

```text
gráficos vectoriales estructurados
```

Los elementos gráficos forman parte del documento y pueden manipularse individualmente.

---

# 39. SVG

SVG significa:

```text
Scalable Vector Graphics
```

Es un formato basado en XML para gráficos vectoriales.

Puede incorporarse directamente en HTML.

Ejemplo:

```html
<svg
    width="200"
    height="100">

    <circle
        cx="50"
        cy="50"
        r="40">
    </circle>

</svg>
```

---

# 40. VENTAJAS DE SVG

SVG resulta especialmente adecuado para:

```text
iconos
logotipos
diagramas
gráficos vectoriales
formas escalables
```

Al ser vectorial, puede escalarse sin la misma pérdida de calidad asociada a imágenes rasterizadas.

---

# 41. CANVAS VS SVG: RESUMEN

| Canvas | SVG |
|---|---|
| Superficie de dibujo | Elementos vectoriales |
| Manipulación habitual mediante JS | Elementos integrados en el DOM |
| Adecuado para gráficos dinámicos | Adecuado para gráficos vectoriales |
| Basado en dibujo | Basado en estructura |
| No representa cada forma como elemento DOM independiente | Cada elemento gráfico puede formar parte de la estructura SVG |

# 49. ACCESIBILIDAD

# 50. HTML NATIVO ANTES QUE ARIA

Una regla muy importante:

```text
usar HTML nativo cuando sea suficiente
```

Por ejemplo, es preferible:

```html

    Guardar
</button>
```

a convertir:

```html
<div role="button">
    Guardar
</div>
```

si no existe una razón específica para hacerlo.

# 51. ROLES ARIA

Ejemplo:

```html

    role="alert">
    Error al guardar
</div>
```

Pero añadir ARIA no convierte automáticamente un elemento en un control completamente accesible.

También pueden ser necesarios:

```text

gestión del foco
estado
eventos
```

# 68. `textContent` VS `innerHTML`

### `textContent`

Trabaja con texto.

```javascript
element.textContent =
    "Hola";
```

### `innerHTML`

Interpreta una cadena como HTML.

```javascript
element.innerHTML =
    "<strong>Hola</strong>";
```

`innerHTML` debe utilizarse con cuidado cuando el contenido procede de fuentes no confiables.

# 69. ALMACENAMIENTO WEB

Los navegadores ofrecen mecanismos de almacenamiento del lado del cliente.

Los más conocidos:

```text
localStorage
sessionStorage
```

---

# 70. `localStorage`

Permite almacenar pares:

```text
clave → valor
```

que permanecen disponibles entre sesiones del navegador, sujeto al origen y a las políticas del navegador.

Ejemplo:

```javascript
localStorage.setItem(
    "usuario",
    "Pedro"
);
```

Leer:

```javascript
localStorage.getItem(
    "usuario"
);
```

Eliminar:

```javascript
localStorage.removeItem(
    "usuario"
);
```

---

# 71. `sessionStorage`

Tiene una API similar:

```javascript
sessionStorage.setItem(
    "usuario",
    "Pedro"
);
```

Su almacenamiento está asociado a la sesión de navegación correspondiente y normalmente desaparece al finalizar esa sesión.

---

# 72. LOCALSTORAGE VS SESSIONSTORAGE

```text
localStorage
→ persiste entre sesiones

sessionStorage
→ asociado a la sesión
```

Ambos almacenan:

```text
strings
```

como valores.

Si necesitamos guardar objetos, normalmente debemos serializarlos, por ejemplo mediante JSON.

# 73. COOKIES

Pueden utilizarse para:

```text

```

Una diferencia importante:

```text
cookies
→ pueden enviarse automáticamente al servidor según sus atributos

→ no se envía automáticamente en cada petición HTTP
```

# 74. HTML5 APIs

HTML5 y la plataforma web moderna están asociadas a numerosas APIs.

Entre otras:

```text
DOM
Web Storage
Geolocation
Canvas
Drag and Drop
History
Web Workers
WebSockets
```

No todas son estrictamente "HTML" en sentido estricto, pero forman parte de la plataforma web que suele aparecer bajo el epígrafe HTML5.

# 75. GEOLOCATION

La API de Geolocation permite solicitar la ubicación del usuario cuando el navegador y el contexto lo permiten.

Conceptualmente:

```javascript
navigator.geolocation
```

El usuario debe conceder permiso cuando corresponda.

---

# 76. DRAG AND DROP

La plataforma web proporciona eventos y APIs para implementar arrastrar y soltar.

Conceptualmente:

```text
dragstart
dragover
drop
dragend
```

---

# 77. HISTORY API

Permite manipular determinadas partes del historial de navegación.

Ejemplos:

```javascript
history.back()
```

y APIs como:

```javascript
history.pushState(...)
history.replaceState(...)
```

Son especialmente relevantes para aplicaciones web tipo SPA.

---

# 78. WEB WORKERS

Los Web Workers permiten ejecutar determinado código JavaScript en un contexto separado del hilo principal.

Pueden ser útiles para tareas intensivas que no deberían bloquear la interfaz.

Conceptualmente:

```text
Página
  │
  ├── hilo principal
  │
  └── Worker
```

---

# 79. WEBSOCKETS

WebSocket permite establecer una comunicación persistente y bidireccional entre cliente y servidor.

Conceptualmente:

```text
Cliente ↔ Servidor
```

A diferencia del modelo HTTP tradicional de petición-respuesta, WebSocket permite que ambos extremos intercambien mensajes a través de una conexión persistente.

# 80. HTML Y SEGURIDAD

HTML por sí mismo no proporciona seguridad completa.

Una aplicación web debe considerar:

```text
validación servidor
control de acceso
gestión de sesiones
protección frente a XSS
CSRF
políticas de seguridad
```

Estos temas se amplían en otras áreas del desarrollo web.

---

# 81. XSS

XSS significa:

```text
Cross-Site Scripting
```

Consiste en la inyección de contenido ejecutable, habitualmente JavaScript, en un contexto donde puede ser interpretado por el navegador.

Una práctica especialmente peligrosa sería insertar directamente contenido no confiable mediante:

```javascript
element.innerHTML = contenidoNoConfiable;
```

cuando ese contenido puede contener HTML malicioso.

---

# 82. `textContent` COMO ALTERNATIVA

Si queremos insertar texto sin interpretarlo como HTML:

```javascript
element.textContent =
    contenido;
```

Esto evita que la cadena se interprete como marcado HTML.

No sustituye todas las medidas de seguridad, pero es una herramienta importante para evitar determinadas formas de inyección al trabajar con texto.

---

# 83. CSP

CSP significa:

```text
Content Security Policy
```

Es un mecanismo de seguridad basado principalmente en cabeceras HTTP que permite controlar qué recursos y comportamientos puede cargar o ejecutar una página.

No es simplemente una etiqueta HTML.

Puede trabajar junto con HTML para mejorar la seguridad de la aplicación.
