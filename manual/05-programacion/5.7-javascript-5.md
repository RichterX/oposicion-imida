# 2. MÓDULOS JAVASCRIPT

Los módulos permiten dividir una aplicación en diferentes archivos.

Por ejemplo:

```text
app.js
usuarios.js
api.js
utils.js
```

Cada módulo puede:

```text
exportar
```

funcionalidades y otros módulos pueden:

```text
importarlas
```

---

# 3. `export`

Podemos exportar una declaración:

```javascript
export const nombre =
    "Pedro";
```

También:

```javascript
export function saludar() {
    return "Hola";
}
```

---

# 4. `import`

Podemos importar:

```javascript
import {
    saludar
} from "./utils.js";
```

---

# 5. EXPORTACIÓN NOMBRADA

Ejemplo:

```javascript
export const PI = 3.14159;

export function sumar(a, b) {
    return a + b;
}
```

Podemos importar:

```javascript
import {
    PI,
    sumar
} from "./math.js";
```

---

# 6. `export default`

Un módulo puede tener una exportación predeterminada:

```javascript
export default function saludar() {
    return "Hola";
}
```

Se importa sin utilizar llaves:

```javascript
import saludar
    from "./saludar.js";
```

### 🧠 Diferencia

```text
named export
→ { nombre }

default export
→ nombre elegido por quien importa
```

---

# 7. RENOMBRAR IMPORTACIONES

Podemos utilizar:

```javascript
import {
    sumar as add
} from "./math.js";
```

Ahora utilizamos:

```javascript
add(2, 3);
```

---

# 8. EXPORTAR CON `as`

También:

```javascript
const sumar = ...;

export {
    sumar as add
};
```

---

# 9. IMPORTAR TODO

Podemos importar el namespace completo:

```javascript
import * as math
    from "./math.js";
```

Y utilizar:

```javascript
math.sumar(2, 3);
```

# 12. `localStorage`

Permite almacenar datos en el navegador asociados al origen.

Ejemplo:

```javascript
localStorage.setItem(
    "nombre",
    "Pedro"
);
```

---

# 13. `localStorage.getItem()`

Obtiene un valor:

```javascript
const nombre =
    localStorage.getItem(
        "nombre"
    );
```

Si la clave no existe:

```text
null
```

---

# 14. `localStorage.removeItem()`

Elimina una entrada:

```javascript
localStorage.removeItem(
    "nombre"
);
```

---

# 15. `localStorage.clear()`

Elimina las entradas almacenadas en ese almacenamiento para el contexto correspondiente:

```javascript
localStorage.clear();
```

---

# 16. `sessionStorage`

Tiene una API muy parecida:

```javascript
sessionStorage.setItem(
    "token",
    "abc"
);
```

Podemos recuperar:

```javascript
sessionStorage.getItem(
    "token"
);
```

---

# 17. `localStorage` VS `sessionStorage`

### `localStorage`

Los datos están pensados para persistir entre sesiones del navegador.

### `sessionStorage`

Los datos están asociados a la sesión de almacenamiento correspondiente a la pestaña/contexto y normalmente desaparecen cuando termina esa sesión.

### 🧠 Resumen

```text
localStorage
→ persistencia

sessionStorage
→ duración de sesión
```

---

# 18. TODO SE ALMACENA COMO STRING

La API de Web Storage almacena valores como cadenas.

Ejemplo:

```javascript
localStorage.setItem(
    "edad",
    30
);
```

Al recuperarlo:

```javascript
localStorage.getItem(
    "edad"
);
```

obtenemos:

```text
"30"
```

no:

```text
30
```

---

# 19. GUARDAR OBJETOS EN LOCALSTORAGE

No podemos almacenar directamente un objeto JavaScript como estructura compleja.

Podemos serializarlo:

```javascript
const usuario = {
    nombre: "Pedro",
    edad: 30
};

localStorage.setItem(
    "usuario",
    JSON.stringify(usuario)
);
```

Después:

```javascript
const usuario =
    JSON.parse(
        localStorage.getItem(
            "usuario"
        )
    );
```

---

# 20. ⚠️ LOCALSTORAGE Y SEGURIDAD

No debemos considerar `localStorage` un almacén seguro para secretos sensibles.

Por ejemplo, almacenar tokens de autenticación en `localStorage` puede aumentar el impacto de un ataque XSS porque JavaScript de la página puede acceder a ellos.

En sistemas de autenticación existen alternativas, como cookies con atributos apropiados, dependiendo de la arquitectura.

---

# 21. COOKIES

Las cookies son pequeños datos asociados a un dominio/origen y enviados por el navegador en determinadas peticiones HTTP según sus reglas.

Se utilizan frecuentemente para:

```text
sesiones
preferencias
identificación
autenticación
```

---

# 22. `document.cookie`

JavaScript puede acceder a las cookies disponibles para scripts mediante:

```javascript
document.cookie
```

Ejemplo:

```javascript
console.log(
    document.cookie
);
```

---

# 23. CREAR UNA COOKIE

Una forma sencilla:

```javascript
document.cookie =
    "usuario=Pedro";
```

Se pueden especificar atributos:

```javascript
document.cookie =
    "usuario=Pedro; Max-Age=3600; Path=/";
```

---

# 24. ATRIBUTOS IMPORTANTES DE COOKIES

Algunos atributos:

```text
Expires
Max-Age
Domain
Path
Secure
HttpOnly
SameSite
```

---

# 25. `HttpOnly`

Una cookie con:

```text
HttpOnly
```

no es accesible mediante:

```javascript
document.cookie
```

Esto es importante para reducir determinados riesgos de robo de cookies mediante JavaScript.

---

# 26. `Secure`

Indica que la cookie debe enviarse mediante conexiones seguras, normalmente HTTPS.

---

# 27. `SameSite`

Controla determinados comportamientos de la cookie en contextos de solicitudes cross-site.

Valores conocidos:

```text
Strict
Lax
None
```

---

# 28. COOKIE VS LOCALSTORAGE

Una diferencia fundamental:

```text
localStorage
→ almacenamiento del navegador
→ no se envía automáticamente en cada petición HTTP

cookie
→ puede enviarse automáticamente al servidor según dominio, path y demás atributos
```

---

# 29. MANEJO DE ERRORES

JavaScript dispone de:

```text
try
catch
finally
throw
Error
```

---

# 30. `try`

Contiene código que puede generar un error:

```javascript
try {
    realizarOperacion();
}
```

---

# 31. `catch`

Captura determinados errores producidos durante la ejecución del `try`.

```javascript
try {
    realizarOperacion();
} catch (error) {
    console.error(error);
}
```

---

# 32. `finally`

Se ejecuta después del bloque de manejo correspondiente, independientemente de que haya ocurrido un error en los casos habituales.

```javascript
try {
    realizarOperacion();
} catch (error) {
    console.error(error);
} finally {
    limpiar();
}
```

---

# 33. `throw`

Permite lanzar una excepción:

```javascript
throw new Error(
    "Algo salió mal"
);
```

También pueden lanzarse otros valores, aunque en código profesional es habitual lanzar objetos `Error` o subtipos apropiados.

---

# 34. OBJETO `Error`

Ejemplo:

```javascript
const error =
    new Error(
        "Usuario no encontrado"
    );
```

Podemos encontrar propiedades como:

```text
name
message
stack
```

---

# 35. TIPOS DE ERROR

JavaScript proporciona distintos constructores de error.

Por ejemplo:

```text
Error
TypeError
ReferenceError
SyntaxError
RangeError
URIError
EvalError
```

---

# 36. `TypeError`

Se produce cuando una operación no es válida para el tipo de valor utilizado.

Ejemplo conceptual:

```javascript
const numero = 10;

numero.foo();
```

---

# 37. `ReferenceError`

Aparece cuando se intenta acceder a una referencia que no existe en el contexto correspondiente.

Ejemplo:

```javascript
console.log(
    variableInexistente
);
```

---

# 38. `SyntaxError`

Indica un problema de sintaxis.

Ejemplo conceptual:

```javascript
if (
    ...
```

cuando falta la sintaxis necesaria para cerrar la construcción.

---

# 39. `RangeError`

Se utiliza cuando un valor está fuera del rango permitido en determinadas operaciones.

---

# 40. ERROR EN CÓDIGO ASÍNCRONO

Con `async/await`:

```javascript
async function cargar() {

    try {

        const datos =
            await obtenerDatos();

    } catch (error) {

        console.error(error);
    }
}
```

Un rechazo de una Promise esperado mediante `await` puede provocar que el control pase al `catch`.

# 41. EXPRESIONES REGULARES

Las expresiones regulares permiten describir patrones de texto.

Ejemplos de usos:

```text
validación
búsqueda
extracción
reemplazo
```

En JavaScript se representan mediante:

```text
RegExp
```

---

# 42. SINTAXIS LITERAL

Ejemplo:

```javascript
const patron =
    /hola/;
```

---

# 43. CONSTRUCTOR `RegExp`

También:

```javascript
const patron =
    new RegExp(
        "hola"
    );
```

---

# 44. `test()`

Comprueba si existe coincidencia.

```javascript
/hola/.test(
    "hola mundo"
);
```

Resultado:

```text
true
```

---

# 45. `match()`

Método de `String`:

```javascript
const resultado =
    "hola mundo".match(
        /hola/
    );
```

Devuelve información sobre la coincidencia o:

```text
null
```

si no hay coincidencia.

---

# 46. `search()`

Devuelve la posición de la primera coincidencia:

```javascript
"hola mundo".search(
    /mundo/
);
```

---

# 47. `replace()`

Permite reemplazar coincidencias:

```javascript
"hola mundo".replace(
    "mundo",
    "Pedro"
);
```

Resultado:

```text
"hola Pedro"
```

También puede utilizar expresiones regulares.

---

# 48. `replaceAll()`

Permite reemplazar todas las coincidencias apropiadas:

```javascript
"hola hola".replaceAll(
    "hola",
    "adiós"
);
```

Resultado:

```text
"adiós adiós"
```

---

# 49. FLAGS

Algunos:

```text

m
s
u

```

---

# 50. FLAG `i`

Ignora mayúsculas y minúsculas.

```javascript
/hola/i
```

Coincide con:

```text
hola
Hola
HOLA
```

---

# 51. FLAG `g`

Busca coincidencias globales.

```javascript
/hola/g
```

Es especialmente importante en operaciones como:

```text
match
replace
```

---

# 52. FLAG `m`

Activa el comportamiento multilínea de los anclajes:

```text
^
$
```

---

# 53. FLAG `s`

Permite que:

```text
.
```

coincida también con terminadores de línea en el modo correspondiente.

---

# 54. CARACTERES ESPECIALES

Algunos elementos frecuentes:

```text
.
^
$
*
+
?
```

---

# 55. `.`

Representa un carácter cualquiera salvo determinados terminadores de línea, salvo que se utilice el comportamiento correspondiente con `s`.

Ejemplo:

```javascript
/a.c/
```

puede coincidir con:

```text
abc

a1c
```

---

# 56. `^`

Representa el inicio según el modo de coincidencia.

Ejemplo:

```javascript
/^Hola/
```

busca:

```text
Hola
```

al comienzo de la cadena o línea según las reglas aplicables.

---

# 57. `$`

Representa el final según el modo de coincidencia.

```javascript
/mundo$/
```

---

# 58. `*`

Indica:

```text
cero o más
```

repeticiones del elemento anterior.

---

# 59. `+`

Indica:

```text
una o más
```

repeticiones.

---

# 60. `?`

Puede indicar:

```text
cero o una
```

repetición según el contexto.

También tiene otros usos en expresiones regulares.

---

# 61. CLASES DE CARACTERES

Ejemplo:


coincide con:

```text

b
c
```

---

# 62. RANGOS

Ejemplo:

```text
[a-z]
```

representa un rango de letras minúsculas según el conjunto de caracteres correspondiente.

También:

```text
[0-9]
```

---

# 63. `\d`

Representa un dígito decimal según las reglas de la expresión regular.

Una forma común de verlo:

```text
\d
```

→ dígito.

---

# 64. `\w`

Representa un carácter de palabra según las reglas de JavaScript RegExp.


# 65. `\s`

Representa espacios en blanco.

Puede incluir:

# 66. GRUPOS

Podemos agrupar expresiones:


# 67. ALTERNATIVAS


# 77. HISTORY API

El navegador proporciona:

```javascript
history
```

para trabajar con el historial de navegación.

Métodos importantes:

```text
back()
forward()
go()
pushState()
replaceState()
```

---

# 78. `history.back()`

Retrocede en el historial:

```javascript
history.back();
```

Conceptualmente equivale a navegar hacia la entrada anterior del historial.

---

# 79. `history.forward()`

Avanza:

```javascript
history.forward();
```

---

# 80. `history.go()`

Permite desplazarse una cantidad determinada:

```javascript
history.go(-1);
```

retrocede una entrada.

```javascript
history.go(1);
```

avanza una entrada.

---

# 81. `pushState()`

Permite añadir una entrada al historial sin provocar necesariamente una navegación tradicional ni recargar la página.

Ejemplo:

```javascript
history.pushState(
    {},
    "",
    "/usuarios"
);
```

Esto resulta especialmente importante en:

```text
SPAs
```

---

# 82. `replaceState()`

Modifica la entrada actual del historial:

```javascript
history.replaceState(
    {},
    "",
    "/login"
);
```

A diferencia de:

```text
pushState
```

no añade una nueva entrada.

---

# 83. EVENTO `popstate`

El evento:

```text
popstate
```

puede utilizarse para reaccionar a determinados cambios de entrada del historial, como los producidos mediante navegación atrás/adelante.

Ejemplo:

```javascript
window.addEventListener(
    "popstate",
    () => {
        console.log(
            "Historial cambiado"
        );
    }
);
```

---

# 84. `location`

El objeto:

```javascript
location
```

representa la URL actual del documento.

Ejemplo:

```javascript
location.href
```

---

# 85. PROPIEDADES DE LOCATION

Algunas propiedades:

```text
href
protocol
host
hostname
port
pathname
search
hash
origin
```

Muchas coinciden conceptualmente con las propiedades de `URL`.

---

# 86. `location.assign()`

Navega a una nueva URL:

```javascript
location.assign(
    "/login"
);
```

---

# 87. `location.replace()`

Navega a otra URL reemplazando la entrada actual del historial:

```javascript
location.replace(
    "/login"
);
```

Esto significa que el usuario no puede volver a esa entrada mediante el botón atrás de la misma forma que si se hubiera añadido una entrada nueva.

---

# 88. `location.reload()`

Recarga el documento:

```javascript
location.reload();
```

---

# 89. HISTORY VS LOCATION

Una forma sencilla de diferenciarlos:

```text
location
→ URL/navegación actual

history
→ historial de navegación
```
