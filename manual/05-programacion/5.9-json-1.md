# 2. ¿QUÉ SIGNIFICA JSON?

JSON significa:

```text
JavaScript Object Notation
```

Es un formato ligero para representar e intercambiar datos estructurados.

Aunque su nombre contiene:

```text
JavaScript
```

JSON no pertenece exclusivamente a JavaScript.

Es un formato independiente del lenguaje que puede ser utilizado por multitud de lenguajes de programación.

---

# 3. ¿PARA QUÉ SE UTILIZA JSON?

JSON se utiliza habitualmente para:

```text
intercambio de datos
APIs
configuración
almacenamiento de información
comunicación cliente-servidor
```

Un escenario extremadamente habitual:

```text
Frontend
   │
   │ JSON
   ↓
Backend
```

Por ejemplo:

```text
Vue
 ↓
HTTP
 ↓
Laravel
 ↓
JSON
```

Esto debería resultarte bastante familiar. 😄

---

# 4. JSON ES TEXTO

JSON es una representación textual de datos.

Ejemplo:

```json
{
    "nombre": "Pedro",
    "edad": 30
}
```

No es una estructura binaria.

Es texto que sigue una sintaxis determinada.

---

# 5. JSON VS OBJETO JAVASCRIPT

No debemos confundir:

```text
JSON
```

con:

```text
objeto JavaScript
```

JSON es texto.

Por ejemplo:

```javascript
const texto =
    '{"nombre":"Pedro"}';
```

Aquí:

```text
texto
→ string
```

No es un objeto JavaScript.

---

# 6. CONVERTIR JSON A OBJETO

JavaScript proporciona:

```javascript
JSON.parse()
```

Ejemplo:

```javascript
const texto =
    '{"nombre":"Pedro","edad":30}';

const usuario =
    JSON.parse(texto);
```

Ahora:

```text
usuario
→ objeto JavaScript
```

---

# 7. CONVERTIR OBJETO A JSON

Utilizamos:

```javascript
JSON.stringify()
```

Ejemplo:

```javascript
const usuario = {
    nombre: "Pedro",
    edad: 30
};

const texto =
    JSON.stringify(usuario);
```

Ahora:

```text
texto
→ string JSON
```

---

# 8. REGLA FUNDAMENTAL

Memoriza:

```text
JSON.parse()
→ JSON string → objeto/valor JavaScript
```

```text
JSON.stringify()
→ objeto/valor JavaScript → JSON string
```

---

# 9. ESTRUCTURA GENERAL

JSON se construye fundamentalmente a partir de:

```text
objetos
arrays
valores
```

Los valores pueden ser:

```text
string
number
boolean
null
object
array
```

---

# 10. OBJETO JSON

Un objeto JSON comienza con:

```text
{
```

y termina con:

```text
}
```

Ejemplo:

```json
{
    "nombre": "Pedro",
    "edad": 30
}
```

---

# 11. PARES CLAVE/VALOR

Los objetos contienen pares:

```text
clave : valor
```

Ejemplo:

```json
{
    "nombre": "Pedro"
}
```

Tenemos:

```text
clave
→ "nombre"

valor
→ "Pedro"
```

---

# 12. LAS CLAVES DEBEN SER STRINGS

En JSON, las claves de un objeto deben escribirse como strings entre comillas dobles.

Correcto:

```json
{
    "nombre": "Pedro"
}
```

Incorrecto:

```json
{
    nombre: "Pedro"
}
```

La segunda forma es válida como sintaxis de objeto JavaScript en determinados contextos, pero **no es JSON válido**.

---

# 13. COMILLAS DOBLES

JSON utiliza:

```text
"
```

para strings.

Ejemplo:

```json
{
    "nombre": "Pedro"
}
```

No debemos utilizar comillas simples como sintaxis JSON:

```json
{
    'nombre': 'Pedro'
}
```

Eso no es JSON válido.

---

# 14. ARRAY JSON

Los arrays utilizan:

```text
[
]
```

Ejemplo:

```json
[
    "Pedro",
    "Ana",
    "Luis"
]
```

---

# 15. ARRAY DE NÚMEROS

```json
[
    10,
    20,
    30
]
```

---

# 16. ARRAY DE OBJETOS

Muy habitual en APIs:

```json
[
    {
        "id": 1,
        "nombre": "Pedro"
    },
    {
        "id": 2,
        "nombre": "Ana"
    }
]
```

---

# 17. OBJETOS ANIDADOS

Los objetos pueden contener otros objetos.

```json
{
    "nombre": "Pedro",
    "direccion": {
        "ciudad": "Murcia",
        "pais": "España"
    }
}
```

Estructura:

```text
usuario
├── nombre
└── direccion
    ├── ciudad
    └── pais
```

---

# 18. ARRAYS ANIDADOS

También podemos tener arrays dentro de objetos:

```json
{
    "nombre": "Pedro",
    "roles": [
        "admin",
        "editor"
    ]
}
```

---

# 19. OBJETOS DENTRO DE ARRAYS DENTRO DE OBJETOS

No existe problema en combinar estructuras.

Ejemplo:

```json
{
    "usuarios": [
        {
            "id": 1,
            "roles": [
                "admin",
                "editor"
            ]
        },
        {
            "id": 2,
            "roles": [
                "editor"
            ]
        }
    ]
}
```

---

# 20. TIPOS PRIMITIVOS JSON

JSON reconoce estos valores fundamentales:

```text
string
number
true
false
null
```

Además:

```text
object
array
```

forman las estructuras compuestas.

---

# 21. STRINGS

Ejemplo:

```json
{
    "nombre": "Pedro"
}
```

Un string JSON está delimitado por:

```text
"
```

---

# 22. ESCAPADO DE STRINGS

Dentro de un string podemos utilizar secuencias de escape.

Por ejemplo:

```json
{
    "mensaje": "Hola \"Pedro\""
}
```

Las comillas internas se escapan con:

```text
\"
```

---

# 23. PRINCIPALES ESCAPES

Algunas secuencias:

| Escape | Significado |
|---|---|
| `\"` | comilla doble |
| `\\` | barra invertida |
| `\/` | barra `/` |
| `\b` | backspace |
| `\f` | form feed |
| `\n` | salto de línea |
| `\r` | retorno de carro |
| `\t` | tabulación |
| `\uXXXX` | carácter Unicode |

---

# 24. UNICODE

JSON permite representar caracteres Unicode mediante:

```text
\uXXXX
```

Ejemplo:

```json
{
    "letra": "\u0041"
}
```

representa:

```text
A
```

---

# 25. NÚMEROS

JSON permite representar números.

Ejemplos:

```json
{
    "entero": 10,
    "decimal": 10.5,
    "negativo": -20
}
```

---

# 26. NOTACIÓN EXPONENCIAL

También pueden utilizarse números en notación exponencial.

Ejemplo:

```json
{
    "valor": 1.5e3
}
```

---

# 27. JSON NO DIFERENCIA TIPOS ENTEROS Y DECIMALES

A nivel de sintaxis JSON existe:

```text
number
```

No hay una categoría sintáctica independiente:

```text
integer
float
decimal
```

como ocurre, por ejemplo, en XML Schema.

---

# 28. BOOLEANOS

JSON utiliza:

```text
true
false
```

en minúsculas.

Correcto:

```json
{
    "activo": true
}
```

Incorrecto:

```json
{
    "activo": True
}
```

---

# 29. `null`

JSON dispone de:

```text
null
```

Ejemplo:

```json
{
    "telefono": null
}
```

Representa ausencia de valor nulo.

---

# 30. NO EXISTEN `undefined` NI `NaN`

Una trampa importante:

JSON no tiene valores propios equivalentes a:

```text
undefined
NaN
Infinity
-Infinity
```

como valores JSON válidos.

---

# 31. PROPIEDADES OPCIONALES

JSON no dispone de una palabra reservada:

```text
optional
```

La ausencia de una propiedad se representa simplemente no incluyendo esa propiedad.

Ejemplo:

```json
{
    "nombre": "Pedro"
}
```

No existe:

```json
{
    "nombre": "Pedro",
    "telefono": undefined
}
```

como JSON válido.

---

# 32. COMAS

Los elementos de un objeto o array se separan mediante:

```text
,
```

Ejemplo:

```json
{
    "nombre": "Pedro",
    "edad": 30
}
```

---

# 33. NO HAY COMA FINAL

JSON no permite una coma final después del último elemento.

Incorrecto:

```json
{
    "nombre": "Pedro",
    "edad": 30,
}
```

Correcto:

```json
{
    "nombre": "Pedro",
    "edad": 30
}
```

---

# 34. OBJETO VACÍO

Es válido:

```json
{}
```

---

# 35. ARRAY VACÍO

También:

```json
[]
```

---

# 36. DOCUMENTO JSON

Un documento JSON puede tener como valor raíz un:

```text
objeto
```

o:

```text
array
```

y, en el estándar moderno, un valor JSON válido puede ser también un valor JSON de cualquier tipo permitido.

Para el examen, recuerda especialmente los casos habituales:

```text
{
    ...
}
```

y:

```text
[
    ...
]
```

---

# 37. WHITESPACE

JSON permite espacios en blanco en posiciones permitidas por la gramática.

Por ejemplo:

```json
{
    "nombre": "Pedro",
    "edad": 30
}
```

y:

```json
{"nombre":"Pedro","edad":30}
```

representan la misma estructura.

---

# 38. JSON NO ADMITE COMENTARIOS

JSON estándar no incluye sintaxis para:

```text
// comentario
```

ni:

```text
/* comentario */
```

Ejemplo inválido:

```json
{
    // nombre del usuario
    "nombre": "Pedro"
}
```

---

# 39. JSON Y CONFIGURACIÓN

JSON se utiliza también en archivos de configuración.

Ejemplo:

```json
{
    "servidor": {
        "host": "localhost",
        "puerto": 3306
    }
}
```

Sin embargo, que una aplicación acepte comentarios o extensiones similares depende de esa aplicación, no del estándar JSON.

---

# 40. JSON Y HTTP

En una API web es habitual enviar:

```text
HTTP
+
JSON
```

Ejemplo de petición:

```http
POST /api/usuarios
Content-Type: application/json
```

Body:

```json
{
    "nombre": "Pedro",
    "email": "pedro@example.com"
}
```

---

# 41. CONTENT-TYPE

Cuando enviamos JSON mediante HTTP, el tipo MIME habitual es:

```text
application/json
```

Esto indica que el cuerpo contiene datos JSON.

---

# 42. RESPUESTA JSON

Una API puede devolver:

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

Body:

```json
{
    "id": 15,
    "nombre": "Pedro"
}
```

---

# 43. JSON EN LARAVEL

En Laravel es habitual devolver datos que terminan serializándose como JSON.

Por ejemplo:

```php
return response()->json([
    'nombre' => 'Pedro',
    'edad' => 30
]);
```

La respuesta resultante será JSON.

---

# 44. JSON Y VUE

En una aplicación Vue, podemos recibir JSON desde una API:

```javascript
const response =
    await fetch('/api/usuarios');

const usuarios =
    await response.json();
```

Aquí:

```text
response
→ Response

response.json()
→ interpreta el cuerpo como JSON
```

---

# 45. `JSON.parse()`

`JSON.parse()` convierte una cadena JSON en un valor JavaScript.

Ejemplo:

```javascript
const texto =
    '{"nombre":"Pedro"}';

const usuario =
    JSON.parse(texto);

console.log(
    usuario.nombre
);
```

Resultado:

```text
Pedro
```

---

# 46. ERROR DE PARSE

Si la cadena no contiene JSON válido:

```javascript
JSON.parse(
    '{nombre:"Pedro"}'
);
```

se producirá un error de parsing, normalmente:

```text
SyntaxError
```

---

# 47. `JSON.stringify()`

Convierte un valor JavaScript a una cadena JSON.

Ejemplo:

```javascript
const usuario = {
    nombre: "Pedro",
    edad: 30
};

const json =
    JSON.stringify(usuario);
```

Resultado conceptual:

```text
'{"nombre":"Pedro","edad":30}'
```

---

# 48. SERIALIZACIÓN

El proceso:

```text
objeto JavaScript
        ↓
JSON.stringify()
        ↓
cadena JSON
```

se denomina:

```text
serialización
```

---

# 49. DESERIALIZACIÓN

El proceso contrario:

```text
cadena JSON
        ↓
JSON.parse()
        ↓
objeto/valor JavaScript
```

se denomina habitualmente:

```text
deserialización
```

---

# 50. PROPIEDADES NO SERIALIZABLES DE LA MISMA FORMA

Al utilizar `JSON.stringify()`, determinados valores JavaScript no tienen representación JSON directa.

Por ejemplo:

```text
undefined
function
Symbol
```

pueden omitirse o transformarse según el contexto.

---

# 51. FUNCIONES

Ejemplo:

```javascript
const usuario = {
    nombre: "Pedro",
    saludar: function () {
        console.log("Hola");
    }
};
```

Al serializar el objeto, la función no se representa como una función JSON.

---

# 52. `undefined` EN OBJETOS

Ejemplo:

```javascript
const usuario = {
    nombre: "Pedro",
    telefono: undefined
};

JSON.stringify(usuario);
```

La propiedad `telefono` se omite del resultado JSON.

---

# 53. `undefined` EN ARRAYS

En arrays el comportamiento es diferente.

Ejemplo:

```javascript
JSON.stringify([
    1,
    undefined,
    3
]);
```

El resultado representa esa posición como:

```json
[
    1,
    null,
    3
]
```

### 🧠 Trampa

```text
undefined en objeto
→ propiedad omitida

undefined en array
→ null
```

---

# 54. JSON Y FECHAS

JavaScript tiene:

```text
Date
```

pero JSON no tiene un tipo nativo:

```text
date
```

Las fechas suelen representarse como strings.

Por ejemplo:

```json
{
    "fecha": "2026-08-16T12:00:00Z"
}
```

---

# 55. JSON NO TIENE TIPOS DE DATOS COMPLEJOS PROPIOS

JSON no dispone directamente de:

```text
Date
Map
Set
Function
RegExp
```

Estos deben representarse mediante valores JSON compatibles.

---

# 56. JSON VS XML

Ambos pueden representar estructuras jerárquicas.

XML:

```xml
<usuario>
    <nombre>Pedro</nombre>
    <edad>30</edad>
</usuario>
```

JSON:

```json
{
    "nombre": "Pedro",
    "edad": 30
}
```

---

# 57. XML: CARACTERÍSTICAS

XML dispone de:

```text
elementos
atributos
namespaces
DTD
XSD
comentarios
CDATA
```

---

# 58. JSON: CARACTERÍSTICAS

JSON dispone de:

```text
objetos
arrays
strings
numbers
boolean
null
```

Es generalmente más compacto para representar estructuras de datos habituales en APIs.

---

# 59. VERBOSIDAD

XML:

```text
<nombre>Pedro</nombre>
```

JSON:

```json
"nombre": "Pedro"
```

En muchas estructuras JSON resulta más compacto.

---

# 60. NAMESPACES

XML tiene un mecanismo específico de namespaces.

JSON no tiene un mecanismo equivalente incorporado en su sintaxis.

---

# 61. ESQUEMAS

XML dispone de mecanismos estandarizados como:

```text
DTD
XSD
```

JSON puede utilizar esquemas externos como:

```text
JSON Schema
```

que estudiaremos posteriormente.

---

# 62. COMENTARIOS

XML:

```xml
<!-- comentario -->
```

JSON estándar:

```text
no tiene comentarios
```

---

# 63. ATRIBUTOS

XML permite:

```xml
<usuario id="15">
```

JSON normalmente modelaría esto como una propiedad:

```json
{
    "id": 15
}
```

---

# 64. XML VS JSON EN APIs

Actualmente es muy habitual encontrar:

```text
REST API
↓
JSON
```

pero XML continúa apareciendo en:

```text
SOAP
sistemas empresariales
integraciones legacy
documentos
configuración
```

---

# 65. VENTAJAS DE JSON

Entre sus ventajas:

```text
sintaxis relativamente sencilla
poca verbosidad
fácil de leer
fácil de generar
fácil de procesar
muy utilizado en APIs web
```

---

# 66. LIMITACIONES DE JSON

JSON estándar no proporciona directamente:

```text
comentarios
namespaces
tipos de fecha
tipado complejo
esquema integrado
```

Algunas de estas necesidades pueden resolverse mediante convenciones o herramientas externas.
