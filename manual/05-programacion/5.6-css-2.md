# 2. POSITION

La propiedad:

```css
position
```

determina cómo se posiciona un elemento dentro del documento.

Valores fundamentales:

```text
static
relative
absolute
fixed
sticky
```

---

# 3. `position: static`

Es el valor inicial habitual.

```css
.elemento {
    position: static;
}
```

El elemento participa en el flujo normal del documento.

Las propiedades:

```text
top
right
bottom
left
```

no lo desplazan como ocurre con elementos posicionados.

---

# 4. `position: relative`

```css
.elemento {
    position: relative;
}
```

El elemento:

```text
permanece en el flujo normal
```

pero puede desplazarse visualmente mediante:

```text
top
right
bottom
left
```

Ejemplo:

```css
.elemento {
    position: relative;
    top: 10px;
}
```

El espacio original del elemento continúa reservado.

---

# 5. `relative` COMO REFERENCIA

Una de las aplicaciones más importantes de:

```css
position: relative;
```

es proporcionar un contexto de posicionamiento para descendientes `absolute`.

Ejemplo:

```css
.card {
    position: relative;
}

.badge {
    position: absolute;
    top: 10px;
    right: 10px;
}
```

El `badge` puede posicionarse tomando como referencia el bloque de posicionamiento correspondiente establecido por `.card`.

---

# 6. `position: absolute`

Un elemento:

```css
position: absolute;
```

queda fuera del flujo normal.

Puede posicionarse mediante:

```text
top
right
bottom
left
```

o propiedades lógicas equivalentes.

---

# 7. REFERENCIA DE `absolute`

Un elemento absolutamente posicionado busca un **bloque contenedor de referencia** apropiado entre sus ancestros posicionados.

Ejemplo:

```css
.card {
    position: relative;
}

.badge {
    position: absolute;
    top: 0;
    right: 0;
}
```

Aquí normalmente el `badge` se posicionará respecto a `.card`.

### 🧠 Trampa

No significa simplemente:

```text
absolute → siempre respecto al padre
```

La referencia depende del contexto de posicionamiento.

---

# 8. `position: fixed`

Un elemento:

```css
position: fixed;
```

queda fuera del flujo normal y se posiciona respecto al viewport en los casos habituales.

Ejemplo:

```css
.boton-ayuda {
    position: fixed;
    right: 20px;
    bottom: 20px;
}
```

Puede permanecer en una posición fija mientras se desplaza la página.

---

# 9. `position: sticky`

Combina características del flujo normal con un comportamiento de posicionamiento durante el desplazamiento.

Ejemplo:

```css
.header {
    position: sticky;
    top: 0;
}
```

El elemento puede desplazarse normalmente hasta alcanzar el umbral indicado y después mantenerse pegado dentro de su contexto de desplazamiento.

---

# 10. RESUMEN DE POSITION

| Valor | Flujo normal | Desplazamiento |
|---|---|---|
| `static` | Sí | No mediante `top/left` |
| `relative` | Sí | Sí |
| `absolute` | No | Sí |
| `fixed` | No | Sí |
| `sticky` | Sí | Sí, según scroll |

---

# 11. `top`, `right`, `bottom`, `left`

Estas propiedades permiten desplazar elementos posicionados.

Ejemplo:

```css
.elemento {
    position: relative;
    left: 20px;
}
```

En CSS moderno también existen propiedades lógicas como:

```text
inset
inset-block
inset-inline
```

---

# 12. `inset`

Permite establecer simultáneamente:

```text
top
right
bottom
left
```

Ejemplo:

```css
.elemento {
    position: absolute;
    inset: 0;
}
```

Conceptualmente equivale a establecer los cuatro desplazamientos a cero.

---

# 13. `z-index`

Controla el orden de apilamiento de elementos posicionados y de determinados contextos de apilamiento.

Ejemplo:

```css
.modal {
    position: fixed;
    z-index: 1000;
}
```

Un valor mayor suele situar el elemento por encima de otro dentro del mismo contexto de apilamiento, pero `z-index` no debe entenderse como una escala global universal.

---

# 14. STACKING CONTEXT

Los elementos pueden crear **contextos de apilamiento**.

Esto explica algunos casos aparentemente extraños en los que:

```text
z-index: 999999
```

no consigue colocar un elemento por encima de otro.

La comparación puede producirse primero entre:

```text
stacking contexts
```

y posteriormente dentro de cada uno.

### 🧠 Idea clave

```text
z-index alto
≠
siempre encima de absolutamente todo
```

---

# 15. FLEXBOX

Flexbox significa:

```text
Flexible Box Layout
```

Está diseñado principalmente para distribuir elementos en:

```text
una dimensión
```

Es decir:

```text
fila
```

o:

```text
columna
```

---

# 16. CONTENEDOR FLEX

Para crear un contenedor Flexbox:

```css
.container {
    display: flex;
}
```

Sus hijos directos se convierten en:

```text
flex items
```

---

# 17. EJE PRINCIPAL

Flexbox trabaja con dos ejes:

```text
main axis
cross axis
```

El eje principal depende de:

```css
flex-direction
```

---

# 18. `flex-direction`

Valores principales:

```text
row
row-reverse
column
column-reverse
```

Por defecto:

```css
flex-direction: row;
```

Esto significa:

```text
main axis → horizontal
cross axis → vertical
```

---

# 19. `row`

```css
flex-direction: row;
```

Los elementos se colocan:

```text
→ → →
```

El eje principal es horizontal.

---

# 20. `column`

```css
flex-direction: column;
```

Los elementos se colocan:

```text
↓
↓
↓
```

El eje principal pasa a ser vertical.

---

# 21. `justify-content`

Controla la distribución de los elementos a lo largo del:

```text
main axis
```

Ejemplos:

```css
justify-content: flex-start;
justify-content: center;
justify-content: flex-end;
justify-content: space-between;
justify-content: space-around;
justify-content: space-evenly;
```

---

# 22. `align-items`

Controla la alineación de los elementos a lo largo del:

```text
cross axis
```

Ejemplos:

```css
align-items: flex-start;
align-items: center;
align-items: flex-end;
align-items: stretch;
```

### 🧠 Trampa clásica

Con:

```css
flex-direction: row;
```

normalmente:

```text
justify-content → horizontal
align-items     → vertical
```

Pero con:

```css
flex-direction: column;
```

se intercambia la orientación de los ejes.

---

# 23. `align-self`

Permite modificar la alineación de un flex item concreto.

Ejemplo:

```css
.item-especial {
    align-self: flex-end;
}
```

Tiene prioridad sobre la alineación establecida por:

```text
align-items
```

para ese elemento.

---

# 24. `flex-wrap`

Por defecto:

```css
flex-wrap: nowrap;
```

Los elementos intentan permanecer en una sola línea.

Podemos permitir varias líneas:

```css
flex-wrap: wrap;
```

---

# 25. `flex-flow`

Es una abreviatura de:

```text
flex-direction
+
flex-wrap
```

Ejemplo:

```css
.container {
    flex-flow: row wrap;
}
```

---

# 26. `gap`

Permite establecer separación entre elementos del layout.

Ejemplo:

```css
.container {
    display: flex;
    gap: 20px;
}
```

También existen:

```text
row-gap
column-gap
```

---

# 27. `justify-content` VS `gap`

No son equivalentes.

```text
gap
→ separación entre items

justify-content
→ distribución del espacio disponible a lo largo del eje principal
```

Pueden utilizarse conjuntamente.

---

# 28. `flex-grow`

Controla cuánto puede crecer un flex item para ocupar espacio disponible.

Ejemplo:

```css
.item {
    flex-grow: 1;
}
```

Si varios elementos tienen:

```text
flex-grow: 1
```

pueden repartirse el espacio libre según sus factores de crecimiento.

---

# 29. `flex-shrink`

Controla cuánto puede reducirse un flex item cuando no hay suficiente espacio.

Ejemplo:

```css
.item {
    flex-shrink: 1;
}
```

El valor inicial habitual es:

```text
1
```

---

# 30. `flex-basis`

Define el tamaño base del elemento antes de distribuir el espacio disponible mediante las reglas flex.

Ejemplo:

```css
.item {
    flex-basis: 200px;
}
```

---

# 31. PROPIEDAD `flex`

Es una abreviatura que combina:

```text
flex-grow
flex-shrink
flex-basis
```

Ejemplo:

```css
.item {
    flex: 1;
}
```

Una forma habitual de interpretarlo es:

```text
flex-grow: 1
flex-shrink: 1
flex-basis: 0%
```

según la expansión de la abreviatura.

---

# 32. `order`

Permite modificar el orden visual de los flex items.

Ejemplo:

```css
.item {
    order: 2;
}
```

El orden por defecto es:

```text
0
```

### ⚠️ Accesibilidad

Cambiar el orden visual no necesariamente cambia el orden lógico del contenido para tecnologías de asistencia o navegación.

No debe utilizarse indiscriminadamente para reorganizar contenido semántico.

---

# 33. `align-content`

Tiene importancia especialmente cuando Flexbox tiene:

```text
múltiples líneas
```

y controla la distribución de esas líneas en el cross axis.

No debe confundirse con:

```text
align-items
```

### Regla

```text
align-items
→ items

align-content
→ líneas de flex
```

---

# 34. FLEXBOX: EJEMPLO

```css
.container {
    display: flex;
    flex-direction: row;
    justify-content: space-between;
    align-items: center;
    gap: 20px;
}
```

Podemos leerlo:

```text
contenedor flex
→ fila
→ distribuir en eje principal
→ centrar en eje transversal
→ separar elementos
```

---

# 35. CENTRADO CON FLEXBOX

Un patrón muy conocido:

```css
.container {
    display: flex;
    justify-content: center;
    align-items: center;
}
```

Con una configuración de fila:

```text
centra horizontalmente
+
centra verticalmente
```

dentro del espacio disponible.

---

# 36. GRID

CSS Grid Layout está diseñado especialmente para layouts en:

```text
dos dimensiones
```

Es decir:

```text
filas
+
columnas
```

---

# 37. CONTENEDOR GRID

Ejemplo:

```css
.container {
    display: grid;
}
```

Los hijos directos pasan a ser:

```text
grid items
```

---

# 38. COLUMNAS

Podemos definir columnas:

```css
.container {
    display: grid;
    grid-template-columns:
        200px
        200px
        200px;
}
```

Esto crea tres columnas.

---

# 39. `fr`

La unidad:

```text
fr
```

representa una fracción del espacio disponible del grid.

Ejemplo:

```css
grid-template-columns:
    1fr 1fr 1fr;
```

Divide el espacio disponible en tres fracciones iguales, teniendo en cuenta las restricciones aplicables.

---

# 40. GRID RESPONSIVE BÁSICO

Un patrón muy útil:

```css
.container {
    display: grid;
    grid-template-columns:
        repeat(3, 1fr);
}
```

`repeat()` evita repetir manualmente la definición.

---

# 41. `repeat()`

Ejemplo:

```css
grid-template-columns:
    repeat(4, 1fr);
```

equivale conceptualmente a:

```css
1fr 1fr 1fr 1fr
```

---

# 42. `grid-template-rows`

Permite definir filas.

```css
.container {
    display: grid;
    grid-template-rows:
        100px
        200px;
}
```

---

# 43. `gap` EN GRID

También podemos utilizar:

```css
gap: 20px;
```

o:

```css
row-gap: 20px;
column-gap: 30px;
```

para controlar la separación.

---

# 44. `grid-column`

Permite indicar dónde empieza y termina un elemento en las columnas.

Ejemplo:

```css
.item {
    grid-column: 1 / 3;
}
```

El elemento ocupa el espacio comprendido entre las líneas de grid 1 y 3.

Por tanto ocupa:

```text
2 tracks
```

---

# 45. `grid-row`

Funciona de manera equivalente con las filas:

```css
.item {
    grid-row: 1 / 3;
}
```

---

# 46. SPAN EN GRID

Podemos indicar cuántos tracks ocupar:

```css
.item {
    grid-column: span 2;
}
```

Significa:

```text
ocupa 2 columnas
```

desde su posición de colocación.

---

# 47. GRID AREAS

Podemos nombrar zonas del layout.

Ejemplo:

```css
.container {
    display: grid;

    grid-template-areas:
        "header header"
        "main   aside"
        "footer footer";
}
```

Y asignarlas:

```css
.header {
    grid-area: header;
}

.main {
    grid-area: main;
}

.aside {
    grid-area: aside;
}

.footer {
    grid-area: footer;
}
```

Es una de las características más potentes de Grid para layouts estructurados.

---

# 48. GRID VS FLEXBOX

Esta distinción es extremadamente importante.

### Flexbox

```text
una dimensión
```

Ideal para:

```text
fila
columna
alineación
distribución de componentes
```

### Grid

```text
dos dimensiones
```

Ideal para:

```text
filas
columnas
layouts completos
estructuras de página
```

---

# 49. ¿CUÁL ELEGIR?

No existe una regla absoluta.

Pero como orientación:

```text
componente lineal
→ Flexbox

layout con filas + columnas
→ Grid
```

También pueden combinarse:

```text
Grid
└── Flexbox
```

o:

```text
Flexbox
└── Grid
```

---

# 50. `auto-fit` Y `auto-fill`

Grid permite patrones responsive muy potentes:

```css
grid-template-columns:
    repeat(
        auto-fit,
        minmax(200px, 1fr)
    );
```

Esto permite adaptar automáticamente el número de columnas disponibles.

---

# 51. `minmax()`

Define un tamaño mínimo y máximo para un track.

Ejemplo:

```css
grid-template-columns:
    minmax(200px, 1fr);
```

El track no debería reducirse por debajo del mínimo indicado, mientras que puede crecer según el espacio disponible y las reglas del grid.

---

# 52. `auto-fit` VS `auto-fill`

Ambos permiten generar tracks repetidos automáticamente.

De forma simplificada:

```text
auto-fit
→ tiende a colapsar tracks vacíos y repartir el espacio

auto-fill
→ mantiene las pistas creadas si caben
```

Es una diferencia más avanzada, pero puede aparecer en preguntas técnicas.

---

# 53. RESPONSIVE DESIGN

Responsive Web Design significa diseñar interfaces capaces de adaptarse a diferentes:

```text
anchos
dispositivos
orientaciones
condiciones de visualización
```

No consiste simplemente en:

```text
hacer una versión móvil
```

---

# 54. MOBILE FIRST

Una estrategia frecuente:

```text
Mobile First
```

consiste en diseñar primero para pantallas pequeñas y ampliar progresivamente el diseño para pantallas mayores.

Ejemplo:

```css
.card {
    width: 100%;
}

@media (min-width: 768px) {
    .card {
        width: 50%;
    }
}
```

---

# 55. MEDIA QUERIES

Las media queries permiten aplicar estilos según determinadas características del entorno.

Ejemplo:

```css
@media (min-width: 768px) {
    .menu {
        display: flex;
    }
}
```

---

# 56. `min-width`

Una media query:

```css
@media (min-width: 768px)
```

se aplica cuando el viewport cumple esa condición de anchura mínima.

---

# 57. `max-width`

Ejemplo:

```css
@media (max-width: 767px) {
    .menu {
        display: none;
    }
}
```

Se aplica cuando se cumple la anchura máxima indicada.

---

# 58. MEDIA FEATURES

Las media queries no se limitan al ancho.

También pueden utilizar características como:

```text
orientation
resolution
hover
pointer
prefers-color-scheme
prefers-reduced-motion
```

---

# 59. ORIENTACIÓN

Podemos detectar orientación:

```css
@media (orientation: landscape) {
    ...
}
```

o:

```css
@media (orientation: portrait) {
    ...
}
```

---

# 60. `prefers-color-scheme`

Permite adaptar el diseño a la preferencia del usuario:

```css
@media (prefers-color-scheme: dark) {
    body {
        background: #111;
        color: white;
    }
}
```

Valores habituales:

```text
light
dark
```

---

# 61. `prefers-reduced-motion`

Permite respetar la preferencia del usuario de reducir movimiento:

```css
@media (prefers-reduced-motion: reduce) {
    * {
        animation: none;
        transition: none;
    }
}
```

Es especialmente relevante para accesibilidad.

---

# 62. VIEWPORT META

Para responsive design en HTML es habitual utilizar:

```html
<meta
    name="viewport"
    content="width=device-width, initial-scale=1">
```

Esto ayuda al navegador móvil a interpretar correctamente el viewport del documento.

---

# 63. IMÁGENES RESPONSIVAS

Podemos combinar:

```text
max-width
+
height
```

Por ejemplo:

```css
img {
    max-width: 100%;
    height: auto;
}
```

Esto permite que una imagen se reduzca para no desbordar su contenedor manteniendo su proporción en este patrón habitual.

---

# 64. `object-fit`

Controla cómo encaja el contenido de una imagen o vídeo dentro de sus dimensiones.

Valores conocidos:

```text
fill
contain
cover
none
scale-down
```

---

# 65. `object-fit: cover`

Ejemplo:

```css
img {
    width: 300px;
    height: 200px;
    object-fit: cover;
}
```

La imagen llena la caja manteniendo su proporción, pudiendo recortar partes.

---

# 66. `object-fit: contain`

```css
img {
    object-fit: contain;
}
```

La imagen se escala para quedar contenida dentro de la caja, manteniendo su proporción.

Puede quedar espacio vacío.

---

# 67. `aspect-ratio`

Permite establecer una relación de aspecto.

Ejemplo:

```css
.video {
    aspect-ratio: 16 / 9;
}
```

Esto facilita mantener proporciones sin depender de hacks antiguos basados exclusivamente en padding.

---

# 68. CONTAINER QUERIES

Las container queries permiten aplicar estilos según el tamaño de un contenedor, en lugar de basarse únicamente en el viewport.

Ejemplo conceptual:

```css
.card-container {
    container-type: inline-size;
}

@container (min-width: 500px) {
    .card {
        display: grid;
    }
}
```

Esto resulta especialmente útil para componentes reutilizables.

---

# 69. MEDIA QUERIES VS CONTAINER QUERIES

### Media Query

Pregunta:

```text
¿qué tamaño tiene el viewport?
```

### Container Query

Pregunta:

```text
¿qué tamaño tiene el contenedor?
```

Esto permite crear componentes más independientes del contexto donde se colocan.

---

# 70. CSS LÓGICO

CSS moderno dispone de propiedades lógicas.

En lugar de pensar únicamente en:

```text
left
right
top
bottom
```

podemos utilizar:

```text
inline
block
```

Ejemplos:

```css
margin-inline: auto;
padding-block: 20px;
```

Esto facilita diseños compatibles con diferentes direcciones de escritura.

---

# 71. `margin-inline`

Ejemplo:

```css
.container {
    margin-inline: auto;
}
```

Es una forma habitual de centrar horizontalmente un elemento con anchura limitada en un contexto de escritura horizontal.

---

# 72. `padding-block`

Ejemplo:

```css
.section {
    padding-block: 40px;
}
```

Controla el padding en el eje de bloque.

---

# 73. CSS Y ACCESIBILIDAD

El layout no debe utilizarse para destruir la estructura semántica.

Por ejemplo:

```text
orden visual
≠
necesariamente orden lógico
```

Esto es especialmente importante con:

```text
order
grid placement
position absolute
```

La presentación debe complementar la estructura HTML, no sustituirla.

---

# 74. UNIDADES FLUIDAS

Para diseños responsive podemos combinar:

```text
%
vw
vh
rem
fr
min()
max()
clamp()
```

Ejemplo:

```css
.container {
    width: min(90%, 1200px);
}
```

Otro:

```css
h1 {
    font-size: clamp(
        2rem,
        5vw,
        4rem
    );
}
```

```text

→ sigue en el flujo

```

## Trampa 2

```text
fixed
→ referencia habitual al viewport

sticky
→ comportamiento ligado al scroll y al contexto
```

---

## Trampa 3

Con Flexbox:

```text
justify-content
→ eje principal

align-items
→ eje transversal
```

No memorices simplemente:

```text
justify = horizontal
align = vertical
```

porque deja de ser cierto al cambiar `flex-direction`.

---

## Trampa 4

```text
Flexbox
→ una dimensión

Grid
→ dos dimensiones
```

---

## Trampa 5

```text
gap
→ espacio entre elementos/tracks

margin
→ margen exterior del elemento
```

No son equivalentes.

---

## Trampa 6

```text
flex-grow
→ crecer

flex-shrink
→ reducir

flex-basis
→ tamaño base
```

---

## Trampa 7

```text

```

ocupa el espacio entre las líneas 1 y 3:

```text
2 columnas
```

No significa "columna número 3".

## Trampa 8

```text
fr
```

no significa:

```text
"fracción fija de toda la pantalla"
```

Representa una fracción del espacio disponible del grid según el algoritmo de layout y las restricciones aplicables.

## Trampa 9

```text
@media
→ viewport / características del dispositivo o entorno

@container
→ tamaño del contenedor
```

## Trampa 10

```text
auto-fit
≠
auto-fill
```

Son parecidos, pero no idénticos.

## Trampa 11

```text
object-fit: cover
→ llena y puede recortar

object-fit: contain
→ contiene y puede dejar espacio
```

## Trampa 12

`z-index` no es una escala global mágica.

Los stacking contexts importan.
