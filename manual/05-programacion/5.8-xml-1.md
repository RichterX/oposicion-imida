# 🟦 5.8 XML · PARTE 1

> **Bloque:** 5 - Programación  
> **Capítulo:** 5.8 - XML  
> **Parte:** 1  
> **Enfoque:** Conceptos fundamentales, estructura, sintaxis, elementos, atributos, prólogo, documentos bien formados, entidades, CDATA y espacios de nombres.

---

# 1. INTRODUCCIÓN

XML significa:

```text
eXtensible Markup Language
```

Es un lenguaje de marcado diseñado para representar y transportar información estructurada.

A diferencia de HTML, XML no está pensado principalmente para presentar información visualmente.

Su objetivo fundamental es:

```text
estructurar
almacenar
transportar
intercambiar
```

datos.

---

# 2. XML NO ES UN LENGUAJE DE PROGRAMACIÓN

XML es un:

```text
lenguaje de marcado
```

No es:

```text
lenguaje de programación
```

No contiene por sí mismo:

```text
bucles
funciones
condicionales
variables
```

Su función es representar información mediante una estructura jerárquica.

---

# 3. XML ES EXTENSIBLE

Una característica fundamental es que XML permite definir nuestras propias etiquetas.

Por ejemplo:

```xml
<usuario>
    <nombre>Pedro</nombre>
    <edad>30</edad>
</usuario>
```

Las etiquetas:

```text
usuario
nombre
edad
```

no vienen impuestas por XML.

El diseñador del documento decide qué vocabulario utilizar.

---

# 4. XML VS HTML

HTML y XML utilizan una sintaxis basada en etiquetas, pero tienen objetivos diferentes.

### HTML

Principalmente:

```text
presentación y estructura de documentos web
```

### XML

Principalmente:

```text
representación e intercambio de datos estructurados
```

---

# 5. DIFERENCIA FUNDAMENTAL

En HTML podemos encontrarnos etiquetas predefinidas como:

```html
<p>
<h1>
<table>
<body>
```

En XML podemos definir:

```xml
<cliente>
<producto>
<pedido>
```

según nuestras necesidades.

---

# 6. ESTRUCTURA BÁSICA

Ejemplo:

```xml
<?xml version="1.0" encoding="UTF-8"?>

<usuario>
    <nombre>Pedro</nombre>
    <edad>30</edad>
</usuario>
```

Podemos distinguir:

```text
prólogo XML
    ↓
elemento raíz
    ↓
elementos hijos
```

---

# 7. DECLARACIÓN XML

La primera línea puede ser:

```xml
<?xml version="1.0" encoding="UTF-8"?>
```

Esta declaración proporciona información sobre el documento XML.

---

# 8. VERSION

La propiedad:

```text
version
```

indica la versión de XML utilizada.

Ejemplo:

```xml
version="1.0"
```

XML 1.0 es la versión que aparece habitualmente en documentos y temarios.

---

# 9. ENCODING

El atributo:

```text
encoding
```

indica la codificación utilizada.

Ejemplo:

```xml
encoding="UTF-8"
```

UTF-8 es una codificación extremadamente habitual.

---

# 10. STANDALONE

Puede aparecer:

```xml
standalone="yes"
```

o:

```xml
standalone="no"
```

Ejemplo:

```xml
<?xml version="1.0"
      encoding="UTF-8"
      standalone="yes"?>
```

Indica si el documento depende de declaraciones externas relacionadas con su DTD.

---

# 11. ELEMENTOS

Los elementos son la pieza fundamental de un documento XML.

Ejemplo:

```xml
<nombre>Pedro</nombre>
```

Tenemos:

```text
etiqueta de apertura
contenido
etiqueta de cierre
```

---

# 12. ELEMENTO RAÍZ

Un documento XML debe tener un único elemento raíz que contenga el resto de la estructura.

Ejemplo correcto:

```xml
<usuarios>

    <usuario>
        <nombre>Pedro</nombre>
    </usuario>

    <usuario>
        <nombre>Ana</nombre>
    </usuario>

</usuarios>
```

La raíz es:

```text
usuarios
```

---

# 13. ELEMENTOS ANIDADOS

Los elementos pueden contener otros elementos.

Ejemplo:

```xml
<usuario>

    <datos>

        <nombre>Pedro</nombre>
        <edad>30</edad>

    </datos>

</usuario>
```

La estructura es jerárquica:

```text
usuario
└── datos
    ├── nombre
    └── edad
```

---

# 14. ELEMENTO VACÍO

Un elemento sin contenido puede escribirse:

```xml
<imagen />
```

También puede escribirse conceptualmente como:

```xml
<imagen></imagen>
```

La primera forma es la sintaxis abreviada para un elemento vacío.

---

# 15. ETIQUETAS DEBEN ESTAR BIEN CERRADAS

Correcto:

```xml
<nombre>Pedro</nombre>
```

Incorrecto:

```xml
<nombre>Pedro
```

Un documento XML debe respetar estrictamente la estructura de apertura y cierre.

---

# 16. SENSIBILIDAD A MAYÚSCULAS

XML distingue entre mayúsculas y minúsculas.

Por ejemplo:

```xml
<Nombre>
```

y:

```xml
<nombre>
```

son nombres diferentes.

### 🧠 Trampa de examen

XML es:

```text
case-sensitive
```

---

# 17. ANIDAMIENTO CORRECTO

Los elementos deben estar correctamente anidados.

Correcto:

```xml
<a>
    <b>
        Texto
    </b>
</a>
```

Incorrecto:

```xml
<a>
    <b>
</a>
</b>
```

Las etiquetas deben cerrarse en el orden inverso al de apertura.

---

# 18. ATRIBUTOS

Los elementos pueden tener atributos.

Ejemplo:

```xml
<usuario
    id="15"
    activo="true">
    Pedro
</usuario>
```

Tenemos:

```text
id
activo
```

como atributos.

---

# 19. VALORES DE ATRIBUTOS

Los valores de los atributos deben estar entre comillas.

Correcto:

```xml
<usuario id="15">
```

No:

```xml
<usuario id=15>
```

En XML, los atributos deben estar correctamente delimitados por comillas.

---

# 20. ATRIBUTOS VS ELEMENTOS

Podemos representar información mediante:

```xml
<usuario id="15">
    <nombre>Pedro</nombre>
</usuario>
```

Aquí:

```text
id
→ atributo

nombre
→ elemento
```

La elección entre atributo y elemento depende del modelo de datos.

---

# 21. REGLAS DE NOMBRES

Los nombres de elementos y atributos deben respetar las reglas de nombres XML.

Ejemplos válidos:

```text
usuario
nombre
usuario1
nombre_completo
```

No debemos comenzar un nombre XML con un número:

```text
1usuario
```

---

# 22. XML Y ESPACIOS EN BLANCO

XML puede contener espacios, saltos de línea e indentación.

Ejemplo:

```xml
<usuario>
    <nombre>
        Pedro
    </nombre>
</usuario>
```

La indentación facilita la lectura humana.

Sin embargo, los espacios pueden formar parte del contenido textual en determinados contextos.

---

# 23. COMENTARIOS

Los comentarios utilizan:

```xml
<!-- comentario -->
```

Ejemplo:

```xml
<usuario>

    <!-- Datos personales -->

    <nombre>Pedro</nombre>

</usuario>
```

---

# 24. COMENTARIOS NO PUEDEN ANIDARSE

No debemos escribir:

```xml
<!--
    comentario
    <!-- otro comentario -->
-->
```

Los comentarios XML no pueden contener otro comentario anidado.

---

# 25. CARACTERES RESERVADOS

Algunos caracteres tienen significado especial en XML.

Por ejemplo:

```text
<
>
&
```

Si necesitamos representar determinados caracteres literalmente, utilizamos entidades.

---

# 26. ENTIDADES PREDEFINIDAS

Las principales entidades XML son:

| Carácter | Entidad |
|---|---|
| `&` | `&amp;` |
| `<` | `&lt;` |
| `>` | `&gt;` |
| `"` | `&quot;` |
| `'` | `&apos;` |

---

# 27. EJEMPLO DE ENTIDADES

Para representar:

```text
5 < 10
```

podemos escribir:

```xml
<texto>
    5 &lt; 10
</texto>
```

---

# 28. AMPERSAND

El carácter:

```text
&
```

tiene un significado especial porque inicia referencias a entidades.

Por ejemplo:

```xml
&amp;
```

representa:

```text
&
```

---

# 29. CDATA

CDATA significa:

```text
Character Data
```

Permite incluir contenido que el parser no debe interpretar como marcado XML dentro de esa sección.

Sintaxis:

```xml
<![CDATA[
    <texto>
        Esto parece XML
    </texto>
]]>
```

El contenido se trata como datos de caracteres.

---

# 30. ¿PARA QUÉ SIRVE CDATA?

Es especialmente útil cuando necesitamos incluir texto que contiene muchos caracteres que normalmente tendrían significado especial.

Por ejemplo:

```xml
<script><![CDATA[
    if (x < 10 && y > 5) {
        ...
    }
]]></script>
```

---

# 31. CDATA NO PUEDE CONTENER `]]>`

La secuencia:

```text
]]>
```

marca el final de una sección CDATA.

Por tanto, no puede aparecer sin dividirse dentro de la sección.

---

# 32. DOCUMENTO BIEN FORMADO

Un documento XML es:

```text
bien formado
```

cuando cumple las reglas sintácticas de XML.

Entre otras:

```text
un único elemento raíz
etiquetas correctamente cerradas
elementos correctamente anidados
atributos entre comillas
nombres válidos
case-sensitive
```

---

# 33. WELL-FORMED VS VALID

No debemos confundir:

```text
bien formado
```

con:

```text
válido
```

Un documento puede estar bien formado y no ser válido respecto de un esquema o DTD.

---

# 34. DOCUMENTO VÁLIDO

Un documento XML es válido cuando, además de estar bien formado, cumple las restricciones definidas por un mecanismo de validación como:

```text
DTD
```

o:

```text
XML Schema / XSD
```

---

# 35. EJEMPLO

Documento:

```xml
<usuario>
    <nombre>Pedro</nombre>
</usuario>
```

Puede ser:

```text
bien formado
```

aunque un XSD determinado exigiera además:

```text
edad
email
```

y el documento no los tuviera.

En ese caso:

```text
bien formado
+
no válido respecto al XSD
```

---

# 36. PRÓLOGO XML

El prólogo puede contener:

```text
declaración XML
DOCTYPE
otras declaraciones asociadas
```

Ejemplo:

```xml
<?xml version="1.0"
      encoding="UTF-8"?>

<usuario>
    ...
</usuario>
```

---

# 37. DOCTYPE

La declaración:

```xml
<!DOCTYPE ...>
```

puede utilizarse para asociar un documento con una DTD.

Ejemplo conceptual:

```xml
<!DOCTYPE usuario SYSTEM "usuario.dtd">
```

---

# 38. DTD

DTD significa:

```text
Document Type Definition
```

Permite definir restricciones sobre la estructura de un documento XML.

Puede describir:

```text
elementos
atributos
entidades
```

entre otras construcciones.

---

# 39. DTD INTERNA

Una DTD puede estar incluida en el propio documento.

Ejemplo conceptual:

```xml
<!DOCTYPE usuario [
    <!ELEMENT usuario (nombre)>
    <!ELEMENT nombre (#PCDATA)>
]>
```

---

# 40. DTD EXTERNA

También puede estar en un archivo separado.

Ejemplo:

```xml
<!DOCTYPE usuario
    SYSTEM "usuario.dtd">
```

---

# 41. `#PCDATA`

En una DTD puede aparecer:

```text
#PCDATA
```

que significa:

```text
Parsed Character Data
```

Es contenido de texto que será procesado por el parser.

---

# 42. XML NAMESPACES

Los espacios de nombres permiten evitar conflictos entre vocabularios XML diferentes.

Imaginemos:

```xml
<tabla>
```

Podría representar:

```text
una tabla HTML
```

o:

```text
una tabla de datos
```

Los namespaces permiten distinguir vocabularios.

---

# 43. `xmlns`

Los namespaces se declaran mediante:

```text
xmlns
```

Ejemplo:

```xml
<libro
    xmlns="http://example.com/libros">
    ...
</libro>
```

---

# 44. NAMESPACE CON PREFIJO

También podemos utilizar un prefijo:

```xml
<libro
    xmlns:lib="http://example.com/libros">

    <lib:titulo>
        XML
    </lib:titulo>

</libro>
```

Aquí:

```text
lib
```

es el prefijo.

---

# 45. URI DEL NAMESPACE

Una declaración como:

```xml
xmlns:lib=
    "http://example.com/libros"
```

asocia el prefijo:

```text
lib
```

con un identificador de namespace.

La URI se utiliza como nombre identificador del espacio de nombres.

No significa necesariamente que el navegador tenga que descargar contenido de esa URL.

---

# 46. DEFAULT NAMESPACE

Podemos declarar un namespace sin prefijo:

```xml
xmlns="http://example.com/libros"
```

Los elementos sin prefijo dentro del ámbito correspondiente pertenecen a ese namespace.

---

# 47. ÁMBITO DE LOS NAMESPACES

Un namespace declarado en un elemento se aplica a ese elemento y a sus descendientes, salvo que sea redefinido.

Ejemplo:

```xml
<root xmlns:a="urn:a">

    <a:elemento />

</root>
```

El prefijo:

```text
a
```

está disponible dentro de ese ámbito.

---

# 48. NAMESPACE Y ATRIBUTOS

Un detalle importante:

Los atributos sin prefijo no pertenecen automáticamente al namespace por defecto.

Ejemplo:

```xml
<elemento
    xmlns="urn:ejemplo"
    id="10">
</elemento>
```

Aquí:

```text
elemento
→ namespace urn:ejemplo

id
→ no pertenece automáticamente a ese namespace
```

---

# 49. XML Y ÁRBOL

XML representa naturalmente una estructura jerárquica.

Ejemplo:

```xml
<empresa>

    <empleado>
        <nombre>Pedro</nombre>

        <puesto>
            Desarrollo
        </puesto>
    </empleado>

</empresa>
```

Árbol:

```text
empresa
└── empleado
    ├── nombre
    └── puesto
```

---

# 50. XML COMO INTERCAMBIO DE DATOS

XML se ha utilizado ampliamente para:

```text
intercambio de información
configuración
servicios web
documentos
integración entre sistemas
```

Ejemplos conocidos históricamente:

```text
SOAP
RSS
Atom
SVG
```

---

# 51. XML Y SOAP

SOAP utiliza XML como formato de mensajes.

Conceptualmente:

```text
Cliente
   ↓
mensaje XML
   ↓
Servicio SOAP
   ↓
respuesta XML
```

---

# 52. XML Y CONFIGURACIÓN

XML también puede utilizarse para archivos de configuración.

Ejemplo:

```xml
<configuracion>

    <baseDatos>
        <host>localhost</host>
        <puerto>3306</puerto>
    </baseDatos>

</configuracion>
```

---

# 53. XML VS JSON

### XML

```text
etiquetas
atributos
namespaces
comentarios
DTD/XSD
```

### JSON

```text
objetos
arrays
pares clave/valor
sintaxis más compacta
```

Ejemplo XML:

```xml
<usuario>
    <nombre>Pedro</nombre>
    <edad>30</edad>
</usuario>
```

JSON:

```json
{
    "nombre": "Pedro",
    "edad": 30
}
```

---

# 54. VENTAJAS DE XML

Entre sus características:

```text
estructura jerárquica
extensibilidad
namespaces
mecanismos de validación
amplio ecosistema
```

---

# 55. DESVENTAJAS DE XML

Frente a JSON, XML puede resultar:

```text
más verboso
más pesado visualmente
más complejo de procesar en algunos escenarios
```

No significa que XML sea peor.

Tiene ventajas importantes en determinados contextos.
