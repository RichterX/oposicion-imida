# 2. JSON EN PHP

PHP proporciona funciones nativas para trabajar con JSON.

Las dos fundamentales son:

```php
json_encode()
json_decode()
```

Podemos relacionarlas con JavaScript:

```text
PHP
                 JavaScript

json_encode()    JSON.stringify()
json_decode()    JSON.parse()
```

No son idénticas en todos sus detalles, pero la equivalencia conceptual es muy útil.

---

# 3. `json_encode()`

Convierte un valor PHP en una cadena JSON.

Ejemplo:

```php
$usuario = [
    'nombre' => 'Pedro',
    'edad' => 30
];

$json = json_encode($usuario);
```

Resultado:

```json
{
    "nombre": "Pedro",
    "edad": 30
}
```

La variable:

```php
$json
```

contiene un:

```text
string
```

---

# 4. ARRAY ASOCIATIVO

Un array asociativo PHP:

```php
[
    'nombre' => 'Pedro',
    'edad' => 30
]
```

normalmente se convierte en un objeto JSON:

```json
{
    "nombre": "Pedro",
    "edad": 30
}
```

---

# 5. ARRAY INDEXADO

Un array indexado:

```php
[
    'Pedro',
    'Ana',
    'Luis'
]
```

se convierte normalmente en:

```json
[
    "Pedro",
    "Ana",
    "Luis"
]
```

---

# 6. ARRAY MIXTO

Los arrays PHP pueden ser más flexibles que las estructuras JSON.

Por ello, al convertir arrays con claves no secuenciales o estructuras mixtas, hay que prestar atención a cómo PHP los representa.

No debemos asumir que:

```text
array PHP
→ siempre objeto JSON
```

ni que:

```text
array PHP
→ siempre array JSON
```

La representación depende de las claves del array.

---

# 7. OBJETOS PHP

También podemos serializar objetos.

Ejemplo:

```php
class Usuario
{
    public string $nombre;
    public int $edad;
}

$usuario = new Usuario();

$usuario->nombre = 'Pedro';
$usuario->edad = 30;

$json = json_encode($usuario);
```

El resultado puede representar las propiedades públicas serializables del objeto.

---

# 8. `json_decode()`

Realiza el proceso contrario:

```text
JSON
↓
PHP
```

Ejemplo:

```php
$json =
    '{"nombre":"Pedro","edad":30}';

$usuario =
    json_decode($json);
```

Por defecto, `json_decode()` devuelve un:

```text
stdClass
```

cuando el JSON raíz es un objeto.

---

# 9. ACCESO A `stdClass`

Ejemplo:

```php
$usuario = json_decode(
    '{"nombre":"Pedro"}'
);

echo $usuario->nombre;
```

Resultado:

```text
Pedro
```

---

# 10. `json_decode()` CON `true`

Podemos solicitar arrays asociativos:

```php
$usuario = json_decode(
    $json,
    true
);
```

Ahora:

```text
$usuario
→ array asociativo
```

Podemos acceder:

```php
echo $usuario['nombre'];
```

---

# 11. 🧠 TRAMPA

```php
json_decode($json)
```

normalmente:

```text
objeto
```

Mientras:

```php
json_decode($json, true)
```

devuelve:

```text
array asociativo
```

Esta diferencia puede aparecer perfectamente en una pregunta de examen.

---

# 12. PARÁMETROS DE `json_decode()`

Conceptualmente:

```php
json_decode(
    $json,
    $associative,
    $depth,
    $flags
);
```

Los parámetros permiten controlar aspectos del proceso de decodificación.

---

# 13. `depth`

Permite establecer la profundidad máxima de recursión.

Ejemplo:

```php
json_decode(
    $json,
    true,
    512
);
```

El valor por defecto depende de la versión de PHP utilizada, pero en PHP moderno es habitual:

```text
512
```

---

# 14. `flags`

Permite modificar el comportamiento mediante constantes de opciones.

Por ejemplo:

```php
JSON_THROW_ON_ERROR
```

---

# 15. `JSON_THROW_ON_ERROR`

Esta opción hace que los errores de codificación/decodificación JSON se gestionen mediante una excepción `JsonException`.

Ejemplo:

```php
try {

    $data = json_decode(
        $json,
        true,
        512,
        JSON_THROW_ON_ERROR
    );

} catch (JsonException $e) {

    echo $e->getMessage();

}
```

---

# 16. ERRORES DE `json_decode()`

Si no utilizamos:

```text
JSON_THROW_ON_ERROR
```

podemos consultar:

```php
json_last_error()
```

Ejemplo:

```php
$data = json_decode($json);

if (json_last_error() !== JSON_ERROR_NONE) {

    echo 'JSON inválido';

}
```

---

# 17. `json_last_error_msg()`

También existe:

```php
json_last_error_msg()
```

que devuelve una descripción del último error JSON.

Ejemplo:

```php
$data = json_decode($json);

if (json_last_error() !== JSON_ERROR_NONE) {

    echo json_last_error_msg();

}
```

---

# 18. ERRORES DE ENCODING

`json_encode()` también puede fallar en determinadas circunstancias.

Por ejemplo, una cadena con una codificación de caracteres no válida puede provocar un error.

Una opción habitual:

```php
JSON_INVALID_UTF8_SUBSTITUTE
```

permite sustituir secuencias UTF-8 inválidas en lugar de provocar un fallo de la misma manera.

---

# 19. OPCIONES DE `json_encode()`

`json_encode()` admite flags.

Ejemplo:

```php
json_encode(
    $data,
    JSON_PRETTY_PRINT
);
```

Esto genera JSON con formato legible.

---

# 20. `JSON_PRETTY_PRINT`

Ejemplo conceptual sin formato:

```json
{"nombre":"Pedro","edad":30}
```

Con:

```php
JSON_PRETTY_PRINT
```

podemos obtener:

```json
{
    "nombre": "Pedro",
    "edad": 30
}
```

Es útil para:

```text
lectura humana
debug
logs
```

No suele ser necesario para ahorrar ancho de banda.

---

# 21. `JSON_UNESCAPED_UNICODE`

Por defecto, determinados caracteres Unicode pueden representarse escapados.

Con:

```php
JSON_UNESCAPED_UNICODE
```

podemos evitar ese escape para caracteres Unicode.

Ejemplo conceptual:

```php
json_encode(
    ['pais' => 'España'],
    JSON_UNESCAPED_UNICODE
);
```

---

# 22. `JSON_UNESCAPED_SLASHES`

Permite evitar el escape de `/` en strings JSON.

---

# 23. `JSON_NUMERIC_CHECK`

Puede convertir strings numéricos a números durante la codificación.

Ejemplo conceptual:

```php
json_encode(
    ['edad' => '30'],
    JSON_NUMERIC_CHECK
);
```

Esto puede producir:

```json
{
    "edad": 30
}
```

### ⚠️ Precaución

Debe utilizarse conscientemente porque modifica cómo determinados strings se representan en JSON.

---

# 24. `JSON_FORCE_OBJECT`

Puede forzar que arrays sean representados como objetos JSON.

Ejemplo conceptual:

```php
json_encode(
    ['Pedro', 'Ana'],
    JSON_FORCE_OBJECT
);
```

Puede producir una estructura de objeto en lugar de array.

---

# 25. `JSON_THROW_ON_ERROR`

Una vez más, merece recordarse:

```text
JSON_THROW_ON_ERROR
```

permite trabajar con excepciones en lugar de depender únicamente de comprobar manualmente el estado de error.

---

# 26. JSON Y UTF-8

JSON trabaja normalmente con Unicode y, en la práctica web, UTF-8 es fundamental.

En PHP debemos prestar atención a la codificación de las cadenas que vamos a serializar.

Una cadena con bytes inválidos puede causar problemas en:

```php
json_encode()
```

# 27. JSON Y HTTP

Ahora conectamos PHP con HTTP.

Una API suele recibir:

```text
HTTP Request
```

y devolver:

```text
HTTP Response
```

con:

```text
JSON
```

---

# 28. `Content-Type`

Cuando el cuerpo contiene JSON, normalmente utilizamos:

```text
Content-Type: application/json
```

Ejemplo:

```http
POST /api/usuarios
Content-Type: application/json
```

Body:

```json
{
    "nombre": "Pedro",
    "email": "pedro@example.com"
}
```

---

# 29. `Accept`

El cliente puede indicar qué formato espera mediante:

```text
Accept
```

Por ejemplo:

```http
Accept: application/json
```

Conceptualmente:

```text
Content-Type
→ formato del cuerpo enviado

Accept
→ formato que el cliente solicita/preferiría recibir
```

---

# 30. 🧠 CONTENT-TYPE VS ACCEPT

Memoriza:

```text
Content-Type
→ "¿Qué estoy enviando?"

Accept
→ "¿Qué quiero recibir?"
```

Es una simplificación útil para examen.

---

# 31. REQUEST JSON

Ejemplo:

```http
POST /api/usuarios
Content-Type: application/json

{
    "nombre": "Pedro",
    "edad": 30
}
```

El servidor recibe:

```text
JSON
```

y puede:

```text
parsearlo
validarlo
procesarlo
guardar datos
```

---

# 32. RESPONSE JSON

Servidor:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
    "id": 15,
    "nombre": "Pedro"
}
```

El cliente puede interpretar el cuerpo como JSON.

---

# 33. CÓDIGOS HTTP

Algunas respuestas habituales:

```text

```

No todos están relacionados exclusivamente con JSON, pero es habitual combinarlos con respuestas JSON en APIs.

# 34. LARAVEL Y JSON

Laravel facilita mucho el trabajo con JSON.

Por ejemplo:

```php
return response()->json([
    'nombre' => 'Pedro',
    'edad' => 30
]);
```

Laravel se encarga de generar una respuesta HTTP adecuada con JSON.

---

# 35. RESPONSE `json()`

La forma:

```php
response()->json(...)
```

crea una respuesta JSON.

Podemos proporcionar:

```text
datos
status HTTP
headers
opciones
```

según el uso y la firma disponible.

---

# 36. STATUS HTTP EN LARAVEL

Ejemplo:

```php
return response()->json(
    [
        'message' => 'Usuario creado'
    ],
    201
);
```

La respuesta tendrá:

```text
HTTP 201 Created
```

y un cuerpo JSON.

---

# 37. HEADERS

También podemos especificar headers.

Conceptualmente:

```php
return response()->json(
    $data,
    200,
    [
        'X-Custom-Header' => 'value'
    ]
);
```

---

# 38. REQUEST EN LARAVEL

Laravel proporciona el objeto:

```php
Request
```

para trabajar con las peticiones HTTP.

Ejemplo:

```php
public function store(
    Request $request
) {

    $nombre =
        $request->input('nombre');

}
```

---

# 39. DATOS JSON DE LA REQUEST

Cuando la petición tiene:

```text
Content-Type: application/json
```

Laravel puede proporcionar acceso a los datos mediante:

```php
$request->input('nombre');
```

o:

```php
$request->all();
```

según la necesidad.

---

# 40. `json()`

Laravel también proporciona acceso al payload JSON mediante métodos específicos del objeto Request.

Conceptualmente:

```php
$request->json();
```

permite trabajar con los datos JSON recibidos.

---

# 41. VALIDACIÓN

Nunca debemos asumir:

```text
JSON recibido
→ datos válidos
```

Laravel permite validar:

```php
$request->validate([
    'nombre' => [
        'required',
        'string'
    ],

    'edad' => [
        'required',
        'integer',
        'min:18'
    ]
]);
```

# 45. JSON RESOURCE



# 46. ¿POR QUÉ UTILIZAR RESOURCES?

Permiten controlar:

```text
qué campos exponemos
cómo se estructuran

```

Esto evita exponer directamente toda la estructura interna del modelo cuando no es conveniente.

---

# 47. JSON Y ELOQUENT

Un modelo Eloquent puede serializarse a JSON.

Por ejemplo:

```php
return response()->json(
    User::find(1)
);
```

Laravel puede convertir el modelo a una representación JSON.

Pero:

```text
"puedo serializarlo"
```

no significa:

```text
"debo exponer todos sus campos"
```

Por seguridad y diseño de API conviene controlar qué se expone.

---

# 48. SERIALIZACIÓN DE MODELOS

Laravel utiliza mecanismos de serialización de modelos para producir:

```text
array
JSON
```

y permite controlar determinados atributos mediante mecanismos del modelo y API Resources.

---

# 49. JSON Y RELACIONES

Un modelo con relaciones puede terminar representándose como:

```json
{
    "id": 1,
    "nombre": "Pedro",
    "roles": [
        {
            "id": 1,
            "nombre": "admin"
        }
    ]
}
```

Esto permite representar estructuras anidadas.

---

# 50. PROBLEMA N+1

Aunque el JSON pueda representar relaciones, hay que tener cuidado con cómo se cargan.

Por ejemplo:

```text
usuarios
+
roles
```

Si cada usuario provoca una consulta adicional:

```text
1 consulta usuarios
+
N consultas roles
```

podemos tener:

```text
N+1
```

En Laravel, normalmente se utiliza:

```php
User::with('roles')->get();
```

para realizar eager loading.

# 52. JSON Y REST

JSON no es REST.

Son conceptos diferentes:

```text
REST
→ estilo arquitectónico

JSON
→ formato de representación de datos
```

Una API REST puede utilizar JSON, pero REST no exige JSON.
