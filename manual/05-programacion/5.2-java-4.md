# 2. ¿QUÉ ES UNA EXCEPCIÓN?

Una excepción representa una situación anómala que ocurre durante la ejecución y que puede alterar el flujo normal del programa.

Ejemplo:

```java
int resultado = 10 / 0;
```

Puede producir:

```text
ArithmeticException
```

Java proporciona mecanismos para:

```text
detectar
capturar
propagar
o lanzar
```

excepciones.

---

# 3. JERARQUÍA BÁSICA

La jerarquía fundamental parte de:

```text
Throwable
│
├── Error
│
└── Exception
```

Dentro de `Exception` encontramos diferentes tipos de excepciones.

Una parte importante:

```text
RuntimeException
```

es una subclase de:

```text
Exception
```

---

# 4. `Error`

Los objetos derivados de:

```java
Error
```

representan problemas graves relacionados con el entorno de ejecución.

Ejemplos:

```text
OutOfMemoryError
StackOverflowError
```

No suelen tratarse como excepciones normales de aplicación.

---

# 5. `Exception`

`Exception` representa condiciones que una aplicación puede querer gestionar.

Ejemplos:

```text
IOException
SQLException
RuntimeException
```

---

# 6. RUNTIMEEXCEPTION

`RuntimeException` representa excepciones no comprobadas por el compilador.

Ejemplos:

```text
NullPointerException
IndexOutOfBoundsException
ArithmeticException
ClassCastException
IllegalArgumentException
```

---

# 7. CHECKED VS UNCHECKED

Esta distinción es fundamental.

## Checked exceptions

Son excepciones que el compilador obliga a:

```text
capturar
```

o:

```text
declarar
```

mediante `throws`.

Ejemplo típico:

```text
IOException
```

## Unchecked exceptions

Son excepciones derivadas de:

```text
RuntimeException
```

y no requieren obligatoriamente captura o declaración.

    ├── RuntimeException

    │   ├── ArithmeticException
    │   ├── ClassCastException
    │   └── ...
    │

        ├── IOException

# 9. `try`

El bloque:

```java
try {
    // código susceptible de excepción
}
```

contiene el código que queremos controlar.

---

# 10. `catch`

Permite capturar una excepción:

```java
try {
    int resultado = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("División por cero");
}
```

---

# 11. `finally`

`finally` permite ejecutar código de limpieza:

```java
try {
    ...
} catch (Exception e) {
    ...
} finally {
    ...
}
```

El bloque `finally` está pensado para ejecutarse al abandonar la estructura, salvo situaciones excepcionales como una terminación abrupta de la JVM.

---

# 12. MULTIPLE `catch`

Podemos capturar diferentes excepciones:

```java
try {
    ...
} catch (IOException e) {
    ...
} catch (SQLException e) {
    ...
}
```

El orden importa cuando existen relaciones de herencia.

Por ejemplo, no debemos colocar:

```java
catch (Exception e)
```

antes de:

```java
catch (IOException e)
```

si esperamos capturar `IOException` específicamente.

---

# 13. MULTI-CATCH

Java permite capturar varios tipos en un único `catch`:

```java
try {
    ...
} catch (IOException | SQLException e) {
    ...
}
```

La sintaxis:

```text
|
```

permite especificar varias alternativas.

---

# 14. `throw`

La palabra:

```java
throw
```

se utiliza para lanzar explícitamente una excepción.

Ejemplo:

```java
throw new IllegalArgumentException(
    "Edad no válida"
);
```

### 🧠 Regla

```text
throw
→ lanza una excepción concreta
```

---

# 15. `throws`

`throws` aparece en la declaración de un método.

Ejemplo:

```java
void leerArchivo()
        throws IOException {
    ...
}
```

Indica que el método puede propagar una excepción.

### 🧠 Regla

```text
throw
→ lanza

throws
→ declara/propaga
```

Esta diferencia es carne de test.

---

# 16. PROPAGACIÓN

Imaginemos:

```java
void metodoA() throws IOException {
    metodoB();
}
```

Si `metodoB()` puede producir una `IOException`, `metodoA()` puede declararla también y dejar que el llamador la gestione.

Conceptualmente:

```text
metodoB()
   ↓
excepción
   ↓
metodoA()
   ↓
llamador
```

---

# 17. CAPTURAR O PROPAGAR

Ante una checked exception normalmente podemos:

```text
capturar
```

o:

```text
declarar con throws
```

Ejemplo:

```java
void leer() throws IOException {
    ...
}
```

---

# 18. CREAR EXCEPCIONES PROPIAS

Podemos definir:

```java
class EdadInvalidaException
        extends Exception {

    public EdadInvalidaException(String mensaje) {
        super(mensaje);
    }
}
```

Después:

```java
throw new EdadInvalidaException(
    "Edad incorrecta"
);
```

---

# 19. EXCEPCIÓN CHECKED PERSONALIZADA

Si heredamos directamente de:

```java
Exception
```

sin pasar por `RuntimeException`, creamos una excepción checked.

Por tanto, el compilador puede exigir:

```text
try/catch
```

o:

```text
throws
```

---

# 20. EXCEPCIÓN UNCHECKED PERSONALIZADA

Podemos hacer:

```java
class EdadInvalidaException
        extends RuntimeException {
}
```

Ahora es:

```text
unchecked
```

---

# 21. TRY-WITH-RESOURCES

Java permite gestionar recursos automáticamente:

```java
try (FileReader reader =
        new FileReader("datos.txt")) {

    ...
}
```

El recurso se cierra automáticamente al finalizar el bloque.

---

# 22. `AutoCloseable`

Para participar en try-with-resources, un recurso debe implementar:

```java
AutoCloseable
```

o una interfaz compatible como:

```java
Closeable
```

Ejemplo conceptual:

```java
class Recurso implements AutoCloseable {

    @Override
    public void close() {
        ...
    }
}
```

---

# 23. VENTAJA DE TRY-WITH-RESOURCES

En lugar de gestionar manualmente:

```text
abrir
usar
cerrar
```

podemos utilizar:

```java
try (Recurso recurso = new Recurso()) {
    ...
}
```

Java se encarga del cierre del recurso.

---

# 24. ORDEN DE CIERRE

Si declaramos varios recursos:

```java
try (
    RecursoA a = new RecursoA();
    RecursoB b = new RecursoB()
) {
    ...
}
```

se cierran en orden inverso:

```text
B
↓
A
```

---

# 25. SUPPRESSED EXCEPTIONS

Durante try-with-resources puede ocurrir que:

```text
el código principal lance una excepción
```

y:

```text
close()
```

también lance otra.

Java puede mantener la excepción producida durante el cierre como:

```text
suppressed exception
```

y asociarla a la excepción principal.

Puede consultarse mediante:

```java
exception.getSuppressed()
```

---

# 26. GENERICS

Los generics permiten escribir código reutilizable manteniendo seguridad de tipos.

Ejemplo:

```java
List<String> nombres =
    new ArrayList<>();
```

Aquí:

```text
String
```

es el parámetro de tipo.

---

# 27. CLASE GENÉRICA

Podemos crear:

```java
class Caja<T> {

    private T valor;

    public void setValor(T valor) {
        this.valor = valor;
    }

    public T getValor() {
        return valor;
    }
}
```

Uso:

```java
Caja<String> caja =
    new Caja<>();
```

---

# 28. MÉTODO GENÉRICO

Un método también puede ser genérico:

```java
public static <T> T obtener(T valor) {
    return valor;
}
```

El:

```text
<T>
```

antes del tipo de retorno declara el parámetro genérico del método.

---

# 29. `T`, `E`, `K`, `V`

Son convenciones habituales:

```text
T
→ Type

E
→ Element

K
→ Key

V
→ Value
```

No son palabras reservadas.

Son simplemente nombres convencionales.

---

# 30. BOUNDED TYPES

Podemos restringir un parámetro genérico:

```java
class CajaNumerica<T extends Number> {
}
```

Ahora `T` debe ser:

```text
Number
```

o una subclase compatible.

---

# 31. WILDCARD `?`

Un wildcard representa un tipo desconocido.

Ejemplo:

```java
List<?> lista;
```

Significa:

```text
List de algún tipo desconocido
```

---

# 32. `? extends`

Ejemplo:

```java
List<? extends Number> lista;
```

Significa que la lista contiene algún tipo que es:

```text
Number
```

o una subclase.

Puede ser:

```text
List<Integer>
List<Double>
List<Long>
```

---

# 33. `? extends` Y LECTURA

Con:

```java
List<? extends Number>
```

podemos leer elementos como:

```java
Number numero = lista.get(0);
```

porque sabemos que el elemento es algún subtipo de `Number`.

Pero no podemos añadir arbitrariamente un:

```java
Integer
```

porque el tipo concreto desconocido podría ser:

```text
Double
```

---

# 34. `? super`

Ejemplo:

```java
List<? super Integer> lista;
```

Significa que la lista es de:

```text
Integer
```

o de algún supertipo de `Integer`.

Podría ser:

```text
List<Integer>
List<Number>
List<Object>
```

---

# 35. `? super` Y ESCRITURA

Con:

```java
List<? super Integer>
```

podemos añadir:

```java
Integer
```

porque cualquiera de los tipos posibles puede almacenar un `Integer`.

---

# 36. PECS

Una regla muy conocida:

```text
PECS
```

significa:

```text
Producer Extends
Consumer Super
```

Es decir:

```text
? extends
→ cuando principalmente producimos/leemos

? super
→ cuando principalmente consumimos/escribimos
```

---

# 37. EJEMPLO DE PECS

Productor:

```java
List<? extends Number> numeros;
```

Consumidor:

```java
List<? super Integer> numeros;
```

### 🧠 Para examen

```text
extends → leer
super   → escribir
```

Es una simplificación útil, aunque el comportamiento real depende del contexto.

---

# 38. STREAM API

La Stream API apareció en:

```text
Java 8
```

Permite procesar secuencias de elementos mediante operaciones declarativas.

Ejemplo:

```java
List<Integer> numeros =
    List.of(1, 2, 3, 4, 5);

numeros.stream()
    .filter(n -> n % 2 == 0)
    .forEach(System.out::println);
```

Resultado:

```text
2
4
```

---

# 39. STREAM VS COLLECTION

Una colección:

```text
almacena datos
```

Un stream:

```text
procesa datos
```

No debemos pensar en un `Stream` como otra colección.

---

# 40. CREAR UN STREAM

Desde una colección:

```java
lista.stream();
```

También existen:

```java
Stream.of(...)
Arrays.stream(...)
```

---

# 41. OPERACIONES INTERMEDIAS

Las operaciones intermedias transforman o filtran el stream y normalmente devuelven otro `Stream`.

Ejemplos:

```text
filter()
map()
sorted()
distinct()
limit()
skip()
```

---

# 42. `filter()`

Filtra elementos según un predicado.

Ejemplo:

```java
numeros.stream()
    .filter(n -> n > 10)
```

Solo continúan los elementos que cumplen:

```text
n > 10
```

---

# 43. `map()`

Transforma cada elemento.

Ejemplo:

```java
numeros.stream()
    .map(n -> n * 2)
```

Si tenemos:

```text
1 2 3
```

obtenemos conceptualmente:

```text
2 4 6
```

---

# 44. `distinct()`

Elimina duplicados según las reglas de igualdad:

```java
numeros.stream()
    .distinct();
```

---

# 45. `sorted()`

Ordena los elementos:

```java
numeros.stream()
    .sorted();
```

También puede recibir un comparador:

```java
personas.stream()
    .sorted(
        Comparator.comparing(Persona::getEdad)
    );
```

---

# 46. `limit()`

Limita el número de elementos:

```java
numeros.stream()
    .limit(5);
```

---

# 47. `skip()`

Ignora los primeros elementos:

```java
numeros.stream()
    .skip(5);
```

---

# 48. OPERACIONES TERMINALES

Una operación terminal produce un resultado final o un efecto.

Ejemplos:

```text
forEach()
collect()
reduce()
count()
min()
max()
findFirst()
findAny()
anyMatch()
allMatch()
noneMatch()
```

---

# 49. `forEach()`

Ejemplo:

```java
numeros.stream()
    .forEach(System.out::println);
```

Es una operación terminal.

---

# 50. `collect()`

Permite recoger los resultados.

Ejemplo:

```java
List<Integer> pares =
    numeros.stream()
        .filter(n -> n % 2 == 0)
        .collect(Collectors.toList());
```

En Java moderno también puede aparecer:

```java
.collect(Collectors.toList())
```

o:

```java
.toList()
```

según la versión de Java utilizada.

---

# 51. `reduce()`

Permite combinar los elementos para obtener un resultado acumulado.

Ejemplo:

```java
int suma =
    numeros.stream()
        .reduce(0, (a, b) -> a + b);
```

Conceptualmente:

```text
1 + 2 + 3 + 4 + 5
```

---

# 52. `count()`

Cuenta elementos:

```java
long cantidad =
    numeros.stream()
        .filter(n -> n > 10)
        .count();
```

El resultado es:

```text
long
```

---

# 53. `findFirst()`

Obtiene el primer elemento, si existe:

```java
Optional<Integer> primero =
    numeros.stream()
        .filter(n -> n > 10)
        .findFirst();
```

Devuelve:

```text
Optional<T>
```

---

# 54. `findAny()`

Obtiene algún elemento que cumpla las condiciones.

Especialmente útil en determinados escenarios paralelos.

Devuelve:

```text
Optional<T>
```

---

# 55. `anyMatch()`

Comprueba si algún elemento cumple una condición:

```java
boolean existe =
    numeros.stream()
        .anyMatch(n -> n > 10);
```

---

# 56. `allMatch()`

Comprueba si todos cumplen una condición:

```java
boolean todos =
    numeros.stream()
        .allMatch(n -> n > 0);
```

---

# 57. `noneMatch()`

Comprueba si ninguno cumple una condición:

```java
boolean ninguno =
    numeros.stream()
        .noneMatch(n -> n < 0);
```

---

# 58. LAZY EVALUATION

Muchas operaciones intermedias de Stream son:

```text
lazy
```

Esto significa que normalmente no se ejecutan completamente hasta que aparece una operación terminal.

Ejemplo:

```java
numeros.stream()
    .filter(...)
    .map(...);
```

sin operación terminal no se procesa toda la secuencia como podríamos esperar.

---

# 59. STREAMS NO SE REUTILIZAN

Una vez consumido un stream mediante una operación terminal, no debemos reutilizarlo.

Ejemplo:

```java
Stream<Integer> stream =
    numeros.stream();

stream.count();

stream.forEach(...);
```

El segundo uso puede producir:

```text
IllegalStateException
```

---

# 60. OPTIONAL

`Optional<T>` representa un valor que puede estar presente o ausente.

Ejemplo:

```java
Optional<String> nombre =
    Optional.of("Pedro");
```

---

# 61. `Optional.empty()`

Representa ausencia de valor:

```java
Optional<String> nombre =
    Optional.empty();
```

---

# 62. `Optional.of()`

Crea un Optional con un valor no nulo:

```java
Optional.of("Pedro");
```

Si proporcionamos:

```java
null
```

se produce:

```text
NullPointerException
```

---

# 63. `Optional.ofNullable()`

Permite trabajar con un valor que puede ser `null`:

```java
Optional<String> nombre =
    Optional.ofNullable(valor);
```

Si `valor` es `null`:

```text
Optional.empty()
```

---

# 64. `isPresent()`

Comprueba si existe un valor:

```java
if (nombre.isPresent()) {
    ...
}
```

---

# 65. `ifPresent()`

Permite ejecutar una acción si existe valor:

```java
nombre.ifPresent(
    n -> System.out.println(n)
);
```

---

# 66. `orElse()`

Devuelve el valor o una alternativa:

```java
String resultado =
    nombre.orElse("Desconocido");
```

---

# 67. `orElseGet()`

Recibe un `Supplier` para generar el valor alternativo:

```java
String resultado =
    nombre.orElseGet(
        () -> obtenerNombre()
    );
```

Esto permite evaluación perezosa de la alternativa.

---

# 68. `orElseThrow()`

Permite lanzar una excepción si no existe valor:

```java
String nombre =
    optional.orElseThrow();
```

También:

```java
optional.orElseThrow(
    () -> new IllegalArgumentException()
);
```

---

# 69. `Optional.map()`

Podemos transformar el valor contenido:

```java
Optional<Integer> longitud =
    nombre.map(String::length);
```

Si el `Optional` está vacío:

```text
continúa vacío
```

---

# 70. `Optional` NO ES UN CONTENEDOR UNIVERSAL

`Optional` está pensado principalmente para representar:

```text
posible ausencia de un valor
```

No debe utilizarse automáticamente para envolver absolutamente todos los atributos o parámetros de una aplicación.

---

# 71. STREAM + OPTIONAL

Ejemplo:

```java
Optional<Integer> resultado =
    numeros.stream()
        .filter(n -> n > 10)
        .findFirst();
```

Esto expresa:

```text
puede existir un resultado
```

sin devolver directamente:

```text
null
```
