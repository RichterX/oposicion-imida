# 1. INTRODUCCIÓN

Hasta ahora hemos trabajado con JavaScript como lenguaje:

```text
variables
funciones
objetos
arrays
clases
JSON
```

Ahora JavaScript entra en contacto directo con la página web.

El concepto fundamental será:

```text
DOM
```

El DOM permite representar el documento HTML como una estructura que JavaScript puede consultar y modificar.

---

# 2. DOM

DOM significa:

```text
Document Object Model
```

Es una representación estructurada del documento.

Podemos imaginar un HTML:

```html
<html>
    <body>
        <h1>Hola</h1>
        <p>Texto</p>
    </body>
</html>
```

como un árbol:

```text
html
└── body
    ├── h1
    │   └── "Hola"
    └── p
        └── "Texto"
```

JavaScript puede utilizar este árbol para:

```text
buscar elementos
crear elementos
eliminar elementos
modificar contenido
modificar atributos
modificar clases
escuchar eventos
```

---

# 3. `document`

El objeto:

```javascript
document
```

representa el documento cargado.

Ejemplos:

```javascript
document.title
```

```javascript
document.body
```

```javascript
document.documentElement
```

---

# 4. SELECCIONAR POR ID

Método clásico:

```javascript
document.getElementById("titulo");
```

HTML:

```html
<h1 id="titulo">
    Hola
</h1>
```

Devuelve el elemento cuyo `id` coincide.

Si no existe:

```text
null
```

---

# 5. `querySelector()`

Permite seleccionar el primer elemento que coincide con un selector CSS.

Ejemplo:

```javascript
const titulo =
    document.querySelector("#titulo");
```

También:

```javascript
const boton =
    document.querySelector(".boton");
```

Y:

```javascript
const input =
    document.querySelector(
        'input[type="email"]'
    );
```

---

# 6. `querySelector()` Y SELECTORES CSS

Una de sus grandes ventajas es que utiliza la sintaxis de selectores CSS.

Por ejemplo:

```javascript
document.querySelector(
    "nav > a"
);
```

o:

```javascript
document.querySelector(
    ".card .title"
);
```

---

# 7. `querySelectorAll()`

Devuelve todos los elementos que coinciden con el selector.

Ejemplo:

```javascript
const botones =
    document.querySelectorAll(
        ".boton"
    );
```

El resultado es un:

```text
NodeList
```

---

# 8. `querySelector()` VS `querySelectorAll()`

```text
querySelector()
→ primer elemento

querySelectorAll()
→ todos los elementos coincidentes
```

---

# 9. `getElementsByClassName()`

Método clásico:

```javascript
document.getElementsByClassName(
    "boton"
);
```

Devuelve una colección de elementos con esa clase.

Normalmente devuelve un:

```text
HTMLCollection
```

---

# 10. `getElementsByTagName()`

Permite seleccionar elementos por nombre de etiqueta.

```javascript
document.getElementsByTagName(
    "p"
);
```

---

# 11. `getElementsByName()`

Selecciona elementos mediante su atributo:

```html
name
```

Ejemplo:

```javascript
document.getElementsByName(
    "email"
);
```

---

# 12. `querySelectorAll()` VS HTMLCollection

Es importante reconocer:

```text
querySelectorAll()
→ NodeList

getElementsByClassName()
→ HTMLCollection

getElementsByTagName()
→ HTMLCollection
```

Aunque las diferencias prácticas pueden ser pequeñas en ejercicios básicos, pueden aparecer en un test.

---

# 13. COLECCIONES LIVE VS STATIC

Algunas colecciones del DOM son:

```text
live
```

y otras:

```text
static
```

Por ejemplo:

```text
HTMLCollection
→ normalmente live

querySelectorAll()
→ NodeList estático
```

Esto significa que una colección live puede reflejar cambios posteriores en el documento.

# 23. `textContent` VS `innerHTML`

`textContent` trata el contenido como texto.

```javascript
elemento.textContent =
    "<strong>Hola</strong>";
```

El resultado visible será literalmente:

```text
<strong>Hola</strong>
```

No se interpreta como HTML.

---

# 24. `innerHTML`

Permite leer o establecer HTML interno.

```javascript
elemento.innerHTML =
    "<strong>Hola</strong>";
```

Ahora el navegador interpreta:

```text
<strong>
```

como HTML.

---

# 25. ⚠️ SEGURIDAD: XSS

Introducir directamente contenido no confiable mediante:

```javascript
innerHTML
```

puede producir vulnerabilidades de:

```text
Cross-Site Scripting
```

cuando el contenido no está correctamente controlado.

Para texto simple suele ser preferible:

```text
textContent
```

---

# 26. `innerText`

Otra propiedad:

```javascript
elemento.innerText
```

está relacionada con el texto renderizado/visible y tiene un comportamiento diferente de `textContent`.

De forma simplificada:

```text
textContent
→ texto del contenido del nodo

innerText
→ texto tal como se representa visualmente
```

`innerText` puede verse afectado por estilos y layout.

# 54. `addEventListener()`

Es la forma habitual de registrar un listener:

```javascript
elemento.addEventListener(
    "click",
    funcion
);
```

Ejemplo:

```javascript
boton.addEventListener(
    "click",
    () => {
        console.log("Click");
    }

```

---

# 55. EVENT HANDLER

La función ejecutada cuando ocurre el evento se denomina:

```text
event handler
```

o:

```text
listener
```

según el contexto.

---

# 56. OBJETO `event`

El navegador proporciona información sobre el evento.

Ejemplo:

```javascript
boton.addEventListener(
    "click",
    (event) => {
        console.log(event);
    }
);
```

El objeto puede proporcionar información como:

```text
target
currentTarget
type
bubbles
defaultPrevented
```

además de propiedades específicas según el tipo de evento.

---

# 57. `event.target`

Indica el objeto que originó el evento.

Ejemplo conceptual:

```javascript
container.addEventListener(
    "click",
    (event) => {
        console.log(
            event.target
        );
    }
);
```

---

# 58. `event.currentTarget`

Indica el objeto cuyo listener está ejecutándose.

Por ejemplo, si tenemos:

```javascript
container.addEventListener(
    "click",
    (event) => {
        console.log(
            event.currentTarget
        );
    }
);
```

`currentTarget` será:

```text
container
```

aunque el click original se haya producido sobre un elemento hijo.

---

# 59. `target` VS `currentTarget`

Esta diferencia es fundamental.

```text
target
→ dónde se originó el evento

currentTarget
→ elemento cuyo listener se está ejecutando
```

---

# 60. `preventDefault()`

Cancela la acción por defecto asociada al evento cuando es cancelable.

Ejemplo:

```javascript
form.addEventListener(
    "submit",
    (event) => {
        event.preventDefault();
    }
);
```

Esto permite evitar el comportamiento de envío tradicional del formulario.

---

# 61. `stopPropagation()`

Impide que el evento continúe propagándose hacia otras fases/ancestros según el modelo de propagación.

Ejemplo:

```javascript
boton.addEventListener(
    "click",
    (event) => {
        event.stopPropagation();
    }
);
```

### ⚠️ Importante

```text
preventDefault()
→ acción por defecto

stopPropagation()
→ propagación del evento
```

No son lo mismo.

---

# 62. `stopImmediatePropagation()`

Además de detener la propagación, impide que otros listeners del mismo objetivo sigan ejecutándose después de la llamada.

Es más fuerte que:

```text
stopPropagation()
```

---

# 63. PROPAGACIÓN DE EVENTOS

Los eventos pueden propagarse por el árbol DOM.

Las fases principales son:

```text
capturing
target
bubbling
```

---

# 64. CAPTURING

En la fase de captura, el evento viaja conceptualmente:

```text
document
   ↓
ancestros
   ↓
target
```

---

# 65. TARGET

El evento alcanza el objetivo:

```text
target
```

---

# 66. BUBBLING

Después puede propagarse hacia arriba:

```text
target
   ↑
padre
   ↑
abuelo
   ↑
document
```

Muchos eventos habituales utilizan bubbling.

---

# 67. CAPTURING CON `addEventListener`

Podemos indicar la fase mediante opciones:

```javascript
elemento.addEventListener(
    "click",
    handler,
    { capture: true }
);
```

---

# 68. BUBBLING POR DEFECTO

Normalmente:

```javascript
elemento.addEventListener(
    "click",
    handler
);
```

utiliza:

```text
capture: false
```

por lo que el listener participa normalmente en bubbling.

---

# 69. EVENT DELEGATION

La delegación de eventos consiste en colocar un listener en un elemento ancestro para gestionar eventos de sus descendientes.

Ejemplo:

```javascript
lista.addEventListener(
    "click",
    (event) => {

        if (
            event.target.matches(".item")
        ) {
            console.log(
                "Item pulsado"
            );
        }
    }
);
```

---

# 70. VENTAJA DE EVENT DELEGATION

Es especialmente útil cuando:

```text
existen muchos elementos
```

o:

```text
los elementos se crean dinámicamente
```

En lugar de añadir un listener a cada elemento:

```text
un listener en el contenedor
```

puede gestionar los eventos de los descendientes.

---

# 71. `matches()`

Permite comprobar si un elemento coincide con un selector CSS.

Ejemplo:

```javascript
elemento.matches(
    ".boton"
);
```

---

# 72. `closest()`

Busca el ancestro más cercano que coincide con un selector.

Ejemplo:

```javascript
const boton =
    event.target.closest(
        ".boton"
    );
```

Es extremadamente útil en delegación de eventos.

---

# 73. `mouseenter` VS `mouseover`

Ambos están relacionados con el puntero.

Pero:

```text
mouseover
→ puede propagarse cuando el puntero entra en descendientes

mouseenter
→ no se comporta igual respecto a la entrada en descendientes
```

Para muchos casos de interfaz, `mouseenter` evita ciertos comportamientos de bubbling asociados a `mouseover`.

---

# 74. `input` VS `change`

En campos de formulario:

```text
input
→ se dispara cuando cambia el valor durante la edición

change
→ se dispara cuando el cambio se confirma según las reglas del control
```

El comportamiento exacto depende del tipo de control.

---

# 75. EVENTO `submit`

Para formularios:

```javascript
form.addEventListener(
    "submit",
    (event) => {
        event.preventDefault();

        // validar / enviar
    }
);
```

Es preferible escuchar:

```text
submit
```

en el formulario que intentar gestionar únicamente el click del botón de envío.

---

# 76. EVENTOS DE TECLADO

Ejemplos:

```text

keyup
```

Podemos inspeccionar:

```javascript

```

Ejemplo:

```javascript

    (event) => {
        console.log(

    }
```

---

# 77. `event.code` VS `event.key`

```text
event.key
→ valor lógico de la tecla pulsada

event.code
→ código físico/posición de la tecla
```

Por ejemplo, según el teclado y distribución:

```text
key
→ "a"

code
→ "KeyA"
```

---

# 78. `DOMContentLoaded`

Este evento se produce cuando el documento HTML ha sido completamente analizado y construido, sin esperar necesariamente a que terminen de cargar todos los recursos externos como imágenes.

Ejemplo:

```javascript
document.addEventListener(
    "DOMContentLoaded",
    () => {
        console.log(
            "DOM preparado"
        );
    }
);
```

---

# 79. `load`

El evento:

```text
load
```

se produce cuando el recurso correspondiente y sus recursos dependientes han terminado de cargar según el objeto involucrado.

En el contexto de la ventana, suele ocurrir después de que los recursos de la página hayan cargado.

---

# 80. `DOMContentLoaded` VS `load`

```text
DOMContentLoaded
→ HTML analizado y DOM construido

load
→ recursos dependientes cargados en el contexto correspondiente
```

### 🧠 Trampa

No son equivalentes.
