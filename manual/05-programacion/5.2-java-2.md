# 2. CLASES Y OBJETOS

Una **clase** puede entenderse como una definición o plantilla que describe:

```text
datos
+
comportamiento
```

Un **objeto** es una instancia concreta de una clase.

Ejemplo:

```java
class Persona {

    String nombre;
    int edad;

    void saludar() {
        System.out.println("Hola");
    }
}
```

Podemos crear:

```java
Persona persona = new Persona();
```

Aquí:

```text
Persona
→ clase / tipo

persona
→ referencia

new Persona()
→ objeto creado
```

---

# 3. `new`

El operador:

```java
new
```

se utiliza habitualmente para crear objetos.

Ejemplo:

```java
Persona persona = new Persona();
```

Conceptualmente:

```text
new
 ↓
crea objeto
 ↓
constructor
 ↓
referencia almacenada
```

# 4. REFERENCIA VS OBJETO

Esto es especialmente importante en Java.

Tenemos:

```java
Persona persona = new Persona();
```

Podemos pensar:

```text
persona
   │
   ▼
[ objeto Persona ]
```

La variable:

```text
persona
```

contiene una referencia al objeto.

No contiene necesariamente el objeto "dentro" de la variable como una estructura de valor.

---

# 5. VARIAS REFERENCIAS AL MISMO OBJETO

Podemos hacer:

```java
Persona p1 = new Persona();
Persona p2 = p1;
```

Ahora:

```text
p1 ─────┐
        ▼
     [OBJETO]
        ▲
        │
p2 ─────┘
```

Ambas referencias apuntan al mismo objeto.

Por tanto:

```java
p1 == p2
```

será:

```text
true
```

# 11. CONSTRUCTORES

Un constructor permite inicializar un objeto cuando se crea.

Ejemplo:

```java
class Persona {

    String nombre;

    Persona(String nombre) {
        this.nombre = nombre;
    }
}
```

Creación:

```java
Persona persona = new Persona("Pedro");
```

---

# 12. CARACTERÍSTICAS DEL CONSTRUCTOR

Un constructor:

```text
Tiene el mismo nombre que la clase
No tiene tipo de retorno
Se ejecuta durante la creación del objeto
```

Correcto:

```java
Persona(String nombre) {
    this.nombre = nombre;
}
```

Incorrecto como constructor:

```java
void Persona(String nombre) {
    ...
}
```

Eso sería un método llamado `Persona`, no un constructor.

---

# 13. CONSTRUCTOR POR DEFECTO

Si una clase no declara ningún constructor, el compilador puede proporcionar un constructor sin argumentos.

Ejemplo:

```java
class Persona {
    String nombre;
}
```

Conceptualmente permite:

```java
Persona p = new Persona();
```

### ⚠️ Importante

Si declaramos nuestro propio constructor:

```java
class Persona {

    Persona(String nombre) {
        ...
    }
}
```

Java ya no proporciona automáticamente el constructor sin argumentos.

Por tanto:

```java
new Persona()
```

puede dejar de ser válido.

---

# 14. SOBRECARGA DE CONSTRUCTORES

Podemos tener varios constructores con diferentes parámetros:

```java
class Persona {

    Persona() {
    }

    Persona(String nombre) {
        ...
    }

    Persona(String nombre, int edad) {
        ...
    }
}
```

Esto es:

```text
constructor overloading
```

---

# 15. `this`

La palabra:

```java
this
```

hace referencia al objeto actual.

Ejemplo:

```java
class Persona {

    private String nombre;

    Persona(String nombre) {
        this.nombre = nombre;
    }
}
```

Aquí:

```text
this.nombre
→ atributo del objeto

nombre
→ parámetro del constructor
```

---

# 16. `this` PARA LLAMAR A OTRO CONSTRUCTOR

También podemos utilizar:

```java
this(...)
```

Ejemplo:

```java
class Persona {

    private String nombre;
    private int edad;

    Persona() {
        this("Desconocido", 0);
    }

    Persona(String nombre, int edad) {
        this.nombre = nombre;
        this.edad = edad;
    }
}
```

### ⚠️ Regla

Una llamada:

```java
this(...)
```

debe aparecer como primera sentencia del constructor.

# 17. MODIFICADORES DE ACCESO

Java dispone de:

```text
public
protected
private
```

y ausencia de modificador, conocida como:

```text
package-private
```

---

# 18. `public`

Un elemento:

```java
public
```

es accesible desde otros contextos que tengan acceso al tipo correspondiente.

Ejemplo:

```java
public void saludar() {
}
```

---

# 19. `private`

```java
private
```

restringe el acceso al ámbito de la propia clase.

Ejemplo:

```java
class Persona {

    private String nombre;
}
```

Desde código externo no podemos hacer directamente:

```java
persona.nombre
```

si `nombre` es privado.

---

# 20. `protected`

`protected` permite acceso:

```text
desde la propia clase
desde clases del mismo paquete
desde subclases según las reglas de Java
```

Es importante no reducirlo simplemente a:

```text
"visible para hijos"
```

porque el paquete también interviene.

---

# 21. PACKAGE-PRIVATE

Si no escribimos ningún modificador:

```java
class Persona {

    String nombre;
}
```

el acceso es:

```text
package-private
```

El miembro es accesible dentro del mismo paquete, sujeto a las reglas correspondientes.

---

# 22. TABLA DE ACCESO

Una simplificación útil para examen:

| Modificador | Misma clase | Mismo paquete | Subclase | Otro paquete |
|---|---:|---:|---:|---:|
| `private` | ✓ | ✗ | ✗ | ✗ |
| package-private | ✓ | ✓ | según pertenencia al paquete | ✗ |
| `protected` | ✓ | ✓ | ✓ según reglas de acceso | ✓ mediante herencia según reglas |
| `public` | ✓ | ✓ | ✓ | ✓ |

### 🧠 Idea fundamental

```text
private
→ clase

package-private
→ paquete

protected
→ paquete + acceso de subclases según reglas

public
→ acceso general
```

# 23. ENCAPSULACIÓN

La encapsulación consiste en controlar cómo se accede y modifica el estado interno de un objeto.

Un patrón muy habitual:

```java
class Persona {

    private String nombre;

    public String getNombre() {
        return nombre;
    }

    public void setNombre(String nombre) {
        this.nombre = nombre;
    }
}
```

Ahora:

```text
estado
→ private

acceso
→ métodos públicos
```

---

# 24. GETTERS Y SETTERS

Convenciones habituales:

```text
getNombre()
→ obtener

setNombre()
→ modificar
```

Ejemplo:

```java
persona.setNombre("Pedro");

String nombre = persona.getNombre();
```

No son una característica obligatoria del lenguaje.

Son una convención muy utilizada para encapsular propiedades.

---

# 25. VALIDACIÓN EN SETTERS

Un setter puede incluir lógica:

```java
public void setEdad(int edad) {

    if (edad >= 0) {
        this.edad = edad;
    }
}
```

Esto permite proteger invariantes del objeto.

---

# 26. `static`

Un miembro `static` pertenece a la clase en lugar de a una instancia concreta.

Ejemplo:

```java
class Contador {

    static int total = 0;
}
```

Podemos acceder:

```java
Contador.total
```

sin crear una instancia.

---

# 27. MÉTODO `static`

Ejemplo:

```java
class Calculadora {

    static int sumar(int a, int b) {
        return a + b;
    }
}
```

Podemos hacer:

```java
int resultado = Calculadora.sumar(2, 3);
```

---

# 28. `static` Y `this`

Un método estático no tiene una instancia implícita.

Por eso no podemos utilizar directamente:

```java
this
```

dentro de un contexto estático.

Tampoco podemos acceder directamente a un atributo de instancia sin disponer de un objeto.

---

# 29. `final`

`final` puede utilizarse en diferentes contextos.

Con una variable:

```java
final int MAX = 100;
```

no podemos reasignarla:

```java
MAX = 200;
```

---

# 30. `final` EN MÉTODOS

Un método `final` no puede ser sobrescrito por una subclase.

```java
public final void ejecutar() {
}
```

---

# 31. `final` EN CLASES

Una clase `final` no puede ser extendida:

```java
public final class Utilidad {
}
```

No podremos:

```java
class MiUtilidad extends Utilidad {
}
```

---

# 32. HERENCIA

La herencia permite crear una clase a partir de otra.

Ejemplo:

```java
class Animal {
}
```

y:

```java
class Perro extends Animal {
}
```

Tenemos:

```text
Animal
   ▲
   │
 Perro
```

`Perro` es una subclase de `Animal`.

---

# 33. `extends`

La palabra:

```java
extends
```

indica herencia de clases.

Ejemplo:

```java
class Perro extends Animal {
}
```

Java permite herencia de una única clase directa:

```text
una clase
→ una superclase directa
```

---

# 34. HERENCIA Y MÉTODOS

```java
class Animal {

    void comer() {
        System.out.println("Comiendo");
    }
}

class Perro extends Animal {
}
```

Podemos hacer:

```java
Perro perro = new Perro();

perro.comer();
```

El método se hereda.

---

# 35. `super`

`super` permite hacer referencia a la superclase.

Por ejemplo:

```java
class Perro extends Animal {

    void mostrar() {
        super.comer();
    }
}
```

Aquí:

```text
super.comer()
→ comportamiento de la superclase
```

---

# 36. `super()` EN CONSTRUCTORES

También podemos llamar al constructor de la superclase:

```java
class Animal {

    Animal(String nombre) {
        ...
    }
}

class Perro extends Animal {

    Perro(String nombre) {
        super(nombre);
    }
}
```

### ⚠️ Regla

Una llamada:

```java
super(...)
```

debe ser la primera sentencia del constructor.

---

# 37. SOBRESCRITURA

Una subclase puede proporcionar una implementación específica de un método heredado.

Ejemplo:

```java
class Animal {

    void hacerSonido() {
        System.out.println("Sonido");
    }
}

class Perro extends Animal {

    @Override
    void hacerSonido() {
        System.out.println("Guau");
    }
}
```

Esto es:

```text
method overriding
```

---

# 38. `@Override`

La anotación:

```java
@Override
```

indica que estamos sobrescribiendo un método heredado.

Es recomendable utilizarla porque el compilador puede detectar errores.

Por ejemplo, si escribimos accidentalmente una firma incorrecta, puede avisarnos de que realmente no estamos sobrescribiendo el método esperado.

---

# 39. SOBRECARGA VS SOBRESCRITURA

Dos conceptos que suelen confundirse.

### Sobrecarga

Mismo nombre:

```text
diferentes parámetros
```

Ejemplo:

```java
void imprimir(int numero) {
}

void imprimir(String texto) {
}
```

### Sobrescritura

Subclase redefine un método heredado:

```java
@Override
void hacerSonido() {
}
```

---

# 40. TABLA COMPARATIVA

| Concepto | Sobrecarga | Sobrescritura |
|---|---|---|
| Inglés | Overloading | Overriding |
| Herencia necesaria | No | Sí |
| Mismo nombre | Sí | Sí |
| Parámetros diferentes | Sí | La firma debe corresponder |
| Ocurre entre | Métodos de una clase/jerarquía | Superclase y subclase |
| `@Override` | No | Sí, recomendado |

---

# 41. POLIMORFISMO

El polimorfismo permite utilizar una referencia de un tipo general para trabajar con objetos de tipos concretos.

Ejemplo:

```java
Animal animal = new Perro();
```

La referencia es:

```text
Animal
```

pero el objeto real es:

```text
Perro
```

---

# 42. POLIMORFISMO EN ACCIÓN

```java
class Animal {

    void hacerSonido() {
        System.out.println("Sonido");
    }
}

class Perro extends Animal {

    @Override
    void hacerSonido() {
        System.out.println("Guau");
    }
}

Animal animal = new Perro();

animal.hacerSonido();
```

Resultado:

```text
Guau
```

El método sobrescrito correspondiente al objeto real se ejecuta.

---

# 43. UPCASTING

Esto:

```java
Animal animal = new Perro();
```

es un ejemplo de conversión hacia un tipo de superclase:

```text
Perro
 ↓
Animal
```

Es habitual y puede realizarse implícitamente cuando existe compatibilidad.

---

# 44. DOWNCASTING

Podemos convertir explícitamente una referencia:

```java
Animal animal = new Perro();

Perro perro = (Perro) animal;
```

Esto es:

```text
downcasting
```

### ⚠️ Riesgo

Si el objeto real no es un `Perro`:

```java
Animal animal = new Gato();

Perro perro = (Perro) animal;
```

se producirá una excepción:

```text
ClassCastException
```

---

# 45. `instanceof`

Podemos comprobar el tipo de un objeto:

```java
if (animal instanceof Perro) {
    Perro perro = (Perro) animal;
}
```

En Java moderno también existe pattern matching:

```java
if (animal instanceof Perro perro) {
    perro.hacerSonido();
}
```

# 46. CLASE `Object`

En Java, todas las clases heredan directa o indirectamente de:

```java
Object
```

Por eso `Object` ocupa una posición fundamental en la jerarquía de clases.

Métodos conocidos:

```text
toString()
equals()
hashCode()
getClass()
```

---

# 47. `toString()`

Permite proporcionar una representación textual de un objeto.

Ejemplo:

```java
@Override
public String toString() {
    return "Persona{nombre='" + nombre + "'}";
}
```

Después:

```java
System.out.println(persona);
```

puede utilizar esa representación.

---

# 48. `equals()`

Se utiliza para definir igualdad lógica entre objetos.

Ejemplo conceptual:

```java
@Override
public boolean equals(Object obj) {
    ...
}
```

No debemos confundir:

```text
==
```

con:

```text
equals()
```

---

# 49. `hashCode()`

`hashCode()` devuelve un valor entero utilizado en estructuras basadas en hash.

Existe una relación importante:

```text
si a.equals(b) es true
→ a.hashCode() debe ser igual a b.hashCode()
```

La relación inversa no garantiza que los objetos sean iguales.

---

# 50. 🧠 REGLA DE `equals()` Y `hashCode()`

Si sobrescribimos:

```java
equals()
```

normalmente debemos sobrescribir también:

```java
hashCode()
```

para mantener el contrato de igualdad utilizado por colecciones como:

```text
HashMap
HashSet
```

---

# 51. CLASE ABSTRACTA

Una clase puede declararse:

```java
abstract class Animal {
}
```

No podemos instanciar directamente una clase abstracta:

```java
new Animal();
```

si `Animal` es abstracta.

Puede utilizarse como base para otras clases.

---

# 52. MÉTODO ABSTRACTO

Podemos declarar:

```java
abstract void hacerSonido();
```

Un método abstracto no proporciona implementación en la clase abstracta.

Una subclase concreta deberá implementarlo, salvo que también sea abstracta.

---

# 53. ABSTRACCIÓN

La abstracción busca representar los aspectos relevantes de una entidad ocultando detalles innecesarios.

En Java podemos utilizar:

```text
clases abstractas
interfaces
```

entre otros mecanismos.

---

# 54. ENCAPSULACIÓN VS ABSTRACCIÓN

No son exactamente lo mismo.

```text
Encapsulación
→ controlar acceso y proteger estado

Abstracción
→ modelar lo esencial y ocultar detalles
```

---

# 55. COMPOSICIÓN

La composición consiste en construir objetos que contienen o utilizan otros objetos.

Ejemplo:

```java
class Motor {
}

class Coche {

    private Motor motor;

    Coche() {
        this.motor = new Motor();
    }
}
```

Conceptualmente:

```text
Coche
  │
  └── Motor
```

---

# 56. HERENCIA VS COMPOSICIÓN

Una regla conceptual útil:

```text
Herencia
→ "es un"

Composición
→ "tiene un"
```

Ejemplo:

```text
Perro es un Animal
Coche tiene un Motor
```

No es una regla absoluta para diseñar sistemas, pero ayuda a interpretar relaciones.

---

# 57. CLASE ANIDADA

Java permite definir clases dentro de otras clases.

Por ejemplo:

```java
class Externa {

    class Interna {
    }
}
```

Existen diferentes tipos de clases anidadas, que veremos con más detalle si el temario lo requiere.

---

# 58. `static` EN CLASES ANIDADAS

Una clase anidada puede ser:

```java
static class Interna {
}
```

Una clase miembro estática no necesita una instancia de la clase externa para existir.

```text

```

Una clase define.

---

```text
new
```

crea un objeto y participa en la inicialización mediante el constructor.

## Trampa 3

Un constructor:

```text
no tiene tipo de retorno
```

## Trampa 4

Si declaramos un constructor propio, no se genera automáticamente el constructor sin argumentos.

## Trampa 5

```text
private
```

significa acceso desde la propia clase, no simplemente "desde el paquete".

---

## Trampa 6

`protected` no significa únicamente "visible desde subclases". El acceso desde el mismo paquete también es relevante.

---

## Trampa 7

```text
static
```

pertenece a la clase, no a una instancia concreta.

---

## Trampa 8

Un método `static` no puede utilizar `this` directamente.

---

## Trampa 9

```text
final variable
→ no reasignable
```

No significa necesariamente que un objeto referenciado sea completamente inmutable.

---

## Trampa 10

```text
extends
```

se utiliza para herencia de clases.

---

## Trampa 11

Java no permite herencia múltiple de clases.

Una clase no puede extender directamente dos clases.

---

## Trampa 12

```text
overloading
→ mismo nombre, parámetros diferentes

overriding
→ redefinir comportamiento heredado
```

---

## Trampa 13

```text
Animal a = new Perro();
```

es válido si `Perro extends Animal`.

La referencia es `Animal`, pero el objeto real es `Perro`.

---

## Trampa 14

```text
== 
```

en referencias comprueba identidad, no igualdad lógica de contenido.

---

## Trampa 15

Si sobrescribimos `equals()`, debemos respetar el contrato de `hashCode()`.
