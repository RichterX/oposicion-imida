# 1. INTRODUCCIÓN

En un programa real pueden producirse situaciones inesperadas:

```text
Dividir entre cero
Acceder a un índice inexistente
Utilizar una clave que no existe
Convertir texto no numérico a entero
Abrir un archivo inexistente
Utilizar un tipo incorrecto
```

Python dispone de un sistema de **excepciones** para detectar y gestionar estas situaciones.

La estructura fundamental es:

```python
try:
    # código que puede producir una excepción
except:
    # gestión de la excepción
```

---

# 2. ERRORES Y EXCEPCIONES

Aunque en el lenguaje cotidiano hablamos de "errores", conviene distinguir varios conceptos.

## 2.1 Error de sintaxis

Se produce cuando el código no cumple la sintaxis de Python.

Ejemplo:

```python
if True
    print("Hola")
```

Falta:

```text
:
```

Python no puede ejecutar correctamente ese código.

---

## 2.2 Error durante la ejecución

El programa puede tener una sintaxis correcta y, sin embargo, encontrarse con un problema durante su ejecución.

Ejemplo:

```python
resultado = 10 / 0
```

La sintaxis es válida, pero se produce:

```text
ZeroDivisionError
```

---

# 3. EXCEPCIONES

Una excepción es una condición excepcional que ocurre durante la ejecución y que puede ser gestionada mediante el mecanismo de excepciones de Python.

Ejemplo:

```python
numero = int("hola")
```

produce:

```text
ValueError
```

Podemos capturarla:

```python
try:
    numero = int("hola")
except ValueError:
    print("El valor no es válido")
```

Resultado:

```text
El valor no es válido
```

---

# 4. `try`

El bloque:

```python
try:
```

contiene el código que queremos ejecutar y que puede producir una excepción.

Ejemplo:

```python
try:
    resultado = 10 / 2
```

Normalmente se combina con `except`.

---

# 5. `except`

`except` permite capturar una excepción.

```python
try:
    resultado = 10 / 0
except ZeroDivisionError:
    print("No se puede dividir entre cero")
```

La excepción se captura y el programa puede continuar.

---

# 6. FLUJO BÁSICO

Podemos representarlo:

```text
             ┌──────────────┐
             │     try      │
             └──────┬───────┘
                    │
             ¿excepción?
              ┌─────┴─────┐
             NO           SÍ
              │            │
              ▼            ▼
          continuar      except
                           │
                           ▼
                       gestionar
```

# 7. CAPTURAR UNA EXCEPCIÓN CON SU TIPO

Es recomendable capturar la excepción concreta cuando sabemos cuál esperamos.

```python
try:
    numero = int("abc")
except ValueError:
    print("Conversión incorrecta")
```

Esto es preferible a capturar absolutamente cualquier excepción sin motivo.

---

# 8. MÚLTIPLES `except`

Podemos tener varios bloques `except`.

```python
try:
    numero = int(input("Número: "))
    resultado = 10 / numero

except ValueError:
    print("Debes introducir un número")

except ZeroDivisionError:
    print("No puedes introducir cero")
```

Python ejecutará el `except` correspondiente a la excepción producida.

---

# 9. ORDEN DE LOS `except`

El orden importa cuando las excepciones tienen relación de herencia.

Por ejemplo:

```python
try:
    ...
except Exception:
    ...
except ValueError:
    ...
```

El segundo bloque sería inalcanzable para `ValueError`, porque:

```text
ValueError
   ↓
Exception
```

Por tanto, normalmente debemos colocar primero las excepciones más específicas.

Correcto:

```python
try:
    ...
except ValueError:
    ...
except Exception:
    ...
```

### 🧠 Regla

```text
Más específica
      ↓
Más general
```

---

# 10. CAPTURAR VARIAS EXCEPCIONES

Podemos capturar varios tipos en un mismo `except`:

```python
try:
    ...
except (ValueError, TypeError):
    print("Error de valor o de tipo")
```

La sintaxis utiliza una tupla de excepciones.

---

# 11. OBTENER EL OBJETO DE LA EXCEPCIÓN

Podemos almacenar la excepción mediante:

```python
as
```

Ejemplo:

```python
try:
    numero = int("abc")
except ValueError as error:
    print(error)
```

La variable:

```python
error
```

contiene el objeto de la excepción.

---

# 12. `else`

El bloque:

```python
else:
```

puede utilizarse después de `try` y `except`.

Se ejecuta **si no se produjo ninguna excepción en el `try`**.

Ejemplo:

```python
try:
    resultado = 10 / 2
except ZeroDivisionError:
    print("Error")
else:
    print("Resultado:", resultado)
```

Resultado:

```text
Resultado: 5.0
```

---

# 13. `try / except / else`

La estructura:

```python
try:
    ...
except:
    ...
else:
    ...
```

significa:

```text
try
 ↓
¿error?
 ├── Sí → except
 └── No → else
```

---

# 14. `finally`

`finally` contiene código que debe ejecutarse independientemente de si se produjo una excepción.

Ejemplo:

```python
try:
    resultado = 10 / 2
except ZeroDivisionError:
    print("Error")
finally:
    print("Fin")
```

Resultado:

```text
Fin
```

El `finally` se ejecuta aunque se produzca una excepción gestionada.

---

# 15. `try / except / finally`

Ejemplo:

```python
try:
    resultado = 10 / 0

except ZeroDivisionError:
    print("Error")

finally:
    print("Esto siempre se ejecuta")
```

Resultado:

```text
Error
Esto siempre se ejecuta
```

---

# 16. `try / except / else / finally`

Podemos utilizar las cuatro partes:

```python
try:
    resultado = 10 / 2

except ZeroDivisionError:
    print("Error")

else:
    print("Correcto")

finally:
    print("Fin")
```

Resultado:

```text
Correcto
Fin
```

### Orden conceptual

```text
try
 ↓
except  ← solo si hay excepción
 ↓
else    ← solo si NO hay excepción
 ↓
finally ← finalmente
```

---

# 17. `finally` Y RECURSOS

`finally` se utiliza frecuentemente para garantizar tareas de limpieza.

Por ejemplo:

```python
archivo = None

try:
    archivo = open("datos.txt")
    contenido = archivo.read()

finally:
    if archivo:
        archivo.close()
```

Aunque se produzca una excepción durante la lectura, intentamos cerrar el archivo.

Más adelante veremos que Python dispone de una forma más apropiada para este caso:

```python
with
```

# 18. `raise`

Podemos provocar manualmente una excepción utilizando:

```python
raise
```

Ejemplo:

```python
raise ValueError("El valor no es válido")
```

Esto genera explícitamente una:

```text
ValueError
```

---

# 19. `raise` DENTRO DE UNA FUNCIÓN

Ejemplo:

```python
def dividir(a, b):
    if b == 0:
        raise ValueError("El divisor no puede ser cero")

    return a / b
```

Ahora:

```python
dividir(10, 0)
```

produce la excepción que hemos generado.

---

# 20. CAPTURAR UNA EXCEPCIÓN GENERADA CON `raise`

Podemos combinar `raise` con `try / except`:

```python
try:
    raise ValueError("Dato incorrecto")

except ValueError as error:
    print(error)
```

Resultado:

```text
Dato incorrecto
```

---

# 21. RELANZAR UNA EXCEPCIÓN

Dentro de un `except` podemos utilizar:

```python
raise
```

sin indicar una excepción concreta para volver a lanzar la excepción actual.

Ejemplo:

```python
try:
    resultado = 10 / 0

except ZeroDivisionError:
    print("Se ha producido un error")
    raise
```

La excepción vuelve a propagarse después de ejecutar el mensaje.

---

# 22. CADENA DE EXCEPCIONES

Python permite indicar que una excepción ha sido provocada por otra mediante:

```python
raise ... from ...
```

Ejemplo:

```python
try:
    numero = int("abc")

except ValueError as error:
    raise RuntimeError("No se pudo procesar el dato") from error
```

Esto permite conservar la relación causal entre ambas excepciones.

Conceptualmente:

```text
ValueError
    ↓
provoca
    ↓
RuntimeError
```

# 24. `ValueError`

Se produce cuando el tipo de dato puede ser correcto, pero el valor no es apropiado.

Ejemplo:

```python
int("hola")
```

produce:

```text
ValueError
```

El problema no es que `"hola"` sea una cadena. El problema es que no representa un entero válido para esa conversión.

---

# 25. `TypeError`

Se produce cuando una operación se realiza sobre un tipo incompatible.

Ejemplo:

```python
"Hola" + 5
```

Produce:

```text
TypeError
```

No podemos sumar directamente una cadena y un entero.

---

# 26. `IndexError`

Se produce cuando intentamos acceder a un índice inexistente.

```python
numeros = [10, 20, 30]

print(numeros[5])
```

Produce:

```text
IndexError
```

---

# 27. `KeyError`

Se produce al acceder a una clave inexistente de un diccionario mediante `[]`.

```python
persona = {
    "nombre": "Pedro"
}

print(persona["edad"])
```

Produce:

```text
KeyError
```

Recordemos:

```python
persona.get("edad")
```

no produce `KeyError` en este caso, sino que devuelve `None` si no indicamos valor por defecto.

---

# 28. `NameError`

Se produce cuando se utiliza un nombre que no está definido.

```python
print(nombre)
```

si `nombre` no existe, produce:

```text
NameError
```

---

# 29. `AttributeError`

Se produce cuando intentamos acceder a un atributo o método que el objeto no posee.

Ejemplo:

```python
numero = 10

numero.append(5)
```

Un entero no dispone del método `append()`.

Se produce:

```text
AttributeError
```

---

# 30. `ZeroDivisionError`

Se produce al dividir entre cero:

```python
10 / 0
```

También:

```python
10 // 0
```

o:

```python
10 % 0
```

producen esta excepción.

---

# 31. `FileNotFoundError`

Se produce cuando intentamos abrir un archivo que no existe.

```python
open("archivo_inexistente.txt")
```

puede producir:

```text
FileNotFoundError
```

---

# 32. `ImportError`

Se produce cuando existe un problema al importar un elemento desde un módulo.

Por ejemplo, intentar importar un nombre inexistente:

```python
from math import elemento_que_no_existe
```

puede producir:

```text
ImportError
```

---

# 33. `ModuleNotFoundError`

Es una excepción específica relacionada con la importación cuando no se encuentra el módulo.

```python
import modulo_inexistente
```

produce:

```text
ModuleNotFoundError
```

Es una subclase de:

```text
ImportError
```

---

# 34. `StopIteration`

Los iteradores utilizan:

```text
StopIteration
```

para indicar que no quedan elementos.

Ejemplo:

```python
numeros = iter([1, 2])

print(next(numeros))
print(next(numeros))
print(next(numeros))
```

La tercera llamada no tiene otro elemento disponible y provoca `StopIteration`.

Los bucles `for` gestionan internamente este mecanismo.

# 35. JERARQUÍA BÁSICA

De forma simplificada:

```text
BaseException
    │
    ├── Exception
    │     │
    │     ├── ValueError
    │     ├── TypeError
    │     ├── IndexError
    │     ├── KeyError
    │     ├── NameError
    │     ├── AttributeError
    │     ├── RuntimeError
    │     └── ...
    │
    ├── KeyboardInterrupt
    ├── SystemExit
    └── GeneratorExit
```

### ⚠️ Importante

No todas las excepciones importantes heredan directamente de `Exception`.

Por ejemplo:

```text
KeyboardInterrupt
SystemExit
GeneratorExit
```

son descendientes directos de `BaseException`.

# 36. ¿POR QUÉ NO CAPTURAR `BaseException`?

Normalmente no debemos hacer:

```python
try:
    ...
except BaseException:
    ...
```

porque podríamos capturar excepciones como:

```text
KeyboardInterrupt
SystemExit
```

que normalmente deberían poder detener la ejecución.

Para errores generales de aplicación suele utilizarse:

```python
except Exception:
```

cuando realmente necesitamos una captura genérica.

---

# 37. CAPTURA GENÉRICA

Podemos escribir:

```python
try:
    ...
except Exception as error:
    print(error)
```

Esto captura muchas excepciones normales derivadas de `Exception`.

Sin embargo, no siempre es buena idea capturar todo indiscriminadamente.

### 🧠 Para el examen

```text
Exception
↓
base habitual para excepciones de aplicación

BaseException
↓
jerarquía superior
```

# 38. CREAR EXCEPCIONES PERSONALIZADAS

Podemos crear nuestras propias excepciones heredando de `Exception`.

Ejemplo:

```python
class SaldoInsuficienteError(Exception):

```

Podemos utilizarla:

```python
raise SaldoInsuficienteError("Saldo insuficiente")
```

# 39. CAPTURAR UNA EXCEPCIÓN PERSONALIZADA

```python
class SaldoInsuficienteError(Exception):
    pass


try:
    raise SaldoInsuficienteError("No hay saldo suficiente")

except SaldoInsuficienteError as error:
    print(error)
```

Resultado:

```text
No hay saldo suficiente
```

# 40. `assert`

Python proporciona:

```python
assert
```

para comprobar una condición.

Ejemplo:

```python
edad = 20

assert edad >= 18
```

Si la condición es verdadera, no ocurre nada.

Si es falsa:

```python
edad = 15

assert edad >= 18
```

se produce:

```text
AssertionError
```

---

# 41. `assert` CON MENSAJE

Podemos proporcionar un mensaje:

```python
edad = 15

assert edad >= 18, "Debe ser mayor de edad"
```

Si falla:

```text
AssertionError: Debe ser mayor de edad
```

---

# 42. `assert` NO ES VALIDACIÓN DE ENTRADA

Aunque pueda parecer útil para validar datos, `assert` está pensado principalmente para comprobar **suposiciones internas del programa**.

Las aserciones pueden desactivarse cuando Python se ejecuta con optimizaciones.

Por ello no debemos utilizar:

```python
assert
```

como mecanismo de seguridad o validación imprescindible.

---

# 43. `assert` Y `AssertionError`

La relación básica es:

```text
assert condición
       │
       ├── True → continúa
       │
       └── False → AssertionError
```

# 44. PROPAGACIÓN DE EXCEPCIONES

Si una función genera una excepción y no la captura, puede propagarse hacia la función que la llamó.

Ejemplo:

```python
def dividir(a, b):
    return a / b


def calcular():
    return dividir(10, 0)


calcular()
```

La excepción se produce en:

```text
dividir()
```

y se propaga hacia:

```text
calcular()
```

y posteriormente hacia el código que llamó a `calcular()`.

---

# 45. PILA DE LLAMADAS

Cuando una excepción no es capturada, Python muestra un **traceback**.

Conceptualmente:

```text
main
 ↓
calcular
 ↓
dividir
 ↓
ZeroDivisionError
```

El traceback ayuda a localizar:

```text
Archivo
Línea
Función
Tipo de excepción
Mensaje
```

---

# 46. EJEMPLO DE TRACEBACK

Un error puede mostrarse aproximadamente así:

```text
Traceback (most recent call last):
  File "programa.py", line 10, in <module>
    calcular()
  File "programa.py", line 7, in calcular
    return dividir(10, 0)
  File "programa.py", line 4, in dividir
    return a / b
ZeroDivisionError: division by zero
```

Lo importante es reconocer:

```text
Traceback
    ↓
recorrido de llamadas
    ↓
excepción final
```

# 47. BUENAS PRÁCTICAS

## Capturar excepciones específicas

Preferible:

```python
try:
    numero = int(valor)
except ValueError:
    ...
```

que:

```python
try:
    numero = int(valor)
except:
    ...
```

---

## No ocultar errores

Evitar:

```python
try:
    ...
except Exception:
    pass
```

Esto puede hacer que un problema real desaparezca silenciosamente.

# 48. EXCEPCIONES Y FLUJO DEL PROGRAMA

Una excepción no capturada normalmente provoca la finalización de la ejecución actual.

Una excepción capturada mediante:

```python
except
```

puede permitir continuar después del bloque de gestión.

Ejemplo:

```python
try:
    10 / 0
except ZeroDivisionError:
    print("Error controlado")

print("El programa continúa")
```

Resultado:

```text
Error controlado
El programa continúa
```

---

# 49. EJEMPLO COMPLETO

```python
def dividir(a, b):
    if b == 0:
        raise ValueError("El divisor no puede ser cero")

    return a / b


try:
    resultado = dividir(10, 0)

except ValueError as error:
    print(f"Error: {error}")

else:
    print(f"Resultado: {resultado}")

finally:
    print("Operación finalizada")
```

Resultado:

```text
Error: El divisor no puede ser cero
Operación finalizada
```

# 53. 🎯 ESTRUCTURA COMPLETA

La estructura más completa que debemos reconocer es:

```python
try:
    # código
except TipoError:
    # gestión
except OtroError:
    # gestión
else:
    # si no hubo excepción
finally:
    # limpieza/finalización
```

No es obligatorio utilizar todas las partes.

Por ejemplo, podemos utilizar simplemente:

```python
try:
    ...
except ValueError:
    ...
```
