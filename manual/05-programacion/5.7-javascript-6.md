# 2. OPTIONAL CHAINING `?.`

El optional chaining permite acceder a propiedades o realizar llamadas evitando un error cuando una parte de la cadena es:

```text
null
```

o:

```text
undefined
```

Ejemplo:

```javascript
const usuario = null;

console.log(
    usuario?.nombre
);
```

Resultado:

```text
undefined
```

En lugar de provocar un `TypeError`.

---

# 3. ACCESO ANIDADO

Podemos utilizar:

```javascript
usuario?.direccion?.ciudad
```

Si:

```text
usuario
```

o:

```text
direccion
```

es `null` o `undefined`, la expresión produce:

```text
undefined
```

---

# 4. OPTIONAL METHOD CALL

También podemos utilizar:

```javascript
usuario.saludar?.();
```

Si `saludar` existe y es invocable, se intenta realizar la llamada.

---

# 5. OPTIONAL INDEX ACCESS

También:

```javascript
usuarios?.[indice]
```

permite utilizar optional chaining con acceso mediante corchetes.

---

# 6. NULLISH COALESCING `??`

El operador:

```javascript
??
```

proporciona un valor alternativo cuando el valor de la izquierda es:

```text
null
```

o:

```text
undefined
```

Ejemplo:

```javascript
const nombre =
    usuario.nombre ?? "Anónimo";
```

---

# 7. `??` VS `||`

Esta diferencia es importantísima.

Con:

```javascript
const valor =
    entrada || 10;
```

se utiliza `10` cuando `entrada` es un valor falsy.

Por ejemplo:

```text
false
0
""
null
undefined
NaN
```

Con:

```javascript
const valor =
    entrada ?? 10;
```

solo se utiliza `10` si:

```text
entrada === null
```

o:

```text
entrada === undefined
```

---

# 8. EJEMPLO

```javascript
const cantidad = 0;

const a =
    cantidad || 10;

const b =
    cantidad ?? 10;
```

Resultado:

```text
a = 10
b = 0
```

### 🧠 Trampa

```text
|| 
→ falsy

??
→ nullish
```

---

# 9. NO MEZCLAR `??` LIBREMENTE CON `&&` Y `||`

JavaScript impone restricciones de sintaxis cuando se mezclan `??` con `&&` o `||` sin paréntesis.

Es preferible escribir explícitamente:

```javascript
(a ?? b) || c
```

o:

```javascript
a ?? (b || c)
```

según la lógica buscada.

# 11. DEFAULT VALUES EN DESTRUCTURING

Ejemplo:

```javascript
const {
    nombre = "Anónimo"
} = usuario;
```

El valor por defecto se utiliza cuando la propiedad obtenida es:

```text
undefined
```

No simplemente cuando es cualquier valor falsy.

Por ejemplo:

```javascript
const {
    edad = 18
} = {
    edad: 0
};
```

Resultado:

```text
edad = 0
```

# 12. REST VS SPREAD

La misma sintaxis:

```text
...
```

puede cumplir funciones diferentes.

### Rest

Recoge elementos restantes:

```javascript
const [
    primero,
    ...resto
] = numeros;
```

### Spread

Expande elementos:

```javascript
const copia = [
    ...numeros
];
```

### 🧠 Regla

```text
rest
→ recoge

spread
→ expande
```

# 13. ITERABLES

Un objeto iterable es aquel que puede proporcionar un iterador para recorrer sus valores.

Ejemplos habituales:

```text
Array
String
Map
Set
```

Podemos utilizar:

```javascript
for...of
```

sobre ellos.

---

# 14. `for...of`

Recorre valores:

```javascript
const numeros = [
    10, 20, 30
];

for (
    const numero of numeros
) {
    console.log(numero);
}
```

Produce:

```text
10
20
30
```

---

# 15. `for...in`

Recorre propiedades enumerables.

Con arrays, normalmente obtendremos índices:

```javascript
const numeros = [
    10, 20, 30
];

for (
    const indice in numeros
) {
    console.log(indice);
}
```

Resultado:

```text
0
1
2
```

---

# 16. `for...of` VS `for...in`

### `for...of`

```text
valores
```

### `for...in`

```text
propiedades enumerables
```

### 🧠 Trampa de examen

Para recorrer valores de un array:

```text
for...of
```

suele ser la opción apropiada.

---

# 17. ITERADORES

Un iterable puede proporcionar un iterador mediante:

```javascript
Symbol.iterator
```

Ejemplo:

```javascript
const numeros = [1, 2, 3];

const iterador =
    numeros[
        Symbol.iterator
    ]();
```

---

# 18. `next()`

Un iterador dispone de:

```javascript
next()
```

Ejemplo conceptual:

```javascript
iterador.next();
```

devuelve un objeto con:

```text
value
done
```

Por ejemplo:

```javascript
{
    value: 1,
    done: false
}
```

---

# 19. FIN DE UN ITERADOR

Cuando no quedan elementos:

```javascript
iterador.next();
```

puede devolver:

```javascript
{
    value: undefined,
    done: true
}
```

---

# 20. GENERATORS

Una generator function se declara utilizando:

```text
function*
```

Ejemplo:

```javascript
function* numeros() {

    yield 1;
    yield 2;
    yield 3;
}
```

---

# 21. `yield`

`yield` produce un valor y puede suspender temporalmente la ejecución del generator.

Ejemplo:

```javascript
function* numeros() {

    yield 1;
    yield 2;
    yield 3;
}
```

---

# 22. EJECUTAR UN GENERATOR

Al llamar:

```javascript
const generador =
    numeros();
```

no obtenemos directamente:

```text
1
2
3
```

Obtenemos un objeto generator.

Podemos hacer:

```javascript
generador.next();
```

Resultado:

```javascript
{
    value: 1,
    done: false
}
```

---

# 23. SIGUIENTE VALOR

```javascript
generador.next();
```

→

```javascript
{
    value: 2,
    done: false
}
```

Después:

```javascript
generador.next();
```

→

```javascript
{
    value: 3,
    done: false
}
```

Y finalmente:

```javascript
generador.next();
```

→

```javascript
{
    value: undefined,
    done: true
}
```

---

# 24. GENERATORS E ITERABLES

Los generators son iterables.

Por tanto:

```javascript
for (
    const numero of numeros()
) {
    console.log(numero);
}
```

puede producir:

```text
1
2
3
```

# 25. SYMBOL

`Symbol` es un tipo primitivo.

Ejemplo:

```javascript
const id =
    Symbol("id");
```

Cada Symbol creado es único.

---

# 26. SYMBOL COMO PROPIEDAD

Podemos utilizar un Symbol como clave:

```javascript
const id =
    Symbol("id");

const usuario = {
    [id]: 123
};
```

---

# 27. SYMBOLS SON ÚNICOS

Aunque tengan la misma descripción:

```javascript
const a =
    Symbol("id");

const b =
    Symbol("id");
```

no son iguales:

```javascript
a === b
```

→

```text
false
```

---

# 28. `Symbol.for()`

Existe un registro global de Symbols mediante:

```javascript
Symbol.for()
```

Ejemplo:

```javascript
const a =
    Symbol.for("usuario");

const b =
    Symbol.for("usuario");
```

Ahora:

```javascript
a === b
```

es:

```text
true
```

---

# 29. `Symbol.iterator`

Es un Symbol conocido utilizado para definir el comportamiento iterable.

Esto conecta conceptos vistos anteriormente:

```text

+
iterables
+
iteradores
```

# 30. WEAKMAP

`WeakMap` es una colección de pares:

```text
clave → valor
```

pero con restricciones importantes.

Las claves deben ser objetos o, en las versiones modernas de ECMAScript, determinados tipos no primitivos según la especificación aplicable.

En el uso clásico:

```javascript
const datos =
    new WeakMap();

const usuario = {};

datos.set(
    usuario,
    "información"
);
```

---

# 31. CARACTERÍSTICA IMPORTANTE DE WEAKMAP

Las referencias a las claves son débiles.

Esto permite que un objeto clave pueda ser eliminado por el garbage collector cuando ya no existen referencias fuertes hacia él.

Por ello:

```text
WeakMap
```

puede ser útil para asociar información privada o auxiliar con objetos sin impedir su recolección.

---

# 32. LIMITACIONES DE WEAKMAP

A diferencia de `Map`, un `WeakMap` no está diseñado para enumerarse.

No tenemos una operación general como:

```text
for...of
```

para recorrer todas sus entradas.

---

# 33. WEAKSET

`WeakSet` almacena objetos de forma débil.

Ejemplo:

```javascript
const objetos =
    new WeakSet();

const usuario = {};

objetos.add(usuario);
```

---

# 34. WEAKSET VS SET

```text
Set
→ valores
→ iterable
→ size

WeakSet
→ objetos
→ referencias débiles
→ no está diseñado para enumeración
```

---

# 35. GARBAGE COLLECTION

JavaScript dispone de gestión automática de memoria.

El motor puede detectar objetos que ya no son alcanzables y recuperar la memoria correspondiente.

Esto se denomina:

```text
Garbage Collection
```

---

# 36. ALCANZABILIDAD

Simplificando, un objeto sigue siendo relevante para el garbage collector mientras pueda alcanzarse desde referencias activas.

Ejemplo:

```javascript
let usuario = {
    nombre: "Pedro"
};
```

Mientras:

```text
usuario
```

mantenga una referencia al objeto, este es alcanzable.

Si hacemos:

```javascript
usuario = null;
```

y no existen otras referencias, el objeto puede quedar disponible para recolección.

---

# 37. NO CONTROLAMOS DIRECTAMENTE EL GARBAGE COLLECTOR

JavaScript no proporciona una instrucción estándar como:

```javascript
free(objeto);
```

para liberar manualmente un objeto.

La gestión de memoria es automática.

# 38. STRICT MODE

JavaScript dispone de:

```text
strict mode
```

que modifica determinadas reglas del lenguaje y ayuda a detectar ciertos errores.

Se activa mediante:

```javascript
"use strict";
```

---

# 39. EFECTOS DEL STRICT MODE

Entre otros cambios, strict mode:

```text
prohíbe determinadas asignaciones problemáticas
hace que ciertas situaciones produzcan errores
cambia determinadas reglas relacionadas con this
```

Ejemplo conceptual:

```javascript
"use strict";

x = 10;
```

Esto produce un error porque:

```text
x
```

no ha sido declarada.

---

# 40. MÓDULOS Y STRICT MODE

Los módulos ES se ejecutan automáticamente en:

```text
strict mode
```

Por tanto, no es necesario escribir:

```javascript
"use strict";
```

para activar strict mode dentro de un módulo.

# 41. XSS

XSS significa:

```text
Cross-Site Scripting
```

Es una vulnerabilidad en la que contenido controlado por un atacante puede terminar siendo interpretado como código en el contexto de una aplicación web.

---

# 42. XSS Y `innerHTML`

Un ejemplo de riesgo:

```javascript
elemento.innerHTML =
    contenidoNoConfiable;
```

Si el contenido no está correctamente controlado, puede abrir la puerta a XSS.

Para texto simple:

```javascript
elemento.textContent =
    contenidoNoConfiable;
```

es una alternativa más segura porque se trata como texto.

---

# 43. CSRF

CSRF significa:

```text
Cross-Site Request Forgery
```

Consiste, de forma simplificada, en conseguir que un navegador autenticado realice una acción no deseada contra una aplicación.

Es diferente de XSS.

---

# 44. XSS VS CSRF

```text
XSS
→ inyección/ejecución de contenido o script no confiable

CSRF
→ inducir solicitudes no deseadas aprovechando una sesión/autenticación existente
```

Son problemas distintos, aunque pueden relacionarse en determinados escenarios.

---

# 45. CORS VS CSRF

Tampoco debemos confundir:

```text
CORS
CSRF
XSS
```

### CORS

Mecanismo del navegador relacionado con solicitudes entre orígenes.

### CSRF

Ataque que intenta conseguir acciones no deseadas aprovechando la autenticación de una víctima.

### XSS

Ataque basado en ejecutar contenido/script no confiable en el contexto de una aplicación.

---

# 46. VALIDACIÓN EN CLIENTE

La validación JavaScript puede mejorar:

```text
experiencia de usuario
```

pero no debe considerarse una sustitución de la validación del servidor.

Un usuario puede:

```text
desactivar JavaScript
modificar las peticiones
usar otra herramienta
```

Por tanto:

```text
cliente
→ UX / validación preliminar

servidor
→ validación de seguridad y reglas de negocio
```

---

# 47. NO CONFIAR EN DATOS DEL CLIENTE

Nunca debemos asumir que:

```javascript
usuario.esAdministrador === true
```

es suficiente para autorizar una operación en el backend.

El servidor debe comprobar los permisos.

---

# 48. PRINCIPIO DE MENOR PRIVILEGIO

Una aplicación debe conceder únicamente los permisos necesarios.

Aplicado al frontend y backend:

```text
no exponer secretos innecesarios
no confiar en datos manipulables por el cliente
limitar permisos
```
