Para una oposición, no basta con reconocer las siglas. Hay que saber:

# 2. ¿QUÉ ES UNA DTD?

DTD significa:

```text
Document Type Definition
```

Una DTD permite definir la estructura permitida para un documento XML.

Puede especificar:

```text
elementos
contenido de elementos
atributos
entidades
```

---

# 3. DTD INTERNA

Una DTD puede aparecer dentro del propio documento XML.

Ejemplo:

```xml
<?xml version="1.0"?>

<!DOCTYPE usuario [

    <!ELEMENT usuario (nombre, edad)>
    <!ELEMENT nombre (#PCDATA)>
    <!ELEMENT edad (#PCDATA)>

]>

<usuario>

    <nombre>Pedro</nombre>
    <edad>30</edad>

</usuario>
```

La DTD está entre:

```text
<!DOCTYPE ... [
    ...
]>
```

---

# 4. DTD EXTERNA

También podemos almacenar la DTD en un archivo independiente.

Por ejemplo:

```xml
<!DOCTYPE usuario SYSTEM "usuario.dtd">
```

Y el archivo:

```text
usuario.dtd
```

contendría las declaraciones correspondientes.

---

# 5. `SYSTEM`

La palabra:

```text
SYSTEM
```

permite indicar un identificador externo para la DTD.

Ejemplo:

```xml
<!DOCTYPE usuario
    SYSTEM "usuario.dtd">
```

---

# 6. `PUBLIC`

También existe:

```text
PUBLIC
```

que permite utilizar un identificador público.

Ejemplo conceptual:

```xml
<!DOCTYPE documento
    PUBLIC "-//Ejemplo//DTD Documento 1.0//ES"
           "documento.dtd">
```

Para el examen conviene reconocer:

```text
SYSTEM
PUBLIC
```

como formas relacionadas con DTD externas.

---

# 7. DECLARACIÓN `ELEMENT`

En una DTD utilizamos:

```text
<!ELEMENT ...>
```

para declarar elementos.

Ejemplo:

```xml
<!ELEMENT nombre (#PCDATA)>
```

Esto indica que:

```text
nombre
```

puede contener texto analizado.

---

# 8. ELEMENTO CON HIJOS

Podemos indicar una estructura:

```xml
<!ELEMENT usuario (nombre, edad)>
```

Esto significa que:

```text
usuario
```

debe contener:

```text
nombre
edad
```

en ese orden.

---

# 9. SECUENCIA CON COMA

La coma:

```text
,
```

representa una secuencia.

Ejemplo:

```xml
<!ELEMENT usuario (nombre, edad, email)>
```

Orden esperado:

```text
nombre
↓
edad
↓
email
```

---

# 10. ELECCIÓN CON `|`

La barra vertical:

```text
|
```

representa una elección.

Ejemplo:

```xml
<!ELEMENT contacto (email | telefono)>
```

El contenido debe utilizar una de las alternativas según la declaración.

---

# 11. AGRUPACIÓN

Los paréntesis:

```text
(...)
```

permiten agrupar estructuras.

Ejemplo:

```xml
<!ELEMENT usuario
    (nombre, (email | telefono))>
```

La estructura exige:

```text
nombre
+
email o telefono
```

---

# 12. CARDINALIDADES DTD

Las DTD permiten especificar cuántas veces puede aparecer una estructura.

Símbolos importantes:

```text
?
*
+
```

---

# 13. `?`

Indica:

```text
cero o una vez
```

Ejemplo:

```xml
<!ELEMENT usuario
    (nombre, telefono?)>
```

El teléfono es opcional.

Puede existir:

```text
0 veces
```

o:

```text
1 vez
```

---

# 14. `*`

Indica:

```text
cero o más veces
```

Ejemplo:

```xml
<!ELEMENT usuario
    (telefono*)>
```

Puede haber:

```text
0
1
2
3
...
```

elementos `telefono`.

---

# 15. `+`

Indica:

```text
una o más veces
```

Ejemplo:

```xml
<!ELEMENT usuario
    (telefono+)>
```

Debe existir al menos:

```text
1 telefono
```

---

# 16. 🧠 TABLA DTD DE CARDINALIDADES

| Símbolo | Significado |
|---|---|
| `?` | cero o una |
| `*` | cero o más |
| `+` | una o más |

Esta tabla merece memoria directa.

---

# 17. `EMPTY`

Una declaración puede indicar que un elemento no tiene contenido:

```xml
<!ELEMENT imagen EMPTY>
```

Esto significa:

```text
imagen
→ elemento vacío
```

---

# 18. `ANY`

También existe:

```xml
<!ELEMENT contenido ANY>
```

Indica que el elemento puede contener cualquier contenido permitido por las reglas correspondientes de la DTD.

Es una declaración muy permisiva.

---

# 19. `#PCDATA`

Ya vimos:

```text
#PCDATA
```

que significa:

```text
Parsed Character Data
```

Ejemplo:

```xml
<!ELEMENT nombre (#PCDATA)>
```

---

# 20. DECLARACIÓN DE ATRIBUTOS

Para declarar atributos se utiliza:

```text
<!ATTLIST ...>
```

Ejemplo:

```xml
<!ATTLIST usuario
    id CDATA #REQUIRED
>
```

Esto declara un atributo:

```text
id
```

para:

```text
usuario
```

---

# 21. `CDATA` EN DTD

No debemos confundir:

```text
CDATA
```

de una declaración de atributo con:

```text
CDATA
```

como sección XML:

```xml
<![CDATA[
    ...
]]>
```

En una DTD:

```text
CDATA
```

es un tipo de atributo.

---

# 22. `#REQUIRED`

Indica que un atributo es obligatorio.

Ejemplo:

```xml
<!ATTLIST usuario
    id CDATA #REQUIRED
>
```

Por tanto:

```xml
<usuario id="10">
```

es compatible.

Mientras:

```xml
<usuario>
```

no cumple esa restricción.

---

# 23. `#IMPLIED`

Indica que el atributo es opcional y no se proporciona un valor predeterminado.

Ejemplo:

```xml
<!ATTLIST usuario
    telefono CDATA #IMPLIED
>
```

---

# 24. `#FIXED`

Indica que el atributo tiene un valor fijo.

Ejemplo:

```xml
<!ATTLIST documento
    tipo CDATA #FIXED "factura"
>
```

---

# 25. VALOR POR DEFECTO

También podemos especificar un valor predeterminado:

```xml
<!ATTLIST usuario
    activo CDATA "true"
>
```

Si no se proporciona el atributo, se utiliza el valor predeterminado según las reglas de DTD.

---

# 26. TIPOS DE ATRIBUTOS

Algunos tipos de atributos DTD:

```text
CDATA
ID
IDREF
IDREFS
NMTOKEN
NMTOKENS
ENTITY
ENTITIES
NOTATION
```

No necesitamos convertir cada uno en una novela, pero sí reconocer los más importantes.

---

# 27. `ID`

El tipo:

```text
ID
```

identifica un elemento de forma única dentro del documento.

Ejemplo:

```xml
<!ATTLIST usuario
    id ID #REQUIRED
>
```

---

# 28. `IDREF`

Permite hacer referencia a un valor `ID` existente.

Ejemplo conceptual:

```xml
<!ATTLIST pedido
    usuario IDREF #REQUIRED
>
```

Si existe:

```xml
<usuario id="u1">
```

un atributo:

```xml
<pedido usuario="u1">
```

puede referenciarlo.

---

# 29. `IDREFS`

Permite múltiples referencias a valores `ID`.

Conceptualmente:

```text
IDREF
→ una referencia

IDREFS
→ varias referencias
```

---

# 30. ENUMERACIONES EN ATRIBUTOS

Una DTD puede restringir un atributo a determinados valores.

Ejemplo:

```xml
<!ATTLIST usuario
    estado
    (activo | inactivo)
    "activo"
>
```

Los valores permitidos serían:

```text
activo
inactivo
```

---

# 31. DTD: EJEMPLO COMPLETO

```xml
<!DOCTYPE usuarios [

    <!ELEMENT usuarios (usuario+)>

    <!ELEMENT usuario
        (nombre, email?, telefono*)>

    <!ELEMENT nombre (#PCDATA)>

    <!ELEMENT email (#PCDATA)>

    <!ELEMENT telefono (#PCDATA)>

    <!ATTLIST usuario
        id ID #REQUIRED
        estado
        (activo | inactivo)
        "activo"
    >

]>
```

Aquí hemos utilizado:

```text
ELEMENT
ATTLIST
+
?
*
#PCDATA
ID
enumeración
valor por defecto
```

# 32. XML SCHEMA

XML Schema es un mecanismo más potente para definir y validar documentos XML.

La especificación más conocida es:

```text
W3C XML Schema
```

Los documentos de esquema suelen utilizar:

```text
XSD
```

como extensión.

---

# 33. ¿POR QUÉ XSD?

XSD permite expresar restricciones de datos mucho más ricas que una DTD.

Entre otras cosas permite definir:

```text
tipos de datos
restricciones numéricas
restricciones de longitud
patrones
cardinalidades
tipos simples
tipos complejos
namespaces
```

---

# 34. XSD TAMBIÉN ES XML

Una diferencia importante:

```text
DTD
→ sintaxis propia

XSD
→ está escrito en XML
```

Ejemplo conceptual:

```xml
<xs:schema
    xmlns:xs="http://www.w3.org/2001/XMLSchema">

    ...

</xs:schema>
```

---

# 35. ELEMENTO `schema`

El elemento raíz habitual de un XSD es:

```xml
<xs:schema>
```

utilizando normalmente el namespace:

```text
http://www.w3.org/2001/XMLSchema
```

---

# 36. `xs:element`

Permite declarar elementos.

Ejemplo:

```xml
<xs:element
    name="nombre"
    type="xs:string"/>
```

Esto declara:

```text
nombre
```

como:

```text
string
```



---

# 39. `xs:integer`

```xml
<xs:element
```

# 40. `xs:decimal`

Números decimales:

```xml
<xs:element
    name="precio"
    type="xs:decimal"/>
```

---

# 41. `xs:boolean`

Valores booleanos:

```xml
<xs:element
    name="activo"
    type="xs:boolean"/>
```

---

# 42. `xs:date`

Fechas:

```xml
<xs:element
    name="fecha"
    type="xs:date"/>
```

Un valor típico:

```text
2026-08-16
```

---

# 43. `xs:dateTime`

```xml
<xs:element
    name="fechaCreacion"
    type="xs:dateTime"/>
```

# 44. TIPOS SIMPLES VS COMPLEJOS

### Simple

Contiene un valor de texto tipado y no tiene elementos hijos ni atributos propios en la misma forma que un complexType.

Ejemplo:

```text
nombre
→ string
```

### Complejo

Puede contener:

```text
elementos
atributos
```

---

# 45. `xs:complexType`

Ejemplo:

```xml
<xs:complexType>

    <xs:sequence>

        <xs:element
            name="nombre"
            type="xs:string"/>

        <xs:element
            name="edad"
            type="xs:integer"/>

    </xs:sequence>

</xs:complexType>
```

---

# 46. `xs:sequence`

Indica que los elementos deben aparecer en el orden definido.

Ejemplo:

```xml
<xs:sequence>

    <xs:element
        name="nombre"/>

    <xs:element
        name="edad"/>

</xs:sequence>
```

Orden:

```text
nombre
↓
edad
```

---

# 47. `xs:choice`

Permite seleccionar una alternativa.

Ejemplo:

```xml
<xs:choice>

    <xs:element
        name="email"/>

    <xs:element
        name="telefono"/>

</xs:choice>
```

Conceptualmente:

```text
email
O
telefono
```

---

# 48. `xs:all`

Permite indicar un grupo cuyos elementos pueden aparecer en cualquier orden, sujeto a las restricciones de `xs:all`.

Ejemplo conceptual:

```xml
<xs:all>

    <xs:element
        name="nombre"/>

    <xs:element
        name="edad"/>

</xs:all>
```

---

# 49. CARDINALIDADES EN XSD

XSD utiliza principalmente:

```text
minOccurs
maxOccurs
```

---

# 50. `minOccurs`

Indica el número mínimo de apariciones.

Ejemplo:

```xml
minOccurs="0"
```

significa:

```text
opcional
```

---

# 51. `maxOccurs`

Indica el número máximo de apariciones.

Ejemplo:

```xml
maxOccurs="1"
```

significa:

```text
como máximo una
```

---

# 52. MÚLTIPLES APARICIONES

Ejemplo:

```xml
<xs:element
    name="telefono"
    type="xs:string"
    minOccurs="0"
    maxOccurs="unbounded"/>
```

Significa:

```text
0 o más teléfonos
```

---

# 53. `unbounded`

El valor:

```text
unbounded
```

permite un número ilimitado de apariciones dentro de las reglas del esquema.

---

# 54. EQUIVALENCIAS DTD / XSD

Podemos pensar:

```text
DTD ?
→ minOccurs="0"
  maxOccurs="1"

DTD *
→ minOccurs="0"
  maxOccurs="unbounded"

DTD +
→ minOccurs="1"
  maxOccurs="unbounded"
```

Esta equivalencia es especialmente útil para estudiar.

---

# 55. VALOR PREDETERMINADO EN XSD

Puede definirse:

```xml
default="activo"
```

Ejemplo:

```xml
<xs:element
    name="estado"
    type="xs:string"
    default="activo"/>
```

---

# 56. VALOR FIJO

También:

```xml
fixed="activo"
```

indica un valor fijo.

---

# 57. RESTRICTIONS

XSD permite crear tipos restringidos.

Por ejemplo:

```xml
<xs:simpleType
    name="EdadType">

    <xs:restriction
        base="xs:integer">

        <xs:minInclusive
            value="0"/>

        <xs:maxInclusive
            value="120"/>

    </xs:restriction>

</xs:simpleType>
```

---

# 58. `minInclusive`

Establece un mínimo incluido.

Ejemplo:

```xml
<xs:minInclusive
    value="0"/>
```

Permite:

```text
0
1
2
...
```

pero no:

```text
-1
```

---

# 59. `maxInclusive`

Establece un máximo incluido.

Ejemplo:

```xml
<xs:maxInclusive
    value="120"/>
```

---

# 60. `minExclusive`

Establece un mínimo exclusivo.

Si:

```xml
<xs:minExclusive
    value="0"/>
```

el valor debe ser:

```text
> 0
```

No puede ser:

```text
0
```

---

# 61. `maxExclusive`

Establece un máximo exclusivo.

Si:

```xml
<xs:maxExclusive
    value="100"/>
```

el valor debe ser:

```text
< 100
```

---

# 62. `length`

Permite establecer una longitud exacta.

Ejemplo:

```xml
<xs:length
    value="5"/>
```

---

# 63. `minLength`

Longitud mínima:

```xml
<xs:minLength
    value="3"/>
```

---

# 64. `maxLength`

Longitud máxima:

```xml
<xs:maxLength
    value="20"/>
```

---

# 65. `pattern`

Permite restringir mediante una expresión de patrón.

Ejemplo conceptual:

```xml
<xs:pattern
    value="[0-9]{5}"/>
```

Puede utilizarse para restringir un valor a un determinado patrón léxico.

---

# 66. `enumeration`

Permite definir valores permitidos.

Ejemplo:

```xml
<xs:restriction
    base="xs:string">

    <xs:enumeration
        value="activo"/>

    <xs:enumeration
        value="inactivo"/>

</xs:restriction>
```

---

# 67. `totalDigits`

Permite restringir el número total de dígitos de determinados tipos numéricos.

---

# 68. `fractionDigits`

Permite restringir el número de dígitos decimales.

Ejemplo conceptual:

```text
precio

```

# 69. EJEMPLO XSD COMPLETO

```xml
<?xml version="1.0"
      encoding="UTF-8"?>

<xs:schema
    xmlns:xs=
        "http://www.w3.org/2001/XMLSchema">

    <xs:element name="usuario">

        <xs:complexType>

            <xs:sequence>

                <xs:element
                    name="nombre"
                    type="xs:string"/>

                <xs:element
                    name="edad"
                    type="xs:integer"/>

                <xs:element
                    name="email"
                    type="xs:string"
                    minOccurs="0"/>

            </xs:sequence>

        </xs:complexType>

    </xs:element>

</xs:schema>
```

Este esquema define:

```text
usuario
├── nombre
├── edad
└── email opcional
```

---

# 70. ATRIBUTOS EN XSD

Los atributos pueden definirse dentro de un `complexType`.

Ejemplo:

```xml
<xs:attribute
    name="id"
    type="xs:string"
    use="required"/>
```

---

# 71. `use="required"`

Indica:

```text
atributo obligatorio
```

---

# 72. `use="optional"`

Indica:

```text
atributo opcional
```

Es el comportamiento habitual si no se especifica otra cosa.

---

# 73. `use="prohibited"`

Indica que el atributo no debe utilizarse en el contexto correspondiente.

Es menos habitual en ejemplos básicos, pero conviene reconocerlo.

---

# 74. DTD VS XSD

| Característica | DTD | XSD |
|---|---|---|
| Sintaxis | Propia | XML |
| Tipos de datos | Limitados | Amplios |
| Restricciones numéricas | Limitadas | Sí |
| Patrones | Limitados | Sí |
| Namespaces | No de forma nativa como XSD | Sí |
| Complejidad | Menor | Mayor |
| Potencia | Menor | Mayor |

# 77. ⚠️ TRAMPAS DE OPOSICIÓN

## Trampa 1

DTD y XSD sirven para:

```text
definir/validar estructura XML
```

No confundirlos con XML en sí.

---

## Trampa 2

```text
DTD
→ sintaxis propia

XSD
→ XML
```

---

## Trampa 3

```text
?
→ 0 o 1

*
→ 0 o más

+
→ 1 o más
```

---

## Trampa 4

En XSD:

```text
minOccurs
→ mínimo

maxOccurs
→ máximo
```

---

## Trampa 5

```text
maxOccurs="unbounded"
```

no significa que el elemento sea obligatorio.

La obligatoriedad depende de:

```text
minOccurs
```

---

## Trampa 6

```text
xs:sequence
→ orden

xs:choice
→ alternativa
```

---

## Trampa 7

XSD permite definir tipos de datos como:

```text
integer
decimal
date
boolean
```

Una DTD no proporciona este sistema de tipos con la misma riqueza.

---

## Trampa 8

```text
#REQUIRED
```

se refiere a un atributo DTD obligatorio.

En XSD:

```text
use="required"
```

cumple una función equivalente respecto a la obligatoriedad del atributo.

---

## Trampa 9

```text
#PCDATA
```

y:

```text
CDATA
```

no son lo mismo en todos los contextos.

En una DTD:

```text
#PCDATA
→ contenido de texto de un elemento

CDATA
→ tipo de atributo
```
