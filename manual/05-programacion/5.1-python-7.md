# 2. ABRIR UN ARCHIVO

La función principal es:

```python
open()
```

Ejemplo:

```python
archivo = open("datos.txt")
```

Por defecto se abre para lectura de texto.

---

# 3. CERRAR UN ARCHIVO

Después de trabajar con un archivo podemos cerrarlo:

```python
archivo.close()
```

Ejemplo:

```python
archivo = open("datos.txt")

contenido = archivo.read()

archivo.close()
```

Cerrar los archivos es importante para liberar recursos.

---

# 4. EL PROBLEMA DE `close()`

Si ocurre una excepción antes de llegar a:

```python
archivo.close()
```

el archivo podría no cerrarse correctamente.

Por eso Python proporciona una estructura mucho más segura:

```python
with
```

---

# 5. `with`

Podemos escribir:

```python
with open("datos.txt") as archivo:
    contenido = archivo.read()
```

Cuando termina el bloque `with`, Python se encarga de gestionar el cierre del archivo.

Esta es la forma recomendada para trabajar con archivos.

---

# 6. VENTAJAS DE `with`

Comparación:

### Sin `with`

```python
archivo = open("datos.txt")

try:
    contenido = archivo.read()
finally:
    archivo.close()
```

### Con `with`

```python
with open("datos.txt") as archivo:
    contenido = archivo.read()
```

El segundo código es más limpio y reduce el riesgo de olvidar cerrar el archivo.

---

# 7. CONTEXT MANAGERS

La estructura:

```python
with ...
```

utiliza el concepto de **context manager**.

Un context manager define qué debe ocurrir:

```text
al entrar en el contexto
y
al salir del contexto
```

En el caso de los archivos:

```text
entrar → abrir/gestionar recurso
salir  → cerrar recurso
```

---

# 8. `__enter__` Y `__exit__`

Los context managers se relacionan con los métodos especiales:

```python
__enter__()
__exit__()
```

Conceptualmente:

```python
with recurso as valor:
    ...
```

implica una gestión equivalente a:

```text
entrar en el contexto
↓
ejecutar bloque
↓
salir del contexto
```

No es necesario implementar estos métodos para utilizar archivos, pero sí reconocer su relación con `with`.

# 9. MODOS DE APERTURA

`open()` permite indicar un modo.

Sintaxis:

```python
open("archivo.txt", "modo")
```

Los más importantes:

```text
r → lectura
w → escritura
a → añadir
x → creación exclusiva
```

---

# 10. MODO `r`

```python
open("datos.txt", "r")
```

Abre el archivo para lectura.

Es el modo predeterminado.

Si el archivo no existe:

```text
FileNotFoundError
```

---

# 11. MODO `w`

```python
open("datos.txt", "w")
```

Abre el archivo para escritura.

Si el archivo existe:

```text
su contenido se sobrescribe
```

Si no existe:

```text
se crea
```

### ⚠️ Trampa

```text
w
```

no significa "añadir".

Sobrescribe el contenido existente.

---

# 12. MODO `a`

```python
open("datos.txt", "a")
```

abre el archivo para añadir contenido al final.

Si existe:

```text
conserva el contenido
+
añade nuevos datos
```

Si no existe, normalmente se crea.

---

# 13. MODO `x`

```python
open("datos.txt", "x")
```

intenta crear un archivo nuevo.

Si ya existe:

```text
FileExistsError
```

Es útil cuando queremos evitar sobrescribir accidentalmente un archivo existente.

---

# 14. MODOS COMBINADOS

Podemos combinar modos con:

```text
+
```

Por ejemplo:

```text
r+ → lectura y escritura
w+ → escritura y lectura
a+ → añadir y lectura
```

Hay diferencias importantes en el comportamiento del puntero y en el contenido, por lo que deben utilizarse conscientemente.

---

# 15. TEXTO VS BINARIO

Podemos trabajar con:

```text
texto
```

o:

```text
binario
```

Los modos binarios utilizan:

```text
b
```

Ejemplo:

```python
open("imagen.jpg", "rb")
```

Esto significa:

```text
r → lectura
b → binario
```

---

# 16. EJEMPLOS DE MODOS

| Modo | Significado |
|---|---|
| `r` | Lectura de texto |
| `w` | Escritura de texto, sobrescribe |
| `a` | Añadir texto |
| `x` | Crear exclusivamente |
| `rb` | Lectura binaria |
| `wb` | Escritura binaria |
| `r+` | Lectura y escritura |
| `w+` | Escritura y lectura, sobrescribe |
| `a+` | Añadir y lectura |

# 24. `writelines()`

Podemos escribir varios elementos:

```python

    "Primera línea\n",
    "Segunda línea\n",
    "Tercera línea\n"

    archivo.writelines(lineas)
```

### ⚠️ Importante

`writelines()` **no añade automáticamente** saltos de línea.

Por eso normalmente debemos incluir:

```text
\n
```

nosotros mismos.

# 54. `DictReader`

# 55. `DictWriter`

Para escribir utilizando diccionarios:

```python

with open(
    "personas.csv",
    "w",
    newline="",
    encoding="utf-8"
) as archivo:

        archivo,
        fieldnames=campos
    )

    escritor.writerow({
        "nombre": "Ana",
        "edad": 25
    })
```

# 63. `dump/load` VS `dumps/loads`

Esta diferencia es **muy importante**.

```text
dump
 ↓
Python → JSON en archivo

dumps
 ↓
Python → JSON en cadena

load
 ↓
JSON desde archivo → Python

loads
 ↓
JSON desde cadena → Python
```

### 🧠 Regla visual

```text
             ARCHIVO       CADENA
Python →    dump           dumps
Python ←    load           loads
```

# 70. SERIALIZACIÓN NO SIEMPRE ES POSIBLE

No todos los objetos Python pueden serializarse directamente a JSON.

Por ejemplo:

```python

datos = {
    "fecha": datetime.datetime.now()
}
```

`datetime` no es serializable directamente por el encoder JSON estándar en este contexto.

Puede ser necesario convertirlo primero a una representación compatible, como una cadena.
