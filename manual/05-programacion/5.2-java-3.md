# 1. INTRODUCCIÓN

En las dos primeras partes hemos construido la base:

```text
Parte 1
→ sintaxis + tipos + control de flujo

Parte 2
→ POO + herencia + polimorfismo
```

Ahora llegamos a una de las zonas más importantes de Java:

```text
INTERFACES
+
COLECCIONES
```

Y aquí aparece una idea fundamental:

```text
Programar contra una interfaz
en lugar de depender de una implementación concreta
```

Por ejemplo:

```java
List<String> nombres = new ArrayList<>();
```

La variable se declara como:

```text
List
```

pero el objeto concreto es:

```text
ArrayList
```

Esta separación entre:

```text
interfaz
   ↓
implementación
```

es omnipresente en Java.

---

# 2. ¿QUÉ ES UNA INTERFAZ?

Una interfaz define un contrato que una clase puede implementar.

Ejemplo:

```java
interface Volador {

    void volar();
}
```

Una clase puede implementarla:

```java
class Pajaro implements Volador {

    @Override
    public void volar() {
        System.out.println("Volando");
    }
}
```

Tenemos:

```text
Volador
   ↑
implements
   │
Pajaro
```

---

# 3. `implements`

Para que una clase implemente una interfaz:

```java
class Pajaro implements Volador {
}
```

Utilizamos:

```text
implements
```

Mientras:

```text
extends
```

se utiliza para herencia de clases.

### 🧠 Regla

```text
class extends class
class implements interface
```

---

# 4. UNA CLASE PUEDE IMPLEMENTAR VARIAS INTERFACES

Java no permite herencia múltiple de clases:

```text
class A extends B, C
```

no es válido.

Pero una clase puede implementar múltiples interfaces:

```java
class Pajaro implements Volador, Animal {
}
```

Esto permite combinar contratos.

---

# 5. INTERFAZ COMO TIPO

Podemos declarar:

```java
Volador objeto = new Pajaro();
```

La referencia es:

```text
Volador
```

pero el objeto real es:

```text
Pajaro
```

Esto es polimorfismo.

---

# 6. MÉTODOS DE UNA INTERFAZ

Tradicionalmente una interfaz podía declarar métodos abstractos:

```java
interface Volador {

    void volar();
}
```

La clase que la implementa debe proporcionar la implementación:

```java
class Pajaro implements Volador {

    @Override
    public void volar() {
        System.out.println("Volando");
    }
}
```

### ⚠️ Importante

El método implementado no puede reducir la visibilidad respecto al contrato de la interfaz.

Por ejemplo, no podemos implementar un método público de interfaz como:

```java
private void volar()
```

---

# 7. MÉTODOS `default`

Java permite métodos `default` en interfaces.

Ejemplo:

```java
interface Volador {

    default void aterrizar() {
        System.out.println("Aterrizando");
    }
}
```

Una clase que implementa la interfaz puede utilizar directamente ese comportamiento:

```java
class Pajaro implements Volador {
}
```

Y:

```java
Pajaro pajaro = new Pajaro();

pajaro.aterrizar();
```

---

# 8. ¿POR QUÉ EXISTEN LOS MÉTODOS `default`?

Permiten añadir comportamiento a interfaces manteniendo compatibilidad con implementaciones existentes en determinados escenarios.

Conceptualmente:

```text
Interfaz
   │
   ├── contrato
   │
   └── comportamiento default
```

---

# 9. MÉTODOS `static` EN INTERFACES

Una interfaz también puede declarar métodos estáticos.

Ejemplo:

```java
interface Matematicas {

    static int doble(int numero) {
        return numero * 2;
    }
}
```

Se invoca mediante la propia interfaz:

```java
int resultado = Matematicas.doble(5);
```

No:

```java
objeto.doble(5);
```

---

# 10. CONSTANTES EN INTERFACES

Los campos declarados en una interfaz son implícitamente:

```text
public
static
final
```

Por ejemplo:

```java
interface Configuracion {

    int MAXIMO = 100;
}
```

Conceptualmente:

```text
public static final int MAXIMO = 100;
```

---

# 11. INTERFACES Y ABSTRACCIÓN

Una interfaz es una herramienta para definir:

```text
qué debe poder hacer un objeto
```

sin obligarnos a definir cómo se implementa internamente todo ese comportamiento.

Ejemplo:

```java
interface Imprimible {

    void imprimir();
}
```

Podemos tener:

```text
Factura
Informe
Etiqueta
Documento
```

todos implementando:

```text
Imprimible
```

pero cada uno con su propia implementación.

---

# 12. INTERFAZ VS CLASE ABSTRACTA

Ambas pueden utilizarse para abstraer comportamiento, pero no son idénticas.

### Interfaz

```text
contrato
+
posibilidad de implementación múltiple
+
default/static methods
```

### Clase abstracta

```text
base común
+
estado de instancia
+
implementación compartida
+
herencia de clase
```

### 🧠 Regla de examen

```text
extends
→ clase

implements
→ interfaz
```

---

# 13. HERENCIA DE INTERFACES

Una interfaz puede extender otra interfaz:

```java
interface Animal {
}

interface Mamifero extends Animal {
}
```

Una interfaz puede extender varias interfaces:

```java
interface Volador {
}

interface Nadador {
}

interface Anfibio extends Volador, Nadador {
}
```

Esto es válido porque no estamos haciendo herencia múltiple de clases.

---

# 14. INTERFACES FUNCIONALES

Una interfaz funcional tiene exactamente un método abstracto.

Ejemplo:

```java
@FunctionalInterface
interface Operacion {

    int calcular(int a, int b);
}
```

Puede utilizarse con una lambda.

---

# 15. `@FunctionalInterface`

La anotación:

```java
@FunctionalInterface
```

indica que la interfaz está destinada a ser funcional.

El compilador puede detectar si intentamos convertirla en una interfaz con más de un método abstracto.

---

# 16. LAMBDA

Una expresión lambda permite representar una implementación funcional de forma compacta.

Ejemplo:

```java
Operacion suma = (a, b) -> a + b;
```

Después:

```java
int resultado = suma.calcular(2, 3);
```

Resultado:

```text
5
```

---

# 17. SINTAXIS DE LAMBDA

Forma general:

```text
(parámetros) -> expresión
```

Ejemplo:

```java
x -> x * 2
```

También puede tener bloque:

```java
x -> {
    return x * 2;
}
```

---

# 18. REFERENCIAS A MÉTODOS

```java
lista.forEach(System.out::println);
```

La sintaxis:

```text
::
```

representa una referencia a método.

# 20. `Predicate<T>`


```java
Predicate<Integer> mayorDeEdad =
    edad -> edad >= 18;
```

Conceptualmente:

```text
T
```

# 21. `Function<T, R>`

Recibe:

```text
T
```

y devuelve:

```text

```

Ejemplo:

Conceptualmente:

```text

```

# 22. `Consumer<T>`

Recibe un valor y no devuelve resultado:


Conceptualmente:

```text

```

---

# 23. `Supplier<T>`

No recibe argumentos y produce un valor:

```java
Supplier<Double> numero =
    () -> Math.random();
```

Conceptualmente:

```text

 ↓

```

---

# 24. `UnaryOperator<T>`

Recibe:

```text
T
```

y devuelve:

```text
T
```

Ejemplo:

```java

    n -> n * 2;
```

---

# 25. `BinaryOperator<T>`

Recibe dos valores del mismo tipo:

```text
T
+
T
↓
T
```

Ejemplo:

```java

    (a, b) -> a + b;
```

# 27. ¿POR QUÉ USAR `enum`?

Cuando una variable debe representar un conjunto cerrado de valores conocidos:

```text

Días
Tipos
Categorías
Roles
```

Es preferible a utilizar constantes enteras o cadenas arbitrarias.

# 28. ENUM CON CAMPOS Y MÉTODOS

Un `enum` puede tener:

```text
campos
constructores
métodos
```

Ejemplo:

```java
enum Planeta {

    TIERRA(1),
    MARTE(2);

    private final int codigo;

    Planeta(int codigo) {

    public int getCodigo() {
        return codigo;
    }
}
```

# 29. MÉTODOS IMPORTANTES DE `enum`

```java
values()

```

Ejemplo:

```java
for (Dia dia : Dia.values()) {

}
```

# 30. `valueOf()`

```java
Dia dia = Dia.valueOf("LUNES");
```

```text

```


# 32. `List`

Una `List` representa una colección:

```text
ordenada
indexada
que permite duplicados
```

Ejemplo:

```java
List<String> nombres = new ArrayList<>();
```

---

# 33. `ArrayList`

Es una implementación de:

```text
List
```

basada en un array redimensionable.

Ejemplo:

```java
List<String> nombres =
    new ArrayList<>();
```

Ventajas típicas:

```text
acceso rápido por índice
```

---

# 34. `LinkedList`

Otra implementación de `List`:

```java
List<String> nombres =
    new LinkedList<>();
```

Internamente utiliza una estructura enlazada.

No debemos memorizarla simplemente como:

```text
"más rápida"
```

porque el rendimiento depende de la operación concreta.

---

# 35. `List` VS `ArrayList`

Una práctica muy habitual:

```java
List<String> nombres =
    new ArrayList<>();
```

en lugar de:

```java
ArrayList<String> nombres =
    new ArrayList<>();
```

La primera forma programa contra la interfaz.

Esto permite cambiar de implementación con mayor facilidad:

```java
List<String> nombres =
    new LinkedList<>();
```

sin cambiar el tipo de la variable.

---

# 36. MÉTODOS HABITUALES DE `List`

```java
add()
get()
set()
remove()
size()
contains()
isEmpty()
clear()
```

Ejemplo:

```java
nombres.add("Ana");
nombres.add("Pedro");

String nombre = nombres.get(0);
```

---

# 37. ÍNDICES DE `List`

Como ocurre con arrays:

```text
primer índice = 0
```

Ejemplo:

```java
nombres.get(0);
```

obtiene el primer elemento.

# 38. `Set`

Un `Set` representa una colección que:

```text
no permite elementos duplicados
```

Ejemplo:

```java
Set<String> nombres =
    new HashSet<>();
```

---

# 39. `HashSet`

`HashSet` es una implementación habitual de:

```text
Set
```

Utiliza hashing para organizar los elementos.

Una característica importante:

```text
no garantiza orden de iteración
```

No debemos asumir que devuelve los elementos en el orden de inserción.

---

# 40. `LinkedHashSet`

`LinkedHashSet` mantiene el orden de inserción de los elementos.

Ejemplo:

```java
Set<String> nombres =
    new LinkedHashSet<>();
```

Conceptualmente:

```text
HashSet
→ sin garantía de orden de iteración

LinkedHashSet
→ mantiene orden de inserción
```

---

# 41. `TreeSet`

`TreeSet` mantiene sus elementos ordenados según su orden natural o un comparador proporcionado.

Ejemplo:

```java
Set<Integer> numeros =
    new TreeSet<>();
```

Si añadimos:

```text
5
1
3
```

la iteración puede producir:

```text
1
3
5
```

---

# 42. `Map`

`Map` representa asociaciones:

```text
clave → valor
```

Ejemplo:

```java
Map<String, Integer> edades =
    new HashMap<>();
```

Podemos almacenar:

```text
"Ana" → 30
"Pedro" → 35
```

---

# 43. `HashMap`

`HashMap` es una implementación habitual de `Map`.

Ejemplo:

```java
Map<String, Integer> edades =
    new HashMap<>();
```

Características importantes:

```text
clave → valor
no garantiza orden de iteración
permite una clave null
permite valores null
```

Para examen conviene recordar que el comportamiento concreto de mapas depende de su implementación.

---

# 44. `LinkedHashMap`

Mantiene el orden de inserción de las entradas.

```java
Map<String, Integer> edades =
    new LinkedHashMap<>();
```

---

# 45. `TreeMap`

Mantiene las claves ordenadas según su orden natural o un comparador.

```java
Map<String, Integer> edades =
    new TreeMap<>();
```

Conceptualmente:

```text
HashMap
→ hashing

LinkedHashMap
→ hashing + orden de inserción

TreeMap
→ claves ordenadas
```

# 50. `Map` Y SUS MÉTODOS

Métodos frecuentes:

```java
put()
get()
remove()
containsKey()
containsValue()
size()
isEmpty()
clear()
```

Ejemplo:

```java
edades.put("Pedro", 35);
```

# 51. `get()` Y CLAVES INEXISTENTES

Si hacemos:

```java
edades.get("Juan");
```

y no existe esa clave en un `Map` normal, el resultado suele ser:

```text
null
```

Esto es diferente de:

```java
edades.getOrDefault("Juan", 0);
```

que devuelve:

```text
0
```

si no encuentra la clave.

---

# 52. `put()`

```java
edades.put("Pedro", 35);
```

Si la clave:

```text
Pedro
```

no existía:

```text
se añade
```

Si ya existía:

```text
se sustituye su valor
```

Por tanto, un `Map` no permite múltiples entradas independientes con la misma clave.

---

# 53. `containsKey()`

```java

```

devuelve:

```text
true / false
```

Comprueba la existencia de una clave.

---

# 54. `containsValue()`

```java
edades.containsValue(35);
```

comprueba si existe un valor concreto.

---

# 55. `keySet()`

```java
edades.keySet()
```

---

# 56. `values()`

```java
edades.values()
```

devuelve una vista de los valores.

```java
for (Map.Entry<String, Integer> entrada :
```

# 59. `hasNext()`

Comprueba si queda otro elemento:

```java

```

Resultado:

```text

```

---

# 60. `next()`

Obtiene el siguiente elemento:

```java
iterator.next()
```

```text

```

---

# 61. `Iterator.remove()`

Un iterador puede permitir eliminar el último elemento devuelto mediante:

```java

```

Esto es importante porque modificar directamente una colección durante determinadas iteraciones puede provocar:

```text
ConcurrentModificationException
```

Algunos métodos conocidos:


Ejemplo:

---

# 66. `Comparable`

Una clase puede implementar:

```java
Comparable<T>
```

para definir un orden natural.

Ejemplo conceptual:

```java
class Persona
    implements Comparable<Persona> {

    @Override
    public int compareTo(Persona otra) {
        return this.edad - otra.edad;
    }
}
```

---

# 67. `compareTo()`

El contrato conceptual:

```text
< 0
→ menor

0
→ equivalente para el orden

> 0
→ mayor
```

No es necesario que el valor sea exactamente:

```text
-1 / 0 / 1
```

Puede ser cualquier entero con el signo apropiado.

---

# 68. `Comparator`

`Comparator<T>` permite definir una estrategia de comparación externa.

Ejemplo:

```java
Comparator<Persona> porEdad =
    Comparator.comparingInt(
        Persona::getEdad
    );
```

Después:

```java
personas.sort(porEdad);
```

---

# 69. `Comparable` VS `Comparator`

| | `Comparable` | `Comparator` |
|---|---|---|
| Método principal | `compareTo()` | `compare()` |
| Define | Orden natural | Orden externo |
| Se implementa en | La propia clase | Objeto comparador |
| Puede haber varios criterios | No es su objetivo principal | Sí |

---

# 70. ORDENACIÓN

Podemos ordenar una lista:

```java
Collections.sort(lista);
```

o:

```java
lista.sort(comparador);
```

En versiones modernas también es habitual utilizar:

```java
Comparator.comparing(...)
```

y referencias a métodos.
