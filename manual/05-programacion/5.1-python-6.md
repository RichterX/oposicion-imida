# 2. ¿QUÉ ES UN MÓDULO?

Un módulo es, fundamentalmente, un archivo Python:

```text
.py
```

que contiene código reutilizable.

Por ejemplo:

```text
calculadora.py
```

podría contener:

```python
def sumar(a, b):
    return a + b


def restar(a, b):
    return a - b
```

Ese archivo constituye un módulo.

---

# 3. IMPORTAR UN MÓDULO

Podemos importar un módulo mediante:

```python
import calculadora
```

Después podemos acceder a sus elementos mediante:

```python
calculadora.sumar(10, 5)
```

o:

```python
calculadora.restar(10, 5)
```

---

# 4. `import`

La forma:

```python
import modulo
```

importa el módulo completo.

Ejemplo:

```python
import math

print(math.sqrt(25))
```

Resultado:

```text
5.0
```

La función `sqrt()` pertenece al módulo:

```text
math
```

---

# 5. `from ... import`

Podemos importar elementos concretos:

```python
from math import sqrt
```

Ahora podemos escribir:

```python
print(sqrt(25))
```

sin utilizar:

```python
math.sqrt()
```

---

# 6. IMPORTAR VARIOS ELEMENTOS

Podemos importar varios nombres:

```python
from math import sqrt, pi
```

Ahora:

```python
print(sqrt(25))
print(pi)
```

---

# 7. ALIAS CON `as`

Podemos asignar un alias:

```python
import math as matematicas
```

Ahora:

```python
matematicas.sqrt(25)
```

También:

```python
from math import sqrt as raiz

print(raiz(25))
```

---

# 8. `import` VS `from`

Con:

```python
import math
```

utilizamos:

```python
math.sqrt(25)
```

Con:

```python
from math import sqrt
```

utilizamos:

```python
sqrt(25)
```

### 🧠 Regla

```text
import modulo
→ importa el módulo

from modulo import elemento
→ importa un elemento concreto
```

---

# 9. `from modulo import *`

Python permite:

```python
from math import *
```

Esto importa los nombres disponibles del módulo.

Sin embargo, **no suele recomendarse** porque:

```text
Puede contaminar el espacio de nombres
Puede provocar conflictos
Hace menos claro de dónde procede cada nombre
```

Por ejemplo:

```python
from math import *
```

hace menos evidente que:

```python
sqrt()
```

procede de:

```text
math
```

# 17. `sys.path`

Uno de los conceptos más importantes de este bloque es:

```python
sys.path
```

Es una lista de ubicaciones donde Python busca módulos cuando realiza importaciones.

Podemos verla:

```python
import sys

print(sys.path)
```

---

# 18. ¿POR QUÉ ES IMPORTANTE `sys.path`?

Cuando hacemos:

```python
import modulo
```

Python necesita encontrar:

```text
modulo.py
```

o un paquete correspondiente.

Para ello utiliza las rutas de búsqueda disponibles.

Conceptualmente:

```text
import modulo
       ↓
Python busca en sys.path
       ↓
encuentra módulo
       ↓
lo carga
```

# 19. `__name__`

Todo módulo Python dispone de una variable especial:

```python
__name__
```

Su valor depende de cómo se esté utilizando el módulo.

Si un archivo se ejecuta directamente, normalmente:

```python
__name__ == "__main__"
```

Si se importa como módulo, normalmente:

```python
__name__ == "nombre_del_modulo"
```

---

# 20. `__main__`

Esto permite escribir:

```python
if __name__ == "__main__":
    print("Ejecutando directamente")
```

Este patrón es extremadamente habitual en Python.

---

# 21. ¿POR QUÉ UTILIZAR `if __name__ == "__main__"`?

Supongamos:

```python
# calculadora.py

def sumar(a, b):
    return a + b


if __name__ == "__main__":
    print(sumar(2, 3))
```

Si ejecutamos directamente:

```text
python calculadora.py
```

se ejecutará:

```text
print(sumar(2, 3))
```

Pero si hacemos:

```python
import calculadora
```

la función se importa, pero el código protegido por:

```python
if __name__ == "__main__":
```

no se ejecuta como parte de la importación.

---

# 22. PATRÓN `__main__`

Este patrón permite separar:

```text
Código reutilizable
```

de:

```text
Código de ejecución directa
```

Ejemplo:

```python
def sumar(a, b):
    return a + b


def main():
    resultado = sumar(10, 20)
    print(resultado)


if __name__ == "__main__":
    main()
```

# 23. PAQUETES

Un paquete permite organizar varios módulos relacionados.

Conceptualmente:

```text
mi_proyecto/
│
└── utilidades/
    ├── calculos.py
    ├── texto.py
    └── fechas.py
```

`utilidades` agrupa varios módulos.

---

# 24. `__init__.py`

Tradicionalmente, un directorio se convierte en un paquete Python mediante:

```text
__init__.py
```

Ejemplo:

```text
utilidades/
├── __init__.py
├── calculos.py
└── texto.py
```

El archivo puede estar vacío:

```python
# __init__.py
```

o contener código de inicialización.

---

# 25. PAQUETES MODERNOS

Desde Python 3.3 existen los llamados **namespace packages**, que pueden existir sin `__init__.py`.

Por tanto:

```text
paquete tradicional
→ normalmente __init__.py

namespace package
→ puede existir sin __init__.py
```

### 🧠 Para oposición

Conviene recordar la asociación tradicional:

```text
__init__.py
→ paquete Python
```

pero sin afirmar que sea absolutamente obligatorio en Python moderno.

---

# 26. IMPORTAR DESDE UN PAQUETE

Supongamos:

```text
utilidades/
├── __init__.py
├── calculos.py
└── texto.py
```

Podemos hacer:

```python
from utilidades import calculos
```

y después:

```python
calculos.sumar(10, 20)
```

---

# 27. IMPORTAR DIRECTAMENTE UNA FUNCIÓN

También:

```python
from utilidades.calculos import sumar
```

Entonces:

```python
print(sumar(10, 20))
```

---

# 28. IMPORTACIONES RELATIVAS

Dentro de un paquete podemos realizar importaciones relativas.

Por ejemplo:

```text
proyecto/
└── paquete/
    ├── __init__.py
    ├── modulo_a.py
    └── modulo_b.py
```

Desde `modulo_b.py` podríamos utilizar:

```python
from .modulo_a import funcion
```

El punto:

```text
.
```

indica el paquete actual.

---

# 29. `..` EN IMPORTACIONES

Podemos utilizar:

```text
.
```

para el paquete actual.

Y:

```text
..
```

para el paquete padre.

Ejemplo conceptual:

```python
from ..utilidades import funcion
```

Las importaciones relativas son especialmente relevantes dentro de estructuras de paquetes.

# 32. ¿QUÉ ES `pip`?

`pip` es el sistema habitual de gestión de paquetes de Python.

Permite:

```text
Instalar paquetes
Actualizar paquetes
Eliminar paquetes
Consultar paquetes
```

---

# 33. INSTALAR UN PAQUETE

Ejemplo:

```bash
pip install requests
```

Esto solicita a `pip` la instalación del paquete:

```text
requests
```

# 34. ACTUALIZAR UN PAQUETE

```bash
pip install --upgrade requests
```

También podemos encontrar:

```bash
pip install -U requests
```

# 35. DESINSTALAR

```bash
pip uninstall requests
```

Normalmente `pip` solicitará confirmación.


# 37. `requirements.txt`

```text
requirements.txt
```

# 38. ¿POR QUÉ ES IMPORTANTE `requirements.txt`?

Permite reproducir aproximadamente el conjunto de dependencias de un proyecto.

Conceptualmente:

```text
Proyecto
   ↓
requirements.txt
   ↓
pip install -r requirements.txt
   ↓
entorno preparado
```

# 39. VERSIONES DE PAQUETES

Podemos especificar restricciones.

Por ejemplo:


significa una versión concreta.


# 40. ENTORNOS VIRTUALES

Uno de los problemas de instalar paquetes globalmente es que diferentes proyectos pueden necesitar diferentes versiones.

Ejemplo:

```text
Proyecto A
→ requests 2.x

Proyecto B
→ otra versión
```

Los **entornos virtuales** permiten aislar las dependencias de cada proyecto.

---

# 41. `venv`

Python incluye el módulo:

```text
venv
```

para crear entornos virtuales.

Ejemplo:

```bash
python -m venv .venv
```

Esto crea normalmente:

```text
.venv/
```

---

# 42. ACTIVAR UN ENTORNO VIRTUAL

En Windows:

```powershell
.venv\Scripts\activate
```

En Linux/macOS:

```bash
source .venv/bin/activate
```

Una vez activado, las instalaciones realizadas mediante `pip` se dirigen al entorno correspondiente.

---

# 43. DESACTIVAR

Para salir:

```bash
deactivate
```

---

# 44. FLUJO HABITUAL

```bash
python -m venv .venv
```

Después activamos:

```text
Windows
.venv\Scripts\activate
```

o:

```text
Linux/macOS
source .venv/bin/activate
```

Después:

```bash

```

Y finalmente:

```bash

```

# 45. ¿POR QUÉ `python -m pip`?

Podemos utilizar:

```bash
python -m pip install requests
```

en lugar de:

```bash
pip install requests
```

La primera forma indica explícitamente qué intérprete de Python debe ejecutar el módulo `pip`.

Esto puede ayudar cuando existen varias instalaciones de Python.

# 48. `requirements.txt` VS `pip freeze`

# 50. IMPORTACIÓN Y EJECUCIÓN

Cuando Python importa un módulo:

```python
import modulo
```

el código de nivel superior del módulo puede ejecutarse durante la importación.

Por eso este patrón:

```python
if __name__ == "__main__":
    ...
```

es tan importante.

Evita que el código pensado para ejecución directa se ejecute automáticamente al importar el módulo.

---

# 51. CACHÉ DE MÓDULOS

Python mantiene módulos importados en:

```python
sys.modules
```

Podemos observarlo:

```python
import sys

print(sys.modules)
```

La idea general:

```text
import
 ↓
buscar/cargar módulo
 ↓
registrar módulo
 ↓
reutilizarlo en importaciones posteriores
```

---

# 52. `__pycache__`

Python puede generar archivos compilados relacionados con los módulos dentro de:

```text
__pycache__/
```

Por ejemplo:

```text
__pycache__/
    modulo.cpython-3xx.pyc
```

Estos archivos contienen bytecode utilizado por Python.

---

# 53. `.py` VS `.pyc`

De forma simplificada:

```text
.py
→ código fuente Python

.pyc
→ bytecode compilado
```

El bytecode no es código máquina nativo de la CPU.

Es una representación que utiliza la máquina virtual de Python.

# 55. `PYTHONPATH`

Existe una variable de entorno conocida como:

```text
PYTHONPATH
```

que puede añadir rutas donde Python buscará módulos.

Conceptualmente:

```text
PYTHONPATH
      ↓
rutas adicionales

      ↓
búsqueda de módulos
```

No suele ser necesario modificarla para proyectos normales, especialmente cuando utilizamos paquetes y entornos virtuales correctamente.
