# 📖 1. ¿Qué es un objeto?

La palabra **objeto** aparece constantemente cuando trabajamos con Active Directory.

Un objeto representa cualquier elemento que pueda administrarse dentro del dominio.

Puede tratarse de una persona.

Puede ser un ordenador.

Puede ser una impresora.

Puede ser un grupo.

Puede ser incluso una carpeta compartida.

Lo importante no es de qué tipo sea.

Lo importante es que Active Directory puede almacenarlo, identificarlo y administrarlo.

Podemos imaginar Active Directory como una enorme base de datos.

Cada fila corresponde a un objeto distinto.

```
+--------------------------------------------------+

              ACTIVE DIRECTORY

+--------------------------------------------------+

 Usuario

 Equipo

 Grupo

 Impresora

 Carpeta

 Servidor

 Contacto

+--------------------------------------------------+
```

Cada uno de ellos tiene una identidad propia.

Y todos pueden administrarse desde un único lugar.

# 💼 Caso real

En el IMIDA comienza a trabajar una nueva investigadora.

Laura García.

Desde el punto de vista del departamento de Recursos Humanos, Laura es simplemente una empleada.

Sin embargo...

Desde el punto de vista de Active Directory...

Laura es un **objeto de tipo Usuario**.

Lo mismo ocurre con su ordenador.

```
Laura García

↓

Objeto Usuario

------------------------

PC-INV-03

↓

Objeto Equipo

------------------------

Impresora Laboratorio

↓

Objeto Impresora
```

Active Directory no administra "personas" ni "ordenadores".

Administra objetos.

Y gracias a ello puede tratarlos todos de una forma uniforme.

---

# 📖 2. Todos los objetos tienen atributos

Si un objeto representa una persona...

¿Cómo sabe Active Directory cuál es su nombre?

¿O su correo electrónico?

¿O su departamento?

La respuesta está en los **atributos**.

Un atributo es una característica que describe un objeto.

Por ejemplo.

Objeto:

```
Laura García
```

Atributos.

```
Nombre

Laura

--------------

Apellidos

García Pérez

--------------

Correo

laura.garcia@imida.local

--------------

Departamento

Investigación

--------------

Teléfono

981 XXX XXX
```

Es decir.

El objeto representa a Laura.

Los atributos describen quién es Laura.

Todos los objetos poseen atributos.

Aunque cada tipo de objeto almacena información diferente.

---

# 📖 3. Tipos de objetos en Active Directory

Ya sabemos que Active Directory representa todos los recursos de la empresa mediante objetos.

Sin embargo, no todos los objetos son iguales.

Cada tipo de objeto tiene una finalidad distinta y almacena atributos específicos.

Algunos representan personas.

Otros representan equipos.

Otros permiten organizar recursos o facilitar la administración.

Los tipos de objetos más habituales son los siguientes.

| Tipo de objeto | Representa |
|----------------|------------|
| Usuario | Personas que pueden iniciar sesión en el dominio |
| Grupo | Conjunto de usuarios o equipos |
| Equipo | Ordenadores unidos al dominio |
| Impresora | Impresoras compartidas |
| Contacto | Personas sin cuenta de inicio de sesión |
| Carpeta compartida | Recursos compartidos de la red |
| Unidad Organizativa (OU) | Contenedor lógico para organizar objetos |

No es necesario memorizar todavía todos estos objetos.

En los próximos capítulos estudiaremos cada uno de ellos con detalle.

---

# 📖 4. Objetos físicos y objetos lógicos

Una forma sencilla de comprender Active Directory consiste en dividir sus objetos en dos grandes grupos.

## Objetos físicos

Representan elementos que existen físicamente.

Por ejemplo:

- un ordenador;
- una impresora;
- un servidor.

```
PC-INV-01

↓

Objeto Equipo

-------------------

IMP-LAB-02

↓

Objeto Impresora

-------------------

SRV-DC01

↓

Objeto Servidor
```

Todos ellos corresponden a dispositivos reales que podemos tocar.

---

## Objetos lógicos

Representan información o estructuras de administración.

No existen físicamente.

Su función consiste en organizar y gestionar el dominio.

Por ejemplo:

- usuarios;
- grupos;
- unidades organizativas;
- contactos.

```
Laura García

↓

Objeto Usuario

------------------

Grupo Investigadores

↓

Objeto Grupo

------------------

OU Investigación

↓

Objeto OU
```

Aunque no puedan tocarse, son igual de importantes que los objetos físicos.

De hecho, la mayor parte del trabajo diario de un administrador consiste en gestionar este tipo de objetos.

# 📖 5. Relaciones entre objetos

Hasta ahora hemos estudiado los objetos de forma independiente.

Sin embargo, Active Directory resulta realmente útil porque los objetos pueden relacionarse entre sí.

Por ejemplo.

Laura pertenece al grupo **Investigadores**.

```
Laura García

        │

Pertenece a

        ▼

Grupo Investigadores
```

Ese grupo, a su vez, dispone de permisos sobre una carpeta compartida.

```
Grupo Investigadores

        │

Tiene acceso a

        ▼

Carpeta Investigación
```

Y esa carpeta se encuentra almacenada en un servidor.

```
Carpeta Investigación

        │

Está alojada en

        ▼

SRV-FILES01
```

Observa que Active Directory no administra únicamente objetos aislados.

También administra las relaciones existentes entre ellos.

Gracias a ello resulta posible controlar el acceso a los recursos de forma sencilla y centralizada.

---

# 🧠 Cadena de funcionamiento

Veamos cómo interactúan varios objetos cuando Laura inicia sesión en el dominio.

```
Laura García
(Objeto Usuario)

        │

Pertenece al grupo

        ▼

Investigadores
(Objeto Grupo)

        │

Tiene permisos sobre

        ▼

Carpeta Investigación
(Objeto Recurso)

        │

Alojada en

        ▼

SRV-FILES01
(Objeto Equipo)
```

Aunque Laura solo introduce su usuario y contraseña, Active Directory consulta automáticamente todas estas relaciones para determinar a qué recursos puede acceder.

---

# 💡 Recuerda

Los objetos rara vez trabajan de forma aislada.

La verdadera potencia de Active Directory reside en las relaciones entre ellos.

Un usuario pertenece a grupos.

Los grupos reciben permisos.

Los permisos permiten acceder a recursos.

Todo ello se administra desde un único lugar.

---

# 🐧 Linux vs Windows

Aunque GNU/Linux y Active Directory utilizan herramientas diferentes, ambos necesitan representar y administrar los recursos de una organización.

La siguiente tabla muestra algunas equivalencias conceptuales.

| GNU/Linux | Active Directory / Windows |
|------------|----------------------------|
| Usuario del sistema | Objeto Usuario |
| Grupo del sistema | Objeto Grupo |
| Equipo Linux | Objeto Equipo |
| Directorio compartido | Carpeta compartida |
| LDAP | Objetos almacenados en Active Directory |
| Archivo de configuración | Atributos de un objeto |

> **Importante**
>
> Mientras que Linux almacena gran parte de esta información en archivos del sistema, Active Directory la organiza mediante objetos y atributos dentro de una base de datos centralizada.

# ⚠️ Errores habituales

Estos son algunos de los errores más frecuentes al comenzar a trabajar con los objetos de Active Directory.

## Error 1

Pensar que únicamente existen objetos Usuario.

**Realidad**

Active Directory administra muchos tipos de objetos diferentes.

Usuarios, grupos, equipos, impresoras, contactos, OU y otros muchos recursos.

---

## Error 2

Confundir un objeto con un atributo.

**Realidad**

El objeto representa el recurso.

Los atributos describen las características de ese recurso.

---

## Error 3

Pensar que todos los objetos representan dispositivos físicos.

**Realidad**

Muchos objetos únicamente existen para facilitar la administración del dominio.

Por ejemplo, los grupos o las Unidades Organizativas.

---

## Error 4

Pensar que un usuario recibe permisos directamente en todos los casos.

**Realidad**

Lo habitual es asignar permisos a grupos y hacer que los usuarios pertenezcan a dichos grupos.

Este enfoque simplifica enormemente la administración del dominio.

---

## Error 5

Creer que los objetos funcionan de forma independiente.

**Realidad**

La mayor parte de la potencia de Active Directory reside en las relaciones entre objetos.

---

# 📌 Puntos clave

- Todo recurso administrado por Active Directory se representa mediante un objeto.
- Cada objeto posee un conjunto de atributos que describen sus características.
- Existen diferentes tipos de objetos según la función que desempeñan.
- Algunos objetos representan recursos físicos y otros estructuras lógicas.
- Los objetos pueden relacionarse entre sí para facilitar la administración del dominio.
- Comprender los objetos es imprescindible antes de estudiar las Unidades Organizativas y las Directivas de Grupo.

# 📝 Resumen

En este capítulo hemos aprendido que Active Directory representa todos los recursos de una organización mediante objetos.

Cada objeto dispone de una identidad propia y de un conjunto de atributos que almacenan su información.

También hemos conocido los principales tipos de objetos presentes en un dominio y la diferencia entre objetos físicos y objetos lógicos.

Por último, hemos visto que la verdadera potencia de Active Directory no reside únicamente en los objetos individuales, sino en las relaciones que existen entre ellos.

Estos conocimientos servirán como base para organizar el dominio en el siguiente capítulo mediante Unidades Organizativas.
