# 📖 1. ¿Cómo se administraban las empresas antes de Active Directory?

Para comprender Active Directory primero debemos entender cómo funcionaban las redes Windows antes de su aparición.

Durante muchos años las pequeñas empresas trabajaban utilizando un **Grupo de trabajo** (*Workgroup*).

En este modelo cada ordenador era completamente independiente.

```
               Grupo de trabajo

 ┌──────────┐   ┌──────────┐   ┌──────────┐
 │  PC-01   │   │  PC-02   │   │  PC-03   │
 └──────────┘   └──────────┘   └──────────┘

 Usuarios      Usuarios      Usuarios

 Contraseñas   Contraseñas   Contraseñas

 Permisos      Permisos      Permisos

 Impresoras    Impresoras    Impresoras
```

Cada equipo almacenaba su propia información.

No existía ningún servidor encargado de administrar la red.

Cada ordenador conocía únicamente a sus propios usuarios.

---

# 📖 2. El problema de los Grupos de trabajo

Mientras la empresa tiene pocos equipos, este sistema funciona razonablemente bien.

Sin embargo, conforme la organización crece comienzan a aparecer numerosos problemas.

## Usuarios duplicados

Supongamos que Ana utiliza tres ordenadores distintos.

En un Grupo de trabajo sería necesario crear el usuario en cada uno de ellos.

```
PC-01

Usuario:
Ana

------------------

PC-02

Usuario:
Ana

------------------

PC-03

Usuario:
Ana
```

Si Ana cambia su contraseña...

Será necesario modificarla manualmente en todos los equipos.

Si olvidamos actualizar uno de ellos, comenzarán los problemas de acceso.

---

## Administración compleja

Ahora imaginemos que la empresa compra veinte ordenadores nuevos.

Cada uno de ellos necesitará configurarse manualmente.

Será necesario crear:

- usuarios;
- grupos;
- permisos;
- impresoras;
- recursos compartidos;
- configuración de seguridad.

Cuantos más equipos existan, mayor será el trabajo del administrador.

---

## Configuraciones diferentes

Con el paso del tiempo cada ordenador acaba siendo distinto.

Puede ocurrir que:

- un usuario exista en un equipo pero no en otro;
- una impresora esté instalada únicamente en algunos equipos;
- determinados permisos sean diferentes;
- algunas políticas de seguridad no estén actualizadas.

El mantenimiento comienza a complicarse.

---

## Problemas de seguridad

Imaginemos ahora que un trabajador abandona la empresa.

El administrador deberá eliminar su cuenta en todos los ordenadores donde exista.

Si olvida hacerlo en uno de ellos, el usuario podría seguir teniendo acceso al sistema.

Este problema resulta especialmente grave en organizaciones grandes.

---

# 💼 Caso real

Una empresa dispone de 120 ordenadores distribuidos en cuatro edificios.

Un empleado cambia su contraseña.

Si la empresa trabaja mediante un Grupo de trabajo, el administrador tendría que modificar esa contraseña en todos los equipos donde exista la cuenta del usuario.

Además, cualquier cambio de permisos, impresoras o configuración debería repetirse manualmente.

Como puedes imaginar, este sistema deja de ser viable cuando el número de equipos comienza a crecer.

Surge entonces una pregunta muy sencilla.

> **¿Y si toda la información estuviera almacenada en un único lugar?**

Precisamente esa idea dio origen a Active Directory.

# 📖 3. ¿Qué es Active Directory?

Ya conocemos el problema.

Las empresas crecían.

Los ordenadores aumentaban.

Los usuarios también.

Administrar cada equipo de forma independiente dejó de ser una solución viable.

Microsoft respondió a este problema desarrollando **Active Directory (AD)**, un servicio capaz de centralizar toda la administración de una infraestructura Windows.

La definición oficial es la siguiente:

> **Active Directory es un servicio de directorio desarrollado por Microsoft que permite almacenar y administrar de forma centralizada usuarios, equipos, grupos, recursos y políticas dentro de un dominio Windows.**

Aunque esta definición es técnicamente correcta, puede resultar demasiado abstracta cuando se estudia por primera vez.

Durante este manual utilizaremos una definición más sencilla.

> **Active Directory es el cerebro de una red Windows.**

¿Por qué?

Porque conoce prácticamente todo lo que ocurre dentro de la organización.

Sabe:

- quién eres;
- dónde trabajas;
- qué ordenador utilizas;
- qué permisos tienes;
- qué impresoras puedes utilizar;
- qué carpetas puedes abrir;
- qué políticas de seguridad deben aplicarse.

Toda esa información se encuentra almacenada en un único lugar.

---

# 📖 4. ¿Qué información almacena Active Directory?

Una idea muy habitual entre quienes comienzan a estudiar Active Directory es pensar que únicamente almacena usuarios y contraseñas.

En realidad almacena muchísima más información.

Podemos imaginar Active Directory como una enorme base de datos de la empresa.

```
               ACTIVE DIRECTORY

            ┌───────────────────┐
            │     Usuarios      │
            ├───────────────────┤
            │     Equipos       │
            ├───────────────────┤
            │    Servidores     │
            ├───────────────────┤
            │      Grupos       │
            ├───────────────────┤
            │   Impresoras      │
            ├───────────────────┤
            │ Recursos compart. │
            ├───────────────────┤
            │    Políticas      │
            ├───────────────────┤
            │     Permisos      │
            └───────────────────┘
```

Cada uno de estos elementos recibe el nombre de **objeto**.

Un objeto representa cualquier recurso que pueda administrarse dentro del dominio.

Más adelante estudiaremos todos estos objetos con detalle.

De momento basta con comprender que Active Directory administra mucho más que usuarios.

---

## Algunos ejemplos de objetos

| Objeto | Ejemplo |
|---------|----------|
| Usuario | Laura García |
| Equipo | PC-INV-03 |
| Servidor | SRV-DC01 |
| Grupo | Investigadores |
| Impresora | IMP-LAB-02 |
| Carpeta compartida | Investigación |
| Unidad Organizativa | Departamento de Investigación |

Observa que prácticamente cualquier elemento de la empresa puede representarse como un objeto.

---

# 📖 5. ¿Qué es un Dominio?

A partir de este momento aparecerá continuamente una palabra nueva.

**Dominio.**

Es muy importante no confundir este concepto con un dominio de Internet.

Cuando hablamos de Active Directory, un dominio representa un conjunto de recursos administrados de forma centralizada.

Por ejemplo.

```
            imida.local

                 │

        ┌────────┼────────┐

     Usuarios   Equipos   Servidores

          Todo administrado
          desde Active Directory
```

Todos los equipos pertenecientes al dominio comparten:

- la misma base de datos de usuarios;
- las mismas políticas de seguridad;
- los mismos mecanismos de autenticación;
- una administración común.

Cuando un empleado inicia sesión en cualquier ordenador perteneciente al dominio, Active Directory reconoce automáticamente quién es.

---

# Grupo de trabajo vs Dominio

Ahora ya podemos comparar ambos modelos.

| Grupo de trabajo | Dominio |
|------------------|----------|
| Administración individual de cada equipo | Administración centralizada |
| Usuarios locales | Usuarios del dominio |
| Configuración independiente | Configuración común |
| Redes pequeñas | Empresas medianas y grandes |
| Difícil mantenimiento | Administración simplificada |

Una frase resume perfectamente la diferencia.

> **En un Grupo de trabajo administramos ordenadores.**

> **En un Dominio administramos toda una organización.**

---

# 📖 6. ¿Qué es un Controlador de Dominio?

Ahora aparece una pregunta lógica.

Si Active Directory almacena toda esta información...

¿Dónde se encuentra?

La respuesta es sencilla.

Se ejecuta en un servidor especial denominado **Controlador de Dominio** (*Domain Controller* o **DC**).

Este servidor responde continuamente a preguntas como:

- ¿Existe este usuario?
- ¿La contraseña es correcta?
- ¿Puede acceder a esta carpeta?
- ¿Qué políticas deben aplicarse?
- ¿Debe cambiar la contraseña?

Podemos imaginarlo como el recepcionista de un edificio de oficinas.

Cada empleado llega a la puerta.

El recepcionista consulta una base de datos.

Si la identidad es correcta...

Permite el acceso.

En caso contrario...

Deniega la entrada.

```
             Usuario

                │

        Usuario + contraseña

                │

                ▼

      Controlador de Dominio

                │

      Consulta Active Directory

                │

        ✔ Acceso permitido

              o

        ❌ Acceso denegado
```

Durante el resto del bloque veremos que el Controlador de Dominio hace mucho más que validar usuarios.

También distribuye políticas, administra equipos y participa en numerosos servicios esenciales.

---

# 📖 7. Autenticación y Autorización

Estos dos conceptos aparecen constantemente en administración de sistemas y es fundamental diferenciarlos.

Aunque suelen utilizarse juntos, representan procesos completamente distintos.

---

## Autenticación

La autenticación responde a una única pregunta.

> **¿Quién eres?**

Cuando escribimos nuestro usuario y contraseña, Active Directory verifica si realmente somos quienes decimos ser.

El resultado únicamente puede ser:

- Usuario válido.
- Usuario no válido.

Todavía no se comprueba ningún permiso.

Simplemente se confirma la identidad.

---

## Autorización

Una vez autenticado el usuario aparece una segunda pregunta.

> **¿Qué puedes hacer?**

Aquí entran en juego los permisos.

Por ejemplo.

Laura pertenece al departamento de Investigación.

Podrá acceder a:

- carpeta Investigación;
- impresora Investigación;
- aplicaciones científicas.

Sin embargo, probablemente no podrá acceder a:

- Recursos Humanos;
- Dirección;
- Contabilidad.

Ya no estamos comprobando quién es.

Estamos comprobando qué recursos tiene autorizados.

---

# 🧠 Cadena de funcionamiento

Cada vez que un usuario inicia sesión en un dominio ocurre, de forma simplificada, el siguiente proceso.

```
Usuario

     │

Introduce usuario y contraseña

     ▼

Equipo cliente

     │

Envía la solicitud

     ▼

Controlador de Dominio

     │

Comprueba identidad

     ▼

Active Directory

     │

Usuario válido

     ▼

Consulta grupos y permisos

     ▼

Aplica políticas de seguridad

     ▼

Permite el acceso al sistema
```

Aunque internamente intervienen protocolos y servicios que estudiaremos más adelante (como DNS o Kerberos), este esquema resume correctamente el funcionamiento general del proceso de inicio de sesión.

# 🐧 Linux vs Windows

Aunque GNU/Linux y Windows Server utilizan herramientas diferentes, ambos persiguen el mismo objetivo: administrar usuarios, permisos y recursos de forma segura.

En la siguiente tabla se muestran algunas equivalencias conceptuales.

| GNU/Linux | Active Directory / Windows |
|------------|----------------------------|
| `/etc/passwd` | Base de datos de usuarios de Active Directory |
| `/etc/group` | Grupos de Active Directory |
| `sudo` | Grupos administrativos del dominio |
| Usuario local | Usuario del dominio |
| SSH | Inicio de sesión en un dominio / PowerShell Remoting |
| Permisos POSIX | ACL NTFS |
| Servidor independiente | Dominio |
| `systemctl` | Administración de servicios del servidor |
| `cron` | GPO + Programador de tareas |

> **Importante**
>
> Estas equivalencias son únicamente orientativas.
>
> Linux y Windows utilizan arquitecturas diferentes, aunque muchos conceptos administrativos son similares.

# ⚠️ Errores habituales

Estos son algunos de los errores más frecuentes al comenzar a estudiar Active Directory.

## Error 1

Pensar que Active Directory es un programa.

**Realidad**

Active Directory es un servicio de directorio integrado en Windows Server.

---

## Error 2

Pensar que únicamente almacena usuarios.

**Realidad**

También administra:

- equipos;
- grupos;
- impresoras;
- políticas;
- recursos compartidos;
- permisos;
- multitud de objetos más.

---

## Error 3

Confundir un Dominio con un dominio de Internet.

**Realidad**

Aunque comparten el nombre, representan conceptos completamente distintos.

---

## Error 4

Pensar que un Dominio y un Controlador de Dominio son lo mismo.

**Realidad**

El Dominio es la organización lógica.

El Controlador de Dominio es el servidor que ejecuta Active Directory y administra ese dominio.

---

## Error 5

Confundir autenticación con autorización.

Recuerda siempre la siguiente regla.

> **Autenticación = ¿Quién eres?**

> **Autorización = ¿Qué puedes hacer?**

---

# 📌 Puntos clave

- Active Directory centraliza la administración de una infraestructura Windows.
- Un Grupo de trabajo administra cada equipo por separado.
- Un Dominio administra toda la organización desde un punto central.
- El Controlador de Dominio ejecuta Active Directory.
- Active Directory almacena mucho más que usuarios.
- Autenticación y autorización representan procesos distintos.
- Active Directory constituye uno de los pilares fundamentales de cualquier infraestructura Windows empresarial.

# 📝 Resumen

En este capítulo hemos estudiado los conceptos fundamentales sobre los que se construirá todo el bloque de Active Directory.

Hemos visto que los Grupos de trabajo resultan adecuados para pequeñas redes, pero presentan importantes limitaciones cuando aumenta el número de equipos y usuarios.

Para resolver este problema aparece Active Directory, un servicio de directorio que permite administrar de forma centralizada usuarios, equipos, grupos, permisos, recursos y políticas de seguridad.

También hemos aprendido la diferencia entre un Dominio y un Grupo de trabajo, el papel del Controlador de Dominio y los conceptos de autenticación y autorización.
