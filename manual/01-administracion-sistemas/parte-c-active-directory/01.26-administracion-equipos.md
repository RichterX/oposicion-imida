# 📖 1. Antes de unirse al dominio

Un ordenador recién instalado funciona como un equipo independiente.

Se trata de un equipo que administra únicamente sus propios usuarios y su propia configuración.

```
PC-INV-01

↓

Usuarios locales

↓

Configuración local

↓

Sin Active Directory
```

Aunque disponga de Windows, todavía no conoce la existencia del dominio.

Por tanto:

- no puede autenticarse mediante cuentas del dominio;
- no recibe Directivas de Grupo;
- no aparece en Active Directory;
- no puede administrarse de forma centralizada.

En otras palabras.

Todavía no forma parte de la infraestructura del IMIDA.

---

# 💼 Caso real

El departamento de Compras entrega un nuevo ordenador al área de Investigación.

El equipo dispone de Windows 11 instalado.

El técnico enciende el ordenador por primera vez.

Todo funciona correctamente.

Sin embargo, Laura intenta iniciar sesión con su cuenta corporativa:

```
IMIDA\lgarcia
```

Windows responde indicando que esa cuenta no existe.

¿Por qué?

Porque el ordenador todavía no pertenece al dominio.

Desde el punto de vista de Active Directory, ese equipo sigue siendo un ordenador completamente independiente.

---

# 📖 2. ¿Qué significa unir un equipo al dominio?

Unir un ordenador al dominio significa registrar ese equipo dentro de Active Directory para que pueda ser administrado de forma centralizada.

Durante este proceso ocurren varias acciones importantes.

- Active Directory crea un objeto Equipo.
- El ordenador establece una relación de confianza con el dominio.
- El equipo podrá autenticar usuarios del dominio.
- Comenzará a recibir las GPO que le correspondan.
- Pasará a formar parte de la infraestructura administrada.

Podemos representar el proceso de forma sencilla.

```
Ordenador nuevo

        │

Se une al dominio

        │

        ▼

Active Directory

crea el objeto Equipo

        │

        ▼

El ordenador ya forma

parte del dominio
```

Unir un equipo al dominio no consiste únicamente en cambiar una opción de Windows.

Supone integrar ese ordenador dentro de toda la infraestructura de Active Directory.

---

# 💼 Caso real

El administrador une **PC-INV-01** al dominio.

Automáticamente aparece un nuevo objeto en Active Directory.

```
IMIDA.LOCAL

│

└── Investigación

      │

      ├── Laura García

      ├── David López

      ├── Grupo Investigadores

      └── PC-INV-01
```

A partir de ese momento el ordenador ya puede formar parte de la administración centralizada.

---

# 💡 Recuerda

Un ordenador no pertenece al dominio simplemente porque tenga Windows instalado.

Debe unirse explícitamente al dominio para que Active Directory pueda administrarlo.

---

# 🧠 Cadena de funcionamiento

Veamos qué ocurre desde que llega un ordenador nuevo.

```
Departamento de Compras

        │

Entrega un nuevo equipo

        │

Administrador

        │

Une el equipo al dominio

        │

Active Directory

crea el objeto Equipo

        │

El ordenador pasa

a formar parte del dominio
```

A partir de ese instante el equipo podrá recibir las mismas políticas y configuraciones que el resto de ordenadores de su departamento.

---

# 📖 3. La cuenta de equipo

Cuando un ordenador se une al dominio, Active Directory crea automáticamente un nuevo objeto de tipo **Equipo**.

Este objeto representa la identidad del ordenador dentro del dominio.

Podemos imaginarlo de forma similar a una cuenta de usuario.

```
Laura García

↓

Cuenta de usuario

------------------------

PC-INV-01

↓

Cuenta de equipo
```

Ambos son objetos almacenados en Active Directory.

La diferencia es que uno representa a una persona y el otro representa a un ordenador.

Gracias a esta cuenta, el equipo puede identificarse ante el dominio y participar en la administración centralizada.

---

# 💡 Recuerda

Los usuarios tienen cuentas.

Los equipos también.

Ambos poseen una identidad propia dentro del dominio.

---

# 💼 Caso real

Tras unir **PC-INV-01** al dominio, el administrador abre la consola **Usuarios y equipos de Active Directory**.

Dentro de la OU correspondiente aparece un nuevo objeto.

```
Investigación

│

├── Laura García

├── David López

├── Grupo Investigadores

└── PC-INV-01
```

Desde ese momento el ordenador deja de ser un simple equipo con Windows.

Ahora forma parte de la infraestructura del IMIDA.

---

# 📖 4. ¿Qué ocurre después de unirse al dominio?

Una vez completada la unión al dominio, el ordenador comienza a integrarse con el resto de la infraestructura.

Entre otras acciones:

- puede autenticar usuarios del dominio;
- recibe las Directivas de Grupo (GPO);
- aplica la configuración corporativa;
- puede acceder a recursos compartidos;
- puede administrarse de forma remota.

Todo ello ocurre de manera transparente para el usuario.

En muchos casos, basta con reiniciar el equipo e iniciar sesión con una cuenta del dominio.

---

# 🧠 Cadena de funcionamiento

```
Ordenador nuevo

        │

Unión al dominio

        │

Creación del objeto Equipo

        │

Reinicio

        │

Inicio de sesión

con cuenta del dominio

        │

Recepción de GPO

        │

Equipo completamente integrado
```

Observa que la unión al dominio es solo el primer paso.

La verdadera integración comienza después.

---

# 📖 5. Administración de equipos

Al igual que ocurre con los usuarios, los equipos también requieren administración.

Las tareas más habituales son:

- cambiar el nombre del equipo;
- moverlo entre OU;
- deshabilitar su cuenta;
- eliminar el objeto cuando deja de utilizarse.

Todas estas operaciones se realizan desde la consola **Usuarios y equipos de Active Directory**.

---

# 💼 Caso real

El departamento de Informática reorganiza el edificio del IMIDA.

Dos ordenadores del departamento de Investigación pasan al laboratorio de Desarrollo.

El administrador únicamente necesita mover los objetos correspondientes a la nueva OU.

```
Antes

Investigación

│

└── PC-INV-05

        │

        ▼

Después

Informática

│

└── PC-INV-05
```

En el siguiente reinicio, el equipo comenzará a recibir las GPO propias del departamento de Informática.

No es necesario volver a configurar el ordenador manualmente.

---

# 📖 6. El ciclo de vida de un equipo

Un equipo dentro de Active Directory atraviesa distintas etapas a lo largo de su vida útil.

```
Compra

      │

      ▼

Instalación de Windows

      │

      ▼

Unión al dominio

      │

      ▼

Creación del objeto Equipo

      │

      ▼

Administración diaria

      │

      ▼

Cambio de OU

(si es necesario)

      │

      ▼

Deshabilitación

      │

      ▼

Eliminación
```

Este ciclo es muy similar al de los usuarios.

La diferencia es que representa la evolución de un ordenador dentro del dominio.

---

# 💼 Caso real

Cinco años después de su compra, **PC-INV-01** es sustituido por un equipo más moderno.

El administrador:

- retira el ordenador antiguo;
- deshabilita temporalmente su cuenta en Active Directory;
- verifica que ya no es necesaria;
- elimina finalmente el objeto Equipo.

Después incorpora el nuevo ordenador siguiendo el mismo proceso estudiado en este capítulo.

---

# 🔄 Conecta con el capítulo anterior

En el capítulo 1.25 aprendimos que las GPO se aplican sobre usuarios y equipos.

Ahora comprendemos por qué.

Solo los equipos que pertenecen al dominio poseen una cuenta en Active Directory y pueden recibir esas políticas.

Sin un objeto Equipo, Active Directory no tendría ningún elemento sobre el que aplicar la configuración corporativa.

---

# 📌 Idea clave

Un ordenador unido al dominio no es simplemente un PC con Windows.

Es un objeto administrado por Active Directory que posee identidad propia, puede recibir GPO y forma parte de la infraestructura corporativa.

---

# 🏗️ Buenas prácticas

La administración de equipos resulta mucho más sencilla cuando se siguen unas normas comunes dentro de la organización.

## Utilizar nombres descriptivos

El nombre de un equipo debe permitir identificarlo fácilmente.

Por ejemplo:

```
PC-ADM-01

PC-ADM-02

PC-INV-01

PC-INV-02

PC-INF-01

SRV-DC-01

SRV-FILE-01
```

Una convención de nombres ayuda a localizar rápidamente cada dispositivo.

---

## Organizar los equipos en la OU correcta

Cada equipo debe pertenecer a la Unidad Organizativa correspondiente a su departamento o función.

De este modo recibirá únicamente las GPO que realmente necesita.

---

## No eliminar inmediatamente los equipos antiguos

Cuando un ordenador deja de utilizarse es recomendable deshabilitar primero su cuenta.

Tras comprobar que ya no es necesaria podrá eliminarse definitivamente.

---

## Mantener actualizada la información

Si un equipo cambia de nombre, departamento o ubicación, la información almacenada en Active Directory también debe actualizarse.

---

# 🐧 Linux vs Windows

La incorporación de equipos también existe en entornos GNU/Linux, aunque suele realizarse mediante herramientas diferentes.

| GNU/Linux | Active Directory / Windows |
|------------|----------------------------|
| Equipo independiente | Equipo fuera del dominio |
| Integración mediante LDAP/Kerberos | Unión al dominio |
| Gestión con Ansible/Puppet | Administración mediante GPO |
| Inventario de equipos | Objetos Equipo en Active Directory |

> **Importante**
>
> En Windows, la unión al dominio forma parte del funcionamiento habitual de Active Directory.
>
> En GNU/Linux pueden emplearse diferentes soluciones según la infraestructura existente.

# ⚠️ Errores habituales

## Error 1

Pensar que instalar Windows implica pertenecer al dominio.

**Realidad**

Un ordenador solo forma parte del dominio después de unirse explícitamente a él.

---

## Error 2

Dejar todos los equipos en la OU predeterminada.

**Realidad**

Una buena organización facilita la aplicación correcta de las GPO.

---

## Error 3

Utilizar nombres poco descriptivos.

**Realidad**

Una convención clara simplifica enormemente la administración.

---

## Error 4

Eliminar directamente la cuenta de un equipo averiado.

**Realidad**

Es recomendable deshabilitarla primero y eliminarla cuando se confirme que ya no será necesaria.

---

## Error 5

Pensar que los equipos solo sirven para que los usuarios inicien sesión.

**Realidad**

Los equipos son objetos propios de Active Directory y forman parte de la administración centralizada.

---

# 📌 Puntos clave

- Un equipo debe unirse al dominio para formar parte de Active Directory.
- La unión crea un objeto Equipo con identidad propia.
- Los equipos pueden administrarse igual que otros objetos del dominio.
- Las OU determinan qué GPO recibirá cada equipo.
- Una correcta organización facilita la administración y el crecimiento de la infraestructura.

---

# 📝 Resumen

En este capítulo hemos estudiado cómo los ordenadores pasan a formar parte de un dominio de Active Directory.

Hemos visto que la unión al dominio crea un objeto Equipo que permite identificar el ordenador, administrarlo de forma centralizada y aplicar automáticamente las Directivas de Grupo correspondientes.

También hemos aprendido que los equipos poseen un ciclo de vida similar al de los usuarios y que una correcta organización mediante OU facilita enormemente la administración de toda la infraestructura.
