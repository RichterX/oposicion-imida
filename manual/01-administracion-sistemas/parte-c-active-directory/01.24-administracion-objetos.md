# 📖 1. Administrar Active Directory

Hasta ahora Active Directory contenía muy pocos objetos.

A partir de este momento comenzaremos a crear, modificar y administrar todos los recursos de la empresa.

La administración de objetos consiste en mantener actualizada la información almacenada en el dominio.

Un administrador realiza tareas como las siguientes:

- crear nuevos usuarios;
- crear grupos;
- incorporar equipos al dominio;
- modificar información de los empleados;
- mover objetos entre OU;
- deshabilitar cuentas;
- eliminar objetos que ya no sean necesarios.

Todas estas acciones se realizan sobre los objetos que estudiamos en el capítulo anterior.

---

# 💼 Caso real

El departamento de Recursos Humanos comunica la incorporación de una nueva investigadora.

Antes de que pueda comenzar a trabajar será necesario:

- crear su cuenta de usuario;
- asignarla a su departamento;
- incorporarla a los grupos correspondientes;
- configurar sus datos personales.

Sin estas tareas, la empleada no podrá iniciar sesión en el dominio.

Administrar Active Directory significa precisamente mantener sincronizada la infraestructura informática con la realidad de la organización.

---

# 📖 2. Herramientas de administración

Windows Server incorpora diferentes herramientas para administrar Active Directory.

La más utilizada es:

**Usuarios y equipos de Active Directory**

(Active Directory Users and Computers)

Habitualmente se abre desde el menú:

```
Administrador del servidor

↓

Herramientas

↓

Usuarios y equipos de Active Directory
```

Desde esta consola es posible:

- crear usuarios;
- crear grupos;
- administrar equipos;
- mover objetos;
- modificar atributos;
- eliminar objetos;
- restaurar objetos (cuando la Papelera de reciclaje de Active Directory está habilitada).

Esta será la herramienta principal utilizada durante todo el capítulo.

---

# 💡 Recuerda

Los administradores no trabajan directamente sobre el dominio.

Trabajan sobre los **objetos** almacenados en él.

Cada acción que realizan consiste en crear, modificar, mover o eliminar alguno de esos objetos.

---

# 📖 3. Crear un usuario

La tarea más habitual que realiza un administrador de Active Directory consiste en crear cuentas de usuario.

Cada empleado que necesite utilizar los recursos de la organización deberá disponer de su propio objeto Usuario dentro del dominio.

Cuando creamos un usuario, Active Directory añade un nuevo objeto a su base de datos.

Ese objeto almacenará toda la información relacionada con esa persona.

Por ejemplo:

```
Objeto Usuario

────────────────────────

Nombre

Laura

Apellidos

García

Usuario

lgarcia

Correo

laura.garcia@imida.local

Departamento

Investigación

Despacho

Edificio A

Teléfono

981 XXX XXX
```

Observa que no estamos creando únicamente un nombre de usuario.

Estamos creando un objeto completo con numerosos atributos.

---

# 💼 Caso real

Es lunes.

Laura García llega al departamento de Investigación para incorporarse a su puesto.

Antes de sentarse delante de un ordenador, el administrador debe crear su cuenta en Active Directory.

Hasta que esa cuenta no exista:

- no podrá iniciar sesión;
- no tendrá acceso al dominio;
- no podrá utilizar recursos compartidos;
- no pertenecerá a ningún grupo.

La creación del usuario constituye el primer paso para integrar a un empleado dentro de la infraestructura informática.

---

# 📖 4. Información que solicita Active Directory

Cuando creamos un nuevo usuario, Active Directory solicita una serie de datos.

Algunos son obligatorios.

Otros son opcionales, aunque muy recomendables.

Los campos más habituales son los siguientes.

| Campo | Descripción |
|--------|-------------|
| Nombre | Nombre del empleado. |
| Apellidos | Apellidos del empleado. |
| Nombre completo | Se genera automáticamente a partir de los anteriores, aunque puede modificarse. |
| Nombre de inicio de sesión (User logon name) | Identificador utilizado para iniciar sesión en el dominio. |
| Contraseña inicial | Clave asignada al usuario. |
| Departamento | Información organizativa del empleado. |
| Cargo | Puesto desempeñado. |
| Teléfono | Información de contacto. |
| Correo electrónico | Dirección de correo corporativa. |

No todos estos campos son obligatorios para crear el usuario.

Sin embargo, mantener esta información actualizada facilitará enormemente la administración del dominio.

---

# 📖 5. Creación del usuario paso a paso

Desde la consola **Usuarios y equipos de Active Directory** el procedimiento habitual es el siguiente.

```
Seleccionar la OU

↓

Clic derecho

↓

Nuevo

↓

Usuario

↓

Introducir los datos

↓

Asignar contraseña

↓

Finalizar
```

Una vez completado el asistente aparecerá un nuevo objeto dentro de la OU seleccionada.

Por ejemplo.

```
IMIDA.LOCAL

│

└── Investigación

      │

      ├── Laura García

      └── David López
```

Es importante comprobar siempre que el usuario se crea en la Unidad Organizativa correcta.

Una ubicación incorrecta puede provocar problemas de administración en capítulos posteriores.

---

# 📖 6. La contraseña inicial

Durante la creación del usuario también se configura una contraseña inicial.

Normalmente el administrador establece una contraseña temporal que el empleado deberá cambiar durante su primer inicio de sesión.

Esta práctica mejora la seguridad del dominio, ya que evita que el administrador conozca la contraseña definitiva del usuario.

Las opciones más habituales durante la creación son:

- El usuario debe cambiar la contraseña en el siguiente inicio de sesión.
- El usuario no puede cambiar la contraseña.
- La contraseña nunca caduca.
- La cuenta está deshabilitada.

Cada organización establecerá estas opciones según su política de seguridad.

En la mayoría de los casos se recomienda obligar al usuario a cambiar su contraseña la primera vez que inicia sesión.

---

# 💡 Recuerda

Crear un usuario no consiste únicamente en asignar un nombre y una contraseña.

Significa crear un nuevo objeto dentro de Active Directory con todos los atributos necesarios para identificar y administrar a ese empleado.

# 📖 7. Otras operaciones habituales sobre objetos

La creación de usuarios representa únicamente una parte del trabajo diario de un administrador.

A lo largo de la vida de una organización, los objetos cambian constantemente.

Los empleados cambian de departamento.

Los equipos se sustituyen.

Se crean nuevos grupos.

Otros dejan de utilizarse.

Por este motivo, Active Directory permite realizar numerosas operaciones sobre los objetos existentes.

Entre las más habituales encontramos:

- modificar atributos;
- mover objetos entre OU;
- añadir usuarios a grupos;
- deshabilitar cuentas;
- eliminar objetos.

Todas estas operaciones pueden realizarse desde la consola **Usuarios y equipos de Active Directory**.

---

# 💼 Caso real

Durante los siguientes meses ocurren varias situaciones en el IMIDA.

Laura cambia de despacho.

David pasa al departamento de Informática.

Se incorpora una nueva investigadora.

Un empleado abandona la organización.

Cada uno de estos cambios exige actualizar la información almacenada en Active Directory.

La infraestructura informática debe reflejar siempre la realidad de la empresa.

# 📖 8. El ciclo de vida de un objeto

Podemos imaginar cada objeto de Active Directory como un elemento que atraviesa distintas etapas.

```
Creación

      │

      ▼

Uso diario

      │

      ▼

Modificación

      │

      ▼

Cambio de departamento
o de ubicación

      │

      ▼

Deshabilitación

      │

      ▼

Eliminación
```

No todos los objetos recorrerán todas estas etapas.

Sin embargo, esta secuencia representa el ciclo de vida habitual de muchos usuarios, grupos y equipos dentro de una organización.

---

# 💡 Recuerda

Un administrador no crea objetos para olvidarse de ellos.

Su trabajo consiste en mantenerlos actualizados durante toda su vida útil.

---

# 🧠 Cadena de funcionamiento

Veamos el recorrido completo de Laura dentro del dominio.

```
Recursos Humanos

        │

Nueva incorporación

        │

Administrador

        │

Crea el usuario

        │

Actualiza sus datos

        │

La añade a un grupo

        │

La traslada a otra OU
(si cambia de departamento)

        │

Deshabilita la cuenta
(al abandonar la organización)

        │

Elimina el objeto
(si deja de ser necesario)
```

Este ciclo resume buena parte del trabajo cotidiano de un administrador de Active Directory.

# 🐧 Linux vs Windows

Aunque los mecanismos son diferentes, tanto GNU/Linux como Active Directory permiten administrar usuarios y grupos durante todo su ciclo de vida.

| GNU/Linux | Active Directory / Windows |
|------------|----------------------------|
| `useradd` | Crear usuario |
| `usermod` | Modificar atributos |
| `passwd` | Cambiar contraseña |
| `usermod -L` | Deshabilitar cuenta |
| `userdel` | Eliminar usuario |
| `groupadd` | Crear grupo |
| `groupmod` | Modificar grupo |

> **Importante**
>
> En GNU/Linux muchas de estas operaciones se realizan desde la línea de comandos.
>
> En Active Directory suelen realizarse mediante herramientas gráficas, aunque también pueden automatizarse mediante PowerShell.

# ⚠️ Errores habituales

## Error 1

Pensar que basta con crear un usuario.

**Realidad**

Los objetos requieren mantenimiento durante toda su vida útil.

---

## Error 2

No actualizar los atributos cuando cambia la información de un empleado.

**Realidad**

La información desactualizada dificulta la administración y puede provocar errores.

---

## Error 3

Eliminar inmediatamente una cuenta cuando un empleado abandona la empresa.

**Realidad**

En muchas organizaciones primero se deshabilita la cuenta y solo posteriormente se elimina, una vez comprobado que ya no es necesaria.

---

## Error 4

Crear usuarios fuera de la OU correspondiente.

**Realidad**

Una estructura organizada facilita enormemente la administración del dominio.

---

## Error 5

Utilizar una única cuenta para varias personas.

**Realidad**

Cada empleado debe disponer de su propia cuenta de usuario para garantizar la trazabilidad y la seguridad.

---

# 📌 Puntos clave

- Active Directory permite administrar el ciclo de vida completo de los objetos.
- Crear un usuario implica crear un nuevo objeto con múltiples atributos.
- Los objetos pueden modificarse, trasladarse, deshabilitarse y eliminarse.
- La información almacenada debe mantenerse siempre actualizada.
- Una correcta administración facilita la seguridad y el mantenimiento del dominio.

## 1.25 Directivas de Grupo (GPO)

Hasta ahora hemos construido y organizado nuestra infraestructura:

- hemos creado el dominio;
- hemos incorporado usuarios y equipos;
- hemos organizado los objetos mediante OU.

Sin embargo, todavía queda una pregunta fundamental:

> **¿Cómo conseguimos que todos los equipos de un departamento compartan la misma configuración sin tener que modificarlos uno a uno?**

La respuesta la encontraremos en las **Directivas de Grupo (Group Policy Objects o GPO)**.

Aprenderemos a aplicar configuraciones centralizadas, reforzar la seguridad del dominio y automatizar la administración de cientos de usuarios y equipos desde un único punto.
