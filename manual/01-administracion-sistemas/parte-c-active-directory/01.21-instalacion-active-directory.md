# 📖 1. ¿Qué es un rol en Windows Server?

En capítulos anteriores vimos que Windows Server puede desempeñar muchas funciones distintas.

Por ejemplo, un servidor puede actuar como:

- servidor DNS;
- servidor DHCP;
- servidor de archivos;
- servidor de impresión;
- servidor web;
- servidor de virtualización.

Windows no instala todas estas funciones por defecto.

En su lugar utiliza un sistema basado en **roles**.

Un rol es un conjunto de servicios que permite al servidor desempeñar una función concreta dentro de la red.

Podemos imaginar un servidor recién instalado como un edificio completamente vacío.

```
+----------------------------------+
|                                  |
|        Windows Server            |
|                                  |
|      (Sin funciones activas)     |
|                                  |
+----------------------------------+
```

El edificio existe.

Pero todavía no sabemos qué actividad realizará.

Cuando instalamos un rol, estamos asignando una función a ese servidor.

---

# 💼 Caso real

Una empresa dispone de cuatro servidores.

Cada uno desempeña una función distinta.

```
SRV-WEB01
Servidor web (IIS)

SRV-FILES01
Servidor de archivos

SRV-DHCP01
Servidor DHCP

SRV-DC01
Active Directory
```

Aunque todos ejecutan Windows Server, cada uno tiene instalados roles diferentes.

Eso permite especializar cada servidor según las necesidades de la organización.

---

# 📖 2. Active Directory Domain Services (AD DS)

Uno de esos roles recibe el nombre de:

**Active Directory Domain Services**, abreviado **AD DS**.

Se trata del rol responsable de proporcionar los servicios necesarios para crear y administrar un dominio Windows.

Es importante observar su nombre completo.

No se llama simplemente "Active Directory".

Se llama **Active Directory Domain Services** porque incluye todos los componentes necesarios para que un servidor pueda actuar como Controlador de Dominio.

Entre otras funciones, AD DS permitirá:

- almacenar usuarios;
- administrar grupos;
- gestionar equipos;
- aplicar políticas de seguridad;
- autenticar usuarios;
- autorizar el acceso a recursos.

Sin embargo...

Hay un detalle muy importante.

> **Instalar AD DS NO crea automáticamente un dominio.**

Muchos administradores principiantes creen que ambos pasos son equivalentes.

No es así.

La instalación únicamente prepara el servidor.

Todavía falta un segundo paso.

---

# 📖 3. Instalar AD DS no convierte el servidor en un Controlador de Dominio

Esta es probablemente la idea más importante del capítulo.

Veamos el proceso completo.

## Paso 1

Instalamos el rol AD DS.

```
Windows Server

        │

Instalar AD DS

        ▼

Servidor preparado

❌ Todavía NO existe un dominio.
```

En este momento Windows copia los archivos necesarios e incorpora las herramientas de administración.

Pero el servidor sigue siendo un servidor "normal".

Todavía no autentica usuarios.

Todavía no existe una base de datos del dominio.

Todavía no existe un bosque.

Todavía no existe ningún dominio.

---

## Paso 2

Promocionamos el servidor.

```
Servidor con AD DS

        │

Promoción

        ▼

Controlador de Dominio

        │

Dominio operativo

        │

Active Directory funcionando
```

Es durante la promoción cuando realmente nace la infraestructura de Active Directory.

En ese momento Windows:

- crea el dominio;
- crea el primer bosque;
- instala la base de datos de Active Directory;
- configura los servicios necesarios para la autenticación;
- convierte el servidor en el primer Controlador de Dominio.

A partir de ese instante toda la organización comenzará a depender de él.

---

# 💡 Recuerda

No confundas estos dos conceptos.

| Acción | Resultado |
|---------|-----------|
| Instalar AD DS | El servidor queda preparado para alojar Active Directory. |
| Promocionar el servidor | Se crea el dominio y el servidor pasa a ser un Controlador de Dominio. |

Esta diferencia aparece con frecuencia en certificaciones técnicas y es un error habitual entre quienes empiezan a trabajar con Active Directory.

---

# 📖 4. ¿Qué ocurre durante la promoción del servidor?

Hasta ahora sabemos que instalar el rol AD DS únicamente prepara el servidor.

Sin embargo, cuando ejecutamos el asistente de promoción ocurre una serie de cambios muy importantes.

Aunque desde el punto de vista del administrador solo pulsamos unos pocos botones, Windows realiza numerosas tareas de forma automática.

Entre ellas destacan las siguientes.

- Crea el primer dominio.
- Crea el primer bosque.
- Instala la base de datos de Active Directory.
- Configura el servicio DNS (si es necesario).
- Convierte el servidor en un Controlador de Dominio.
- Configura los servicios de autenticación.
- Reinicia el servidor para completar la instalación.

En otras palabras, el servidor deja de comportarse como un Windows Server convencional para convertirse en el centro de administración de toda la empresa.

---

# 📖 5. El primer bosque y el primer dominio

Cuando se instala Active Directory por primera vez aparece un concepto nuevo:

**Bosque (Forest).**

No debemos preocuparnos todavía por todos los detalles.

Los estudiaremos más adelante.

Por ahora basta con entender la siguiente idea.

```
Bosque
   │
   └──────── Dominio
```

Un bosque es la estructura lógica más grande de Active Directory.

Dentro de un bosque pueden existir uno o varios dominios.

Cuando instalamos el primer Controlador de Dominio ocurre algo muy sencillo.

Como todavía no existe nada...

Windows crea automáticamente:

- el primer bosque;
- el primer dominio.

Por ejemplo.

```
Bosque

IMIDA.LOCAL

        │

Dominio raíz

IMIDA.LOCAL
```

En ese momento ambos coinciden.

Más adelante, una organización muy grande podría añadir nuevos dominios al mismo bosque.

Pero en la mayoría de empresas pequeñas y medianas existirá un único bosque con un único dominio.

---

# 💡 Recuerda

En la primera instalación:

- Primer bosque ✔
- Primer dominio ✔
- Primer Controlador de Dominio ✔

Todo ello se crea durante el mismo proceso de promoción.

---

# 📖 6. La base de datos NTDS

Una vez creado el dominio surge una nueva pregunta.

¿Dónde guarda Active Directory toda la información?

La respuesta es:

En una base de datos denominada **NTDS**.

Su archivo principal recibe el nombre de:

```
NTDS.DIT
```

En esta base de datos se almacenan, entre otros elementos:

- usuarios;
- grupos;
- equipos;
- unidades organizativas (OU);
- información de autenticación;
- relaciones entre objetos.

Podemos imaginarla como el gran "archivo" de la empresa.

```
             Active Directory

                    │

             Base de datos NTDS

                    │

     ┌────────────────────────────┐
     │ Usuarios                   │
     │ Equipos                    │
     │ Grupos                     │
     │ OU                         │
     │ Permisos                   │
     │ Relaciones                 │
     └────────────────────────────┘
```

Es importante comprender que los administradores normalmente no interactúan directamente con este archivo.

Utilizan herramientas gráficas o PowerShell.

Windows se encarga de modificar la base de datos de forma segura.

---

# 📖 7. ¿Por qué también se instala DNS?

Durante la promoción del servidor aparece un mensaje que suele sorprender a muchos administradores.

Windows propone instalar también el servicio **DNS**.

Esto provoca una duda muy frecuente.

> ¿Qué relación existe entre DNS y Active Directory?

Aunque normalmente asociamos DNS con Internet y páginas web, dentro de una red Windows desempeña un papel completamente distinto.

Los equipos del dominio necesitan localizar continuamente al Controlador de Dominio.

Para conseguirlo utilizan DNS.

Cuando un usuario intenta iniciar sesión ocurre, de forma simplificada, el siguiente proceso.

```
Usuario

     │

Inicia sesión

     ▼

Equipo cliente

     │

Pregunta a DNS

     │

"¿Dónde está el
Controlador de Dominio?"

     ▼

DNS responde

     ▼

El equipo contacta
con el DC

     ▼

Active Directory
autentica al usuario
```

Sin DNS, los equipos no sabrían dónde encontrar el Controlador de Dominio.

Por ese motivo ambas tecnologías trabajan estrechamente unidas.

En la mayoría de instalaciones, el propio Controlador de Dominio también actúa como servidor DNS.

Más adelante estudiaremos este servicio con mucho más detalle.

---

# 💼 Caso real

El departamento de Informática instala un nuevo ordenador.

El equipo todavía no conoce la dirección del Controlador de Dominio.

Cuando el usuario intenta iniciar sesión por primera vez, el ordenador consulta al servidor DNS.

Gracias a esa consulta descubre dónde se encuentra **SRV-DC01** y puede enviar la solicitud de autenticación.

Todo este proceso ocurre en apenas unos segundos y resulta completamente transparente para el usuario.

# 📌 Idea clave

La promoción de un servidor no consiste únicamente en instalar un programa.

Supone transformar un servidor Windows convencional en el núcleo de autenticación y administración de toda la empresa.

A partir de ese momento, usuarios, equipos y recursos dependerán del Controlador de Dominio para poder trabajar de forma coordinada.

# 🐧 Linux vs Windows

Aunque GNU/Linux y Windows Server implementan mecanismos diferentes para la administración centralizada, ambos persiguen el mismo objetivo: facilitar la gestión de usuarios, equipos y recursos dentro de una organización.

La siguiente tabla muestra algunas equivalencias conceptuales.

| GNU/Linux | Active Directory / Windows |
|------------|----------------------------|
| Servidor Linux | Controlador de Dominio |
| LDAP | Active Directory Domain Services |
| `/etc/passwd` | Base de datos de Active Directory |
| `/etc/group` | Grupos del dominio |
| Kerberos | Kerberos (también utilizado por Active Directory) |
| DNS | DNS integrado con Active Directory |
| Servicio instalado | Rol del servidor |
| systemd | Servicios de Windows |

> **Importante**
>
> Aunque Active Directory utiliza tecnologías como LDAP, Kerberos y DNS, Microsoft las integra dentro de un único servicio de directorio, facilitando enormemente la administración de entornos Windows.

# ⚠️ Errores habituales

Estos son algunos de los errores más frecuentes al instalar Active Directory por primera vez.

## Error 1

Pensar que instalar AD DS crea automáticamente un dominio.

**Realidad**

La instalación únicamente incorpora el rol.

El dominio no existe hasta completar la promoción del servidor.

---

## Error 2

Confundir un servidor Windows con un Controlador de Dominio.

**Realidad**

Todo Controlador de Dominio es un servidor Windows.

Pero no todo servidor Windows actúa como Controlador de Dominio.

---

## Error 3

Creer que DNS es opcional.

**Realidad**

Active Directory depende de DNS para localizar los Controladores de Dominio.

Sin DNS el proceso de autenticación no funcionaría correctamente.

---

## Error 4

Pensar que NTDS es un programa.

**Realidad**

NTDS es la base de datos donde Active Directory almacena la información del dominio.

---

## Error 5

Pensar que un bosque y un dominio son exactamente lo mismo.

**Realidad**

En la primera instalación ambos coinciden, pero conceptualmente son estructuras diferentes.

Un bosque puede contener varios dominios.

---

# 📌 Puntos clave

- Active Directory Domain Services (AD DS) es un rol de Windows Server.
- Instalar AD DS no convierte automáticamente un servidor en Controlador de Dominio.
- La promoción crea el primer bosque, el primer dominio y la base de datos NTDS.
- Un Controlador de Dominio centraliza la autenticación y administración de la organización.
- Active Directory depende del servicio DNS para localizar los Controladores de Dominio.
- La base de datos NTDS almacena toda la información del dominio.

---

# 📝 Resumen

En este capítulo hemos aprendido cómo comienza realmente una infraestructura Active Directory.

En primer lugar, hemos visto que Active Directory se instala como un **rol de Windows Server**, denominado **Active Directory Domain Services (AD DS)**.

Posteriormente, el servidor debe promocionarse a **Controlador de Dominio**, proceso durante el cual Windows crea el primer bosque, el primer dominio y la base de datos NTDS, además de configurar los servicios necesarios para la autenticación.

También hemos comprendido la importancia del servicio DNS dentro del dominio y la diferencia entre instalar un rol y transformar un servidor en el núcleo de administración de toda la organización.

Con estos conocimientos ya estamos preparados para comenzar a trabajar con los distintos objetos que forman parte de Active Directory.
