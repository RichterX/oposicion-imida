# 📖 2. ¿Qué es una Unidad Organizativa?

Una **Unidad Organizativa**, conocida habitualmente por sus siglas **OU (Organizational Unit)**, es un contenedor lógico utilizado para organizar objetos dentro de Active Directory.

Una OU no representa una persona.

No representa un ordenador.

No representa una impresora.

Su única función consiste en organizar otros objetos.

Podemos imaginar una OU como una carpeta dentro del Explorador de archivos.

```
Documentos

│

├── Trabajo

├── Personal

└── Fotografías
```

Las carpetas no contienen información propia.

Simplemente ayudan a mantener los archivos ordenados.

Con las OU ocurre exactamente lo mismo.

```
IMIDA.LOCAL

│

├── Dirección

├── Administración

├── Investigación

└── Informática
```

Dentro de cada OU almacenaremos los objetos correspondientes.

Por ejemplo.

```
Investigación

│

├── Laura García

├── David López

├── PC-INV-01

├── PC-INV-02

└── Grupo Investigadores
```

La OU no sustituye a los objetos.

Simplemente los organiza.

---

# 📌 Idea clave

Las OU no existen para almacenar información.

Existen para mantener organizado el dominio.

Cuanto mayor sea una organización, más importante resultará disponer de una estructura clara y bien planificada.

# 📖 3. Organización jerárquica de las OU

Hasta ahora hemos visto que las Unidades Organizativas permiten mantener ordenados los objetos del dominio.

Sin embargo, una empresa no suele organizarse en un único nivel.

Por ejemplo, el departamento de Investigación puede dividirse en varios laboratorios.

El departamento de Informática puede tener un área de soporte y otra de desarrollo.

Active Directory permite representar esta estructura mediante una jerarquía de OU.

Veamos un ejemplo.

```
IMIDA.LOCAL

│

├── Dirección

├── Administración

├── Investigación

│     ├── Laboratorio A

│     ├── Laboratorio B

│     └── Laboratorio C

│

└── Informática

      ├── Soporte

      └── Desarrollo
```

Observa que unas OU pueden contener otras OU.

De esta forma es posible representar la organización real de una empresa.

Cuanto mayor sea la organización, más útil resultará esta estructura.

---

# OU padre y OU hija

Cuando una OU contiene otra OU, hablamos de una relación jerárquica.

La OU superior recibe el nombre de **OU padre**.

La OU situada dentro de ella recibe el nombre de **OU hija**.

Por ejemplo.

```
Investigación

│

├── Laboratorio A

├── Laboratorio B

└── Laboratorio C
```

En este caso:

- **Investigación** es la OU padre.
- **Laboratorio A**, **Laboratorio B** y **Laboratorio C** son OU hijas.

Esta organización permite dividir grandes departamentos en áreas más pequeñas y fáciles de administrar.

---

# 💼 Caso real

El departamento de Informática del IMIDA tiene veinte técnicos.

Sin embargo, no todos realizan el mismo trabajo.

La organización decide dividir el departamento en dos equipos.

```
Informática

│

├── Soporte

└── Desarrollo
```

Ahora resulta mucho más sencillo localizar usuarios y equipos.

Además, en el futuro será posible aplicar configuraciones diferentes a cada área sin afectar al resto del departamento.

# 📖 4. ¿Qué puede contener una OU?

Una Unidad Organizativa puede almacenar distintos tipos de objetos.

Entre los más habituales encontramos:

- usuarios;
- grupos;
- equipos;
- impresoras publicadas;
- otras OU.

Por ejemplo.

```
Investigación

│

├── Laura García

├── David López

├── Grupo Investigadores

├── PC-INV-01

├── PC-INV-02

└── Laboratorio A
```

Observa que la OU actúa como un contenedor.

Su función consiste únicamente en mantener organizados todos esos objetos.

# 📖 5. Lo que una OU NO es

Cuando se empieza a trabajar con Active Directory es muy habitual confundir las OU con otros elementos del dominio.

Veamos las diferencias más importantes.

## Una OU no es un Grupo

Los grupos sirven para reunir usuarios o equipos con un objetivo común, normalmente relacionado con los permisos.

Las OU sirven para organizar objetos.

Por ejemplo.

```
Grupo

Investigadores

↓

Permisos sobre carpetas

----------------------------

OU

Investigación

↓

Organización del dominio
```

Aunque ambos pueden contener usuarios, su finalidad es completamente distinta.

---

## Una OU no es un Dominio

El dominio representa toda la infraestructura de Active Directory.

Las OU son únicamente divisiones internas utilizadas para organizar ese dominio.

```
Dominio

IMIDA.LOCAL

│

├── Dirección

├── Administración

├── Investigación

└── Informática
```

Las OU forman parte del dominio.

Nunca lo sustituyen.

---

## Una OU no es una carpeta del disco duro

Aunque la comparación con una carpeta resulta muy útil para comprender su funcionamiento, una OU no almacena archivos.

Lo que almacena son objetos de Active Directory.

Por tanto, una OU no existe dentro del sistema de archivos del servidor.

Existe únicamente dentro del dominio.

# 💡 Recuerda

Hazte siempre esta pregunta.

> **¿Quiero organizar objetos?**

Entonces probablemente necesites una **OU**.

> **¿Quiero conceder permisos?**

Entonces probablemente necesites un **Grupo**.

Esta sencilla regla evita una gran parte de los errores que cometen los administradores principiantes.

# 🧠 Cadena de funcionamiento

Veamos cómo se organiza un nuevo empleado dentro del dominio.

```
Nuevo empleado

        │

Se crea un objeto Usuario

        │

Se identifica su departamento

        │

Se almacena en la OU correspondiente

        │

Posteriormente podrán aplicarse

```

Observa que la OU no concede permisos por sí misma.

Su misión consiste en mantener organizada la estructura del dominio y preparar el terreno para la administración posterior.

---

# 📌 Idea clave

Las OU representan la estructura organizativa de la empresa.

No existen para conceder permisos, sino para mantener el dominio ordenado, facilitar la administración y permitir la aplicación de políticas específicas a cada área.

# 🐧 Linux vs Windows

Aunque GNU/Linux y Active Directory organizan la información de formas diferentes, ambos utilizan estructuras jerárquicas para facilitar la administración.

| GNU/Linux | Active Directory / Windows |
|------------|----------------------------|
| Directorio | Unidad Organizativa (OU) |
| Árbol de directorios | Jerarquía de OU |
| Archivo | Objeto de Active Directory |
| Subdirectorio | OU hija |
| Directorio principal | OU padre |

> **Importante**
>
> Una OU no almacena archivos como un directorio de Linux. La comparación únicamente sirve para comprender que ambos sistemas utilizan estructuras jerárquicas para mantener organizada la información.

# 🏗️ Buenas prácticas

Una buena estructura de OU facilitará enormemente la administración del dominio.

Al diseñar una jerarquía conviene seguir algunas recomendaciones.

- Organizar las OU siguiendo la estructura administrativa de la organización.
- Utilizar nombres claros y consistentes.
- Evitar niveles de profundidad innecesarios.
- Diseñar pensando en el crecimiento futuro de la empresa.
- Mantener una estructura sencilla y fácil de comprender.
- Documentar la jerarquía utilizada.

No existe un único diseño correcto.

Cada organización adaptará su estructura a sus necesidades.

Sin embargo, un diseño claro simplificará enormemente la administración diaria.

---

# ⚠️ Errores habituales

## Error 1

Pensar que una OU sirve para conceder permisos.

**Realidad**

Las OU organizan objetos.

Los permisos normalmente se conceden mediante grupos.

---

## Error 2

Confundir una OU con un Grupo.

**Realidad**

Un Grupo reúne objetos para facilitar la asignación de permisos.

Una OU organiza objetos dentro del dominio.

---

## Error 3

Crear demasiados niveles de OU.

**Realidad**

Una estructura excesivamente profunda dificulta la administración.

Lo recomendable es mantener una jerarquía sencilla y lógica.

---

## Error 4

Organizar las OU siguiendo únicamente criterios técnicos.

**Realidad**

En la mayoría de organizaciones resulta más práctico organizarlas según departamentos, sedes o funciones administrativas.

---

## Error 5

Pensar que una OU almacena archivos.

**Realidad**

Las OU contienen objetos de Active Directory, no archivos del sistema.

---

# 📌 Puntos clave

- Las OU permiten organizar los objetos de Active Directory.
- Una OU es un contenedor lógico.
- Las OU pueden contener otras OU, usuarios, grupos, equipos y otros objetos.
- Una OU no sustituye a un Grupo ni a un Dominio.
- La estructura jerárquica facilita la administración de grandes organizaciones.
- Una buena planificación de las OU simplifica la administración futura.

---

# 📝 Resumen

En este capítulo hemos aprendido que las Unidades Organizativas constituyen la principal herramienta para organizar un dominio de Active Directory.

Las OU actúan como contenedores lógicos capaces de almacenar usuarios, grupos, equipos y otros objetos, permitiendo estructurar el dominio de forma jerárquica.

También hemos visto que una OU no concede permisos ni sustituye a los grupos, sino que facilita la administración y prepara el dominio para la aplicación de Directivas de Grupo y la delegación de tareas administrativas.

Una correcta planificación de las OU permitirá mantener una infraestructura ordenada, escalable y sencilla de administrar.
