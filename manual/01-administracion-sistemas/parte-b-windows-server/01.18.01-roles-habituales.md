# 🧠 ¿Por qué es importante conocerlos?

Un rol define la función del servidor en la red.

Si eliges bien los roles:

- el servidor será más seguro;
- consumirá menos recursos;
- será más fácil de mantener;
- responderá mejor a las necesidades del servicio.

Instalar roles sin criterio aumenta complejidad y superficie de ataque.

# Resumen rápido de roles habituales

| Rol | Para qué sirve |
|-----|----------------|
| AD DS | Gestionar dominio, usuarios y equipos |
| DNS Server | Resolver nombres a direcciones IP |
| DHCP Server | Asignar IP automáticamente |
| Web Server (IIS) | Publicar webs y aplicaciones |
| File and Storage Services | Compartir y administrar archivos |
| Hyper-V | Crear y ejecutar máquinas virtuales |
| Print and Document Services | Centralizar impresoras y colas |

---

# 1) Active Directory Domain Services (AD DS)

AD DS convierte el servidor en **Controlador de Dominio**.

Permite administración centralizada de:

- usuarios;
- grupos;
- equipos;
- autenticación y autorización.

## ¿Cuándo se usa?

Cuando hay varios equipos y se necesita un inicio de sesión unificado y políticas comunes.

## Ejemplo real

Un investigador inicia sesión con su cuenta corporativa y puede acceder a recursos de diferentes equipos sin crear una cuenta local en cada uno.

## Comandos relacionados

- `Get-WindowsFeature AD-Domain-Services`
- `Install-WindowsFeature AD-Domain-Services`

---

# 2) DNS Server

DNS traduce nombres (por ejemplo, `intranet.imida.local`) a direcciones IP.

Sin DNS, los usuarios tendrían que recordar direcciones numéricas.

## ¿Cuándo se usa?

Prácticamente siempre que existe un dominio o servicios internos.

## Ejemplo real

En lugar de escribir `10.10.20.15`, los usuarios acceden a `ficheros.imida.local`.

## Comandos relacionados

- `Get-WindowsFeature DNS`
- `Install-WindowsFeature DNS`

---

# 3) DHCP Server

DHCP asigna direcciones IP automáticamente a los equipos de la red.

También puede entregar:

- máscara de subred;
- puerta de enlace;
- servidores DNS.

## ¿Cuándo se usa?

Cuando no quieres configurar manualmente la red de cada equipo.

## Ejemplo real

Un portátil nuevo se conecta a la red del centro y recibe IP válida en segundos.

## Comandos relacionados

- `Get-WindowsFeature DHCP`
- `Install-WindowsFeature DHCP`

---

# 4) Web Server (IIS)

IIS permite publicar:

- páginas web;
- aplicaciones internas;
- APIs;
- portales corporativos.

## ¿Cuándo se usa?

Cuando necesitas exponer servicios web en intranet o internet.

## Ejemplo real

Publicar una web interna para consultar protocolos de laboratorio.

## Comandos relacionados

- `Get-WindowsFeature Web-Server`
- `Install-WindowsFeature Web-Server`

---

# 5) File and Storage Services

Este rol permite compartir carpetas y administrar almacenamiento.

Incluye capacidades como:

- recursos compartidos SMB;
- cuotas;
- administración de volúmenes.

## ¿Cuándo se usa?

Cuando varios usuarios deben acceder a documentación común de forma controlada.

## Ejemplo real

Compartir la carpeta `D:\Investigacion` con permisos distintos para cada grupo.

## Comandos relacionados

- `Get-WindowsFeature FS-FileServer`
- `Install-WindowsFeature FS-FileServer`

---

# 6) Hyper-V

Hyper-V habilita virtualización en Windows Server.

Permite crear y administrar máquinas virtuales en el mismo hardware físico.

## ¿Cuándo se usa?

Cuando quieres consolidar servicios, aislar entornos o montar laboratorios.

## Ejemplo real

Tener un servidor físico con varias máquinas virtuales: una para pruebas, otra para servicios web y otra para base de datos.

## Comandos relacionados

- `Get-WindowsFeature Hyper-V`
- `Install-WindowsFeature Hyper-V -IncludeManagementTools`

---

# 7) Print and Document Services

Centraliza la gestión de impresoras y colas de impresión.

Facilita:

- publicar impresoras para toda la organización;
- controlar colas;
- aplicar permisos de impresión.

## ¿Cuándo se usa?

Cuando hay varias impresoras compartidas entre departamentos.

## Ejemplo real

Todos los equipos del área administrativa imprimen en una impresora de red gestionada desde el servidor.

## Comandos relacionados

- `Get-WindowsFeature Print-Services`
- `Install-WindowsFeature Print-Services`

---

# Cómo elegir qué rol instalar

Antes de instalar, responde estas preguntas:

1. ¿Qué servicio necesita realmente la organización?
2. ¿Cuántos usuarios/equipos lo van a usar?
3. ¿Qué impacto tendría si ese servicio falla?
4. ¿Qué requisitos de seguridad y copia de seguridad existen?
5. ¿Puede ese rol convivir con otros en el mismo servidor?

Regla práctica:

✔ Instalar solo lo necesario.

✔ Documentar cada cambio.

✔ Revisar eventos y estado tras cada instalación.

# 🐧 Linux vs 🪟 Windows

| Necesidad | GNU/Linux (ejemplo) | Windows Server |
|-----------|----------------------|----------------|
| Dominio | Samba/LDAP | AD DS |
| Resolución de nombres | Bind9 | DNS Server |
| Asignación IP | isc-dhcp-server | DHCP Server |
| Web | Apache/Nginx | IIS |
| Compartición de archivos | Samba/NFS | File Services |
| Virtualización | KVM | Hyper-V |
| Impresión | CUPS | Print Services |

🎯 El objetivo funcional es el mismo en ambos sistemas; cambia la herramienta.

---

# ⚠️ Errores frecuentes

❌ Instalar todos los roles en el mismo servidor "por comodidad".

✔ Separar funciones críticas cuando sea posible.

---

❌ Confundir la instalación del rol con su configuración completa.

✔ Instalar es solo el inicio; después hay que configurarlo y mantenerlo.

---

❌ No validar requisitos previos (red, DNS, almacenamiento, copias).

✔ Revisar dependencias antes de desplegar.

# 📝 Resumen

Los roles habituales de Windows Server permiten cubrir necesidades clave de una organización: identidad (AD DS), nombres (DNS), red (DHCP), web (IIS), archivos (File Services), virtualización (Hyper-V) e impresión (Print Services).

Comprender su función te ayuda a diseñar servidores más seguros, eficientes y fáciles de administrar.

La idea principal no es instalar todo, sino instalar solo lo que aporta valor al servicio.
