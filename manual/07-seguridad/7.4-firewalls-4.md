# 🔥 BLOQUE 07 · SEGURIDAD
# 7.4 · FIREWALLS
## Parte 4 · Casos integrales, análisis de políticas, errores y cierre del capítulo

> **Objetivo:** cerrar 7.4 transformando toda la teoría anterior en capacidad de análisis. Esta parte está orientada a examen: leer una arquitectura, detectar una mala regla, proponer una política, identificar el control adecuado y razonar qué ocurre cuando algo falla.
>
> NIST recomienda que las soluciones de firewall se seleccionen, configuren, prueben, desplieguen y gestionen dentro de una política de seguridad, y que antes de producción se verifiquen conectividad, reglas, compatibilidad, gestión, logging, rendimiento y otros aspectos. citeturn0search0turn0search24

# 🧭 1. EL MÉTODO PARA RESOLVER UN CASO DE FIREWALL

Cuando aparezca un escenario en el examen, no empieces pensando:

> "¿Qué tecnología me suena?"

Empieza por:

```text
1. ¿QUÉ QUIERO PROTEGER?
          ↓
2. ¿DE QUIÉN?
          ↓
3. ¿QUÉ COMUNICACIONES SON NECESARIAS?
          ↓
4. ¿QUÉ COMUNICACIONES NO SON NECESARIAS?
          ↓
5. ¿DÓNDE COLOCO EL CONTROL?
          ↓
6. ¿QUÉ REGLA LO EXPRESA?
          ↓
7. ¿CÓMO LO REGISTRO?
          ↓
8. ¿CÓMO LO PRUEBO?
```

Esta forma de razonar es mucho más útil que memorizar cientos de reglas aisladas.

# 🧠 5. ¿POR QUÉ NO EXPONER LA DB?

Porque:

```text
DB
↓
activo crítico
```

y:

```text
Internet
↓
DB
```

aumenta enormemente la superficie de ataque.

La arquitectura correcta es:

```text
Internet
 ↓
Web
 ↓
App
 ↓
DB
```

no:

```text
Internet
 ├── Web
 ├── App
 └── DB
```

# 🧩 14. CASO 8 · REGLAS SOMBREADAS

Tenemos:

```text
1. ALLOW 10.0.0.0/8 → SERVER TCP/443
2. DENY 10.10.10.50 → SERVER TCP/443
```

Queremos:

```text
10.10.10.50
→ DENY
```

Pero si el firewall procesa de arriba abajo:

```text
10.10.10.50
     ↓
REGLA 1
     ↓
ALLOW
```

la regla 2 puede no aplicarse.

### Solución

Colocar primero la excepción:

```text
1. DENY 10.10.10.50 → SERVER TCP/443
2. ALLOW 10.0.0.0/8 → SERVER TCP/443
```

# 🚨 15. CASO 9 · REGLA ANY/ANY

Encontramos:

```text
ALLOW
ANY
ANY
ANY
```

Pregunta:

> ¿Es necesariamente incorrecta?

No podemos decirlo sin conocer el contexto.

Pero:

```text
ANY/ANY/ANY
```

es una regla extremadamente amplia y debe estar fuertemente justificada.

En una política restrictiva normalmente se busca:

```text
DENY BY DEFAULT
+
ALLOW ESPECÍFICO
```

# 🧩 16. CASO 10 · TRÁFICO SALIENTE

Un servidor web puede salir a Internet.

¿Debemos permitir:

```text
SERVER
 ↓
ANY
 ↓
INTERNET
```

sin restricciones?

No necesariamente.

Podemos establecer:

```text
SERVER
 ↓
DNS
HTTPS
NTP
 ↓
DESTINOS NECESARIOS
```

y bloquear el resto.

El filtrado saliente puede ayudar a limitar comunicaciones no autorizadas y determinados movimientos posteriores a una intrusión.

# 🧠 17. EGRESS FILTERING

La idea:

```text

       ↓
¿ESTÁ AUTORIZADO?
       ↓
   SÍ       NO
   ↓        ↓
ALLOW     DENY
```

No solo protegemos:

```text
ENTRAR
```

También:

```text
SALIR
```

# 🧩 18. CASO 11 · IP SPOOFING

```text

```

Pero:

```text

```

Esto debería levantar sospechas.

Una interfaz externa no debería aceptar sin más tráfico que afirma proceder de una red que no puede ser válida en ese contexto.

# 🔄 21. ¿QUÉ DEBE PROBARSE EN HA?

No basta con:

```text
"los dos están encendidos."
```

Hay que comprobar:

```text
✓ caída del activo
✓ cambio al respaldo
✓ mantenimiento
✓ recuperación
✓ sincronización
✓ conservación del estado
✓ conectividad
✓ reglas
```

NIST recomienda probar también la sincronización de políticas cuando existen múltiples firewalls con reglas sincronizadas. citeturn0search24

## 1
**P:** ¿Qué hace un firewall?

**R:** Controla el flujo de tráfico según una política de seguridad.

**P:** ¿Qué es un WAF?

**P:** ¿Qué hace NAT?

**P:** ¿Qué hace PAT?

**R:** Traduce direcciones y puertos para multiplexar conexiones.

**P:** ¿Qué hace IDS?

**R:** Falsificación de información de origen o identidad.

## 16
**P:** ¿Qué es HA?

**R:** Alta disponibilidad mediante componentes redundantes.

## 17
**P:** ¿Qué es failover?

**R:** Cambio a un componente de respaldo ante fallo.

## 18
**P:** ¿Qué es egress filtering?

**R:** Control del tráfico que sale de una red.

## 19
**P:** ¿Qué es SIEM?

**R:** Sistema que centraliza y correlaciona eventos y logs de seguridad.

## 20
**P:** ¿Qué principio debe guiar las reglas?

**R:** Mínimo privilegio: permitir solo lo necesario.
