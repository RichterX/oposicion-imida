# 🧭 1. UNA REGLA PARA ESTUDIAR ATAQUES

Cuando aparezca un ataque, intenta responder siempre estas cinco preguntas:

```text
1. ¿CÓMO ENTRA?
2. ¿QUÉ QUIERE CONSEGUIR?
3. ¿QUÉ RECURSO ATACA?
4. ¿QUÉ PRINCIPIO CIA AFECTA?
5. ¿CÓMO PUEDO DEFENDERME?
```

Ejemplo:

```text
RANSOMWARE

¿CÓMO ENTRA?
→ phishing / vulnerabilidad / credenciales

¿QUÉ QUIERE?
→ extorsión

¿QUÉ ATACA?
→ sistemas y datos

¿CIA?
→ disponibilidad principalmente
  + posible confidencialidad/integridad

¿DEFENSA?
→ backups + EDR + MFA + segmentación + parcheado
```

---

# 🌐 2. ATAQUES CONTRA APLICACIONES WEB

Las aplicaciones web presentan una superficie de ataque especialmente amplia porque exponen funcionalidades a través de Internet.

Ejemplo:

```text
INTERNET
   ↓
WEB
   ↓
API
   ↓
APLICACIÓN
   ↓
BASE DE DATOS
```

Un fallo en cualquiera de estas capas puede tener consecuencias importantes.

---

# 💉 3. INYECCIÓN

Una inyección ocurre cuando datos controlados por el atacante son interpretados como parte de una instrucción o consulta.

Conceptualmente:

```text
ENTRADA DEL USUARIO
        ↓
APLICACIÓN
        ↓
INTERPRETACIÓN COMO CÓDIGO
        ↓
COMPORTAMIENTO NO DESEADO
```

Tipos conocidos:

```text
SQL Injection
Command Injection
LDAP Injection
NoSQL Injection
```

---

# 🗄️ 4. SQL INJECTION

Una aplicación construye consultas SQL de forma insegura utilizando directamente entrada del usuario.

Conceptualmente:

```text
USUARIO
 ↓
ENTRADA MALICIOSA
 ↓
APLICACIÓN
 ↓
SQL
 ↓
BASE DE DATOS
```

Consecuencias posibles:

```text
LECTURA DE DATOS
MODIFICACIÓN
BORRADO
AUTENTICACIÓN INCORRECTA
```

Puede afectar especialmente:

```text
CONFIDENCIALIDAD
+
INTEGRIDAD
+
DISPONIBILIDAD
```

---

# 🛡️ 5. PREVENCIÓN DE SQL INJECTION

Medidas importantes:

```text
CONSULTAS PARAMETRIZADAS
+
PREPARED STATEMENTS
+
VALIDACIÓN DE ENTRADAS
+
MÍNIMO PRIVILEGIO EN DB
+
GESTIÓN SEGURA DE ERRORES
```

La defensa principal debe estar en la aplicación.

Un firewall de red por sí solo:

```text
NO
```

soluciona una vulnerabilidad de SQL.

---

# 🧪 6. COMMAND INJECTION

La aplicación utiliza datos externos para construir comandos del sistema.

Conceptualmente:

```text
INPUT
 ↓
APLICACIÓN
 ↓
SHELL / COMANDO
 ↓
SISTEMA OPERATIVO
```

Si el atacante consigue introducir instrucciones adicionales:

```text
APLICACIÓN
 ↓
EJECUCIÓN NO AUTORIZADA
```

---

# 🖥️ 7. PREVENCIÓN DE COMMAND INJECTION

Preferencias:

```text
NO CONSTRUIR COMANDOS CON INPUT
```

y:

```text
APIS SEGURAS
+
VALIDACIÓN
+
LISTAS PERMITIDAS
+
MÍNIMO PRIVILEGIO
```

---

# 🌐 8. XSS

**Cross-Site Scripting (XSS)** ocurre cuando contenido controlado por un atacante termina siendo ejecutado como código en el navegador de una víctima.

Conceptualmente:

```text
ATACANTE
 ↓
CONTENIDO MALICIOSO
 ↓
WEB
 ↓
NAVEGADOR DE LA VÍCTIMA
 ↓
EJECUCIÓN
```

---

# 🧩 9. TIPOS DE XSS

### Stored XSS

El contenido malicioso queda almacenado:

```text
ATACANTE
 ↓
BASE DE DATOS
 ↓
WEB
 ↓
VÍCTIMA
```

### Reflected XSS

El contenido se refleja en una respuesta:

```text
PETICIÓN
 ↓
SERVIDOR
 ↓
RESPUESTA
 ↓
VÍCTIMA
```

### DOM-based XSS

El problema puede producirse en el procesamiento del DOM por JavaScript en el cliente.

---

# 🛡️ 10. DEFENSA CONTRA XSS

Controles:

```text
OUTPUT ENCODING
+
VALIDACIÓN
+
SANITIZACIÓN CUANDO CORRESPONDA
+
CONTENT SECURITY POLICY
+
COOKIES CON ATRIBUTOS ADECUADOS
```

Idea:

> **No confíes en que lo que llega al navegador es seguro.**

---

# 🔐 11. CSRF

**Cross-Site Request Forgery** intenta conseguir que un usuario autenticado realice una acción que no pretendía realizar.

Ejemplo conceptual:

```text
USUARIO
 ↓
AUTENTICADO EN WEB A
 ↓
VISITA WEB MALICIOSA B
 ↓
SE ENVÍA PETICIÓN A A
 ↓
ACCIÓN NO DESEADA
```

---

# 🛡️ 12. DEFENSA CONTRA CSRF

Medidas habituales:

```text
TOKENS CSRF
+
SAME-SITE COOKIES
+
VALIDACIÓN DEL ORIGEN/REFERER CUANDO PROCEDA
```

---

# 🧠 13. XSS VS CSRF

Memorización:

```text
XSS
→ EJECUTAR CONTENIDO/CÓDIGO EN EL CONTEXTO DEL NAVEGADOR

CSRF
→ HACER QUE UNA VÍCTIMA AUTENTICADA REALICE UNA PETICIÓN NO DESEADA
```

---

# 🔑 14. ATAQUES CONTRA CONTRASEÑAS

Las contraseñas pueden atacarse mediante:

```text
BRUTE FORCE
PASSWORD SPRAYING
CREDENTIAL STUFFING
DICCIONARIO
PHISHING
MALWARE
```

---

# 💥 15. BRUTE FORCE

Prueba muchas combinaciones contra una cuenta o servicio.

```text
PASSWORD 1
PASSWORD 2
PASSWORD 3
...
PASSWORD N
```

Puede ser muy costoso si la contraseña es fuerte, pero peligroso cuando existen:

```text
CONTRASEÑAS DÉBILES
SIN LIMITACIÓN
SIN MFA
```

---

# 🌧️ 16. PASSWORD SPRAYING

En lugar de probar muchas contraseñas contra una cuenta:

```text
MUCHAS CONTRASEÑAS
→ UNA CUENTA
```

se utiliza:

```text
UNA / POCAS CONTRASEÑAS COMUNES
→ MUCHAS CUENTAS
```

Ejemplo conceptual:

```text
Password2026!
   ↓
usuario1
usuario2
usuario3
usuario4
```

Objetivo:

> evitar determinadas defensas basadas en múltiples intentos sobre una misma cuenta.

---

# 🔄 17. CREDENTIAL STUFFING

Utiliza credenciales obtenidas de otras filtraciones.

```text
FILTRACIÓN WEB A
      ↓
usuario + contraseña
      ↓
PROBAR EN WEB B
```

Funciona especialmente cuando los usuarios:

```text
REUTILIZAN CONTRASEÑAS
```

---

# 🧠 18. BRUTE FORCE VS SPRAYING VS STUFFING

```text
BRUTE FORCE
→ muchas contraseñas
→ una cuenta

PASSWORD SPRAYING
→ pocas contraseñas
→ muchas cuentas

CREDENTIAL STUFFING
→ credenciales robadas
→ otros servicios
```

Esta comparación es carne de examen. 🥩

---

# 🎣 19. PHISHING

MITRE define phishing como mensajes enviados para intentar conseguir acceso a sistemas de las víctimas. Puede ser masivo o dirigido, como spearphishing. citeturn0search10

Variantes Enterprise:

```text
SPEARPHISHING ATTACHMENT
SPEARPHISHING LINK
SPEARPHISHING VIA SERVICE
SPEARPHISHING VOICE
```

citeturn0search10

---

# 🎯 20. SPEARPHISHING

Phishing dirigido:

```text
VÍCTIMA CONCRETA
```

Ejemplo:

```text
INVESTIGADOR
 ↓
correo aparentemente de dirección
 ↓
documento
 ↓
credenciales / malware
```

---

# 📱 21. SMISHING

Phishing mediante:

```text
SMS
```

Puede dirigir a:

```text
WEB FALSA
```

o pedir:

```text
INSTALACIÓN
CREDENCIALES
ACCIÓN URGENTE
```

MITRE recoge el smishing como una forma de phishing, especialmente relevante también en dispositivos móviles. citeturn0search6

---

# 📞 22. VISHING

Phishing mediante:

```text
LLAMADA DE VOZ
```

Ejemplo:

```text
"Soy soporte técnico"
       ↓
"Necesito verificar su cuenta"
       ↓
CREDENCIALES
```

---

# 📱 23. QUISHING

Una variante basada en:

```text
QR
```

El usuario escanea:

```text
QR MALICIOSO
 ↓
WEB FALSA
 ↓
CREDENCIALES
```

MITRE recoge específicamente el uso malicioso de QR codes en campañas de phishing móvil. citeturn0search6

---

# 🧠 24. DEEPFAKE Y VISHING

Los ataques de ingeniería social pueden utilizar:

```text
VOZ CLONADA
+
IMAGEN FALSA
+
IDENTIDAD SUPLANTADA
```

El objetivo es aumentar:

```text
CONFIANZA
```

y reducir:

```text
SOSPECHA
```

# 🦠 25. MALWARE

Recordatorio:

```text
MALWARE
├── VIRUS
├── GUSANO
├── TROYANO
├── RANSOMWARE
├── SPYWARE
├── ROOTKIT
├── RAT
└── INFOSTEALER
```

No todas estas categorías tienen exactamente el mismo comportamiento.

# 🐀 26. RAT

**Remote Access Trojan**.

Busca proporcionar al atacante:

```text
ACCESO REMOTO
```

Puede permitir:

```text
EJECUTAR COMANDOS
ROBAR DATOS
CAPTURAR INFORMACIÓN
MANTENER ACCESO
```

---

# 🕵️ 27. INFOSTEALER

Malware orientado a robar información.

Puede buscar:

```text
CREDENCIALES
COOKIES
DATOS DEL NAVEGADOR
TOKENS
INFORMACIÓN PERSONAL
```

MITRE documenta técnicas específicas para obtener credenciales almacenadas en navegadores, gestores de contraseñas y otros almacenes. citeturn0search0

---

# 💰 28. RANSOMWARE

Cadena típica:

```text
ACCESO
 ↓
EJECUCIÓN
 ↓
PERSISTENCIA
 ↓
DESCUBRIMIENTO
 ↓
MOVIMIENTO LATERAL
 ↓
DATOS
 ↓
CIFRADO / BLOQUEO
 ↓
EXTORSIÓN
```

---

# 🔥 29. DOBLE EXTORSIÓN

Un atacante puede:

```text
1. ROBAR DATOS
2. CIFRAR SISTEMAS
3. AMENAZAR CON PUBLICAR DATOS
```

Así combina:

```text
DISPONIBILIDAD
+
CONFIDENCIALIDAD
```

---

# 🧨 30. WIPERS

Un wiper busca:

```text
DESTRUIR
```

datos o sistemas.

A diferencia del ransomware:

```text
RANSOMWARE
→ busca obtener beneficio mediante extorsión

WIPER
→ busca destrucción / sabotaje
```

Aunque en un incidente real las motivaciones pueden solaparse.

---

# 🌊 31. DoS

Denial of Service:

```text
OBJETIVO
 ↓
SATURACIÓN
 ↓
SERVICIO NO DISPONIBLE
```

Principal impacto:

```text
DISPONIBILIDAD
```

---

# 🌊 32. DDoS

Distributed Denial of Service:

```text
MÚLTIPLES ORÍGENES
       ↓
       ↓
       ↓
   SERVICIO
       ↓
   SATURACIÓN
```

Una botnet puede utilizarse para generar tráfico distribuido.

MITRE incluye distintas técnicas de impacto relacionadas con Network Denial of Service, Direct Network Flood y Reflection Amplification. citeturn0search1

---

# 📡 33. REFLECTION / AMPLIFICATION

Conceptualmente:

```text
ATACANTE
 ↓
SERVIDORES INTERMEDIOS
 ↓↓↓↓↓
VÍCTIMA
```

La respuesta puede ser mayor que la solicitud inicial en determinados protocolos y configuraciones.

Resultado:

```text
AMPLIFICACIÓN
```

---

# 🧬 34. SUPPLY CHAIN ATTACK

Un atacante puede comprometer:

```text
PROVEEDOR
SOFTWARE
DEPENDENCIA
ACTUALIZACIÓN
```

para llegar posteriormente a:

```text
ORGANIZACIÓN OBJETIVO
```

MITRE considera la compromisión de la cadena de suministro una técnica de acceso inicial. citeturn0search1

---

# 📦 35. DEPENDENCIAS DE SOFTWARE

Una aplicación puede depender de:

```text
LIBRERÍA A
LIBRERÍA B
LIBRERÍA C
```

Si una dependencia es comprometida:

```text
APLICACIÓN
 ↓
DEPENDENCIA
 ↓
CÓDIGO MALICIOSO
```

El riesgo se extiende a todos los consumidores.

---

# ☁️ 36. AMENAZAS CLOUD

El cloud no elimina los problemas de seguridad.

Ejemplos:

```text
CUENTAS COMPROMETIDAS
MALA CONFIGURACIÓN
PERMISOS EXCESIVOS
TOKENS ROBADOS
SECRETOS EXPUESTOS
STORAGE PÚBLICO
```

MITRE contempla cuentas cloud comprometidas y su posible uso para acceso inicial, persistencia, escalada o evasión. citeturn0search9

---

# 🔑 37. CUENTAS CLOUD

Una cuenta cloud comprometida puede permitir:

```text
ACCESO
 ↓
DATOS
 ↓
RECURSOS
 ↓
OTRAS CUENTAS
 ↓
MOVIMIENTO
```

Además, una cuenta privilegiada puede tener efectos mucho mayores.

---

# 🪪 38. TOKENS Y CREDENCIALES CLOUD

No debemos pensar únicamente en:

```text
USUARIO + CONTRASEÑA
```

También existen:

```text
TOKENS
CLAVES API
CERTIFICADOS
CREDENCIALES DE SERVICIO
IDENTIDADES DE MÁQUINA
```

Un token comprometido puede permitir actuar como una identidad legítima.

---

# 📱 39. DISPOSITIVOS MÓVILES

Amenazas habituales:

```text
PHISHING
APLICACIONES MALICIOSAS
ROBO DEL DISPOSITIVO
CREDENCIALES
PERMISOS EXCESIVOS
CONFIGURACIONES INSEGURAS
```

MITRE dispone de una matriz Mobile específica con tácticas como Initial Access, Execution, Persistence, Credential Access, Discovery, Lateral Movement, C2, Exfiltration e Impact. citeturn0search5

# 🏢 40. INSIDER THREAT

Una amenaza interna puede proceder de:

```text
EMPLEADO
CONTRATISTA
PROVEEDOR
ADMINISTRADOR
```

Puede ser:

```text
MALICIOSA
```

o:

```text
ACCIDENTAL
```

Ejemplo:

```text
EMPLEADO
 ↓
ENVÍA DOCUMENTO CONFIDENCIAL
 ↓
DESTINATARIO INCORRECTO
```

No hace falta que exista intención maliciosa para producir un incidente.

---

# 🧠 41. AMENAZA INTERNA VS CUENTA COMPROMETIDA

No son exactamente lo mismo.

```text
INSIDER
→ persona con acceso legítimo que puede actuar
  de forma maliciosa o accidental

CUENTA COMPROMETIDA
→ identidad legítima utilizada por un atacante
```

Ambas pueden ser difíciles de distinguir únicamente por:

```text
usuario + contraseña
```

---

# 🧱 42. ATAQUES DE DENEGACIÓN DE SERVICIO CONTRA APLICACIONES

No todo DDoS consiste en enviar enormes cantidades de paquetes.

Puede atacarse:

```text
APLICACIÓN
```

con operaciones costosas.

Ejemplo conceptual:

```text
MUCHAS PETICIONES
        ↓
OPERACIÓN MUY COSTOSA
        ↓
CPU / DB
        ↓
SATURACIÓN
```

# 🕸️ 43. WEB SHELL

Conceptualmente:

```text
WEB VULNERABLE
      ↓
CÓDIGO MALICIOSO
      ↓
WEB SHELL
      ↓
COMANDOS
```

```text
PERSISTENCIA
EJECUCIÓN
```

# 🧨 44. DEFACEMENT

Consiste en modificar el contenido visible de un sitio web.

Ejemplo:

```text
WEB LEGÍTIMA
     ↓
ATACANTE
     ↓
PÁGINA ALTERADA
```

```text
INTEGRIDAD
```

```text
DISPONIBILIDAD

```

# 🔐 45. ATAQUES DE MAN-IN-THE-MIDDLE

Un atacante intenta situarse entre dos partes:

```text
A
↕
ATACANTE
↕
B
```

Objetivos posibles:

```text
ESCUCHAR

```

Los mecanismos criptográficos y la validación adecuada de certificados ayudan a prevenir determinados escenarios.

---

# 🔁 46. REPLAY ATTACK

El atacante captura una comunicación válida:

```text
MENSAJE VÁLIDO
     ↓
CAPTURA
     ↓
REUTILIZACIÓN
```

Si el protocolo no evita la reutilización:

```text
PETICIÓN
→ puede parecer legítima
```

MITRE menciona replay attacks como un ejemplo de ataque contra mecanismos de autenticación cuando estos no validan correctamente las solicitudes. citeturn0search3

---

# 🧩 47. ATAQUES DE SESIÓN

Una sesión autenticada puede estar representada mediante:

```text
COOKIE

SESSION ID
```

Si un atacante consigue ese material:

```text
ATACANTE
 ↓
TOKEN
 ↓
APLICACIÓN
 ↓
SESION VÁLIDA
```

puede intentar actuar como el usuario.

---

# 🛡️ 48. DEFENSAS CONTRA ATAQUES DE SESIÓN

Medidas:

```text
HTTPS
+
COOKIES SECURE
+
HTTPONLY
+
SAMESITE
+
ROTACIÓN
+

+
REVOCACIÓN
```


---

# 🧠 49. ATAQUE VS VULNERABILIDAD

Ejemplo:

```text
XSS
```

es:

```text
TÉCNICA / ATAQUE
```

mientras que:

```text
aplicación que inserta
entrada del usuario sin escapar
```

representa:

```text
VULNERABILIDAD
```

No debemos mezclarlos.

# 🛡️ 50. MATRIZ ATAQUE → DEFENSA

| Ataque | Controles principales |
|---|---|
| SQL Injection | consultas parametrizadas, validación, mínimo privilegio |
| Command Injection | evitar shell, validación, APIs seguras |
| XSS | output encoding, CSP, sanitización |
| CSRF | tokens, SameSite |
| Brute Force | MFA, rate limiting, bloqueo |
| Password Spraying | MFA, detección, políticas de identidad |
| Credential Stuffing | MFA, contraseñas únicas, detección |
| Phishing | filtros, formación, MFA |
| Ransomware | EDR, backups, segmentación, parcheado |
| DDoS | protección DDoS, rate limiting, capacidad |
| Supply Chain | SBOM, control de dependencias, firma/verificación |
| Cloud compromise | MFA, IAM, least privilege, logging |
| Insider | mínimo privilegio, DLP, auditoría |
| Session theft | HTTPS, cookies seguras, expiración/revocación |

# 🚨 53. LAS 20 TRAMPAS DE EXAMEN

### 1.
```text
SQL Injection = malware
```
❌ No.

Es una técnica de ataque contra aplicaciones/consultas.

### 2.
```text
XSS = CSRF
```
❌ No.

Son ataques diferentes.

### 3.
```text
Brute Force = Credential Stuffing
```
❌ No.

Uno prueba combinaciones; el otro reutiliza credenciales obtenidas.

### 4.
```text
Password Spraying = muchas contraseñas sobre una cuenta
```
❌ No.

Busca pocas contraseñas contra muchas cuentas.

### 5.
```text
Phishing solo ocurre por email
```
❌ No.

Puede utilizar distintos medios electrónicos.

### 6.
```text
Ransomware siempre solo cifra
```
❌ No.

Puede incluir robo de datos y extorsión.

### 7.
```text
DDoS = siempre tráfico enorme de paquetes
```
❌ No.

También puede buscar agotar recursos de aplicaciones.

### 8.
```text
Cloud = automáticamente seguro
```
❌ No.

La configuración y las identidades siguen siendo críticas.

### 9.
```text
Cuenta válida = usuario legítimo
```
❌ No necesariamente.

Puede tratarse de una cuenta comprometida.

### 10.
```text
Insider = siempre atacante malicioso
```
❌ No.

Puede existir error o negligencia.

### 11.
```text

```
❌ No.

### 12.

### 13.

```text
MFA elimina todo riesgo de phishing
```

# 🎴 56. ANKI ESENCIAL

## Tarjeta 1

**P:** ¿Qué es SQL Injection?

**R:** Ataque que aprovecha la construcción insegura de consultas SQL mediante entradas controladas por el atacante.

## Tarjeta 2

**P:** ¿Qué es XSS?

**R:** Ataque que consigue ejecutar contenido/código controlado por el atacante en el contexto del navegador de una víctima.

## Tarjeta 3

**P:** ¿Qué es CSRF?

**R:** Ataque que induce a un usuario autenticado a realizar una acción que no pretendía.

## Tarjeta 4

**P:** ¿Qué es brute force?

**R:** Prueba sistemática de múltiples combinaciones de credenciales.

## Tarjeta 5

**P:** ¿Qué es password spraying?

**R:** Uso de pocas contraseñas contra muchas cuentas.

## Tarjeta 6

**P:** ¿Qué es credential stuffing?

**R:** Reutilización de credenciales obtenidas de otras filtraciones o compromisos.

## Tarjeta 7

**P:** ¿Qué es spearphishing?

**R:** Phishing dirigido a una persona, organización o grupo concreto.

## Tarjeta 8

**P:** ¿Qué es smishing?

**R:** Phishing mediante SMS/mensajería.

## Tarjeta 9

**P:** ¿Qué es vishing?

**R:** Phishing mediante llamadas o voz.

## Tarjeta 10

**P:** ¿Qué es quishing?

**R:** Phishing que utiliza códigos QR como mecanismo de redirección.

## Tarjeta 11

**P:** ¿Qué es un RAT?

**R:** Remote Access Trojan, malware que proporciona capacidades de acceso/control remoto.

## Tarjeta 12

**P:** ¿Qué es un infostealer?

**R:** Malware especializado en robar información, como credenciales, cookies o tokens.

## Tarjeta 13

**P:** ¿Qué es ransomware?

**R:** Malware/ataque que bloquea o cifra recursos y busca extorsionar a la víctima, pudiendo combinar robo de datos.

## Tarjeta 14

**P:** ¿Qué es un wiper?

**R:** Malware o mecanismo orientado principalmente a destruir o inutilizar datos/sistemas.

## Tarjeta 15

**P:** ¿Qué es DDoS?

**R:** Ataque distribuido de denegación de servicio.

## Tarjeta 16

**P:** ¿Qué es un supply chain attack?

**R:** Ataque que compromete un elemento de la cadena de suministro para alcanzar al objetivo.

## Tarjeta 17

**P:** ¿Qué es una amenaza interna?

**R:** Amenaza procedente de una persona con acceso legítimo, de forma maliciosa o accidental.

## Tarjeta 18

**P:** ¿Qué es defacement?

**R:** Alteración no autorizada del contenido visible de un sitio web.

## Tarjeta 19

**P:** ¿Qué es un ataque MitM?

**R:** Ataque en el que el adversario se sitúa entre dos partes para interceptar o manipular comunicaciones.

## Tarjeta 20

**P:** ¿Qué es un replay attack?

**R:** Reutilización de una comunicación previamente capturada para intentar conseguir un efecto no autorizado.
