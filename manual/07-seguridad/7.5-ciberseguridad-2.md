# 🔐 BLOQUE 07 · SEGURIDAD
# 7.5 · CIBERSEGURIDAD
## Parte 2 · Ciclo del ataque, MITRE ATT&CK, acceso, ejecución, persistencia y movimiento lateral

> **Objetivo:** entender cómo se desarrolla un ataque real desde la preparación y el reconocimiento hasta el acceso inicial, la ejecución, la persistencia, la escalada de privilegios, el descubrimiento y el movimiento lateral.
>
> Esta parte utiliza como marco de referencia **MITRE ATT&CK**, una base de conocimiento de tácticas y técnicas observadas en operaciones reales. ATT&CK distingue entre **tácticas**, que representan el objetivo del adversario, y **técnicas**, que describen cómo intenta conseguirlo. citeturn0search0turn0search4

---

# 🧭 1. DEL "ATAQUE" AL CICLO COMPLETO

En la Parte 1 vimos:

```text
AMENAZA
   ↓
VULNERABILIDAD
   ↓
EXPLOIT
   ↓
ATAQUE
```

Pero un ataque real puede ser mucho más largo.

Un adversario puede:

```text
RECOPILAR INFORMACIÓN
        ↓
PREPARAR RECURSOS
        ↓
CONSEGUIR ACCESO
        ↓
EJECUTAR CÓDIGO
        ↓
MANTENERSE
        ↓
OBTENER MÁS PRIVILEGIOS
        ↓
DESCUBRIR EL ENTORNO
        ↓
MOVERSE
        ↓
BUSCAR DATOS
        ↓
CONTROLAR SISTEMAS
        ↓
EXFILTRAR
        ↓
IMPACTAR
```

MITRE ATT&CK modela estos objetivos mediante tácticas. En Enterprise aparecen actualmente tácticas como Reconnaissance, Resource Development, Initial Access, Execution, Persistence, Privilege Escalation, Stealth, Defense Impairment, Credential Access, Discovery, Lateral Movement, Collection, Command and Control, Exfiltration e Impact. citeturn0search0turn0search1

---

# 🧠 2. TÁCTICA VS TÉCNICA

Esta distinción es fundamental.

### Táctica

Responde:

> **¿Qué quiere conseguir el atacante?**

Ejemplo:

```text
PERSISTENCIA
```

### Técnica

Responde:

> **¿Cómo intenta conseguirlo?**

Por tanto:

```text
TÁCTICA
   ↓
OBJETIVO

TÉCNICA
   ↓
MÉTODO
```

---

# 🗺️ 3. MITRE ATT&CK

MITRE ATT&CK es una base de conocimiento utilizada para describir comportamientos de adversarios y relacionarlos con tácticas y técnicas.

No es:

```text
un antivirus
```

ni:

```text
un firewall
```

ni:

```text
un producto comercial
```

Es un:

> **marco de conocimiento y modelado del comportamiento del adversario.**

citeturn0search4

# 🧩 4. LAS TÁCTICAS COMO "MAPA"

Podemos pensar:

```text
RECONOCIMIENTO
      ↓
DESARROLLO DE RECURSOS
      ↓
ACCESO INICIAL
      ↓
EJECUCIÓN
      ↓
PERSISTENCIA
      ↓
ESCALADA
      ↓
EVASIÓN / IMPEDIMENTO DE DEFENSAS
      ↓
CREDENCIALES
      ↓
DESCUBRIMIENTO
      ↓
MOVIMIENTO LATERAL
      ↓
RECOLECCIÓN
      ↓
C2
      ↓
EXFILTRACIÓN
      ↓
IMPACTO
```

⚠️ No debe interpretarse como una secuencia rígida. Un atacante puede saltar fases, repetirlas o realizar varias en paralelo.

# 🔎 5. RECONOCIMIENTO

El objetivo es:

> **obtener información que ayude a planificar operaciones futuras.**

Ejemplos de información:

```text
DOMINIOS
SUBDOMINIOS
DIRECCIONES IP
EMPLEADOS
TECNOLOGÍAS
SERVICIOS
ORGANIZACIÓN
REDES
```

MITRE incluye dentro de Reconnaissance actividades como escaneo activo y recopilación de información sobre hosts, identidades y redes de la víctima. citeturn0search0turn0search3

---

# 🌐 6. RECONOCIMIENTO PASIVO

El atacante utiliza información disponible sin interactuar directamente de forma significativa con el objetivo.

Ejemplos:

```text
WEB CORPORATIVA
REDES SOCIALES
DNS
CERTIFICADOS
DOCUMENTACIÓN PÚBLICA
REPOSITORIOS
NOTICIAS
```

Ventaja para el atacante:

```text
MENOR PROBABILIDAD DE DETECCIÓN
```

---

# 🛰️ 7. RECONOCIMIENTO ACTIVO

Aquí el atacante interactúa directamente con sistemas.

Ejemplos:

```text
ESCANEO
ENUMERACIÓN
SONDEO DE SERVICIOS
```

Esto puede dejar:

```text
LOGS
ALERTAS
TRÁFICO ANÓMALO
```

---

# 🔍 8. ESCANEO

El escaneo busca descubrir:

```text
HOSTS
PUERTOS
SERVICIOS
VERSIONES
VULNERABILIDADES
```

Ejemplo conceptual:

```text
IP
 ↓
PUERTOS
 ↓
SERVICIOS
 ↓
VERSIONES
 ↓
POSIBLES VULNERABILIDADES
```

---

# 🧩 9. ENUMERACIÓN

La enumeración profundiza en la información obtenida.

Por ejemplo:

```text
¿QUÉ PUERTOS ESTÁN ABIERTOS?
```

Escaneo.

Después:

```text
¿QUÉ SERVICIO?
¿QUÉ VERSIÓN?
¿QUÉ USUARIOS?
¿QUÉ RECURSOS?
```

Enumeración.

---

# 🧠 10. RECONOCIMIENTO VS ENUMERACIÓN

Para examen:

```text
RECONOCIMIENTO
→ recopilar información del objetivo

ESCANEO
→ identificar exposición

ENUMERACIÓN
→ obtener información más detallada de servicios/recursos
```

No son términos perfectamente equivalentes, aunque en documentación práctica pueden solaparse.

# 🧰 11. DESARROLLO DE RECURSOS

Antes de atacar, un adversario puede preparar recursos:

```text
DOMINIOS
CUENTAS
INFRAESTRUCTURA
MALWARE
HERRAMIENTAS
CERTIFICADOS
```

MITRE incluye esta actividad como **Resource Development**, destinada a establecer recursos que puedan apoyar operaciones posteriores. citeturn0search7

# 🎯 12. ACCESO INICIAL

Objetivo:

> **entrar en el entorno objetivo.**

Algunas vías habituales:

```text
PHISHING
EXPLOTACIÓN DE APLICACIONES PÚBLICAS
CUENTAS VÁLIDAS
SERVICIOS REMOTOS
SUPPLY CHAIN
MEDIOS EXTRAÍBLES
```

MITRE recoge estas categorías dentro de Initial Access. citeturn0search0turn0search11

---

# 🎣 13. PHISHING COMO ACCESO INICIAL

Ejemplo:

```text

   ↓
```

```text
CREDENCIALES
```

```text

```

# 🔑 15. CUENTAS VÁLIDAS

No siempre hace falta explotar una vulnerabilidad.

Si el atacante obtiene:

```text
USUARIO
+
CONTRASEÑA
```

puede intentar utilizarlos legítimamente.

Por eso:

> **una autenticación correcta no demuestra necesariamente que el usuario sea legítimo.**

Puede tratarse de:

```text
CREDENCIALES ROBADAS
```

# 🧠 16. SERVICIOS REMOTOS

Ejemplos:

```text
VPN
RDP
SSH
SERVICIOS DE ACCESO REMOTO
```

Por eso debemos aplicar:


# ⚙️ 18. EJECUCIÓN

Una vez conseguido acceso:

> el adversario necesita ejecutar acciones o código.

Ejemplos:

```text
SCRIPTS
COMANDOS
MALWARE
MACROS
PROCESOS
```

MITRE define Execution como la táctica orientada a ejecutar código malicioso. citeturn0search0

---

# 🖥️ 19. COMMAND AND SCRIPTING

Los atacantes pueden abusar de intérpretes legítimos:

```text
POWERSHELL
CMD
BASH
PYTHON
```

La idea:

```text
HERRAMIENTA LEGÍTIMA
        ↓
USO MALICIOSO
```

Esto puede dificultar la detección frente a malware completamente desconocido.

---

# 🧠 20. LIVING OFF THE LAND

Concepto:

> utilizar herramientas ya presentes en el sistema.

Ejemplo conceptual:

```text
ATACANTE
 ↓
POWERSHELL
 ↓
ACCIÓN MALICIOSA
```

No necesariamente necesita introducir un ejecutable extraño.

Ventaja:

```text
MENOS ARTEFACTOS NUEVOS
```

---

# 🪝 21. PERSISTENCIA

Objetivo:

> **mantener el acceso al sistema después de reinicios, cambios de credenciales o determinadas medidas defensivas.**

MITRE define Persistence como la búsqueda de mantener el foothold del adversario. citeturn0search0

---

# 🔄 22. EJEMPLO DE PERSISTENCIA

Conceptualmente:

```text

 ↓
PERSISTENCIA
 ↓
REINICIO
 ↓

 ↓

```

---

# 🧰 23. MECANISMOS DE PERSISTENCIA

Dependiendo del sistema:

```text
SERVICIOS
TAREAS PROGRAMADAS
CUENTAS
INICIO AUTOMÁTICO
CLAVES DE REGISTRO
SCRIPTS
BACKDOORS
```

No todos los mecanismos son maliciosos por naturaleza.

Lo importante es:

> **su uso no autorizado.**

# 👑 24. ESCALADA DE PRIVILEGIOS

El atacante puede comenzar como:

```text
USUARIO
```

y querer convertirse en:

```text
ADMINISTRADOR
```

o conseguir privilegios superiores.

MITRE define Privilege Escalation como la búsqueda de obtener permisos de mayor nivel. citeturn0search0

---

# 🧩 25. ESCALADA VERTICAL VS HORIZONTAL

### Vertical

```text
USUARIO
 ↓
ADMIN
```

Aumentan los privilegios.

### Horizontal

```text
USUARIO A
 ↓
CUENTA DE USUARIO B
```

Se obtiene acceso a otro recurso o identidad con un nivel de privilegio similar.

⚠️ En terminología de seguridad, "movimiento lateral" suele tener un significado más amplio que el simple salto entre dos cuentas.

# 🔑 26. CREDENCIAL ACCESS



# 🔎 28. DISCOVERY

Una vez dentro, el atacante quiere entender:

```text
¿DÓNDE ESTOY?
¿QUÉ USUARIOS EXISTEN?
¿QUÉ SERVIDORES HAY?
¿QUÉ REDES EXISTEN?
¿QUÉ SOFTWARE?
¿QUÉ DOMINIO?
¿DÓNDE ESTÁN LOS DATOS?
```

MITRE define Discovery como la fase en la que el adversario intenta conocer el entorno. citeturn0search0

# 🗺️ 29. DISCOVERY DE SISTEMA

# ↔️ 32. MOVIMIENTO LATERAL

Objetivo:

> **moverse desde un sistema comprometido hacia otros sistemas.**

Ejemplo:

```text
PC USUARIO
    ↓
SERVIDOR
    ↓
CONTROLADOR DE DOMINIO
    ↓
SERVIDOR DE DATOS
```

MITRE define Lateral Movement como el movimiento a través del entorno comprometido. citeturn0search0

---

# 🔐 33. MOVIMIENTO LATERAL CON CREDENCIALES

Ejemplo:

```text
CUENTA ROBADA
      ↓
SERVIDOR A
      ↓
SERVIDOR B
      ↓
SERVIDOR C
```

```text

```

---

# 🧱 34. SEGMENTACIÓN CONTRA MOVIMIENTO LATERAL

Supongamos:

```text

     │
     X
     │

```

con reglas específicas.

Aunque un PC quede comprometido:

```text

 ↓

```

# 🧠 35. MÍNIMO PRIVILEGIO CONTRA MOVIMIENTO LATERAL

Si un usuario solo necesita:

```text

```

no debería tener:

```text
SERVIDOR A
+
B
+
C
+
DB
+
ADMIN
```

El mínimo privilegio reduce las oportunidades de movimiento.

# 🧩 36. COMANDO Y CONTROL

Una vez comprometido un sistema, el atacante puede necesitar comunicarse con él.

Esto se denomina:

> **Command and Control (C2 o C&C).**

Objetivo:

```text

   ↕
SISTEMA COMPROMETIDO
```

MITRE define Command and Control como la comunicación utilizada para controlar sistemas comprometidos. citeturn0search0

# 🧪 44. CASO INTEGRAL · IMIDA

Supongamos:

```text
1. Un investigador recibe un correo falso.
2. Accede a un enlace.
3. Se ejecuta código malicioso.
4. El atacante obtiene acceso.
5. Busca información del equipo.
6. Obtiene credenciales.
7. Accede a otro servidor.
8. Encuentra datos de investigación.
9. Los copia.
10. Los envía fuera.
```

# 🛡️ 45. ¿CÓMO DEFENDER CADA FASE?

| Fase | Controles posibles |
|---|---|
| Reconocimiento | reducir exposición, monitorización |
| Acceso inicial | MFA, parcheado, filtros, formación |
| Ejecución | EDR, application control, scripting controls |
| Persistencia | monitorización, hardening |
| Escalada | mínimo privilegio, parcheado |
| Credenciales | MFA, protección de secretos |
| Discovery | segmentación, monitorización |
| Movimiento lateral | firewalls internos, segmentación, mínimo privilegio |
| C2 | DNS security, proxy, EDR, SIEM |
| Collection | DLP, control de acceso |
| Exfiltración | DLP, egress filtering, monitorización |
| Impacto | backups, continuidad, recuperación |

# 🚨 47. INDICADORES DE COMPROMISO

Un:

> **IOC (Indicator of Compromise)**

Ejemplos:


---

# 🧠 48. IOC VS IOA

### IOC

Se centra en:

```text
EVIDENCIA
```

de compromiso.

### IOA

> **Indicator of Attack**

se centra más en:

```text
COMPORTAMIENTO
```

que puede indicar un ataque.

Simplificando:

```text
IOC
→ "¿Qué evidencia dejó?"

IOA
→ "¿Qué comportamiento está ocurriendo?"
```

# 🚨 52. TRAMPAS DE EXAMEN

### 1. Reconocimiento = acceso inicial

❌ No.

```text
RECONOCIMIENTO
→ información

INITIAL ACCESS
→ entrada
```

---

### 2. Vulnerabilidad = exploit

❌ No.

```text
VULNERABILIDAD
→ debilidad

EXPLOIT
→ aprovechamiento
```

---

### 3. Ransomware = única técnica

❌ No.

Puede ser una cadena completa de técnicas.

---

### 4. Tener credenciales válidas = usuario legítimo

❌ No necesariamente.

Pueden estar robadas.

---

### 5. Movimiento lateral = acceso inicial

❌ No.

```text
INITIAL ACCESS
→ entrar

LATERAL MOVEMENT
→ desplazarse dentro
```

---

### 6. Persistencia = escalada

❌ No.

```text
PERSISTENCIA
→ permanecer

PRIVILEGE ESCALATION
→ obtener más privilegios
```

---

### 7. IDS = EDR

❌ No.

Son tecnologías diferentes y con ámbitos diferentes.

---

### 8. IOC = vulnerabilidad

❌ No.

```text
IOC
→ evidencia/indicador de posible compromiso
```

---

### 9. SIEM = antivirus

❌ No.

```text
SIEM
→ recopila/correlaciona eventos
```

---

### 10. C2 = exfiltración

❌ No.

```text
C2
→ comunicación/control

EXFILTRACIÓN
→ robo de datos
```

# 🧪 59. CASO DE EXAMEN

> Un atacante envía un correo de phishing a un empleado. Obtiene sus credenciales, accede a la VPN, identifica otros servidores, utiliza las credenciales para acceder a uno de ellos, localiza documentos de investigación y finalmente los copia a un servidor externo.

Identificamos:

```text
PHISHING
→ INITIAL ACCESS

CREDENCIALES
→ CREDENTIAL ACCESS

IDENTIFICAR SERVIDORES
→ DISCOVERY

ACCEDER A OTRO SERVIDOR
→ LATERAL MOVEMENT

LOCALIZAR DOCUMENTOS
→ COLLECTION

COPIAR FUERA
→ EXFILTRATION
```

### Controles

```text
PHISHING
→ correo seguro + formación

CREDENCIALES
→ MFA

VPN
→ MFA + restricciones

DISCOVERY
→ segmentación + monitorización

MOVIMIENTO LATERAL
→ firewalls internos + mínimo privilegio

DATOS
→ control de acceso + DLP

EXFILTRACIÓN
→ egress filtering + monitorización
```
