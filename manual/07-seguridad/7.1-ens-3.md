# 🔐 BLOQUE 07 · SEGURIDAD
# 7.1 · ESQUEMA NACIONAL DE SEGURIDAD
## Parte 3 · Categorización, dimensiones y medidas de seguridad

> **Objetivo:** dominar la parte más característica del ENS: cómo se determina la categoría de un sistema, cómo se asignan niveles a las dimensiones de seguridad y cómo se seleccionan las medidas del Anexo II.
>
> **Norma de referencia:** Real Decreto 311/2022, de 3 de mayo, en su texto consolidado.

---

# 🧭 1. DE LOS RIESGOS A LAS MEDIDAS

Hasta ahora hemos construido:

```text
PRINCIPIOS
     ↓
GESTIÓN DE RIESGOS
     ↓
RESPONSABILIDADES
```

Ahora aparece la pregunta fundamental:

> **¿Qué nivel de protección necesita exactamente este sistema?**

La respuesta se obtiene mediante:

```text
DIMENSIONES
     ↓
NIVELES DE SEGURIDAD
     ↓
CATEGORÍA DEL SISTEMA
     ↓
MEDIDAS DE SEGURIDAD
     ↓
REFUERZOS
```

El Anexo I establece la categorización y el Anexo II las medidas de seguridad. citeturn3search0

---

# 🔐 2. LAS CINCO DIMENSIONES

El Anexo I utiliza cinco dimensiones:

```text
C → Confidencialidad
I → Integridad
T → Trazabilidad
A → Autenticidad
D → Disponibilidad
```

Estas dimensiones permiten valorar el impacto que tendría un incidente sobre la información o los servicios.

---

# 🔒 3. CONFIDENCIALIDAD [C]

Pregunta:

> **¿Qué ocurre si alguien no autorizado conoce la información?**

Ejemplo:

```text
Resultados científicos reservados
        ↓
acceso no autorizado
        ↓
pérdida de confidencialidad
```

---

# 🧱 4. INTEGRIDAD [I]

Pregunta:

> **¿Qué ocurre si la información se modifica de manera no autorizada?**

Ejemplo:

```text
Resultado de laboratorio:
4,7
  ↓
atacante
  ↓
47
```

La información ya no es fiable.

---

# 🧾 5. TRAZABILIDAD [T]

Pregunta:

> **¿Podemos reconstruir quién hizo qué y cuándo?**

Ejemplo:

```text
Usuario A
↓
10:43
↓
modifica registro 532
↓
acción registrada
```

La trazabilidad es especialmente importante para:

```text
auditoría
+
investigación
+
responsabilidades
```

---

# 🪪 6. AUTENTICIDAD [A]

Pregunta:

> **¿Podemos confiar en la identidad u origen?**

Ejemplo:

```text
¿La petición procede realmente
del sistema autorizado?
```

La autenticidad se relaciona con mecanismos de identificación y autenticación.

---

# 🟢 7. DISPONIBILIDAD [D]

Pregunta:

> **¿Podemos utilizar la información o el servicio cuando lo necesitamos?**

Ejemplo:

```text
Sistema de muestras
        ↓
cae durante 8 horas
        ↓
investigación paralizada
```

Tenemos un impacto sobre disponibilidad.

---

# 📊 8. CADA DIMENSIÓN TIENE SU PROPIO NIVEL

Una información o servicio puede verse afectado en una o varias dimensiones.

Para cada dimensión afectada se asigna:

```text
BAJO
MEDIO
ALTO
```

Si una dimensión no resulta afectada:

> **no se le asigna ningún nivel.**

Esto es muy importante.

No debemos pensar:

```text
Sistema = ALTO en todo
```

automáticamente.

Podemos tener:

```text
C → MEDIO
I → ALTO
T → BAJO
A → BAJO
D → MEDIO
```

---

# 🟢 9. NIVEL BAJO

Se aplica cuando las consecuencias del incidente producirían un:

> **perjuicio limitado**

sobre:

```text
funciones de la organización
+
activos
+
individuos afectados
```

Ejemplos conceptuales:

```text
reducción apreciable de capacidad
daño menor
incumplimiento formal subsanable
perjuicio menor a una persona
```

---

# 🟡 10. NIVEL MEDIO

Se aplica cuando el incidente produciría un:

> **perjuicio grave**

sobre:

```text
funciones
+
activos
+
individuos
```

Ejemplos:

```text
interrupción importante
daño considerable
incumplimiento grave
perjuicio grave a una persona
```

---

# 🔴 11. NIVEL ALTO

Se aplica cuando las consecuencias del incidente producirían un:

> **perjuicio muy grave**

sobre:

```text
funciones
+
activos
+
individuos
```

La idea que debes conservar es:

```text
BAJO
→ perjuicio limitado

MEDIO
→ perjuicio grave

ALTO
→ perjuicio muy grave
```

---

# 🧠 12. TRAMPA: NIVEL ≠ CATEGORÍA

Aquí aparece una de las trampas favoritas.

Tenemos:

```text
NIVEL
→ se asigna a una DIMENSIÓN

CATEGORÍA
→ se asigna al SISTEMA
```

Por ejemplo:

```text
Confidencialidad → MEDIO
Integridad       → ALTO
Disponibilidad   → BAJO
```

Esto son **niveles de las dimensiones**.

La categoría del sistema será otra cosa.

---

# 🏷️ 13. CATEGORÍAS DEL SISTEMA

El ENS establece tres categorías:

```text
BÁSICA
MEDIA
ALTA
```

La categoría representa el equilibrio entre:

```text
importancia del sistema
+
riesgos
+
esfuerzo de seguridad requerido
```

bajo el principio de proporcionalidad.

---

# 🧮 14. REGLA PARA DETERMINAR LA CATEGORÍA

La regla es muy sencilla y muy importante:

### Si alguna dimensión alcanza ALTO:

```text
→ CATEGORÍA ALTA
```

### Si ninguna llega a ALTO pero alguna llega a MEDIO:

```text
→ CATEGORÍA MEDIA
```

### Si ninguna llega a MEDIO pero alguna llega a BAJO:

```text
→ CATEGORÍA BÁSICA
```

### Fórmula mental

```text
¿HAY ALTO?
   │
  SÍ → ALTA
  NO
   ↓
¿HAY MEDIO?
   │
  SÍ → MEDIA
  NO
   ↓
¿HAY BAJO?
   │
  SÍ → BÁSICA
```

Esta regla está en el Anexo I. citeturn3search0

---

# 🧪 15. EJEMPLO 1

Tenemos:

```text
C → BAJO
I → BAJO
T → BAJO
A → BAJO
D → BAJO
```

Categoría:

> **BÁSICA**

---

# 🧪 16. EJEMPLO 2

Tenemos:

```text
C → MEDIO
I → BAJO
T → BAJO
A → BAJO
D → BAJO
```

Categoría:

> **MEDIA**

---

# 🧪 17. EJEMPLO 3

Tenemos:

```text
C → MEDIO
I → ALTO
T → BAJO
A → MEDIO
D → MEDIO
```

Categoría:

> **ALTA**

Porque existe al menos una dimensión en nivel ALTO.

---

# 🧪 18. EJEMPLO 4 · TRAMPA

Tenemos:

```text
C → ALTO
I → BAJO
T → BAJO
A → NO AFECTADA
D → MEDIO
```

Categoría:

> **ALTA**

Pero atención:

> La existencia de una dimensión ALTA **no convierte automáticamente todas las demás dimensiones en ALTO**.

Cada dimensión conserva su propio nivel.

---

# 🧠 19. UNA CATEGORÍA NO CAMBIA LOS NIVELES

Esto es fundamental.

Supongamos:

```text
C → ALTO
I → BAJO
D → MEDIO
```

La categoría es:

```text
ALTA
```

Pero continúa siendo:

```text
C → ALTO
I → BAJO
D → MEDIO
```

La categoría sirve para modular las medidas de seguridad del sistema.

No modifica artificialmente los niveles de las dimensiones.

---

# 🔄 20. ¿QUÉ PASA SI HAY MUCHAS INFORMACIONES Y SERVICIOS?

Un mismo sistema puede:

```text
tratar diferentes informaciones
+
prestar diferentes servicios
```

En ese caso, para cada dimensión se toma:

> **el mayor nivel de seguridad establecido para cualquiera de las informaciones y servicios afectados.**

Ejemplo:

```text
Información A:
C → BAJO

Información B:
C → MEDIO

Información C:
C → ALTO
```

Para el sistema:

```text
C → ALTO
```

---

# 🧭 21. SECUENCIA OFICIAL DE CATEGORIZACIÓN

El Anexo I establece una secuencia de actuaciones.

### Paso 1

Identificar el nivel de seguridad correspondiente a:

```text
cada información
+
cada servicio
```

en función de sus dimensiones.

### Paso 2

Determinar la categoría del sistema.

En resumen:

```text
INFORMACIÓN/SERVICIOS
       ↓
DIMENSIONES
       ↓
NIVELES
       ↓
CATEGORÍA
```

Las guías CCN-STIC complementan los criterios necesarios para una adecuada categorización. citeturn3search0

---

# 📅 22. ¿CUÁNDO SE REEVALÚA?

La categoría debe reevaluarse:

```text
ANUALMENTE
```

o:

```text
cuando se produzcan modificaciones significativas
en los criterios utilizados para determinarla.
```

⚠️ Esto es una cifra que puede aparecer perfectamente en un test.

---

# 🛡️ 23. DE LA CATEGORÍA A LAS MEDIDAS

Una vez conocemos:

```text
dimensiones
+
niveles
+
categoría
```

seleccionamos las medidas de seguridad.

El Anexo II indica que las medidas son proporcionales a:

```text
dimensiones de seguridad relevantes
+
categoría del sistema
```

citeturn0search0

---

# 🧩 24. LOS TRES GRUPOS DEL ANEXO II

Las medidas se dividen en:

```text
ORG
OP
MP
```

## ORG

> Marco organizativo.

Organización global de la seguridad.

## OP

> Marco operacional.

Protección de la operación del sistema como conjunto integral.

## MP

> Medidas de protección.

Protección de activos concretos.

Esta estructura está definida expresamente en el Anexo II. citeturn0search0

---

# 🏢 25. ORG · MARCO ORGANIZATIVO

Ejemplos:

```text
org.1 → Política de seguridad
org.2 → Normativa de seguridad
org.3 → Procedimientos de seguridad
org.4 → Proceso de autorización
```

Estas medidas afectan a la organización global de la seguridad.

---

# ⚙️ 26. OP · MARCO OPERACIONAL

Ejemplos:

```text
op.pl → Planificación
op.acc → Control de acceso
op.exp → Explotación
op.ext → Servicios externos
op.cont → Continuidad
op.mon → Monitorización
```

El marco operacional protege el funcionamiento del sistema como conjunto.

---

# 🛡️ 27. MP · MEDIDAS DE PROTECCIÓN

Ejemplos:

```text
mp.if → Instalaciones
mp.per → Personal
mp.eq → Equipos
mp.com → Comunicaciones
mp.si → Soportes de información
mp.sw → Aplicaciones
mp.info → Información
mp.s → Servicios
```

Aquí protegemos activos concretos.

---

# 🧱 28. MEDIDA BASE + REFUERZOS

Una de las novedades importantes del ENS 2022 es el modelo:

```text
MEDIDA BASE
      +
REFUERZOS
```

No todas las categorías exigen exactamente el mismo nivel de protección.

Podemos tener:

```text
BÁSICA
→ medida base

MEDIA
→ medida base + R1

ALTA
→ medida base + R1 + R2
```

dependiendo de la medida concreta.

El Anexo II especifica individualmente cuándo se aplica cada refuerzo. citeturn0search0

---

# 🧠 29. NO TODOS LOS REFUERZOS SON OBLIGATORIOS

Algunos refuerzos pueden aparecer como:

```text
[R1 o R2]
```

Esto significa que existe una elección entre alternativas previstas.

Además, algunos refuerzos tienen carácter opcional y pueden aplicarse cuando el análisis de riesgos lo recomiende.

Por tanto:

> **No memorices "ALTA = siempre todos los refuerzos".**

Hay que mirar la medida concreta.

---

# 🧮 30. EJEMPLO DE SELECCIÓN

Imaginemos una medida con:

```text
BÁSICA → medida base
MEDIA  → base + R1
ALTA   → base + R1 + R2
```

Si nuestro sistema es:

```text
CATEGORÍA MEDIA
```

aplicaremos:

```text
BASE + R1
```

No:

```text
BASE + R1 + R2
```

---

# 🧠 31. LAS MEDIDAS PUEDEN DEPENDER DE LA DIMENSIÓN

No todas las medidas se aplican únicamente por categoría.

El Anexo II puede indicar:

```text
categoría
```

o:

```text
dimensiones concretas
```

Por ejemplo:

```text
D → Disponibilidad
```

puede determinar la aplicación de una medida relacionada con capacidad o continuidad.

Por ello hay que leer las tablas del Anexo II con atención.

---

# 🔍 32. SECUENCIA DE SELECCIÓN DE MEDIDAS

La secuencia oficial puede resumirse como:

```text
1. Identificar tipos de activos
          ↓
2. Determinar dimensiones relevantes
          ↓
3. Determinar nivel de cada dimensión
          ↓
4. Determinar categoría del sistema
          ↓
5. Seleccionar medidas + refuerzos
```

Este esquema merece estar grabado.

---

# 📄 33. DECLARACIÓN DE APLICABILIDAD

Las medidas seleccionadas se formalizan en un documento denominado:

> **Declaración de Aplicabilidad**

La Declaración de Aplicabilidad debe estar:

> **firmada por el Responsable de la Seguridad.**

Puede incluir:

```text
medidas seleccionadas
+
medidas adicionales
+
justificaciones
+
decisiones derivadas del análisis de riesgos
```

El ENS establece que las medidas mínimas son ampliables a criterio del Responsable de la Seguridad. citeturn3search0

---

# 🧩 34. ¿SE PUEDEN SUSTITUIR MEDIDAS?

Sí.

Las medidas del Anexo II pueden ser reemplazadas por:

> **medidas compensatorias**

siempre que se justifique documentalmente que protegen igual o mejor frente al riesgo sobre los activos y satisfacen los principios básicos y requisitos mínimos aplicables.

No es:

```text
"me invento otra medida"
```

sino:

```text
medida alternativa
+
justificación documental
+
protección equivalente o superior
+
cumplimiento ENS
```

---

# 🧱 35. SUBSISTEMAS CON DIFERENTES NECESIDADES

Un sistema puede contener subsistemas que requieran:

```text
diferentes niveles de medidas
```

En determinadas condiciones pueden segregarse.

Por ejemplo:

```text
SISTEMA GENERAL
│
├── Subsistema A → necesidades BÁSICAS
│
└── Subsistema B → necesidades ALTA
```

La segregación permite aplicar el nivel correspondiente cuando la información y los servicios afectados puedan delimitarse adecuadamente.

---

# 🏗️ 36. MADUREZ DE LAS MEDIDAS

El ENS no solo pregunta:

> "¿Has implantado la medida?"

También utiliza un modelo de madurez:

> **CMM · Capability Maturity Model**

Se establecen cinco niveles:

```text
L0 → Inexistente
L1 → Inicial. Ad hoc
L2 → Reproducible, pero intuitivo
L3 → Proceso definido
L4 → Gestionado y medible
L5 → Optimizado
```

---

# 🟢 37. L0 · INEXISTENTE

No existe un proceso que soporte el servicio requerido.

```text
Proceso
↓
NO EXISTE
```

---

# 🟠 38. L1 · INICIAL / AD HOC

Características:

```text
reactivo
+
informal
+
poco predecible
+
dependencia del esfuerzo personal
```

Los procedimientos, cuando existen, pueden ser incompletos y no aplicarse sistemáticamente.

---

# 🟡 39. L2 · REPRODUCIBLE, PERO INTUITIVO

Ya existen:

```text
prácticas institucionalizadas
+
métricas básicas
+
seguimiento razonable
```

Pero los procedimientos todavía pueden:

```text
no estar suficientemente documentados
+
no cubrir todos los aspectos
```

---

# 🟢 40. L3 · PROCESO DEFINIDO

Existe:

```text
normativa
+
procedimientos detallados
+
documentación
+
coordinación
+
formación
```

El proceso está claramente definido.

---

# 🔵 41. L4 · GESTIONADO Y MEDIBLE

Existe:

```text
métricas de efectividad
+
métricas de eficiencia
+
uso sistemático de métricas
+
gestión de riesgos
```

El servicio resultante presenta un alto nivel de calidad.

---

# 🟣 42. L5 · OPTIMIZADO

La organización está orientada a:

```text
mejora continua
+
métricas intensivas
+
innovación
```

Es el nivel superior.

---

# 🎯 43. MADUREZ MÍNIMA SEGÚN CATEGORÍA

Esta tabla es **muy importante**:

| Categoría | Madurez mínima |
|---|---|
| **BÁSICA** | **L2 · Reproducible, pero intuitivo** |
| **MEDIA** | **L3 · Proceso definido** |
| **ALTA** | **L4 · Gestionado y medible** |

El ENS establece estos niveles mínimos para las medidas que sean de aplicación al sistema. citeturn1view1

### 🧠 Memoriza

```text
BÁSICA → L2
MEDIA  → L3
ALTA   → L4
```

No necesitas L5 para cumplir el mínimo del ENS.

---

# 🔍 44. CATEGORÍA Y MADUREZ NO SON LO MISMO

Otra trampa:

```text
CATEGORÍA
→ BÁSICA / MEDIA / ALTA

MADUREZ
→ L0 / L1 / L2 / L3 / L4 / L5
```

Son escalas diferentes.

Ejemplo:

```text
Sistema:
Categoría → MEDIA

Medidas:
Madurez mínima → L3
```

---

# 🧪 45. CASO PRÁCTICO COMPLETO

El IMIDA dispone de un sistema de gestión de resultados científicos.

Tras analizarlo:

```text
C → MEDIO
I → ALTO
T → MEDIO
A → BAJO
D → MEDIO
```

### Paso 1 · Categoría

Existe:

```text
I → ALTO
```

Por tanto:

> **Categoría ALTA**

### Paso 2 · No modificar dimensiones

Seguimos teniendo:

```text
C → MEDIO
I → ALTO
T → MEDIO
A → BAJO
D → MEDIO
```

### Paso 3 · Medidas

Seleccionamos las medidas del Anexo II teniendo en cuenta:

```text
dimensiones
+
niveles
+
categoría ALTA
```

### Paso 4 · Madurez

La madurez mínima exigida para las medidas aplicables será:

> **L4**

---

# 🧪 46. CASO PRÁCTICO 2

Otro sistema:

```text
C → BAJO
I → BAJO
T → BAJO
A → BAJO
D → MEDIO
```

Categoría:

> **MEDIA**

Porque D alcanza MEDIO.

Pero:

```text
C → BAJO
I → BAJO
T → BAJO
A → BAJO
D → MEDIO
```

no se convierten en MEDIO.

La categoría es MEDIA, mientras que los niveles individuales permanecen como fueron determinados.

---

# 🧠 47. EL ERROR QUE NO DEBES COMETER

Nunca hagas:

```text
D → MEDIO
↓
CATEGORÍA MEDIA
↓
TODAS LAS DIMENSIONES → MEDIO
```

Eso es:

> ❌ INCORRECTO.

La categoría y los niveles de las dimensiones son conceptos distintos.

# 🚨 49. TRAMPAS DE EXAMEN

## ❌ Trampa 1

> "Si una dimensión es ALTA, todas las dimensiones pasan a ALTO."

Incorrecto.

Solo determina que la:

> **categoría del sistema es ALTA.**

---

## ❌ Trampa 2

> "Categoría MEDIA significa que todas las dimensiones son MEDIO."

Incorrecto.

La categoría es una clasificación del sistema.

---

## ❌ Trampa 3

> "BÁSICA significa que todas las dimensiones son BAJO."

Incorrecto.

Puede haber dimensiones no afectadas y otras en BAJO.

---

## ❌ Trampa 4

> "La categoría se determina antes que los niveles de las dimensiones."

Incorrecto.

Primero:

```text
niveles
↓
categoría
```

---

## ❌ Trampa 5

> "Las medidas del Anexo II son iguales para todos."

Incorrecto.

Son proporcionales a:

```text
dimensiones
+
categoría
```

---

## ❌ Trampa 6

> "Los refuerzos siempre son obligatorios."

Incorrecto.

Depende de la medida, categoría, dimensión y, en determinados casos, del análisis de riesgos.

---

## ❌ Trampa 7

> "Cumplir ENS exige alcanzar L5."

Incorrecto.

Los mínimos son:

```text
BÁSICA → L2
MEDIA → L3
ALTA → L4
```

# 🧠 54. LA FÓRMULA DEL ENS

Memoriza esta secuencia:

```text
1. ¿QUÉ PROTEJO?
   Información + servicios

2. ¿QUÉ DIMENSIONES AFECTA?
   C I T A D

3. ¿QUÉ NIVEL TIENE CADA UNA?
   Bajo / Medio / Alto

4. ¿QUÉ CATEGORÍA TIENE EL SISTEMA?
   Básica / Media / Alta

5. ¿QUÉ MEDIDAS APLICO?
   ORG / OP / MP

6. ¿NECESITO REFUERZOS?
   Depende de medida + categoría + dimensiones + riesgos

7. ¿QUÉ MADUREZ NECESITO?
   Básica → L2
   Media  → L3
   Alta   → L4
```
