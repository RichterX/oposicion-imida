# 🔥 BLOQUE 07 · SEGURIDAD
# 7.4 · FIREWALLS
## Parte 1 · Fundamentos, arquitectura, filtrado y tipos de cortafuegos

> **Objetivo:** comprender qué es un firewall, qué problema resuelve, cómo decide si permite o bloquea tráfico, dónde puede desplegarse y cuáles son sus principales tipos y tecnologías.
>
> **Fuentes técnicas de referencia:** NIST SP 800-41 Rev. 1 sobre firewalls y políticas de firewall, e INCIBE para conceptos y aplicaciones prácticas en ciberseguridad. NIST define los firewalls como dispositivos o programas que controlan el flujo de tráfico entre redes o hosts con diferentes posturas de seguridad. citeturn0search0

---

# 🧭 1. ¿QUÉ ES UN FIREWALL?

Un:

> **firewall**, o **cortafuegos**,

es un dispositivo o programa diseñado para:

```text
CONTROLAR
    ↓
TRÁFICO DE RED
    ↓
PERMITIR / DENEGAR
    ↓
SEGÚN REGLAS
```

Su función principal es establecer un punto de control entre distintos dominios de seguridad.

Por ejemplo:

```text
             INTERNET
                 │
                 ↓
          ┌─────────────┐
          │  FIREWALL   │
          └─────────────┘
                 │
                 ↓
          RED INTERNA
```

NIST describe precisamente esta función como el control del flujo de tráfico entre redes o hosts que emplean diferentes políticas de seguridad. citeturn0search0

---

# 🛡️ 2. ¿PARA QUÉ SIRVE?

Un firewall permite controlar:

```text
✓ tráfico entrante
✓ tráfico saliente
✓ conexiones permitidas
✓ conexiones bloqueadas
✓ determinados protocolos
✓ determinados puertos
✓ determinadas direcciones IP
✓ determinados servicios
```

INCIBE señala que los cortafuegos pueden filtrar conexiones entrantes y salientes y aplicar reglas personalizadas para decidir qué tráfico se permite y cuál se bloquea. citeturn0search9turn0search15

---

# 🚪 3. LA METÁFORA DE LA PUERTA

Imagina una red como un edificio.

Sin control:

```text
INTERNET
   ↓
"Pasad todos."
   ↓
RED INTERNA
```

Con firewall:

```text
INTERNET
   ↓
┌───────────────────┐
│      FIREWALL     │
│                   │
│ ¿Quién eres?      │
│ ¿De dónde vienes? │
│ ¿A dónde vas?     │
│ ¿Qué protocolo?   │
│ ¿Qué puerto?      │
│ ¿Está permitido?  │
└───────────────────┘
   ↓
RED INTERNA
```

Pero cuidado:

> Un firewall no es simplemente una puerta cerrada.

Es un:

> **mecanismo de aplicación de una política de seguridad sobre el tráfico.**

---

# 🧩 4. FIREWALL = REGLAS + TRÁFICO + DECISIÓN

Podemos simplificarlo:

```text
TRÁFICO
   ↓
INSPECCIÓN
   ↓
REGLAS
   ↓
DECISIÓN
   ↓
┌───────────┬───────────┐
↓           ↓
PERMITIR    DENEGAR
```

En función de la tecnología, la inspección puede realizarse a diferentes niveles y con diferentes grados de profundidad. INCIBE señala que los firewalls modernos pueden llegar a analizar tráfico en capas superiores, incluso mediante inspección profunda de paquetes (DPI). citeturn0search7

---

# 🌐 5. TRÁFICO ENTRANTE Y SALIENTE

Un error frecuente es pensar:

> "El firewall solo protege contra conexiones que vienen de Internet."

No.

También puede controlar:

```text
TRÁFICO SALIENTE
```

Por ejemplo:

```text
SERVIDOR INTERNO
      ↓
     DNS
      ↓
   INTERNET
```

Una política puede determinar si esa comunicación está permitida.

INCIBE recomienda considerar tanto el filtrado del tráfico entrante como del saliente. citeturn0search7

---

# 📥 6. TRÁFICO ENTRANTE

Ejemplo:

```text
INTERNET
   ↓
TCP 443
   ↓
SERVIDOR WEB
```

El firewall puede permitirlo si existe una regla como:

```text
ORIGEN: cualquiera
DESTINO: servidor web
PROTOCOLO: TCP
PUERTO: 443
ACCIÓN: PERMITIR
```

---

# 📤 7. TRÁFICO SALIENTE

Ejemplo:

```text
SERVIDOR
   ↓
TCP 443
   ↓
INTERNET
```

El firewall también puede aplicar una política:

```text
ORIGEN: servidor
DESTINO: Internet
PROTOCOLO: TCP
PUERTO: 443
ACCIÓN: PERMITIR
```

---

# 🔢 8. DIRECCIONES IP

Una regla puede basarse en:

```text
IP ORIGEN
+
IP DESTINO
```

Ejemplo:

```text
192.168.1.0/24
        ↓
10.0.0.10
        ↓
PERMITIR
```

También podemos denegar:

```text
203.0.113.50
        ↓
10.0.0.10
        ↓
DENEGAR
```

---

# 🚪 9. PUERTOS

Los firewalls pueden utilizar puertos como criterio.

Ejemplos habituales:

```text
HTTP  → 80
HTTPS → 443
DNS   → 53
SSH   → 22
SMTP  → 25
```

Ejemplo:

```text
Internet
   ↓
TCP/22
   ↓
Servidor
```

Una regla podría:

```text
DENEGAR
```

el acceso SSH desde Internet.

Mientras que:

```text
Red administración
   ↓
TCP/22
   ↓
Servidor
```

podría:

```text
PERMITIR
```

---

# 📡 10. PROTOCOLOS

Una regla puede especificar:

```text
TCP
UDP
ICMP
```

y otros protocolos dependiendo de la tecnología.

Ejemplo:

```text
ORIGEN: red interna
DESTINO: Internet
PROTOCOLO: TCP
PUERTO: 443
ACCIÓN: PERMITIR
```

# 🧱 11. FILTRADO DE PAQUETES

Uno de los mecanismos clásicos es:

> **packet filtering**

o:

> **filtrado de paquetes.**

El firewall analiza información de los paquetes y aplica reglas.

Puede considerar elementos como:

```text
IP origen
IP destino
protocolo
puerto origen
puerto destino
```

NIST identifica el filtrado de paquetes como una de las tecnologías fundamentales de firewall. citeturn0search0

---

# 📦 12. FIREWALL DE FILTRADO DE PAQUETES

Conceptualmente:

```text
PAQUETE
   ↓
┌──────────────────────┐
│ IP origen            │
│ IP destino           │
│ Protocolo            │
│ Puerto origen        │
│ Puerto destino       │
└──────────────────────┘
   ↓
REGLAS
   ↓
PERMITIR / DENEGAR
```

Es relativamente sencillo y eficiente.

Pero tiene una limitación:

> puede no conocer el contexto completo de una comunicación.

---

# 🔄 13. FIREWALL STATEFUL

Para superar parte de esa limitación aparece la:

> **stateful inspection**

o:

> **inspección con estado.**

Un firewall stateful mantiene información sobre las conexiones activas.

NIST explica que la inspección con estado mantiene una **tabla de estados** y bloquea paquetes que se desvían del estado esperado de la conexión. citeturn0search24

---

# 📋 14. TABLA DE ESTADOS

Podemos imaginar:

```text
┌──────────────┬──────────────┬──────┬─────────────┐
│ IP origen    │ IP destino   │Port  │ Estado      │
├──────────────┼──────────────┼──────┼─────────────┤
│192.168.1.10  │8.8.8.8       │443   │ ESTABLISHED │
└──────────────┴──────────────┴──────┴─────────────┘
```

Si llega un paquete inesperado:

```text
PAQUETE
   ↓
¿CORRESPONDE A UNA CONEXIÓN CONOCIDA?
   ↓
NO
   ↓
DENEGAR
```

---

# 🧠 15. STATEFUL VS PACKET FILTERING

| Característica | Filtrado de paquetes | Stateful |
|---|---|---|
| IP origen/destino | ✅ | ✅ |
| Puertos | ✅ | ✅ |
| Protocolos | ✅ | ✅ |
| Estado de conexión | ❌ | ✅ |
| Tabla de estados | ❌ | ✅ |
| Contexto de sesión | Limitado | Mayor |

### 🧠 Regla de memoria

```text
PACKET FILTER
→ "¿Este paquete cumple una regla?"

STATEFUL
→ "¿Este paquete pertenece a una conexión válida?"
```

---

# 🪞 16. EJEMPLO STATEFUL

Un equipo interno inicia:

```text
192.168.1.10
      ↓
TCP 443
      ↓
8.8.8.8
```

El firewall permite la conexión.

Registra:

```text
ESTADO = ESTABLISHED
```

Cuando llega la respuesta:

```text
8.8.8.8
      ↓
respuesta
      ↓
192.168.1.10
```

el firewall reconoce que pertenece a una conexión ya existente.

Por tanto:

```text
PERMITIR
```

NIST utiliza precisamente este modelo de seguimiento de conexiones mediante una tabla de estados. citeturn0search24

# 🧱 17. FIREWALL DE CIRCUITO

Existe también el concepto de:

> **circuit-level gateway**

o:

> **pasarela de nivel de circuito.**

Su función se sitúa principalmente en el control de conexiones o sesiones, sin necesariamente inspeccionar el contenido completo de la aplicación.

Conceptualmente:

```text
CLIENTE
   ↓
CIRCUITO
   ↓
SERVIDOR
```

Puede comprobar que una conexión cumple determinados requisitos antes de permitirla.

---

# 🧑‍💻 18. FIREWALL DE APLICACIÓN / PROXY

Un:

> **application-level gateway**

o:

> **proxy firewall**

actúa como intermediario entre cliente y servidor.

En lugar de permitir directamente:

```text
CLIENTE ─────────→ SERVIDOR
```

se produce:

```text
CLIENTE
   ↓
PROXY / FIREWALL
   ↓
SERVIDOR
```

El firewall puede comprender protocolos de aplicación concretos.

---

# 🔎 19. PROXY

Un proxy puede actuar como intermediario:

```text
CLIENTE
   ↓
PROXY
   ↓
INTERNET
```

El servidor externo no necesariamente recibe directamente la conexión original del cliente.

El proxy puede aplicar políticas adicionales.

---

# 🌐 20. FIREWALL DE APLICACIÓN WEB · WAF

Un:

> **WAF (Web Application Firewall)**

es un firewall especializado en proteger aplicaciones web.

INCIBE lo define como un cortafuegos específico para aplicar reglas de filtrado sobre comunicaciones HTTP. citeturn0search7turn0search17

---

# 🕸️ 21. ¿QUÉ PROTEGE UN WAF?

Especialmente tráfico:

```text
HTTP / HTTPS
```

Puede aplicar reglas frente a ataques web habituales como:

```text
XSS
SQL Injection
```

entre otros. INCIBE señala precisamente estas capacidades como ejemplos de protección de un WAF. citeturn0search7

---

# 🧪 22. EJEMPLO WAF

Un atacante envía:

```text
GET /search?q=' OR 1=1 --
```

El tráfico llega:

```text
INTERNET
   ↓
WAF
   ↓
¿PATRÓN MALICIOSO?
   ↓
SÍ
   ↓
BLOQUEAR
```

La petición no llega al servidor web si la política del WAF la bloquea.

# 🏢 23. FIREWALL DE RED

Un firewall puede desplegarse como dispositivo dedicado en la infraestructura:

```text
INTERNET
   ↓
FIREWALL
   ↓
DMZ
   ↓
RED INTERNA
```

Es habitual en arquitecturas empresariales.

---

# 💻 24. FIREWALL DE HOST

También puede existir como software instalado directamente en un equipo:

```text
INTERNET
    ↓
┌───────────────┐
│   ORDENADOR   │
│               │
│   FIREWALL    │
└───────────────┘
```

Es un:

> **host-based firewall**

o firewall basado en host.

Puede controlar el tráfico específico de ese equipo.

---

# 🏠 25. FIREWALL PERSONAL

En un ordenador doméstico:

```text
PC
 ↓
FIREWALL PERSONAL
 ↓
INTERNET
```

Puede controlar las conexiones entrantes y salientes de las aplicaciones.

INCIBE explica que el firewall personal permite bloquear o permitir comunicaciones entrantes y salientes realizadas por cada programa del equipo. citeturn0search14

---

# 🏗️ 26. FIREWALL DE RED VS HOST

| Firewall | Ubicación | Alcance |
|---|---|---|
| De red | Infraestructura | Varias máquinas/redes |
| De host | Equipo | Un equipo |
| Personal | Equipo usuario | Un equipo |

Pueden coexistir.

---

# 🏛️ 27. ARQUITECTURA PERIMETRAL

Una arquitectura clásica:

```text
                 INTERNET
                     │
                     ↓
               FIREWALL
                     │
            ┌────────┴────────┐
            ↓                 ↓
           DMZ             RED INTERNA
```

La DMZ permite separar servicios expuestos de la red interna.

---

# 🌐 28. DMZ

La:

> **DMZ (Demilitarized Zone)**

es una red intermedia destinada habitualmente a alojar servicios que necesitan ser accesibles desde redes externas.

Ejemplo:

```text
INTERNET
    │
    ↓
FIREWALL EXTERNO
    │
    ↓
   DMZ
 ┌───────┐
 │ WEB   │
 │ MAIL  │
 └───────┘
    │
    ↓
FIREWALL INTERNO
    │
    ↓
RED INTERNA
```

---

# 🧱 29. ¿POR QUÉ USAR DMZ?

Si un servidor web es comprometido:

```text
INTERNET
   ↓
SERVIDOR WEB
   ↓
COMPROMETIDO
```

no queremos que el atacante tenga automáticamente acceso a:

```text
BASE DE DATOS
+
SERVIDORES INTERNOS
+
EQUIPOS DE USUARIOS
```

La segmentación reduce el alcance potencial.

NIST incluye la arquitectura perimetral y DMZ dentro de las consideraciones de diseño de entornos de firewall. citeturn0search2

---

# 🔥 30. FIREWALLS EN SERIE

Podemos tener:

```text
INTERNET
   ↓
FIREWALL 1
   ↓
DMZ
   ↓
FIREWALL 2
   ↓
RED INTERNA
```

Esto permite aplicar políticas diferentes en distintos puntos.

---

# 🧩 31. FIREWALLS INTERNOS

No todo firewall debe estar en el perímetro.

Podemos segmentar:

```text
RED USUARIOS
      │
      ↓
  FIREWALL
      │
      ↓
RED SERVIDORES
```

o:

```text
USUARIOS
   ↓
FIREWALL
   ↓
BASE DE DATOS
```

Esto reduce el movimiento lateral.

NIST destaca que los firewalls pueden desplegarse también en ubicaciones internas para proteger sistemas y redes sensibles, no únicamente en el perímetro. citeturn0search13

---

# 🚦 32. POLÍTICA DE FIREWALL

Un firewall necesita una:

> **política de seguridad.**

Sin ella:

```text
FIREWALL
+
REGLAS ALEATORIAS
=
CAOS
```

La política define:

```text
qué se permite
qué se bloquea
qué se registra
qué excepciones existen
```

NIST dedica una parte importante de su guía a establecer, configurar, probar, desplegar y gestionar políticas de firewall. citeturn0search0

---

# 📝 33. REGLAS

Una regla puede representarse como:

```text
ORIGEN
DESTINO
PROTOCOLO
PUERTO
ACCIÓN
```

Ejemplo:

```text
ORIGEN:     10.0.0.0/24
DESTINO:    10.0.10.20
PROTOCOLO:  TCP
PUERTO:     443
ACCIÓN:     ALLOW
```

---

# 🚫 34. ALLOW / DENY

Las acciones habituales incluyen:

```text
ALLOW
→ permitir

DENY
→ denegar

DROP
→ descartar silenciosamente

REJECT
→ rechazar comunicando el rechazo
```

### ⚠️ DROP VS REJECT

```text
DROP
→ "no respondo"

REJECT
→ "rechazo la conexión"
```

Esta diferencia puede tener consecuencias en diagnóstico y exposición de información.

---

# 🔢 35. ORDEN DE LAS REGLAS

En muchos firewalls las reglas se procesan:

```text
de arriba
hacia abajo
```

hasta encontrar una coincidencia.

Ejemplo:

```text
1. DENY  203.0.113.50 → ANY
2. ALLOW ANY → TCP/443
3. DENY  ANY → ANY
```

El tráfico procedente de:

```text
203.0.113.50
```

queda bloqueado por la primera regla.

---

# ⚠️ 36. REGLAS DEMASIADO PERMISIVAS

Mala práctica:

```text
ALLOW
ANY
ANY
ANY
```

Equivale aproximadamente a:

> permitir prácticamente todo.

Una política restrictiva puede partir del principio:

```text
DENEGAR POR DEFECTO
+
PERMITIR SOLO LO NECESARIO
```

---

# 🛡️ 37. DENEGACIÓN POR DEFECTO

Conceptualmente:

```text
DEFAULT
   ↓
DENY
```

Y después:

```text
EXCEPCIONES
   ↓
ALLOW
```

Ejemplo:

```text
DEFAULT DENY

ALLOW TCP/443
ALLOW DNS
ALLOW SSH DESDE RED ADMIN
```

Este enfoque reduce la superficie de exposición.

---

# 📊 38. LOGGING

Un firewall puede registrar eventos:

```text
✓ conexión permitida
✓ conexión bloqueada
✓ origen
✓ destino
✓ puerto
✓ protocolo
✓ fecha/hora
```

Esto ayuda a:

```text
auditoría
+
detección
+
diagnóstico
+
respuesta a incidentes
```

---

# 🔍 39. MONITORIZACIÓN

El firewall no debería considerarse:

> "configúralo una vez y olvídate."

Debe gestionarse:

```text
CONFIGURAR
   ↓
MONITORIZAR
   ↓
REVISAR
   ↓
ACTUALIZAR
   ↓
PROBAR
```

NIST recomienda considerar selección, configuración, pruebas, despliegue y gestión continua de las soluciones de firewall. citeturn0search0

---

# 🧠 40. FIREWALL NO ES ANTIVIRUS

No confundir:

```text
FIREWALL
→ controla tráfico

ANTIVIRUS / EDR
→ detecta y responde frente a software
  malicioso y comportamientos sospechosos
```

Pueden complementarse.

---

# 🧠 41. FIREWALL NO ES IDS

Un:

> **IDS (Intrusion Detection System)**

se centra en:

```text
DETECTAR
+
ALERTAR
```

Normalmente funciona de manera pasiva.

Un:

> **IPS (Intrusion Prevention System)**

puede:

```text
DETECTAR
+
BLOQUEAR
```

INCIBE distingue precisamente IDS como mecanismo pasivo de detección y alerta e IPS como mecanismo activo capaz de bloquear comportamientos maliciosos. citeturn0search7

---

# 🧩 42. FIREWALL VS IDS VS IPS

| Tecnología | Función principal |
|---|---|
| Firewall | Controlar tráfico según política |
| IDS | Detectar y alertar |
| IPS | Detectar y bloquear |

Pueden coexistir:

```text
INTERNET
   ↓
FIREWALL
   ↓
IPS
   ↓
SERVIDORES
```

---

# 🚀 43. FIREWALL TRADICIONAL

Un firewall tradicional puede basarse principalmente en:

```text
IP
+
PUERTO
+
PROTOCOLO
+
ESTADO
```

Es una primera capa fundamental.

---

# 🧠 44. NGFW

Un:

> **NGFW (Next-Generation Firewall)**

amplía las capacidades tradicionales.

Puede incorporar funciones como:

```text
inspección profunda
+
identificación de aplicaciones
+
control más avanzado
+
integración con otras funciones de seguridad
```

INCIBE diferencia entre firewall tradicional, UTM y NGFW como categorías de soluciones con capacidades crecientes. citeturn0search15

---

# 🧰 45. UTM

Un:

> **UTM (Unified Threat Management)**

integra varias funciones de seguridad en una misma plataforma.

Puede combinar:

```text
FIREWALL
+
ANTIVIRUS
+
IPS
+
VPN
+
FILTRADO WEB
+
OTRAS FUNCIONES
```

No todos los productos UTM tienen exactamente las mismas capacidades.

---

# 🆚 46. TRADICIONAL VS UTM VS NGFW

| Tipo | Idea |
|---|---|
| Firewall tradicional | Filtrado/control de tráfico |
| UTM | Varias funciones de seguridad integradas |
| NGFW | Firewall avanzado con mayor contexto e inspección |

No son categorías perfectamente excluyentes en todos los productos comerciales.

# 🌐 47. NAT Y FIREWALL

Muchos firewalls también pueden realizar:

> **NAT (Network Address Translation).**

Por ejemplo:

```text
192.168.1.10
      ↓
   FIREWALL
      ↓
203.0.113.20
```

El firewall puede traducir la dirección privada a una dirección pública.

### ⚠️ Trampa

```text
NAT
≠
FIREWALL
```

Aunque puedan coexistir en el mismo dispositivo.

---

# 🔒 48. VPN Y FIREWALL

Muchos firewalls empresariales también incorporan:

> **VPN**

para permitir conexiones remotas seguras.

Ejemplo:

```text
TRABAJADOR
    ↓
   VPN
    ↓
FIREWALL
    ↓
RED CORPORATIVA
```

Pero:

```text
VPN
≠
FIREWALL
```

Son tecnologías diferentes que pueden integrarse.

---

# 🧪 49. CASO PRÁCTICO · SERVIDOR WEB DEL IMIDA

Supongamos:

```text
INTERNET
    ↓
FIREWALL
    ↓
DMZ
    ↓
SERVIDOR WEB
```

Queremos:

```text
HTTP  → permitir
HTTPS → permitir
SSH   → solo administración interna
```

Política:

```text
ALLOW ANY → WEB TCP/80
ALLOW ANY → WEB TCP/443

ALLOW RED_ADMIN → WEB TCP/22

DENY ANY → WEB TCP/22
```

---

# 🧪 50. CASO PRÁCTICO · BASE DE DATOS

Tenemos:

```text
WEB
 ↓
BASE DE DATOS
```

No queremos:

```text
INTERNET
 ↓
BASE DE DATOS
```

Por tanto:

```text
ALLOW WEB → DB TCP/3306
DENY ANY → DB TCP/3306
```

Así, el puerto MySQL no queda directamente expuesto a Internet.

---

# 🧪 51. CASO PRÁCTICO · RED DE ADMINISTRACIÓN

Queremos que solo la red administrativa acceda por SSH:

```text
10.10.10.0/24
        ↓
      TCP/22
        ↓
    SERVIDORES
```

Regla:

```text
ALLOW 10.10.10.0/24 → SERVIDORES TCP/22
```

Y:

```text
DENY ANY → SERVIDORES TCP/22
```

---

# 🧪 52. CASO PRÁCTICO · WAF

Aplicación:

```text
https://app.imida.example
```

Arquitectura:

```text
INTERNET
    ↓
   WAF
    ↓
WEB SERVER
    ↓
APPLICATION
    ↓
DATABASE
```

El WAF inspecciona principalmente las peticiones web y puede bloquear patrones maliciosos conocidos.

# 🚨 53. TRAMPAS DE EXAMEN

### ❌ Trampa 1

> "Un firewall solo filtra tráfico entrante."

Incorrecto.

Puede controlar tráfico entrante y saliente.

---

### ❌ Trampa 2

> "Un firewall es un antivirus."

Incorrecto.

Controla tráfico de red; no sustituye necesariamente a antivirus/EDR.

---

### ❌ Trampa 3

> "Stateful y stateless son lo mismo."

Incorrecto.

Stateful mantiene información sobre conexiones.

---

### ❌ Trampa 4

> "NAT y firewall son sinónimos."

Incorrecto.

NAT traduce direcciones; un firewall aplica políticas de control de tráfico.

---

### ❌ Trampa 5

> "Un WAF protege cualquier protocolo de red."

Incorrecto.

Está especializado principalmente en tráfico web/aplicaciones HTTP.

---

### ❌ Trampa 6

> "IDS bloquea automáticamente."

No como característica esencial.

```text
IDS → detectar/alertar
IPS → detectar/prevenir
```

---

### ❌ Trampa 7

> "Una DMZ es Internet."

Incorrecto.

Es una zona de red intermedia con una política de seguridad propia.

---

### ❌ Trampa 8

> "Si tengo firewall perimetral, ya no necesito segmentación interna."

Incorrecto.

Los firewalls también pueden utilizarse internamente para reducir movimiento lateral.

---

### ❌ Trampa 9

> "ALLOW ANY ANY es una política segura."

No.

Es excesivamente permisiva.

---

### ❌ Trampa 10

> "El firewall se configura una vez y no necesita mantenimiento."

Incorrecto.

Debe gestionarse, monitorizarse, probarse y revisarse.

# 🎴 56. TARJETAS ANKI

## Tarjeta 1

**P:** ¿Qué es un firewall?

**R:** Dispositivo o programa que controla el flujo de tráfico entre redes o hosts con diferentes políticas de seguridad.

---

## Tarjeta 2

**P:** ¿Qué puede controlar un firewall?

**R:** Tráfico entrante y saliente mediante reglas basadas, entre otros criterios, en IP, puertos, protocolos y estado.

---

## Tarjeta 3

**P:** ¿Qué es un firewall stateful?

**R:** Un firewall que mantiene información sobre el estado de las conexiones y utiliza esa información para decidir si permite tráfico.

---

## Tarjeta 4

**P:** ¿Qué es un WAF?

**R:** Web Application Firewall, especializado en filtrar y proteger comunicaciones de aplicaciones web, principalmente HTTP.

---

## Tarjeta 5

**P:** ¿Qué es una DMZ?

**R:** Zona de red intermedia utilizada habitualmente para alojar servicios que necesitan estar expuestos, separándolos de la red interna.

---

## Tarjeta 6

**P:** ¿Qué diferencia hay entre IDS e IPS?

**R:** IDS detecta y alerta; IPS puede detectar y bloquear/prevenir.

---

## Tarjeta 7

**P:** ¿Qué diferencia hay entre firewall de red y firewall de host?

**R:** El primero protege o controla varias redes/equipos desde la infraestructura; el segundo se ejecuta en un equipo concreto.

---

## Tarjeta 8

**P:** ¿Qué es DENY BY DEFAULT?

**R:** Política en la que se deniega el tráfico por defecto y solo se permiten las comunicaciones expresamente autorizadas.

---

## Tarjeta 9

**P:** ¿Qué diferencia hay entre DROP y REJECT?

**R:** DROP descarta el tráfico sin responder; REJECT rechaza la comunicación notificando el rechazo.

---

## Tarjeta 10

**P:** ¿Qué es un NGFW?

**R:** Firewall de nueva generación con capacidades avanzadas de inspección y control más allá del filtrado tradicional.
