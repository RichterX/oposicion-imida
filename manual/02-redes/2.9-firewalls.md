# El problema

Imaginemos una empresa conectada a Internet.

```
Internet

↓

Empresa
```

Sin ningún tipo de protección.

¿Qué podría ocurrir?

- Cualquier equipo de Internet podría intentar acceder a nuestros servidores.
- Podrían realizarse escaneos de puertos.
- Sería posible intentar ataques automatizados.
- Los equipos internos podrían acceder libremente a cualquier servicio externo.

En definitiva:

No existiría ningún control sobre el tráfico.

Necesitamos un mecanismo que decida:

> **¿Qué comunicaciones están permitidas y cuáles deben bloquearse?**

Ese mecanismo es el:

```
Firewall
```

---

# ¿Qué es un firewall?

Un **firewall** (cortafuegos) es un dispositivo o software encargado de controlar el tráfico de red aplicando un conjunto de reglas de seguridad.

Su función consiste en decidir:

```
¿Permitir?

o

¿Bloquear?
```

cada comunicación que intenta atravesarlo.

Podemos imaginarlo como el control de acceso de un edificio.

No cualquiera puede entrar.

Solo quien cumple las normas establecidas.

---

# ¿Dónde se instala un firewall?

Normalmente encontramos el firewall situado entre la red interna e Internet.

```
Internet

↓

Firewall

↓

Red corporativa
```

Sin embargo, en organizaciones grandes también es habitual encontrar firewalls:

- Entre distintas VLAN.
- Entre departamentos.
- Delante de servidores críticos.
- Protegiendo centros de datos.
- En la nube.

Hoy en día un firewall no protege únicamente el perímetro de la empresa.

También ayuda a segmentar y proteger la propia red interna.

---

# ¿Qué puede controlar un firewall?

Un firewall moderno puede tomar decisiones basándose en numerosos criterios.

Por ejemplo:

- Dirección IP origen.
- Dirección IP destino.
- Puerto origen.
- Puerto destino.
- Protocolo (TCP, UDP, ICMP...).
- Usuario autenticado.
- Aplicación utilizada.
- Hora del día.
- Zona de la red.

Cuantos más criterios pueda analizar, mayor será su capacidad para aplicar políticas de seguridad.

---

# Política de seguridad

Todo firewall funciona mediante reglas.

Por ejemplo:

```
Permitir

↓

HTTPS

↓

Internet → Servidor Web
```

o

```
Bloquear

↓

Telnet

↓

Internet → Red interna
```

Cada paquete que atraviesa el firewall se compara con esas reglas.

La primera regla que coincide determina la acción.

---

# Principio de mínimo privilegio

Una de las mejores prácticas en seguridad consiste en aplicar el principio de:

```
Mínimo privilegio
```

La idea es muy sencilla.

En lugar de permitir todo y bloquear solo lo peligroso:

Se hace exactamente lo contrario.

```
Bloquear todo

↓

Permitir únicamente lo necesario
```

Esta filosofía reduce enormemente la superficie de ataque.

Es una práctica muy habitual en organizaciones y administraciones públicas.

---

# Tipos de firewall

Existen distintos tipos de firewall.

Los más importantes son:

- Filtrado de paquetes.
- Stateful Inspection.
- Firewalls de nueva generación (NGFW).

En este capítulo nos centraremos especialmente en los dos primeros, ya que constituyen la base de la mayoría de soluciones actuales.

---

# Un ejemplo sencillo

Supongamos que un usuario intenta acceder a una página web.

```
PC

↓

Firewall

↓

Internet
```

El firewall analiza la comunicación.

Comprueba las reglas.

Y decide:

```
¿Está permitido HTTPS?

↓

Sí.

↓

La comunicación continúa.
```

Si la regla no existiera:

La conexión sería bloqueada.

---

# El firewall no sustituye al antivirus

Es importante no confundir ambos conceptos.

| Firewall | Antivirus |
|-----------|------------|
| Controla comunicaciones | Analiza archivos y procesos |
| Protege la red | Protege el sistema operativo |
| Trabaja con tráfico de red | Trabaja sobre el equipo |

En una infraestructura moderna ambos mecanismos son complementarios.

---

# Conceptos importantes

Antes de continuar debes recordar:

- Un firewall controla el tráfico de red mediante reglas.
- Puede permitir o bloquear comunicaciones.
- Analiza información como direcciones IP, puertos o protocolos.
- Su objetivo principal es proteger la infraestructura frente a accesos no autorizados.
- El principio de mínimo privilegio recomienda permitir únicamente el tráfico imprescindible.

---

# Filtrado de paquetes

Los primeros firewalls eran relativamente sencillos.

Su funcionamiento consistía en analizar cada paquete de forma independiente.

Para decidir si debía permitirlo o bloquearlo comprobaban información como:

- Dirección IP origen.
- Dirección IP destino.
- Puerto origen.
- Puerto destino.
- Protocolo.

Por este motivo reciben el nombre de:

```
Packet Filtering

(Filtrado de paquetes)
```

---

# ¿Cómo piensa un firewall de filtrado?

Supongamos la siguiente regla.

```
Permitir

Origen:

Cualquiera

Destino:

Servidor Web

Puerto:

443

Protocolo:

TCP
```

Cuando llega un paquete:

```
Cliente

↓

Firewall

↓

¿Coincide con la regla?

↓

Sí

↓

Permitir
```

Si no coincide:

```
Bloquear
```

Cada paquete se analiza de forma completamente independiente.

---

# Un ejemplo

Supongamos un servidor web.

```
Servidor

↓

HTTPS

↓

Puerto 443
```

El firewall recibe un paquete.

```
Origen

200.10.15.8

Destino

Servidor Web

Puerto

443

TCP
```

La regla permite ese tráfico.

Por tanto:

```
Permitir
```

---

# Limitaciones del filtrado de paquetes

Este tipo de firewall presenta un inconveniente importante.

No recuerda nada.

Cada paquete se analiza como si fuera el primero.

Por ejemplo:

Si llega un paquete TCP:

El firewall no sabe:

- Si pertenece a una conexión ya establecida.
- Si forma parte de una respuesta.
- Si alguien intenta suplantar una comunicación.

Simplemente compara el paquete con las reglas.

---

# Stateful Inspection

Los firewalls modernos utilizan una técnica mucho más avanzada.

Se denomina:

```
Stateful Inspection

(Inspección con estado)
```

La idea es sencilla.

Además de analizar cada paquete:

El firewall recuerda las conexiones activas.

---

# Una analogía

Imaginemos el control de acceso de un edificio.

### Filtrado de paquetes

El vigilante mira únicamente el DNI.

Cada vez.

Aunque la misma persona haya entrado hace diez segundos.

No recuerda nada.

---

### Stateful Inspection

Ahora imaginemos otro vigilante.

Además del DNI:

Mantiene una lista de todas las personas que ya han accedido al edificio.

Cuando alguien sale:

Comprueba que realmente había entrado antes.

Recuerda todo el contexto de la visita.

Eso mismo hace un firewall Stateful.

---

# Tabla de estados

Para conseguirlo mantiene una:

```
State Table

(Tabla de estados)
```

En ella registra información como:

- IP origen.
- IP destino.
- Puerto origen.
- Puerto destino.
- Protocolo.
- Estado de la conexión.

Visualmente:

| Origen | Destino | Estado |
|----------|-----------|---------|
|192.168.1.20|172.217.x.x|ESTABLISHED|
|192.168.1.35|193.146.x.x|ESTABLISHED|

Cuando llega un nuevo paquete:

El firewall consulta esta tabla.

---

# Ejemplo

Pedro abre una página web.

```
PC

↓

HTTPS

↓

Servidor Web
```

El firewall observa:

```
Nueva conexión

↓

La registra

↓

Permite el tráfico
```

Cuando llegan los paquetes de respuesta:

```
Servidor

↓

Firewall

↓

¿Pertenece a una conexión existente?

↓

Sí

↓

Permitir
```

No necesita volver a evaluar todas las reglas desde cero.

---

# Ventajas del Stateful Inspection

Las principales ventajas son:

- Mayor seguridad.
- Mejor rendimiento.
- Detección de conexiones inválidas.
- Protección frente a determinadas técnicas de ataque.
- Seguimiento completo de las comunicaciones.

Por ello prácticamente todos los firewalls empresariales actuales funcionan mediante inspección con estado.

---

# ACL (Access Control List)

Las decisiones del firewall se basan en:

```
ACL

Access Control List
```

Una ACL es simplemente un conjunto ordenado de reglas.

Ejemplo:

```
Regla 1

Permitir HTTPS

↓

Regla 2

Permitir DNS

↓

Regla 3

Bloquear Telnet

↓

Regla 4

Bloquear todo lo demás
```

Cada paquete se compara con ellas.

---

# ¿Cómo evalúa una ACL?

El firewall analiza las reglas **de arriba hacia abajo**.

Cuando encuentra la primera coincidencia:

Detiene la búsqueda.

Aplica esa acción.

Visualmente:

```
Paquete

↓

Regla 1

↓

¿Coincide?

↓

No

↓

Regla 2

↓

¿Coincide?

↓

Sí

↓

Aplicar acción

↓

Fin
```

El orden de las reglas es, por tanto, fundamental.

---

# Buenas prácticas al crear ACL

Una ACL bien diseñada suele seguir varias recomendaciones:

- Colocar primero las reglas más específicas.
- Evitar reglas duplicadas.
- Documentar su finalidad.
- Revisarlas periódicamente.
- Finalizar con una regla de denegación por defecto.

Una práctica muy habitual consiste en:

```
Permitir únicamente lo necesario.

↓

Denegar el resto.
```

---

# Diferencia entre ACL y Firewall

Es frecuente confundir ambos conceptos.

| Firewall | ACL |
|-----------|-----|
| Dispositivo o software | Conjunto de reglas |
| Aplica políticas de seguridad | Define qué está permitido y qué no |
| Puede contener muchas ACL | Forma parte de la configuración del firewall |

Podemos decir que:

> **La ACL es el "libro de normas" que utiliza el firewall para tomar decisiones.**

---

# Conceptos importantes

Antes de continuar debes recordar:

- El filtrado de paquetes analiza cada paquete de forma independiente.
- Stateful Inspection mantiene una tabla con el estado de las conexiones.
- Los firewalls modernos utilizan inspección con estado.
- Una ACL es un conjunto ordenado de reglas.
- Las ACL se evalúan de arriba hacia abajo y se aplica la primera coincidencia.

# NAT (Network Address Translation)

En muchas redes corporativas los equipos utilizan direcciones IP privadas.

Por ejemplo:

```
192.168.1.25
```

Sin embargo, esas direcciones **no pueden utilizarse directamente en Internet**.

En algún punto será necesario traducirlas a una dirección pública.

Esa función recibe el nombre de:

```
NAT

Network Address Translation
```

Por el momento basta con recordar que NAT permite que los equipos con direcciones privadas puedan comunicarse con Internet.

Estudiaremos su funcionamiento con detalle en el siguiente capítulo.

---

# PAT (Port Address Translation)

PAT es una variante de NAT.

Permite que **muchos equipos compartan una única dirección IP pública**.

Es el mecanismo utilizado en la mayoría de hogares y empresas.

Gracias a PAT:

```
PC 1

↓

PC 2

↓

PC 3

↓

Router

↓

Una única IP pública
```

Todo ello es posible gracias a la utilización de los números de puerto.

En el próximo capítulo estudiaremos exactamente cómo funciona.

# DMZ (Demilitarized Zone)

Hasta ahora hemos visto dos zonas:

```
Internet

↓

Red interna
```

Pero...

¿Qué ocurre si una empresa necesita publicar un servidor web?

No parece buena idea colocarlo directamente dentro de la red interna.

La solución consiste en crear una zona intermedia.

```
DMZ
```

---

# ¿Qué es una DMZ?

Una **DMZ (Demilitarized Zone)** es una red aislada donde se sitúan los servidores que deben ser accesibles desde Internet.

Visualmente:

```
Internet

↓

Firewall

↓

DMZ

↓

Red interna
```

La DMZ actúa como una zona de separación entre Internet y la red corporativa.

---

# ¿Qué servidores suelen colocarse en una DMZ?

Habitualmente encontramos:

- Servidores Web.
- Servidores de correo.
- Servidores DNS públicos.
- Proxies inversos.
- Servidores FTP públicos.
- Portales corporativos.

Todos ellos necesitan recibir conexiones desde Internet.

---

# ¿Por qué utilizar una DMZ?

Imaginemos que un atacante consigue comprometer un servidor web.

Si ese servidor estuviera dentro de la red interna:

```
Servidor comprometido

↓

Acceso directo a la empresa
```

Las consecuencias podrían ser muy graves.

En cambio, si el servidor se encuentra en una DMZ:

```
Internet

↓

Servidor Web

↓

DMZ

↓

Firewall

↓

Red interna
```

El atacante todavía tendría que superar una nueva capa de protección para alcanzar la red corporativa.

---

# Flujo típico

Una infraestructura sencilla podría representarse así:

```
Internet

↓

Firewall

├───────────────┐

DMZ             LAN

Servidor Web    Usuarios

Servidor Mail   Servidores internos
```

Cada zona posee políticas de seguridad diferentes.

No todo el tráfico está permitido entre ellas.

# FortiGate

Uno de los firewalls empresariales más utilizados actualmente es:

```
FortiGate
```

Fabricado por:

```
Fortinet
```

Es habitual encontrarlo en:

Entre sus capacidades destacan:

- Firewall.
- VPN.
- NAT.
- Filtrado Web.
- IPS (Intrusion Prevention System).

Es un claro ejemplo de:

```
NGFW
```

# Buenas prácticas

Al administrar un firewall FortiGate es recomendable:

- Cambiar las contraseñas por defecto.
- Actualizar el firmware periódicamente.
- Utilizar HTTPS o SSH para la administración.
- Realizar copias de seguridad de la configuración.
- Revisar regularmente los registros de eventos.
- Aplicar el principio de mínimo privilegio.

Estas recomendaciones son aplicables a prácticamente cualquier firewall empresarial.

---

# ⚠️ Errores clásicos de oposición

❌ Pensar que NAT proporciona seguridad por sí mismo.

➡️ NAT traduce direcciones IP.

La seguridad la proporcionan las políticas del firewall.

---

❌ Creer que una DMZ forma parte de la red interna.

➡️ Es una zona independiente diseñada para alojar servicios accesibles desde Internet.

---

❌ Pensar que todos los servidores deben ubicarse en la DMZ.

➡️ Solo aquellos que necesiten ser accesibles desde redes externas.

Los servidores internos (por ejemplo, bases de datos o Controladores de Dominio) normalmente permanecen en la red corporativa.

---

❌ Confundir FortiGate con un simple router.

➡️ FortiGate es un firewall de nueva generación que integra múltiples funciones de seguridad.

# 📖 Resumen final

Los firewalls constituyen uno de los elementos fundamentales de la seguridad en redes. Controlan el tráfico mediante reglas, analizan las conexiones utilizando técnicas como el **Stateful Inspection** y aplican políticas definidas mediante **ACL**. Además, integran funciones complementarias como **NAT**, **PAT** y la gestión de **DMZ**, permitiendo proteger tanto la red interna como los servicios expuestos a Internet. Soluciones empresariales como **FortiGate** reúnen estas capacidades en una única plataforma, convirtiéndose en una pieza clave de las infraestructuras de red modernas.
