# ¿Qué es una red informática?

Una **red informática** es un conjunto de dispositivos interconectados que pueden comunicarse entre sí para compartir información, recursos y servicios.

Estos dispositivos pueden intercambiar datos gracias a un conjunto de reglas denominadas **protocolos de comunicación**, utilizando distintos medios físicos o inalámbricos.

Una red permite, por ejemplo:

- Compartir archivos.
- Compartir impresoras.
- Acceder a Internet.
- Utilizar servidores centralizados.
- Compartir bases de datos.
- Administrar usuarios de forma centralizada.
- Comunicarse mediante correo electrónico, videoconferencia o mensajería.

Actualmente prácticamente todas las organizaciones utilizan redes informáticas, desde pequeñas oficinas hasta grandes centros de datos distribuidos por todo el mundo.

---

# Componentes básicos de una red

Aunque existen multitud de dispositivos, los componentes fundamentales de una red suelen ser los siguientes:

## Equipos cliente

Son los dispositivos utilizados por los usuarios finales.

Ejemplos:

- Ordenadores.
- Portátiles.
- Smartphones.
- Tablets.

Los clientes consumen los recursos ofrecidos por otros equipos de la red.

---

## Servidores

Son equipos que ofrecen servicios al resto de dispositivos.

Algunos ejemplos son:

- Servidor web.
- Servidor de archivos.
- Servidor DNS.
- Servidor DHCP.
- Servidor de correo.
- Controlador de Dominio.

En una organización es habitual que varios servidores trabajen conjuntamente.

---

## Dispositivos de interconexión

Permiten conectar los diferentes equipos de la red.

Los más habituales son:

- Switches.
- Routers.
- Firewalls.
- Puntos de acceso Wi-Fi.

Cada uno desempeña una función diferente, que estudiaremos en capítulos posteriores.

---

## Medio de transmisión

Es el canal utilizado para transportar la información entre dispositivos.

Puede ser:

### Cableado

- Par trenzado (UTP/STP).
- Fibra óptica.
- Cable coaxial (actualmente muy poco utilizado en redes LAN).

### Inalámbrico

- Wi-Fi.
- Redes móviles.
- Radio.
- Enlaces punto a punto.

El medio utilizado influye directamente en la velocidad, el alcance y la fiabilidad de la comunicación.

---

# ¿Cómo viaja la información?

Cuando un usuario solicita una página web, envía un correo electrónico o accede a un servidor, la información no viaja como un único bloque.

Los datos se dividen en pequeñas unidades llamadas **paquetes**, que recorren la red hasta llegar al destino.

Cada paquete puede seguir rutas distintas y posteriormente reconstruirse correctamente gracias a los protocolos de comunicación.

Este mecanismo mejora la eficiencia y la fiabilidad de la transmisión.

---

# Elementos fundamentales de una comunicación

Para que exista comunicación entre dos dispositivos son necesarios, al menos:

- Un emisor.
- Un receptor.
- Un medio de transmisión.
- Un lenguaje común (protocolo).
- Un mensaje.

Si alguno de estos elementos falla, la comunicación no podrá establecerse correctamente.

---

# ¿Qué es un protocolo?

Un **protocolo** es un conjunto de normas que define cómo deben comunicarse los dispositivos de una red.

Gracias a los protocolos, equipos fabricados por empresas diferentes pueden intercambiar información correctamente.

Algunos protocolos muy conocidos son:

- HTTP
- HTTPS
- FTP
- SSH
- DNS
- DHCP
- SMTP
- POP3
- IMAP

Cada protocolo está diseñado para una función concreta y será estudiado en capítulos posteriores.

# Clasificación de las redes según su alcance

Las redes informáticas pueden clasificarse atendiendo a la extensión geográfica que abarcan. Esta clasificación permite comprender qué tecnologías son más adecuadas en cada situación y qué dispositivos suelen intervenir.

Las más habituales son:

- PAN
- LAN
- MAN
- WAN

Aunque **PAN** no aparecía inicialmente en el índice, es conveniente conocerla porque ocasionalmente aparece en preguntas tipo test.

---

## PAN (Personal Area Network)

Una **PAN (Personal Area Network)** es una red de muy corto alcance destinada a conectar dispositivos personales.

Su cobertura suele limitarse a unos pocos metros.

### Ejemplos

- Un teléfono móvil conectado a unos auriculares Bluetooth.
- Un smartwatch sincronizado con un smartphone.
- Un portátil utilizando un ratón inalámbrico.

### Tecnologías habituales

- Bluetooth
- NFC
- USB
- Infrarrojos (prácticamente en desuso)

### Características

- Alcance muy reducido.
- Bajo consumo energético.
- Pocos dispositivos conectados.
- Administración muy sencilla.

---

## LAN (Local Area Network)

Una **LAN** conecta dispositivos dentro de un área geográfica pequeña.

Es el tipo de red más habitual en:

- Empresas.
- Institutos.
- Universidades.
- Oficinas.
- Viviendas.

Generalmente pertenece a una única organización.

### Características

- Alta velocidad.
- Baja latencia.
- Administración propia.
- Coste relativamente reducido.

### Ejemplo

```
Empresa

PC1
│
├──── Switch ─── Servidor
│
├──── PC2
│
└──── Impresora
```

Todo el edificio comparte la misma red local.

---

## MAN (Metropolitan Area Network)

Una **MAN** conecta varias LAN distribuidas dentro de una misma ciudad o área metropolitana.

Habitualmente es utilizada por:

- Ayuntamientos.
- Universidades con varios campus.
- Hospitales.
- Grandes empresas con distintas sedes en una misma ciudad.

### Características

- Cobertura de varios kilómetros.
- Alta velocidad.
- Conecta múltiples LAN.

### Ejemplo

```
Campus Norte

        │

Campus Centro

        │

Campus Sur
```

Los distintos edificios funcionan como una única infraestructura.

---

## WAN (Wide Area Network)

Una **WAN** conecta redes situadas en grandes áreas geográficas.

Puede abarcar:

- Países.
- Continentes.
- Todo el planeta.

Internet constituye el ejemplo más conocido de WAN.

### Características

- Gran alcance.
- Mayor latencia.
- Menor velocidad que una LAN (en igualdad de tecnología).
- Utiliza infraestructuras de operadores de telecomunicaciones.

### Ejemplo

```
Madrid

      │

Murcia

      │

París

      │

Nueva York
```

Todas las sedes permanecen conectadas.

---

# Comparativa PAN, LAN, MAN y WAN

| Tipo | Alcance | Ejemplo |
|-------|----------|----------|
| PAN | Pocos metros | Bluetooth |
| LAN | Edificio | Empresa |
| MAN | Ciudad | Universidad |
| WAN | Países o continentes | Internet |

# Topologías de red

Una **topología** describe la forma en que los dispositivos se encuentran conectados físicamente o de forma lógica.

Elegir una topología adecuada influye en aspectos como:

- Rendimiento.
- Escalabilidad.
- Tolerancia a fallos.
- Coste de implantación.
- Facilidad de mantenimiento.

Las topologías más importantes son:

- Bus.
- Estrella.
- Anillo.
- Malla.
- Árbol.
- Híbrida.

---

## Topología en bus

Todos los dispositivos comparten un único cable principal.

```
PC ─── PC ─── PC ─── PC
```

### Ventajas

- Muy económica.
- Fácil de instalar.

### Inconvenientes

- Un fallo en el cable principal afecta a toda la red.
- Muchas colisiones.
- Muy difícil de ampliar.

Actualmente prácticamente no se utiliza.

---

## Topología en estrella

Todos los dispositivos se conectan a un equipo central (normalmente un switch).

```
         Switch

      /    |    \

    PC    PC    PC

          |

      Servidor
```

Es la topología más utilizada en la actualidad.

### Ventajas

- Muy sencilla de ampliar.
- Fácil de administrar.
- Un fallo en un cable solo afecta a ese equipo.

### Inconveniente

Si falla el switch central, toda la red deja de funcionar.

---

---

## Topología en anillo

En una topología en **anillo**, cada dispositivo se conecta únicamente con sus dos vecinos inmediatos, formando un circuito cerrado.

```
      PC1
    /     \
  PC2     PC4
    \     /
      PC3
```

Los datos circulan siguiendo el anillo hasta alcanzar el equipo de destino.

Dependiendo de la implementación, la comunicación puede realizarse:

- En un único sentido.
- En ambos sentidos (anillo doble).

### Ventajas

- No existen colisiones como en una topología en bus.
- El rendimiento es predecible cuando el tráfico es elevado.

### Inconvenientes

- Un fallo en un único enlace puede interrumpir toda la comunicación (salvo anillos redundantes).
- Ampliar la red resulta más complejo.

Actualmente apenas se utiliza en redes LAN modernas, aunque algunos sistemas industriales y de telecomunicaciones siguen empleando variantes de esta topología.

---

## Topología en malla

En una topología en **malla**, los dispositivos disponen de múltiples conexiones entre sí.

```
      PC1
     / | \
   /   |   \
 PC2---PC3---PC4
```

Existen dos variantes:

### Malla completa

Cada dispositivo está conectado con todos los demás.

### Malla parcial

Solo algunos dispositivos mantienen múltiples conexiones.

---

### Ventajas

- Muy alta disponibilidad.
- Excelente tolerancia a fallos.
- Existen múltiples rutas alternativas.

---

### Inconvenientes

- Elevado coste.
- Gran cantidad de cableado.
- Configuración más compleja.

---

Su uso es habitual en:

- Centros de datos.
- Redes de operadores.
- Infraestructuras críticas.
- Backbone de Internet.

---

## Topología en árbol

La topología en árbol combina varias estrellas formando una estructura jerárquica.

```
             Core Switch
            /           \
      Switch A       Switch B
      /   |   \        /   |   \
    PC   PC  PC     PC   PC  Servidor
```

Es probablemente la topología más utilizada en organizaciones medianas y grandes.

---

### Ventajas

- Muy escalable.
- Fácil administración.
- Permite segmentar la red.

---

### Inconvenientes

- Si falla el nodo raíz pueden verse afectados numerosos equipos.
- Requiere un diseño adecuado.

---

## Topología híbrida

En la práctica, la mayoría de las redes actuales utilizan una combinación de varias topologías.

Por ejemplo:

- Estrella dentro de cada edificio.
- Malla entre centros de datos.
- WAN para comunicar sedes.

Por ello se habla de **topologías híbridas**.

---

# Comparativa de topologías

| Topología | Ventaja principal | Inconveniente principal |
|------------|------------------|-------------------------|
| Bus | Muy económica | Poco fiable |
| Estrella | Fácil de ampliar | Dependencia del switch |
| Anillo | Sin colisiones | Difícil ampliación |
| Malla | Alta disponibilidad | Muy costosa |
| Árbol | Escalable | Dependencia de la jerarquía |
| Híbrida | Flexible | Diseño más complejo |

# ¿Por qué existen los modelos por capas?

Imaginemos que dos fabricantes desarrollan ordenadores completamente distintos.

Si cada uno diseñara su propio método para enviar información, ambos equipos serían incapaces de comunicarse.

Para evitar este problema surgieron los **modelos de referencia**.

Un modelo divide la comunicación en pequeñas tareas independientes.

Cada capa se ocupa únicamente de una función concreta.

De esta forma:

- Cada fabricante puede desarrollar sus propios dispositivos.
- Todos siguen las mismas reglas.
- Equipos distintos pueden comunicarse correctamente.

Es exactamente la misma idea que una cadena de montaje.

Cada operario realiza una única tarea y el resultado final funciona correctamente.

---

# Modelo OSI

El **Modelo OSI (Open Systems Interconnection)** fue desarrollado por la **ISO (International Organization for Standardization)** para establecer un marco común de comunicaciones entre sistemas abiertos.

Su objetivo principal no era crear protocolos nuevos, sino definir una arquitectura estándar que permitiera que equipos de distintos fabricantes pudieran comunicarse siguiendo las mismas reglas.

El modelo divide el proceso de comunicación en **siete capas**, donde cada una tiene una responsabilidad concreta y ofrece servicios a la capa superior mientras utiliza los servicios de la inferior.

Esta separación facilita:

- El diseño de protocolos.
- La interoperabilidad entre fabricantes.
- La resolución de problemas.
- La evolución de las tecnologías sin afectar al resto del sistema.

Aunque Internet utiliza realmente el modelo TCP/IP, el modelo OSI sigue siendo la referencia utilizada para aprender redes y diagnosticar incidencias.

---

# Las siete capas del modelo OSI

Desde el usuario hasta el cable:

```
7 Aplicación

6 Presentación

5 Sesión

4 Transporte

3 Red

2 Enlace de datos

1 Física
```

Una forma clásica de memorizarlo es recordar que los datos "bajan" desde la aplicación hasta el medio físico cuando se envían y "suben" en sentido contrario cuando se reciben.

**No es necesario memorizar todavía qué hace cada capa.**

En el siguiente apartado veremos la función de cada una y comprenderemos por qué están organizadas precisamente de esta manera.

---

# ¿Qué hace cada capa del modelo OSI?

Ahora que conocemos las siete capas, veamos qué función desempeña cada una siguiendo un ejemplo real.

Supongamos que Pedro abre su navegador y accede a:

```
https://www.imida.es
```

Desde que pulsa **Enter** hasta que la página aparece en pantalla, los datos atraviesan las siete capas del modelo OSI.

---

## Capa 7 · Aplicación

Es la capa más cercana al usuario.

Aquí se encuentran las aplicaciones y protocolos que utilizamos diariamente.

Ejemplos:

- HTTP / HTTPS
- FTP
- SSH
- DNS
- SMTP
- POP3
- IMAP

Cuando escribimos una dirección web, el navegador genera una petición HTTP o HTTPS.

---

## Capa 6 · Presentación

Su misión consiste en preparar los datos para que puedan ser interpretados correctamente.

Entre sus funciones destacan:

- Codificación.
- Compresión.
- Cifrado.

Por ejemplo:

Cuando accedemos mediante HTTPS, esta capa participa en el cifrado de la información utilizando TLS.

---

## Capa 5 · Sesión

Gestiona el establecimiento, mantenimiento y cierre de las comunicaciones entre aplicaciones.

Se encarga de:

- Abrir sesiones.
- Mantenerlas activas.
- Cerrarlas correctamente.

Aunque actualmente muchas de estas funciones son asumidas por otros protocolos, sigue siendo una capa importante desde el punto de vista conceptual.

---

## Capa 4 · Transporte

Garantiza que la información llegue correctamente al destino.

Sus funciones principales son:

- Fragmentación de datos.
- Control de errores.
- Control de flujo.
- Reenvío de segmentos perdidos.

Los protocolos más importantes son:

- TCP
- UDP

**TCP** garantiza la entrega.

**UDP** prioriza la velocidad.

Estudiaremos ambos protocolos con detalle más adelante.

---

## Capa 3 · Red

Su misión consiste en llevar los datos desde el origen hasta el destino, incluso aunque tengan que atravesar múltiples redes.

Aquí aparece uno de los conceptos más importantes de todo el bloque:

👉 **La dirección IP.**

Los routers trabajan principalmente en esta capa.

Protocolo principal:

- IP

---

## Capa 2 · Enlace de datos

Permite la comunicación entre dispositivos conectados a la misma red física.

Aquí aparecen conceptos como:

- Direcciones MAC.
- Switches.
- Tramas Ethernet.
- ARP.

Cuando un switch recibe una trama Ethernet, toma sus decisiones utilizando la dirección MAC.

---

## Capa 1 · Física

Es la capa más cercana al hardware.

Se ocupa de transmitir los bits mediante el medio físico.

Ejemplos:

- Cable UTP.
- Fibra óptica.
- Wi-Fi.
- Conectores RJ45.

Aquí no existen todavía direcciones IP ni direcciones MAC.

Únicamente viajan señales eléctricas, ópticas o de radio.

---

# Resumen rápido del modelo OSI

| Capa | Función principal | Ejemplos |
|------:|-------------------|-----------|
| 7 | Aplicación | HTTP, HTTPS, DNS, SMTP |
| 6 | Presentación | Cifrado, compresión |
| 5 | Sesión | Gestión de sesiones |
| 4 | Transporte | TCP, UDP |
| 3 | Red | IP, routers |
| 2 | Enlace | Ethernet, MAC, switches |
| 1 | Física | Cable, fibra, Wi-Fi |

---

# Modelo TCP/IP

Aunque el modelo OSI es el utilizado para explicar el funcionamiento de las redes, Internet utiliza realmente el **modelo TCP/IP**.

Este modelo simplifica las siete capas del modelo OSI en cuatro.

| Modelo TCP/IP | Capas OSI equivalentes |
|---------------|------------------------|
| Aplicación | 5, 6 y 7 |
| Transporte | 4 |
| Internet | 3 |
| Acceso a la red | 1 y 2 |

La mayoría de protocolos actuales se diseñan siguiendo este modelo.

---

# Comparación OSI vs TCP/IP

| Modelo OSI | Modelo TCP/IP |
|-------------|---------------|
| 7 capas | 4 capas |
| Modelo teórico | Modelo práctico |
| ISO | Departamento de Defensa de EE. UU. (DoD) |
| Referencia académica | Base de Internet |

> **💡 Consejo para la oposición:** cuando una pregunta hable de "modelo de referencia", normalmente se refiere al **modelo OSI**. Cuando pregunte por el funcionamiento real de Internet, la respuesta suele ser **TCP/IP**.

# Encapsulación

La **encapsulación** es el proceso mediante el cual cada capa añade su propia información antes de enviar los datos a la siguiente.

Imaginemos que enviamos un mensaje:

```
Hola
```

Durante el envío ocurre lo siguiente:

```
Aplicación

↓

Datos

↓

Transporte

↓

Segmento

↓

Red

↓

Paquete

↓

Enlace

↓

Trama

↓

Física

↓

Bits
```

Cada capa añade una cabecera con la información necesaria para que la siguiente pueda realizar su trabajo.

En el equipo receptor ocurre el proceso inverso, denominado **desencapsulación**, eliminando las cabeceras capa a capa hasta recuperar el mensaje original.

# ¿Qué es un protocolo?

Un **protocolo** es un conjunto de normas que define cómo deben comunicarse los dispositivos de una red.

Gracias a ellos, equipos fabricados por empresas diferentes pueden intercambiar información sin problemas.

Algunos de los protocolos más importantes son:

| Protocolo | Función |
|------------|----------|
| HTTP | Navegación web |
| HTTPS | Navegación web segura |
| FTP | Transferencia de archivos |
| SSH | Administración remota segura |
| DNS | Resolución de nombres |
| DHCP | Asignación automática de IP |
| SMTP | Envío de correo |
| POP3 | Recepción de correo |
| IMAP | Sincronización de correo |
