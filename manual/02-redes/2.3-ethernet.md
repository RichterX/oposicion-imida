# ¿Qué es Ethernet?

**Ethernet** es el conjunto de tecnologías que permite la comunicación entre dispositivos dentro de una red local (LAN).

Cuando varios ordenadores están conectados mediante un switch y un cable de red, lo que realmente están utilizando es Ethernet.

Actualmente es, con diferencia, la tecnología más empleada en redes cableadas de empresas, administraciones públicas y centros de datos.

Aunque solemos decir simplemente "la red", en realidad nos referimos a una red Ethernet.

---

# Un poco de historia

Ethernet fue desarrollado en la década de 1970 por Xerox PARC.

Posteriormente evolucionó hasta convertirse en un estándar internacional gestionado por el **IEEE**.

Desde entonces ha ido aumentando enormemente su velocidad:

| Tecnología | Velocidad |
|------------|-----------|
| Ethernet | 10 Mbps |
| Fast Ethernet | 100 Mbps |
| Gigabit Ethernet | 1 Gbps |
| 10 Gigabit Ethernet | 10 Gbps |
| 40/100 Gigabit Ethernet | Centros de datos |

Hoy en día, lo habitual en empresas es encontrar redes Gigabit Ethernet (1000 Mbps).

---

# IEEE 802.3

Ethernet está definido por el estándar **IEEE 802.3**.

El **IEEE (Institute of Electrical and Electronics Engineers)** es una organización internacional encargada de desarrollar numerosos estándares tecnológicos.

Dentro de la familia IEEE 802 encontramos varios estándares muy conocidos:

| Estándar | Tecnología |
|-----------|------------|
| IEEE 802.3 | Ethernet |
| IEEE 802.11 | Wi-Fi |
| IEEE 802.1Q | VLAN |
| IEEE 802.1X | Control de acceso a la red |

En oposición es frecuente preguntar simplemente:

> **¿Qué estándar define Ethernet?**

La respuesta correcta es:

**IEEE 802.3**

# ¿Cómo identifica Ethernet a los dispositivos?

Hasta ahora hemos aprendido que un ordenador posee una dirección IP.

Sin embargo, Ethernet **no utiliza direcciones IP para mover las tramas dentro de una red local**.

Utiliza otro identificador denominado:

# Dirección MAC

La dirección **MAC (Media Access Control)** identifica de forma única una interfaz de red.

Cada tarjeta de red dispone de su propia dirección MAC.

Podemos imaginarla como el "número de serie" del adaptador de red.

---

# Formato de una dirección MAC

Una dirección MAC tiene una longitud de **48 bits**.

Habitualmente se representa mediante seis grupos de dos dígitos hexadecimales.

Ejemplo:

```
00:1A:2B:3C:4D:5E
```

También puede escribirse así:

```
00-1A-2B-3C-4D-5E
```

o incluso:

```
001A.2B3C.4D5E
```

Dependiendo del fabricante o del sistema operativo.

---

# ¿Qué significa cada parte?

Una dirección MAC se divide en dos partes:

```
00:1A:2B

↓

Fabricante

(OUI)

-------------------------

3C:4D:5E

↓

Número único del dispositivo
```

Los tres primeros bytes identifican al fabricante de la tarjeta de red.

Los tres últimos identifican el dispositivo concreto.

---

# Diferencias entre IP y MAC

Es muy habitual que el tribunal pregunte por las diferencias entre ambas.

| Dirección IP | Dirección MAC |
|---------------|---------------|
| Identifica una interfaz de forma lógica | Identifica una interfaz físicamente |
| Puede cambiar | Normalmente permanece fija |
| Trabaja en la capa 3 | Trabaja en la capa 2 |
| Utilizada por routers | Utilizada por switches |
| Ejemplo: 192.168.1.25 | Ejemplo: 00:1A:2B:3C:4D:5E |

Una forma sencilla de recordarlo es:

**IP = dónde está el equipo.**

**MAC = quién es el equipo.**

---

# ¿Por qué existen ambas?

Imaginemos una empresa.

La dirección IP sería similar a la dirección de una oficina:

```
Planta 2

Despacho 14
```

La dirección MAC sería comparable al número de serie del ordenador que hay dentro de ese despacho.

Si el ordenador cambia de despacho (cambia de red), su IP puede cambiar.

Sin embargo, el número de serie del equipo seguirá siendo el mismo.

Con las direcciones MAC ocurre exactamente igual.

---

# Buenas prácticas

Conviene recordar las siguientes ideas:

- La dirección MAC pertenece a la tarjeta de red.
- Una IP puede modificarse mediante configuración manual o DHCP.
- Una misma máquina puede tener varias direcciones MAC si dispone de varias interfaces de red.
- Las direcciones MAC se utilizan únicamente dentro del enlace local; no viajan intactas a través de Internet.

# La trama Ethernet

En el capítulo anterior vimos que los datos se encapsulan a medida que atraviesan las capas del modelo OSI.

Cuando los datos llegan a la **capa 2 (Enlace de Datos)**, se encapsulan dentro de una **trama Ethernet**.

Una trama Ethernet es la unidad de información que viaja por una red Ethernet.

De forma simplificada, una trama contiene:

```
┌──────────────────────────────────────────────┐
│ Dirección MAC destino                        │
├──────────────────────────────────────────────┤
│ Dirección MAC origen                         │
├──────────────────────────────────────────────┤
│ Tipo (EtherType)                             │
├──────────────────────────────────────────────┤
│ Datos (paquete IP)                           │
├──────────────────────────────────────────────┤
│ FCS (detección de errores)                   │
└──────────────────────────────────────────────┘
```

No es necesario memorizar todos los campos, pero sí comprender la idea principal:

> **Ethernet no transporta directamente una IP. Transporta una trama que contiene un paquete IP en su interior.**

---

# Del paquete a la trama

Supongamos que Pedro quiere enviar un documento a María.

Pedro conoce la IP de María:

```
192.168.1.40
```

Cuando la información baja por las capas del modelo OSI ocurre algo parecido a esto:

```
Aplicación

↓

HTTP

↓

TCP

↓

IP

↓

Ethernet

↓

Trama Ethernet

↓

Cable
```

Es decir:

El paquete IP queda encapsulado dentro de una trama Ethernet.

---

# ¿Cómo sabe la trama a quién debe entregarse?

Aquí aparece una pregunta muy importante.

Pedro conoce la IP:

```
192.168.1.40
```

Pero Ethernet **no trabaja con IP**.

Trabaja con:

```
MAC
```

Entonces...

> **¿Cómo averigua Pedro la dirección MAC de María?**

La respuesta es:

**ARP.**

Pero antes necesitamos comprender cómo funciona el switch.

---

# El switch

Un **switch** es el dispositivo encargado de interconectar equipos dentro de una red Ethernet.

Su función consiste en recibir tramas Ethernet y enviarlas únicamente al puerto donde se encuentra el destinatario.

Trabaja principalmente en la:

```
Capa 2

↓

Enlace de Datos
```

Por ello utiliza:

```
Direcciones MAC
```

No toma decisiones utilizando direcciones IP.

---

# La tabla MAC (CAM Table)

Todo switch mantiene una tabla interna donde relaciona:

```
Dirección MAC

↓

Puerto físico
```

Por ejemplo:

| Puerto | Dirección MAC |
|----------|----------------|
| 1 | 00:11:22:33:44:01 |
| 2 | 00:11:22:33:44:02 |
| 3 | 00:11:22:33:44:03 |
| 4 | Servidor |

Gracias a esta tabla sabe exactamente dónde enviar cada trama.

---

# ¿Cómo aprende un switch?

Aquí ocurre algo muy interesante.

Cuando el switch recibe una trama:

```
MAC origen

00:11:22:33:44:55
```

lo primero que hace es:

```
Aprender

↓

Esa MAC está conectada al puerto 5.
```

Es decir, el switch **aprende automáticamente** observando las MAC de origen.

No hace falta configurarlas manualmente.

Este proceso recibe el nombre de **aprendizaje MAC (MAC Learning)**.

---

# ¿Qué ocurre si no conoce el destino?

Supongamos la siguiente situación.

Pedro envía una trama.

El switch conoce la MAC de Pedro.

Pero todavía **no sabe dónde está María**.

Entonces realiza una operación denominada:

```
Flooding
```

Consiste en enviar la trama por **todos los puertos**, excepto por aquel desde el que la recibió.

```
             Switch

         /   |   |   \

       PC   PC   PC   PC

          ↑

     Llega una trama

↓

El switch no conoce el destino.

↓

La envía a todos.
```

Cuando María responde, el switch aprende también su MAC.

A partir de ese momento ya no volverá a inundar la red para comunicarse con ella.

---

# Ventajas del switch

Comparado con los antiguos hubs, un switch ofrece numerosas ventajas:

- Reduce el tráfico innecesario.
- Evita la mayoría de las colisiones.
- Aumenta el rendimiento.
- Aprende automáticamente la ubicación de los equipos.
- Escala mucho mejor.

Por este motivo los hubs prácticamente han desaparecido de las redes modernas.

---

# Switch vs Hub

| Hub | Switch |
|------|---------|
| Repite todo | Envía solo al destino |
| No aprende | Aprende MAC automáticamente |
| Muchas colisiones | Muy pocas colisiones |
| Poco eficiente | Muy eficiente |

Es muy frecuente que el tribunal pregunte esta diferencia.

# El problema pendiente...

Hasta ahora sabemos que:

Pedro quiere enviar información a:

```
192.168.1.40
```

Pero Ethernet necesita conocer una MAC.

Pedro solo conoce una IP.

Entonces...

> **¿Cómo obtiene la dirección MAC correspondiente a esa IP?**

La respuesta es el protocolo:

```
ARP
```

Y precisamente será el siguiente apartado.

---

# ARP (Address Resolution Protocol)

El protocolo **ARP (Address Resolution Protocol)** permite obtener la dirección **MAC** correspondiente a una dirección **IP** dentro de una red local.

Recordemos:

Pedro quiere enviar información a:

```
192.168.1.40
```

Pedro conoce la IP.

Pero Ethernet necesita una MAC.

ARP actúa como un "traductor" entre ambos mundos.

```
IP

↓

ARP

↓

MAC
```

Por ello se dice que ARP realiza una **resolución de direcciones**.

---

# ¿Cuándo se utiliza ARP?

ARP solo se utiliza cuando el destino pertenece a la **misma red local**.

Ejemplo:

```
Pedro

192.168.1.25

↓

María

192.168.1.40
```

Ambos pertenecen a:

```
192.168.1.0/24
```

Como están en la misma red, Pedro necesita conocer la MAC de María.

Aquí entra en funcionamiento ARP.

---

# Paso a paso

Supongamos:

```
Pedro

IP

192.168.1.25

MAC

00:11:22:33:44:55
```

Quiere enviar información a:

```
María

IP

192.168.1.40
```

Pero desconoce su dirección MAC.

Entonces ocurre lo siguiente.

---

## Paso 1 · Comprobación de la caché ARP

Antes de preguntar nada, Pedro consulta una pequeña tabla almacenada en memoria denominada:

```
ARP Cache
```

En ella guarda las asociaciones IP ⇄ MAC utilizadas recientemente.

Ejemplo:

| Dirección IP | Dirección MAC |
|---------------|----------------|
|192.168.1.1|AA:AA:AA:AA:AA:AA|
|192.168.1.30|BB:BB:BB:BB:BB:BB|

Si encuentra la dirección buscada, el proceso termina aquí.

Si no aparece...

Continúa con el siguiente paso.

---

## Paso 2 · ARP Request

Pedro envía una petición ARP.

La pregunta es muy sencilla:

> **¿Quién tiene la IP 192.168.1.40?**

La petición se envía mediante **broadcast**.

Destino:

```
FF:FF:FF:FF:FF:FF
```

Esta dirección MAC especial significa:

```
Todos los equipos de la red.
```

Por tanto, todos reciben la petición.

---

## Paso 3 · Todos escuchan

El switch recibe la trama.

Como es un broadcast:

La envía por todos sus puertos.

Todos los equipos la reciben.

Cada uno compara la IP solicitada con la suya.

---

## Paso 4 · Responde únicamente María

Solo un equipo responde.

```
María

↓

Sí.

Yo soy

192.168.1.40
```

Entonces envía un:

```
ARP Reply
```

Que contiene:

```
Mi MAC es:

44:55:66:77:88:99
```

A diferencia del ARP Request, esta respuesta se envía únicamente a Pedro (unicast).

---

## Paso 5 · Actualización de la caché

Pedro almacena la nueva asociación.

```
192.168.1.40

↓

44:55:66:77:88:99
```

Así no tendrá que volver a preguntar durante un tiempo.

---

## Paso 6 · Envío de la trama

Ahora sí.

Pedro puede construir la trama Ethernet.

```
Destino

44:55:66:77:88:99

Origen

00:11:22:33:44:55

Datos

Paquete IP
```

El switch consulta su tabla MAC y la entrega únicamente a María.

La comunicación queda establecida.

---

# El proceso completo

Visualmente:

```
Pedro quiere enviar un archivo

↓

↓

No conoce la MAC

↓

↓

↓

↓

↓

```

Supongamos ahora:

```
Pedro

```

Quiere acceder a:

```

```

Pedro comprueba la máscara.

Descubre que:

```
8.8.8.8

↓

```

Entonces ya no necesita la MAC del servidor de Google.

Necesita la MAC del:

```

```

Por tanto:

El router será quien continúe el envío hacia Internet.

Esta es una pregunta muy habitual en las oposiciones.

# 🎓 Resumen del capítulo

Al finalizar este capítulo debes recordar las siguientes ideas:

- Ethernet está definido por el estándar IEEE 802.3.
- Ethernet utiliza direcciones MAC para comunicar dispositivos dentro de una LAN.
- Una dirección MAC tiene 48 bits y suele representarse en hexadecimal.
- Los switches trabajan principalmente en la capa de Enlace (capa 2) y toman decisiones basadas en direcciones MAC.
- Un switch aprende automáticamente las direcciones MAC observando las tramas que recibe.
- Si no conoce la MAC de destino, realiza flooding.
- ARP permite obtener la dirección MAC asociada a una dirección IP dentro de la misma red local.
- Las peticiones ARP se envían por broadcast y las respuestas ARP por unicast.
- Si el destino pertenece a otra red, ARP resuelve la MAC del gateway, no la del destino final.

# 📖 Resumen final

Ethernet constituye la tecnología predominante en las redes locales modernas y se basa en la transmisión de tramas identificadas mediante direcciones MAC. Los switches optimizan el tráfico aprendiendo automáticamente la ubicación de cada dispositivo, mientras que el protocolo ARP actúa como puente entre el direccionamiento lógico (IP) y el físico (MAC). Comprender cómo interactúan Ethernet, switches y ARP resulta esencial para entender el funcionamiento de una LAN y constituye la base para los próximos capítulos dedicados a DNS, DHCP, VLAN y el encaminamiento de paquetes.
