# El problema

Imaginemos una empresa con 800 ordenadores.

Cada equipo necesita conocer como mínimo:

- Dirección IP.
- Máscara de red.
- Gateway.
- Servidor DNS.

Una posibilidad sería configurar manualmente todos esos datos.

Sin embargo, esto tendría numerosos inconvenientes:

- Muchísimo tiempo de administración.
- Errores humanos.
- Conflictos de direcciones IP.
- Dificultad para sustituir equipos.
- Escasa escalabilidad.

Claramente necesitamos una solución mejor.

---

# ¿Qué es DHCP?

**DHCP (Dynamic Host Configuration Protocol)** es un protocolo que permite asignar automáticamente la configuración de red a los dispositivos que se conectan a una red.

Gracias a DHCP, un equipo puede obtener automáticamente:

- Dirección IP.
- Máscara de red.
- Gateway.
- Servidores DNS.
- Tiempo de concesión (Lease).
- Otros parámetros adicionales.

Todo ello sin intervención del usuario.

---

# Un ejemplo cotidiano

Supongamos que compramos un portátil nuevo.

Llegamos a casa.

Lo conectamos al Wi-Fi.

Unos segundos después...

Ya tenemos Internet.

En ningún momento hemos configurado:

- IP.
- Máscara.
- Gateway.
- DNS.

Todo ese trabajo lo ha realizado automáticamente DHCP.

---

# Antes de DHCP...

Hace años era habitual configurar manualmente cada ordenador.

Por ejemplo:

```
IP

192.168.1.15

Máscara

255.255.255.0

Gateway

192.168.1.1

DNS

8.8.8.8
```

En una red pequeña podía ser aceptable.

En una organización con cientos o miles de equipos era completamente inviable.

DHCP resolvió este problema automatizando todo el proceso.

---

# ¿Cómo funciona DHCP?

La idea es muy sencilla.

Existe un servidor DHCP que dispone de un conjunto de direcciones IP disponibles.

Cuando un nuevo dispositivo se conecta a la red:

```
Cliente

↓

Necesito una dirección IP
```

El servidor responde:

```
Puedes utilizar esta.

192.168.1.25
```

Y además le proporciona el resto de la configuración necesaria.

---

# Componentes del sistema DHCP

En cualquier infraestructura DHCP intervienen tres elementos principales.

## Cliente DHCP

Es el dispositivo que solicita configuración.

Ejemplos:

- Ordenadores.
- Portátiles.
- Impresoras.
- Smartphones.
- Servidores.
- Cámaras IP.

---

## Servidor DHCP

Es el encargado de administrar las direcciones IP.

Entre sus funciones destacan:

- Asignar direcciones.
- Evitar duplicados.
- Gestionar concesiones.
- Renovar configuraciones.

En redes Windows suele instalarse como un rol de Windows Server.

En Linux existen varias implementaciones, como ISC DHCP o Kea DHCP.

---

## Ámbito (Scope)

Un ámbito es el conjunto de direcciones IP que el servidor puede asignar.

Por ejemplo:

```
192.168.1.100

↓

192.168.1.200
```

Todas esas direcciones podrán entregarse automáticamente a los clientes.

Las direcciones fuera del ámbito permanecerán libres para configuraciones manuales o para otros usos.

---

# ¿Qué información entrega DHCP?

Además de la dirección IP, DHCP suele proporcionar:

- Dirección IP.
- Máscara de red.
- Gateway.
- Servidor DNS.
- Dominio DNS.
- Tiempo de concesión.
- Otros parámetros específicos de la organización.

Por ello muchas veces se dice que DHCP entrega la **configuración completa de red**.

---

# ¿Qué ocurre al conectar un equipo?

Supongamos que Pedro conecta un portátil nuevo a la red corporativa.

En ese instante el ordenador todavía no sabe:

- Quién es.
- Qué IP utilizar.
- Dónde está el router.
- Qué servidor DNS debe consultar.

Lo único que sabe es que necesita pedir ayuda.

Y precisamente ahí comienza uno de los procesos más importantes de todo el protocolo DHCP.

```
Cliente

↓

"Necesito una dirección IP."
```

Ese intercambio recibe un nombre muy conocido:

# DORA

Lo estudiaremos en el siguiente apartado.

---

# El proceso DORA

Cuando un equipo se conecta por primera vez a una red, todavía no dispone de:

- Dirección IP.
- Máscara.
- Gateway.
- Servidor DNS.

En realidad, el equipo no sabe absolutamente nada sobre la red en la que acaba de conectarse.

Por eso necesita iniciar una conversación con el servidor DHCP.

Esa conversación recibe el nombre de:

# DORA

Cada letra representa uno de los cuatro mensajes intercambiados entre cliente y servidor.

```
D

Discover

↓

O

Offer

↓

R

Request

↓

A

Acknowledge
```

---

# El escenario

Imaginemos nuevamente a Pedro.

Acaba de conectar un portátil nuevo a la red de la empresa.

En ese momento el portátil todavía no tiene dirección IP.

Visualmente:

```
Portátil

↓

IP

???

↓

Gateway

???

↓

DNS

???
```

Lo único que sabe es:

```
"Necesito configuración."
```

---

# Paso 1 · Discover

El portátil envía un mensaje denominado:

```
DHCP Discover
```

Podemos imaginarlo diciendo:

> **"¡Hola! ¿Hay algún servidor DHCP por aquí?"**

Como todavía no conoce ninguna dirección IP, este mensaje se envía mediante **broadcast**.

Destino:

```
255.255.255.255
```

Todos los equipos de la red reciben el mensaje.

Pero únicamente responderá el servidor DHCP.

---

# Paso 2 · Offer

El servidor DHCP responde con un:

```
DHCP Offer
```

Es como si dijera:

> **"Sí, estoy aquí. Puedes utilizar esta configuración."**

Por ejemplo:

```
IP

192.168.1.120

Máscara

255.255.255.0

Gateway

192.168.1.1

DNS

192.168.1.10

Lease

8 horas
```

Todavía no se ha asignado definitivamente.

Simplemente es una oferta.

---

# Paso 3 · Request

El cliente responde:

```
DHCP Request
```

Es decir:

> **"Acepto esa dirección IP."**

Este mensaje también sirve para informar al resto de posibles servidores DHCP (si existieran varios) de cuál ha sido la oferta seleccionada.

De esta forma, los demás liberan las direcciones que habían reservado temporalmente.

---

# Paso 4 · Acknowledge

Finalmente el servidor responde:

```
DHCP ACK
```

(ACK = Acknowledge)

Es equivalente a decir:

> **"Perfecto. La dirección IP ya es oficialmente tuya."**

En ese instante el cliente configura automáticamente:

- Dirección IP.
- Máscara.
- Gateway.
- DNS.
- Tiempo de concesión.

Y ya puede comenzar a comunicarse con normalidad.

---

# La conversación completa

Podemos representarla así:

```
Cliente

↓

¿Hay algún servidor DHCP?

(Discover)

↓

Servidor

↓

Sí.

Puedes utilizar esta IP.

(Offer)

↓

Cliente

↓

La acepto.

(Request)

↓

Servidor

↓

Perfecto.

Ya es tuya.

(Acknowledge)
```

---

# Esquema visual de DORA

```
Cliente                        Servidor DHCP

    │                                 │
    │ ---- Discover ----------------> │
    │                                 │
    │ <----- Offer ------------------ │
    │                                 │
    │ ---- Request -----------------> │
    │                                 │
    │ <------ ACK ------------------- │
    │                                 │

Configuración completada
```

Este esquema aparece con frecuencia en libros de redes y ayuda a recordar el orden correcto.

---

# ¿Por qué Discover es broadcast?

Una pregunta típica de oposición es:

> **¿Por qué el primer mensaje se envía mediante broadcast?**

La respuesta es sencilla.

Porque el cliente aún no conoce:

- La dirección IP del servidor DHCP.
- Ni siquiera sabe si existe uno.

Por tanto envía el mensaje a toda la red.

Será el servidor quien responda.

---

# ¿Y por qué el servidor puede responder?

Aunque el cliente todavía no tenga IP, el servidor sí la tiene.

Además, escucha continuamente las peticiones DHCP que llegan por la red.

Cuando recibe un Discover:

- Selecciona una dirección disponible.
- La reserva temporalmente.
- Envía un Offer.

---

# ¿Qué ocurre si hay varios servidores DHCP?

Es una situación perfectamente posible.

En ese caso:

- Todos los servidores reciben el Discover.
- Cada uno puede enviar una Offer.
- El cliente selecciona una de ellas.
- Envía un Request indicando cuál acepta.
- Los demás servidores descartan sus ofertas.

Este mecanismo evita que un cliente termine utilizando dos direcciones IP diferentes.

---

# ¿Qué ocurre si no responde ningún servidor?

Si ningún servidor DHCP responde:

El cliente no obtiene configuración automáticamente.

En Windows suele asignarse una dirección denominada:

```
APIPA

169.254.x.x
```

Estas direcciones permiten una comunicación muy limitada dentro de la misma red local, pero **no proporcionan acceso normal a la red corporativa ni a Internet**.

> **💡 Nota para la oposición:** conocer la existencia de APIPA puede darte algún punto extra, aunque lo estudiaremos con más detalle cuando veamos resolución de problemas de red.

---

# Conceptos clave

Al terminar este apartado debes recordar:

- DHCP utiliza el proceso DORA.
- Discover y Request son mensajes enviados por el cliente.
- Offer y ACK son respuestas del servidor.
- El primer mensaje es broadcast porque el cliente aún no conoce al servidor DHCP.
- La configuración de red solo se aplica tras recibir el mensaje ACK.

---

# Concesiones (Leases)

Cuando un servidor DHCP asigna una dirección IP, **no la entrega para siempre**.

La asigna durante un periodo determinado denominado:

```
Lease

(Concesión)
```

Por ejemplo:

```
8 horas

24 horas

7 días
```

Durante ese tiempo la dirección queda reservada para ese cliente.

Esto evita que otro equipo pueda utilizar la misma dirección IP.

---

# ¿Por qué existen las concesiones?

Imaginemos un hotel.

Cuando un huésped llega, recibe una habitación.

Pero cuando abandona el hotel:

La habitación vuelve a quedar disponible.

Con DHCP ocurre exactamente igual.

```
Cliente

↓

Obtiene IP

↓

Utiliza la red

↓

Finaliza la concesión

↓

La IP vuelve al servidor
```

Gracias a ello una empresa puede reutilizar continuamente las direcciones disponibles.

---

# Renovación de una concesión

El cliente no espera hasta el último segundo.

Antes de que expire la concesión intenta renovarla automáticamente.

Normalmente solicita renovar la misma dirección IP.

Si el servidor responde correctamente:

```
La concesión se amplía.
```

Todo ello ocurre de forma transparente para el usuario.

---

# Reservas DHCP

En algunas ocasiones interesa que un determinado equipo **siempre reciba la misma dirección IP**, aunque siga utilizando DHCP.

Para ello existen las:

```
Reservas
```

Una reserva relaciona:

```
Dirección MAC

↓

Dirección IP fija
```

Ejemplo:

| Dirección MAC | Dirección IP |
|---------------|--------------|
| 00:11:22:33:44:55 | 192.168.1.20 |

Cada vez que ese equipo solicite configuración mediante DHCP:

Obtendrá siempre la misma dirección.

---

# ¿Cuándo utilizar reservas?

Las reservas son muy habituales en dispositivos que deben mantener una dirección estable.

Por ejemplo:

- Impresoras de red.
- Servidores.
- Cámaras IP.
- Teléfonos IP.
- Equipos de administración.

De esta forma seguimos disfrutando de la administración centralizada de DHCP sin necesidad de configurar manualmente cada dispositivo.

---

# Exclusiones

Las exclusiones indican al servidor DHCP qué direcciones **no debe asignar nunca**.

Ejemplo:

Ámbito:

```
192.168.1.1

↓

192.168.1.200
```

Exclusiones:

```
192.168.1.1

↓

192.168.1.20
```

Como consecuencia:

Las direcciones comprendidas entre `.1` y `.20` nunca serán entregadas automáticamente.

---

# ¿Para qué sirven las exclusiones?

Suelen reservarse para equipos configurados manualmente.

Por ejemplo:

```
192.168.1.1

↓

Router

192.168.1.2

↓

Firewall

192.168.1.10

↓

Servidor DNS

192.168.1.15

↓

Servidor Web
```

Así evitamos conflictos entre direcciones asignadas manualmente y automáticamente.

---

# Diferencia entre reserva y exclusión

Es una de las preguntas favoritas en las oposiciones.

| Reserva | Exclusión |
|----------|-----------|
| La IP sí puede asignarse | La IP nunca se asigna |
| Siempre al mismo equipo | A ningún equipo |
| Basada en la MAC | Basada en el rango de IP |

Una regla sencilla para recordarlo:

- **Reserva** → "Esta IP es siempre para este equipo."
- **Exclusión** → "Esta IP no la utiliza DHCP."

# DHCP Relay

Hasta ahora hemos supuesto que el cliente y el servidor DHCP pertenecen a la misma red.

Pero...

¿Qué ocurre si el servidor DHCP se encuentra en otra subred?

Aquí aparece el concepto de:

```
DHCP Relay
```

---

# El problema

Supongamos:

```
Red A

Cliente

192.168.1.x

↓

Router

↓

Servidor DHCP

192.168.2.x
```

Recordemos que el primer mensaje DHCP (Discover) se envía mediante **broadcast**.

Los routers **no reenvían broadcasts** por defecto.

Por tanto:

El Discover nunca llegaría al servidor DHCP.

---

# La solución: DHCP Relay

El router puede actuar como:

```
DHCP Relay Agent
```

Su función consiste en:

1. Recibir el mensaje Discover.
2. Convertirlo en un mensaje dirigido al servidor DHCP.
3. Reenviar la respuesta al cliente.

Visualmente:

```
Cliente

↓

DHCP Discover

↓

Router (Relay)

↓

Servidor DHCP

↓

Offer

↓

Router

↓

Cliente
```

Gracias al Relay un único servidor DHCP puede dar servicio a múltiples redes distintas.

---

# Ventajas del DHCP Relay

- Centraliza la administración.
- Reduce el número de servidores DHCP.
- Facilita el mantenimiento.
- Escala mucho mejor en grandes organizaciones.

Es habitual encontrar un único servidor DHCP atendiendo decenas de VLAN mediante Relay.

# 🎓 Resumen del capítulo

Al finalizar este capítulo debes recordar las siguientes ideas:

- DHCP asigna automáticamente la configuración de red.
- El proceso de asignación sigue la secuencia **DORA**:
  - Discover
  - Offer
  - Request
  - Acknowledge
- Una concesión (Lease) tiene una duración limitada y puede renovarse.
- Una reserva garantiza que un dispositivo reciba siempre la misma dirección IP basándose en su dirección MAC.
- Una exclusión impide que determinadas direcciones IP sean asignadas por DHCP.
- DHCP Relay permite que un servidor DHCP atienda clientes situados en otras subredes.

# 📖 Resumen final

DHCP es uno de los servicios fundamentales de cualquier infraestructura de red moderna. Automatiza la configuración de los dispositivos, evita conflictos de direcciones IP y simplifica enormemente la administración. El proceso DORA permite que un cliente obtenga su configuración de forma segura, mientras que conceptos como las concesiones, reservas y exclusiones ofrecen flexibilidad para adaptarse a las necesidades de una organización. En redes con múltiples subredes o VLAN, el uso de **DHCP Relay** permite centralizar el servicio sin renunciar a una arquitectura escalable y fácil de mantener.
