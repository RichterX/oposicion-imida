# El problema

Imaginemos una vivienda.

En ella existen los siguientes dispositivos.

```
Portátil

↓

Móvil

↓

Tablet

↓

Televisión

↓

Consola

↓

Impresora Wi-Fi

↓

Domótica
```

Todos ellos utilizan Internet al mismo tiempo.

Sin embargo...

Cuando consultamos nuestra dirección IP pública observamos algo curioso.

Todos parecen salir a Internet utilizando exactamente la misma dirección.

La pregunta es inevitable.

> **¿Cómo puede Internet distinguir quién está enviando cada comunicación?**

Ahora imaginemos una empresa.

Tiene:

- 500 empleados.
- 700 ordenadores.
- 300 teléfonos IP.
- 120 impresoras.
- 80 cámaras IP.

En total:

Más de **1.200 dispositivos**.

¿Necesitaría la empresa 1.200 direcciones IP públicas?

La respuesta es:

```
No.
```

Gracias a NAT.

---

# ¿Por qué existe NAT?

Cuando se diseñó Internet se utilizó el protocolo:

```
IPv4
```

Una dirección IPv4 tiene:

```
32 bits
```

Esto permite aproximadamente:

```
4.294 millones

de direcciones.
```

Durante los primeros años parecía una cantidad enorme.

Pero con el crecimiento de Internet comenzaron a aparecer problemas.

Hoy en día existen:

- Ordenadores.
- Teléfonos móviles.
- Tablets.
- Televisores inteligentes.
- Consolas.
- Cámaras IP.
- Sensores IoT.
- Vehículos conectados.

El número de dispositivos supera ampliamente el número de direcciones IPv4 disponibles.

---

# La solución

Una de las soluciones adoptadas fue reservar determinados rangos de direcciones para uso privado.

Estas direcciones:

- No son válidas en Internet.
- Solo funcionan dentro de redes privadas.

Posteriormente, un dispositivo realiza la traducción hacia una dirección pública.

Ese mecanismo recibe el nombre de:

```
NAT

Network Address Translation
```

---

# Direcciones privadas

Los rangos privados definidos por la RFC 1918 son:

| Rango | Prefijo |
|--------|----------|
|10.0.0.0 - 10.255.255.255|10.0.0.0/8|
|172.16.0.0 - 172.31.255.255|172.16.0.0/12|
|192.168.0.0 - 192.168.255.255|192.168.0.0/16|

Estas direcciones pueden utilizarse libremente dentro de organizaciones y hogares.

No son enrutables a través de Internet.

---

# Dirección pública

La dirección pública es aquella que identifica nuestra conexión frente al resto de Internet.

Por ejemplo:

```
83.45.126.210
```

Esta dirección sí es única a nivel mundial.

Es asignada normalmente por el proveedor de acceso a Internet (ISP).

---

# Un ejemplo sencillo

Supongamos el siguiente escenario.

```
PC

192.168.1.20

↓

Router

↓

Internet
```

El ordenador intenta acceder a una página web.

Pero existe un problema.

```
192.168.1.20
```

No es una dirección válida en Internet.

El router debe sustituirla por la dirección pública.

Por ejemplo:

```
83.45.126.210
```

Desde ese momento:

Toda Internet cree que la comunicación procede de esa dirección pública.

---

# ¿Qué significa NAT?

NAT significa:

```
Network

↓

Address

↓

Translation
```

Es decir:

```
Traducción de direcciones de red.
```

Su función consiste precisamente en modificar las direcciones IP cuando un paquete atraviesa un router o un firewall.

---

# ¿Dónde se realiza NAT?

Habitualmente encontramos NAT en:

- Routers domésticos.
- Firewalls.
- Routers empresariales.
- Equipos FortiGate.
- Dispositivos perimetrales.

Todos ellos realizan la traducción de direcciones entre la red privada e Internet.

---

# NAT no es un mecanismo de seguridad

Es muy frecuente escuchar frases como:

> "NAT protege la red."

No es del todo correcto.

NAT **no fue diseñado como una medida de seguridad**.

Su objetivo principal consiste en traducir direcciones IP.

La protección de la red corresponde al firewall y a sus políticas de seguridad.

Aunque NAT dificulta ciertas conexiones entrantes, no debe considerarse un sustituto de un firewall.

# Conceptos importantes

Antes de continuar debes recordar:

- NAT surgió como una solución para reducir el consumo de direcciones IPv4 públicas.
- Las direcciones privadas no pueden utilizarse directamente en Internet.
- Un router o firewall traduce las direcciones privadas en públicas.
- NAT modifica las direcciones IP de los paquetes.
- NAT no sustituye a un firewall.

---

# El viaje de un paquete con NAT

Hasta ahora sabemos que un ordenador con una dirección privada no puede comunicarse directamente con Internet.

Veamos ahora qué ocurre cuando Pedro abre su navegador.

Su ordenador tiene la dirección:

```
192.168.1.20
```

Y quiere acceder a:

```
https://www.imida.es
```

---

# Paso 1 · El ordenador genera el paquete

El navegador crea un paquete IP.

```
Origen

192.168.1.20

↓

Destino

150.214.xxx.xxx
```

El paquete llega al router.

---

# Paso 2 · El router detecta una dirección privada

El router analiza el paquete.

Observa:

```
Origen

192.168.1.20
```

Y sabe inmediatamente una cosa.

Esa dirección pertenece a un rango privado.

No puede enviarla directamente a Internet.

Debe traducirla.

---

# Paso 3 · NAT modifica la dirección

El router sustituye la dirección IP origen.

Antes:

```
Origen

192.168.1.20
```

Después:

```
Origen

83.45.126.210
```

El destino permanece exactamente igual.

```
Destino

150.214.xxx.xxx
```

Ahora sí puede enviar el paquete.

---

# Paso 4 · El servidor responde

Desde el punto de vista del servidor web:

La petición procede de:

```
83.45.126.210
```

Nunca llega a conocer la dirección privada:

```
192.168.1.20
```

El servidor responde a la dirección pública.

---

# Paso 5 · El router realiza la traducción inversa

Cuando la respuesta vuelve desde Internet:

```
Destino

83.45.126.210
```

El router consulta su tabla NAT.

Comprueba que esa comunicación pertenece realmente al equipo:

```
192.168.1.20
```

Realiza la traducción inversa.

Y entrega finalmente el paquete al ordenador de Pedro.

Todo este proceso ocurre en apenas unos milisegundos.

---

# Esquema completo

```
PC

192.168.1.20

↓

Router

↓

NAT

↓

83.45.126.210

↓

Internet

↓

Servidor Web

↓

83.45.126.210

↓

Router

↓

NAT inverso

↓

192.168.1.20
```

Observa que:

El servidor únicamente conoce la dirección pública.

---

# La tabla NAT

Para poder devolver correctamente las respuestas:

El router mantiene una tabla de traducciones.

Por ejemplo:

| Dirección privada | Dirección pública |
|-------------------|-------------------|
|192.168.1.20|83.45.126.210|
|192.168.1.21|83.45.126.210|

En este momento todavía no sabemos cómo distingue el router ambos equipos.

Lo estudiaremos cuando expliquemos PAT.

---

# NAT estático

La modalidad más sencilla es:

```
Static NAT
```

En ella existe una correspondencia fija entre una dirección privada y una dirección pública.

Ejemplo:

| Privada | Pública |
|----------|----------|
|192.168.1.20|83.45.126.210|

Siempre que aparezca:

```
192.168.1.20
```

El router utilizará:

```
83.45.126.210
```

Nunca cambia.

---

# ¿Cuándo utilizar NAT estático?

Es útil cuando un equipo debe mantener siempre la misma dirección pública.

Por ejemplo:

- Servidor Web.
- Servidor de correo.
- Servidor VPN.
- Servidor FTP.

Estos servicios necesitan ser localizables siempre mediante la misma dirección IP pública.

---

# NAT dinámico

Existe otra modalidad.

```
Dynamic NAT
```

En este caso:

El router dispone de un conjunto de direcciones públicas.

Cuando un equipo necesita salir a Internet:

Se le asigna temporalmente una de ellas.

Visualmente:

```
Pool público

83.45.126.210

83.45.126.211

83.45.126.212
```

Cada cliente utiliza una dirección libre mientras dura la comunicación.

Después vuelve al grupo disponible.

---

# NAT dinámico

Ejemplo.

```
PC 1

↓

83.45.126.210


PC 2

↓

83.45.126.211


PC 3

↓

83.45.126.212
```

Cuando finaliza la comunicación:

Las direcciones públicas pueden reutilizarse para otros equipos.

---

# Limitaciones del NAT dinámico

Aunque reduce el número de direcciones públicas necesarias:

Sigue existiendo un inconveniente.

Si tenemos:

```
500 ordenadores
```

y únicamente:

```
10 direcciones públicas
```

Solo diez equipos podrían acceder simultáneamente a Internet.

Necesitamos una solución mejor.

---

# La respuesta

La solución consiste en permitir que **todos los equipos compartan una única dirección IP pública al mismo tiempo**.

Ese mecanismo recibe el nombre de:

```
PAT

Port Address Translation
```

Y será el protagonista del siguiente apartado.

---

# Conceptos importantes

Antes de continuar debes recordar:

- NAT modifica las direcciones IP cuando un paquete atraviesa el router.
- El servidor remoto solo conoce la dirección IP pública.
- El router mantiene una tabla de traducciones.
- NAT estático establece una relación fija entre una dirección privada y otra pública.
- NAT dinámico utiliza un conjunto (pool) de direcciones públicas disponibles.
- Ninguno de estos dos mecanismos explica todavía cómo cientos de equipos pueden compartir una única dirección pública simultáneamente.

---

# PAT (Port Address Translation)

En el apartado anterior vimos que NAT dinámico sigue teniendo una limitación importante.

Si disponemos de:

```
10 direcciones públicas
```

Solo podremos mantener simultáneamente:

```
10 traducciones.
```

Pero...

¿Qué ocurre si tenemos cientos de equipos?

La solución consiste en utilizar también los números de puerto.

Ese mecanismo recibe el nombre de:

```
PAT

Port Address Translation
```

También se conoce como:

```
NAT Overload
```

---

# La idea fundamental

PAT permite que **muchos equipos compartan una única dirección IP pública al mismo tiempo**.

¿Cómo lo consigue?

Utilizando los puertos TCP y UDP.

Recordemos que una comunicación no se identifica únicamente mediante una dirección IP.

También intervienen los puertos.

Por ejemplo:

```
192.168.1.20

Puerto

52341
```

Cada conexión utiliza un puerto diferente.

---

# Una analogía

Imaginemos un edificio.

```
Calle Mayor 25
```

Todos los vecinos comparten la misma dirección postal.

Sin embargo:

Cada uno vive en un apartamento distinto.

```
25

↓

1ºA

↓

2ºB

↓

3ºC

↓

4ºA
```

La dirección del edificio sería:

```
IP pública
```

Mientras que el número del apartamento sería:

```
Puerto
```

Gracias a ello el cartero sabe exactamente dónde entregar cada carta.

PAT hace exactamente lo mismo con los paquetes de red.

---

# Ejemplo

Supongamos tres ordenadores.

```
PC1

192.168.1.20


PC2

192.168.1.21


PC3

192.168.1.22
```

Todos desean acceder simultáneamente a Internet.

El router traduce las comunicaciones.

| Dirección privada | Puerto origen | Dirección pública | Puerto público |
|-------------------|--------------|-------------------|----------------|
|192.168.1.20|52100|83.45.126.210|40001|
|192.168.1.21|52101|83.45.126.210|40002|
|192.168.1.22|52102|83.45.126.210|40003|

Observa que:

Todos utilizan:

```
La misma IP pública.
```

Lo único que cambia es el puerto.

---

# El viaje de una respuesta

Cuando el servidor responde:

```
Destino

83.45.126.210

Puerto

40002
```

El router consulta su tabla.

Detecta:

```
40002

↓

192.168.1.21
```

Y entrega correctamente el paquete.

Gracias a ello miles de conexiones pueden coexistir utilizando una única dirección IP pública.

---

# Port Forwarding

Hasta ahora todas las conexiones se iniciaban desde la red interna.

Pero...

¿Qué ocurre si queremos publicar un servidor web?

Necesitamos indicar al router qué debe hacer cuando llegue una conexión desde Internet.

Aquí aparece el concepto de:

```
Port Forwarding

(Redirección de puertos)
```

---

# Ejemplo

Supongamos un servidor web interno.

```
192.168.1.100
```

Queremos que cualquier usuario de Internet pueda acceder a él.

Configuramos:

```
IP Pública

↓

Puerto 80

↓

192.168.1.100

Puerto 80
```

Cuando alguien acceda a nuestra dirección pública:

El router reenviará automáticamente la conexión al servidor interno.

---

# SNAT y DNAT

En entornos profesionales también aparecen dos términos muy habituales.

## SNAT

```
Source NAT
```

Modifica:

```
La dirección IP origen.
```

Es el tipo de NAT utilizado habitualmente cuando los equipos salen a Internet.

---

## DNAT

```
Destination NAT
```

Modifica:

```
La dirección IP destino.
```

Se utiliza principalmente para:

- Publicar servidores.
- Port Forwarding.
- Balanceadores de carga.

---

# NAT en FortiGate

En FortiGate la configuración NAT suele realizarse dentro de las propias políticas de firewall.

Una política típica podría ser:

```
LAN

↓

WAN

↓

NAT

↓

Enabled
```

A partir de ese momento el firewall traducirá automáticamente las direcciones privadas hacia la dirección pública configurada en la interfaz WAN.

También permite configurar:

- NAT estático.
- PAT.
- VIP (Virtual IP).
- Port Forwarding.
- SNAT.
- DNAT.

Todo ello desde la interfaz gráfica o mediante CLI.

---

# Ventajas de NAT y PAT

Las principales ventajas son:

- Ahorro de direcciones IPv4 públicas.
- Posibilidad de utilizar redes privadas.
- Facilidad de administración.
- Flexibilidad.
- Compatibilidad con prácticamente todos los routers y firewalls.

Sin NAT sería prácticamente imposible mantener la Internet actual basada en IPv4.

---

# Inconvenientes

No todo son ventajas.

NAT también presenta algunos inconvenientes.

- Rompe el principio extremo a extremo de Internet.
- Puede complicar determinados protocolos.
- Dificulta algunas conexiones entrantes.
- Hace más complejo el diagnóstico de incidencias.
- Algunas aplicaciones requieren configuraciones adicionales.

Precisamente por estas limitaciones surgió IPv6, donde cada dispositivo puede disponer de una dirección pública única.

---

# Relación con IPv6

Uno de los objetivos principales de IPv6 consiste en reducir la dependencia de NAT.

Gracias al enorme espacio de direcciones IPv6:

Cada dispositivo puede disponer de una dirección global única.

Sin embargo:

NAT continúa siendo muy utilizado debido a la enorme implantación de IPv4.

---

# ⚠️ Errores clásicos de oposición

❌ Pensar que NAT y PAT son exactamente lo mismo.

➡️ NAT traduce direcciones.

PAT traduce direcciones **y puertos**, permitiendo compartir una misma IP pública.

---

❌ Creer que NAT proporciona seguridad.

➡️ NAT traduce direcciones.

La seguridad depende del firewall y de sus reglas.

---

❌ Confundir SNAT con DNAT.

➡️ SNAT modifica la dirección origen.

➡️ DNAT modifica la dirección destino.

---

❌ Pensar que Port Forwarding crea una VPN.

➡️ Simplemente redirige conexiones hacia un equipo interno.

# 🎓 Resumen del capítulo

Al finalizar este capítulo debes recordar:

- NAT traduce direcciones IP privadas en públicas.

- Port Forwarding publica servicios internos hacia Internet.
- SNAT modifica la dirección origen.

- FortiGate integra todas estas funciones dentro de sus políticas de firewall.

# 📖 Resumen final

NAT surgió como una respuesta al agotamiento de las direcciones IPv4, permitiendo que redes privadas completas pudieran acceder a Internet utilizando un número reducido de direcciones públicas. A partir de este concepto aparecieron distintas modalidades, como **NAT estático**, **NAT dinámico** y **PAT**, siendo este último el mecanismo que hace posible que cientos de dispositivos compartan simultáneamente una única dirección IP pública mediante el uso de puertos. Técnicas como **Port Forwarding**, **SNAT** y **DNAT** amplían estas capacidades y forman parte de la configuración habitual de routers y firewalls empresariales como **FortiGate**. Comprender estos mecanismos resulta esencial para entender el funcionamiento de las redes IPv4 modernas y constituye un conocimiento frecuente en las pruebas de oposición.
