# ¿Qué es DNS?

El **DNS (Domain Name System)** es un sistema distribuido que permite traducir nombres de dominio legibles por las personas en direcciones IP comprensibles para los equipos.

Por ejemplo:

```
www.imida.es

↓

193.146.xxx.xxx
```

Los ordenadores **no navegan utilizando nombres**.

Siempre se comunican mediante direcciones IP.

DNS existe precisamente para evitar que las personas tengamos que memorizar esas direcciones.

---

# ¿Por qué es necesario DNS?

Imagina Internet sin DNS.

Cada vez que quisieras visitar una página web tendrías que recordar su dirección IP.

Por ejemplo:

En lugar de escribir:

```
www.openai.com
```

tendrías que introducir algo parecido a:

```
172.xxx.xxx.xxx
```

Y hacer lo mismo para:

- Bancos.
- Universidades.
- Administraciones públicas.
- Correo electrónico.
- Tiendas online.

Sería completamente inviable.

DNS actúa como una enorme guía telefónica de Internet.

---

# Nombre de dominio vs Dirección IP

Es muy importante no confundir ambos conceptos.

| Nombre de dominio | Dirección IP |
|-------------------|--------------|
| Fácil de recordar | Difícil para las personas |
| Utilizado por los usuarios | Utilizado por los equipos |
| Puede cambiar de IP | Identifica una interfaz de red |

Por ejemplo:

```
www.imida.es
```

es únicamente un nombre.

El servidor realmente posee una dirección IP.

Si mañana cambia esa IP, los usuarios seguirán escribiendo exactamente el mismo nombre.

Solo será necesario actualizar el registro DNS correspondiente.

---

# ¿Cómo funciona DNS?

Cuando escribimos una dirección web ocurren muchos más pasos de los que imaginamos.

Supongamos:

Pedro abre el navegador.

Escribe:

```
www.imida.es
```

¿Qué ocurre?

Veámoslo paso a paso.

---

# Paso 1 · El navegador necesita una IP

El navegador sabe que para comunicarse necesita una dirección IP.

Pero únicamente dispone del nombre:

```
www.imida.es
```

Por tanto solicita:

```
Necesito la IP correspondiente.
```

Aquí comienza el proceso DNS.

---

# Paso 2 · Comprobación de la caché local

Antes de preguntar a ningún servidor, el sistema comprueba si ya conoce la respuesta.

Busca en varios lugares:

- Caché del navegador.
- Caché del sistema operativo.
- Archivo `hosts` (si existe una entrada).

Si encuentra la IP:

```
Proceso terminado.
```

No será necesario realizar ninguna consulta DNS.

---

# Paso 3 · Consulta al servidor DNS

Si la información no está almacenada localmente, el equipo consulta el servidor DNS configurado.

Habitualmente será:

- El router doméstico.
- El servidor DNS corporativo.
- El DNS proporcionado por el ISP.
- Un servidor público (Google, Cloudflare, OpenDNS...).

Por ejemplo:

```
8.8.8.8
```

o

```
1.1.1.1
```

---

# Paso 4 · El servidor responde

Si el servidor conoce la respuesta:

Devuelve la dirección IP.

Ejemplo:

```
www.imida.es

↓

193.146.xxx.xxx
```

Ahora el navegador ya puede iniciar la conexión TCP y continuar con la comunicación HTTP o HTTPS.

---

# ¿Qué ocurre realmente?

Podemos resumir todo el proceso así:

```
Pedro escribe:

www.imida.es

↓

¿Está en mi caché?

↓

Sí

↓

Obtengo la IP


-----------------------


No

↓

Pregunto al servidor DNS

↓

Obtengo la IP

↓

Conecto al servidor web
```

---

# Un ejemplo completo

```
Usuario

↓

www.imida.es

↓

DNS

↓

193.146.xxx.xxx

↓

TCP

↓

HTTPS

↓

Servidor web

↓

Página mostrada
```

Observa un detalle importante.

**DNS únicamente participa al principio.**

Una vez obtenida la dirección IP:

DNS desaparece del proceso.

Toda la comunicación posterior se realiza utilizando la dirección IP.

---

# ¿Qué ocurre si DNS falla?

Si el servidor DNS no responde:

No podremos resolver nombres.

Aunque Internet siga funcionando perfectamente.

Por ejemplo:

```
https://193.146.xxx.xxx
```

podría seguir funcionando.

Mientras que:

```
https://www.imida.es
```

no.

Por eso muchas veces se dice:

> "Tengo Internet, pero no navego."

En realidad:

La conexión existe.

Lo que ha fallado es la resolución de nombres.

---

# Conceptos que debes recordar

- DNS traduce nombres de dominio en direcciones IP.
- Los equipos siempre se comunican utilizando direcciones IP.
- Los usuarios utilizan nombres porque son más fáciles de recordar.
- Antes de consultar un servidor DNS, el equipo intenta utilizar su propia caché.
- Una vez obtenida la IP, DNS deja de intervenir en la comunicación.

---

# ¿Quién conoce la dirección IP?

En el apartado anterior dejamos la siguiente pregunta en el aire:

```
Pedro escribe:

www.imida.es

↓

¿Quién sabe cuál es su dirección IP?
```

La respuesta no es tan sencilla como parece.

No existe un único servidor DNS que conozca todos los dominios de Internet.

Sería imposible mantener una base de datos tan enorme y, además, supondría un único punto de fallo.

En su lugar, DNS utiliza una **estructura jerárquica y distribuida**.

Cada servidor conoce únicamente una pequeña parte de la información.

Juntos forman uno de los sistemas distribuidos más grandes del mundo.

---

# La jerarquía DNS

Podemos imaginar DNS como un gran árbol.

```
                    .

              (Raíz)

                 │

      ┌──────────┴──────────┐

      .com               .es

        │                  │

   openai.com         imida.es

        │                  │

 www.openai.com     www.imida.es
```

Cada nivel conoce únicamente el siguiente.

Por ejemplo:

- Los servidores raíz conocen dónde están los dominios `.com`, `.es`, `.org`, etc.
- Los servidores `.es` conocen qué servidores gestionan `imida.es`.
- El servidor de `imida.es` conoce finalmente la dirección IP de `www.imida.es`.

Gracias a esta organización no existe un único servidor gigantesco.

---

# Servidores raíz (Root Servers)

En la parte superior de la jerarquía encontramos los **servidores raíz**.

No conocen la dirección IP de todas las páginas web.

Su función consiste únicamente en indicar qué servidores gestionan cada dominio de nivel superior (TLD).

Por ejemplo:

```
www.imida.es

↓

Servidor raíz

↓

"No conozco esa IP.

Pregunta a los servidores del dominio .es"
```

Es importante comprender que el servidor raíz **no responde con la IP final**, sino con una referencia al siguiente nivel.

---

# Servidores TLD (Top-Level Domain)

Los **TLD (Top-Level Domains)** son los dominios de nivel superior, como:

- `.com`
- `.es`
- `.org`
- `.net`
- `.edu`
- `.gov`

Cada uno dispone de servidores especializados que conocen qué servidores son responsables de los dominios registrados bajo ese TLD.

Siguiendo nuestro ejemplo:

```
www.imida.es

↓

Servidor .es

↓

"El dominio imida.es está gestionado por estos servidores DNS"
```

De nuevo, el servidor TLD no devuelve la IP final.

Simplemente indica dónde continuar la búsqueda.

---

# Servidor DNS autoritativo

Finalmente llegamos al servidor que realmente conoce la información del dominio.

Este servidor recibe el nombre de:

**Servidor DNS autoritativo**.

Es el responsable de almacenar los registros DNS oficiales del dominio.

Por ejemplo:

```
www.imida.es

↓

193.146.xxx.xxx
```

La respuesta obtenida aquí es la que finalmente recibirá el usuario.

---

# DNS autoritativo

Un **servidor DNS autoritativo** contiene la información oficial de una zona DNS.

Es decir:

No pregunta a otros servidores.

No realiza búsquedas adicionales.

Simplemente responde utilizando los datos almacenados en su propia base de datos.

Ejemplos de información que almacena:

- Direcciones IP.
- Servidores de correo.
- Alias.
- Registros de texto.
- Servidores secundarios.

Cuando un servidor es autoritativo para una zona, se considera la fuente oficial de esa información.

---

# DNS recursivo

El usuario normalmente **no consulta directamente** al servidor autoritativo.

Consulta a un servidor denominado:

**Servidor DNS recursivo**.

Este servidor realiza todo el trabajo de búsqueda.

Si no conoce la respuesta:

1. Consulta los servidores raíz.
2. Consulta el TLD correspondiente.
3. Consulta el servidor autoritativo.
4. Obtiene la dirección IP.
5. Devuelve la respuesta al cliente.

Desde el punto de vista del usuario, todo ocurre de forma transparente.

---

# Ejemplo completo

Supongamos nuevamente que Pedro escribe:

```
www.imida.es
```

El recorrido sería:

```
Pedro

↓

Servidor DNS recursivo

↓

Servidor raíz

↓

Servidor .es

↓

Servidor autoritativo

↓

193.146.xxx.xxx

↓

Servidor recursivo

↓

Pedro
```

Observa que Pedro únicamente habla con un servidor:

El DNS recursivo.

Es éste quien realiza el resto del trabajo.

---

# Diferencias entre DNS recursivo y autoritativo

| DNS Recursivo | DNS Autoritativo |
|----------------|------------------|
| Busca la respuesta | Ya conoce la respuesta |
| Consulta otros servidores | No consulta a nadie |
| Atiende a los clientes | Gestiona una zona DNS |
| Utiliza caché | Almacena la información oficial |

Es una comparación muy habitual en preguntas tipo test.

---

# ¿Por qué funciona tan rápido?

Una pregunta muy frecuente es:

> Si cada consulta tuviera que recorrer toda la jerarquía DNS, ¿Internet no sería lentísimo?

La respuesta es:

**No**, gracias a la **caché DNS**.

Será precisamente el siguiente apartado.

---

# Registros DNS

Hasta ahora hemos visto que un servidor DNS responde consultas.

Pero...

> **¿Dónde almacena esa información?**

La respuesta está en los **registros DNS**.

Un registro DNS es una entrada dentro de una zona DNS que asocia un nombre con determinada información.

Cada tipo de registro tiene una finalidad distinta.

---

# Registro A

Es el registro más utilizado.

Asocia un nombre de dominio con una dirección **IPv4**.

Ejemplo:

```
www.imida.es

↓

193.146.xxx.xxx
```

Cuando el navegador pregunta:

> ¿Cuál es la IP de www.imida.es?

La respuesta procede normalmente de un registro **A**.

---

# Registro AAAA

Cumple exactamente la misma función que el registro A.

La diferencia es que trabaja con **IPv6**.

Ejemplo:

```
www.imida.es

↓

2001:db8::25
```

---

# Registro CNAME

**CNAME (Canonical Name)** permite crear un alias para otro nombre.

Ejemplo:

```
ftp.imida.es

↓

www.imida.es
```

En lugar de mantener dos registros independientes, ambos nombres apuntan al mismo destino.

Es muy útil cuando varios servicios deben compartir la misma dirección IP.

---

# Registro MX

El registro **MX (Mail Exchange)** indica qué servidor recibe el correo electrónico de un dominio.

Ejemplo:

```
usuario@empresa.es

↓

Servidor de correo:

mail.empresa.es
```

Sin un registro MX correctamente configurado, el correo electrónico no podría entregarse correctamente.

---

# Registro NS

El registro **NS (Name Server)** indica qué servidores DNS son responsables de una zona.

Por ejemplo:

```
imida.es

↓

ns1.imida.es

ns2.imida.es
```

Gracias a este registro otros servidores saben dónde consultar la información oficial del dominio.

---

# Registro PTR

Mientras que el registro A resuelve:

```
Nombre

↓

IP
```

El registro PTR realiza la operación inversa.

```
IP

↓

Nombre
```

Por ello se conoce como **resolución inversa** (*Reverse DNS*).

Se utiliza, por ejemplo:

- En servidores de correo.
- En auditorías.
- En herramientas de diagnóstico.

---

# Registro TXT

Permite almacenar información de texto asociada a un dominio.

Actualmente se utiliza con frecuencia para:

- Verificación de dominios.
- SPF.
- DKIM.
- DMARC.
- Validaciones de servicios en la nube.

En oposición basta con conocer su finalidad general.

---

# Registro SRV

Este registro es especialmente importante para administradores de sistemas.

Define dónde se encuentra un determinado servicio.

Por ejemplo:

```
LDAP

↓

Servidor A
```

o

```
Kerberos

↓

Servidor B
```

En entornos Windows Server y **Active Directory**, los registros **SRV** son fundamentales.

Gracias a ellos un cliente puede localizar automáticamente:

- Controladores de Dominio.
- Servidores LDAP.
- Servidores Kerberos.
- Catálogo Global.

> **💡 Relación con el Bloque 1:** cuando estudiamos Active Directory vimos que un cliente localiza un Controlador de Dominio utilizando DNS. Ahora ya sabemos que esa localización se realiza, precisamente, mediante registros **SRV**.

---

# Resumen de los principales registros

| Registro | Función |
|-----------|---------|
| A | Nombre → IPv4 |
| AAAA | Nombre → IPv6 |
| CNAME | Alias de otro nombre |
| MX | Servidor de correo |
| NS | Servidor autoritativo de la zona |
| PTR | IP → Nombre |
| TXT | Información de texto |
| SRV | Localización de servicios |

No es necesario memorizar todos los ejemplos, pero sí conocer la finalidad de cada tipo de registro.

---

# Caché DNS

Una de las razones por las que DNS funciona tan rápido es la utilización de **caché**.

Cuando un servidor DNS obtiene una respuesta, la guarda temporalmente.

Si otro usuario realiza la misma consulta poco después:

```
www.imida.es

↓

Ya conozco la respuesta

↓

No necesito volver a consultar Internet
```

Esto reduce enormemente:

- El tráfico.
- El tiempo de respuesta.
- La carga de los servidores autoritativos.

---

# TTL (Time To Live)

Las respuestas DNS no permanecen indefinidamente en la caché.

Cada registro posee un valor denominado:

```
TTL

(Time To Live)
```

Indica durante cuánto tiempo puede mantenerse almacenada la respuesta.

Cuando el TTL expira:

```
La entrada se elimina.

↓

Será necesario realizar una nueva consulta.
```

---

# Ventajas de la caché DNS

La caché proporciona numerosas ventajas:

- Navegación más rápida.
- Menor consumo de ancho de banda.
- Menor carga sobre Internet.
- Reducción del número de consultas DNS.

Gracias a ella millones de usuarios pueden consultar continuamente los mismos dominios sin sobrecargar la infraestructura DNS mundial.

---

# Ejemplo completo

Imaginemos que Pedro visita por primera vez:

```
www.imida.es
```

El proceso será:

```
Pedro

↓

Consulta DNS

↓

Servidor recursivo

↓

Servidores raíz

↓

Servidor .es

↓

Servidor autoritativo

↓

Obtiene la IP

↓

Guarda la respuesta en caché
```

Cinco minutos después vuelve a acceder a la misma página.

Ahora ocurre:

```
Pedro

↓

Consulta DNS

↓

La respuesta ya está en caché

↓

Obtiene la IP inmediatamente
```

Todo el recorrido anterior deja de ser necesario.

# 🎓 Resumen del capítulo

Al finalizar este capítulo debes recordar las siguientes ideas:

- DNS traduce nombres de dominio en direcciones IP.
- La resolución de nombres sigue una estructura jerárquica.
- Los servidores raíz dirigen la consulta hacia el TLD correspondiente.
- Los servidores TLD indican qué servidor es autoritativo para un dominio.
- Los servidores autoritativos contienen la información oficial de una zona.
- Los servidores recursivos realizan las consultas en nombre del cliente.
- Los registros DNS almacenan distintos tipos de información (A, AAAA, MX, NS, CNAME, PTR, TXT y SRV).
- La caché DNS mejora enormemente el rendimiento.
- El TTL determina cuánto tiempo permanece válida una respuesta en la caché.

# 📖 Resumen final

DNS constituye uno de los servicios esenciales de cualquier infraestructura de red. Gracias a su arquitectura jerárquica y distribuida es posible resolver millones de nombres de dominio de forma eficiente y escalable. La combinación de servidores recursivos, servidores autoritativos, registros DNS y mecanismos de caché permite que Internet funcione con la rapidez que conocemos hoy en día. Además, en entornos empresariales como Windows Server y Active Directory, DNS deja de ser un simple servicio de navegación y se convierte en un componente crítico para la autenticación, la localización de servicios y el funcionamiento del dominio.
