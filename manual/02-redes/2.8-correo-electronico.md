# El problema

Imaginemos la siguiente situación.

Pedro trabaja en una empresa.

Necesita enviar un correo a María.

```
pedro@empresa.es

↓

maria@universidad.es
```

Pedro pulsa:

```
Enviar
```

Y unos segundos después...

María recibe el mensaje.

Parece algo muy sencillo.

Pero realmente han intervenido numerosos protocolos y servidores.

La pregunta es:

> **¿Cómo encuentra Internet el servidor donde debe entregarse ese correo?**

---

# ¿Qué es el correo electrónico?

El correo electrónico es un servicio que permite intercambiar mensajes entre usuarios conectados a una red.

Además del texto, puede transportar:

- Imágenes.
- Documentos.
- Vídeos.
- Audio.
- Archivos comprimidos.
- Firmas digitales.

Actualmente constituye uno de los servicios más utilizados de Internet.

---

# Componentes de un sistema de correo

En cualquier sistema de correo intervienen varios elementos.

```
Usuario

↓

Cliente de correo

↓

Servidor SMTP

↓

Internet

↓

Servidor de correo destino

↓

Buzón

↓

Cliente del destinatario
```

Cada componente tiene una función distinta.

---

# Cliente de correo

Es la aplicación utilizada por el usuario.

Ejemplos:

- Microsoft Outlook.
- Mozilla Thunderbird.
- Apple Mail.
- Aplicaciones móviles.
- Correo web (Webmail).

Su función consiste en:

- Escribir mensajes.
- Leer correos.
- Organizar carpetas.
- Gestionar contactos.

El cliente **no entrega directamente** el correo al destinatario.

Siempre necesita un servidor de correo.

---

# Servidor de correo

Es el encargado de:

- Recibir mensajes.
- Almacenarlos.
- Enviarlos.
- Distribuirlos al destinatario.

Podemos imaginarlo como una oficina de correos.

Los usuarios depositan allí sus mensajes.

Y posteriormente el servidor los entrega al destino correspondiente.

---

Supongamos nuevamente:

```

Escribe un correo para:

```

```

Cuando pulsa:

```

El mensaje sigue un recorrido mucho más largo.

# El recorrido del correo

De forma simplificada:

```
Pedro

↓

Cliente de correo

↓

Servidor SMTP

↓

Servidor de correo destino

↓

Buzón de María

↓

Cliente de María
```

Observa un detalle importante.

Pedro nunca habla directamente con el ordenador de María.

Toda la comunicación pasa por servidores de correo.

---

# ¿Cómo sabe Internet dónde entregar el mensaje?

Aquí aparece un concepto que ya conocemos perfectamente.

```
DNS
```

El servidor SMTP necesita localizar el servidor de correo responsable del dominio:

```
universidad.es
```

Para conseguirlo realiza una consulta DNS.

Pero...

No utiliza un registro A.

Utiliza un registro especial denominado:

```
MX

(Mail Exchange)
```

Lo estudiaremos con detalle más adelante.

# Los tres protocolos principales

En un sistema de correo aparecen tres protocolos fundamentales.

```
SMTP

↓

Enviar correo


POP3

↓

Descargar correo


IMAP

↓

Sincronizar correo
```

Es muy importante comprender que:

SMTP y POP3 **no hacen lo mismo**.

SMTP e IMAP **tampoco**.

Cada protocolo tiene una función muy concreta.

---

# SMTP

SMTP significa:

```
Simple Mail Transfer Protocol
```

Es el protocolo encargado de:

**Enviar correos electrónicos.**

Siempre que un mensaje sale de un cliente o de un servidor de correo:

Interviene SMTP.

Por tanto:

```
Enviar

↓

SMTP
```

Es una de las asociaciones más importantes de todo el capítulo.

---

# ¿Dónde aparece SMTP?

SMTP interviene en dos momentos distintos.

Primero:

```
Cliente

↓

Servidor de correo
```

Después:

```
Servidor origen

↓

Servidor destino
```

Es decir:

SMTP no solo envía el correo desde el usuario.

También permite que los propios servidores intercambien mensajes entre sí.

---

# Conceptos importantes

Antes de continuar debes recordar:

- El correo electrónico siempre pasa por uno o varios servidores.
- El cliente de correo no entrega directamente los mensajes al destinatario.
- SMTP es el protocolo encargado del envío.
- DNS participa localizando el servidor de correo del dominio de destino.
- Los registros MX permiten identificar qué servidor recibe el correo de un dominio.

---

# SMTP (Simple Mail Transfer Protocol)

En el apartado anterior vimos que SMTP es el protocolo encargado del envío de correo electrónico.

Cada vez que un usuario pulsa:

```
Enviar
```

El cliente de correo utiliza SMTP para entregar el mensaje al servidor.

Visualmente:

```
Pedro

↓

Outlook

↓

SMTP

↓

Servidor de correo
```

Pero SMTP no termina ahí.

Una vez recibido el mensaje, el propio servidor puede volver a utilizar SMTP para enviarlo al servidor del destinatario.

Por tanto, SMTP interviene tanto en el envío desde el cliente como en el intercambio entre servidores.

---

# ¿Qué hace realmente SMTP?

SMTP no almacena los mensajes.

No permite leer el correo.

Su única misión consiste en:

```
Transportar correo electrónico.
```

Una forma sencilla de recordarlo es:

```
SMTP

↓

Enviar
```

---

# POP3 (Post Office Protocol versión 3)

Supongamos ahora que María abre su cliente de correo.

Necesita descargar los mensajes almacenados en el servidor.

Aquí aparece:

```
POP3
```

POP3 significa:

```
Post Office Protocol v3
```

Su función consiste en:

**Descargar los mensajes desde el servidor al equipo del usuario.**

---

# ¿Cómo funciona POP3?

Podemos imaginar una oficina de correos.

```
Servidor

↓

Buzón
```

María llega.

Recoge todas sus cartas.

Se las lleva a casa.

Una vez descargadas, normalmente los mensajes dejan de estar disponibles en el servidor (aunque muchos clientes modernos permiten conservar una copia).

Visualmente:

```
Servidor

↓

POP3

↓

PC de María
```

---

# Características principales de POP3

POP3 fue diseñado pensando en una época en la que:

- Internet era lento.
- Las conexiones eran caras.
- Los usuarios consultaban el correo desde un único ordenador.

Por ello:

- Descarga los mensajes al dispositivo.
- Permite leerlos sin conexión.
- Reduce el espacio ocupado en el servidor.

---

# Ventajas de POP3

- Muy sencillo.
- Bajo consumo de recursos.
- Funciona sin conexión una vez descargado el correo.
- Adecuado para equipos que siempre utilizan el mismo buzón.

---

# Limitaciones de POP3

Hoy en día presenta algunos inconvenientes importantes.

Imaginemos que María consulta el correo desde:

- El ordenador del trabajo.
- Su portátil.
- El móvil.

Con POP3 pueden aparecer problemas:

- Los mensajes descargados en un dispositivo pueden no estar disponibles en otro.
- Las carpetas no permanecen sincronizadas.
- Los correos leídos o eliminados no siempre reflejan el mismo estado en todos los equipos.

Precisamente para resolver estos problemas nació IMAP.

---

# IMAP (Internet Message Access Protocol)

IMAP fue diseñado para una forma de trabajar mucho más moderna.

En lugar de descargar los mensajes y gestionarlos localmente:

Mantiene el correo almacenado en el servidor.

Los dispositivos simplemente sincronizan la información.

---

# ¿Cómo funciona IMAP?

Volvamos a la oficina de correos.

Con IMAP:

Las cartas permanecen siempre en el buzón.

Cada vez que María quiere consultarlas:

Va al buzón.

Las lee.

Y las vuelve a dejar allí.

Todos los dispositivos consultan exactamente el mismo buzón.

---

# Ejemplo

```
Servidor

↓

IMAP

↓

Portátil

↓

Móvil

↓

Tablet

↓

PC
```

Todos muestran exactamente:

- Los mismos mensajes.
- Las mismas carpetas.
- Los mismos correos leídos.
- Los mismos correos eliminados.

Todo permanece sincronizado.

---

# Ventajas de IMAP

- Sincronización entre dispositivos.
- Carpetas compartidas.
- Copias centralizadas.
- Ideal para teletrabajo.
- Muy utilizado en empresas.

Actualmente es el protocolo más habitual para acceder al correo electrónico.

---

# POP3 vs IMAP

Esta comparación aparece con mucha frecuencia en oposición.

| POP3 | IMAP |
|-------|------|
| Descarga el correo | Sincroniza el correo |
| Pensado para un único equipo | Pensado para varios dispositivos |
| Puede funcionar completamente sin conexión | Requiere conexión para aprovechar todas sus funciones |
| Menor uso del servidor | Mayor uso del servidor |
| Gestión local | Gestión centralizada |

Una forma sencilla de recordarlo es:

**POP3 = me llevo el correo.**

**IMAP = el correo permanece en el servidor.**

---

# ¿Qué utiliza actualmente la mayoría de empresas?

Hoy en día la inmensa mayoría de organizaciones utilizan:

```
IMAP
```

¿Por qué?

Porque permite trabajar simultáneamente desde:

- Ordenador.
- Portátil.
- Smartphone.
- Tablet.
- Webmail.

Todo permanece sincronizado automáticamente.

---

# Conceptos importantes

Antes de continuar debes recordar:

- SMTP envía el correo.
- POP3 descarga el correo al dispositivo.
- IMAP mantiene el correo en el servidor y sincroniza todos los clientes.
- SMTP nunca se utiliza para leer mensajes.
- POP3 e IMAP son protocolos de acceso al buzón, no de envío.

---

# El viaje completo de un correo electrónico

Hasta ahora conocemos los protocolos implicados.

Pero...

> **¿Qué ocurre exactamente desde que pulsamos "Enviar" hasta que el destinatario recibe el mensaje?**

Veámoslo paso a paso.

---

# El escenario

Pedro trabaja en:

```
empresa.es
```

Quiere enviar un correo a María.

```
maria@universidad.es
```

Cuando pulsa:

```
Enviar
```

Comienza el siguiente proceso.

---

# Paso 1 · El cliente entrega el correo

Pedro escribe el mensaje.

Pulsa:

```
Enviar
```

Su cliente de correo establece una conexión con el servidor SMTP configurado.

```
Pedro

↓

Outlook

↓

SMTP

↓

Servidor empresa.es
```

En este momento el correo todavía no ha salido de la organización.

Simplemente ha llegado al servidor de correo de la empresa.

---

# Paso 2 · El servidor analiza el destinatario

El servidor observa la dirección:

```
maria@universidad.es
```

Detecta que el dominio de destino es:

```
universidad.es
```

Ahora necesita responder a una pregunta.

> **¿Qué servidor recibe el correo de universidad.es?**

Aquí entra nuevamente en juego DNS.

---

# Paso 3 · Consulta DNS

El servidor SMTP realiza una consulta DNS.

Pero no busca una dirección IP cualquiera.

Busca un:

```
Registro MX
```

(Mail Exchange)

---

# Registro MX

El registro MX indica cuál es el servidor encargado de recibir el correo electrónico de un dominio.

Ejemplo:

```
universidad.es

↓

MX

↓

mail.universidad.es
```

Ahora el servidor conoce el nombre del servidor responsable del correo.

Sin embargo...

Todavía necesita conocer su dirección IP.

---

# Paso 4 · Resolución del nombre

El servidor realiza una nueva consulta DNS.

Esta vez utiliza un:

```
Registro A

(o AAAA si utiliza IPv6)
```

Obtiene finalmente la dirección IP.

Por ejemplo:

```
mail.universidad.es

↓

193.146.xxx.xxx
```

Ahora ya sabe exactamente dónde debe entregar el mensaje.

---

# Paso 5 · Entrega del correo

El servidor SMTP establece una conexión con el servidor SMTP del dominio de destino.

```
Servidor empresa.es

↓

SMTP

↓

Servidor universidad.es
```

El mensaje queda almacenado en el buzón de María.

---

# Paso 6 · María consulta su correo

Horas después...

María abre Outlook.

Su cliente utiliza:

```
IMAP
```

para consultar el servidor.

```
Servidor universidad.es

↓

IMAP

↓

Outlook
```

El mensaje aparece inmediatamente en su bandeja de entrada.

---

# El recorrido completo

Visualmente:

```
Pedro

↓

Cliente de correo

↓

SMTP

↓

Servidor empresa.es

↓

Consulta DNS

↓

Registro MX

↓

Servidor universidad.es

↓

Buzón

↓

IMAP

↓

María
```

Observa que durante un único envío han intervenido varios protocolos distintos.

Cada uno realiza una tarea completamente diferente.

---

# ¿Qué papel desempeña cada protocolo?

Podemos resumir todo el proceso de esta forma:

| Protocolo | Función |
|-----------|---------|
| SMTP | Envía el correo |
| DNS | Localiza el servidor de destino |
| MX | Indica qué servidor recibe el correo del dominio |
| Registro A / AAAA | Obtiene la dirección IP del servidor de correo |
| IMAP | Permite consultar el buzón |
| POP3 | Alternativa para descargar el correo |

Es muy habitual que el tribunal combine varios de estos conceptos en una misma pregunta.

---

# Arquitectura completa

```
Pedro

↓

Outlook

↓

SMTP

↓

Servidor empresa.es

↓

DNS

↓

Registro MX

↓

mail.universidad.es

↓

Registro A

↓

193.146.xxx.xxx

↓

SMTP

↓

Servidor universidad.es

↓

IMAP

↓

María
```

Este esquema resume prácticamente todo el funcionamiento del correo electrónico en Internet.

# Relación con otros capítulos

Observa cómo este tema conecta con contenidos que ya hemos estudiado.

### DNS

Los registros MX permiten localizar el servidor de correo.

---

### Direccionamiento IP

Una vez obtenido el registro MX, es necesario resolver el nombre mediante un registro A o AAAA.

---

### TCP/IP

Los protocolos SMTP, POP3 e IMAP funcionan sobre la pila TCP/IP.

---

### Active Directory

En muchas empresas el servidor de correo se integra con:

- Active Directory.
- LDAP.
- Kerberos.

De este modo los usuarios utilizan las mismas credenciales para acceder al dominio y al correo electrónico.

# ⚠️ Errores clásicos de oposición

❌ Pensar que SMTP sirve para leer el correo.

➡️ SMTP **solo envía** mensajes.

---

❌ Creer que POP3 e IMAP hacen exactamente lo mismo.

➡️ Ambos permiten acceder al correo, pero POP3 lo descarga mientras que IMAP lo sincroniza.

---

❌ Pensar que el registro MX contiene directamente la dirección IP.

➡️ El registro MX contiene el **nombre del servidor de correo**. Después será necesario resolver ese nombre mediante un registro A o AAAA.

---

❌ Creer que el cliente envía directamente el correo al destinatario.

➡️ El mensaje siempre pasa por uno o varios servidores SMTP.

---

# 🎓 Resumen del capítulo

Al finalizar este capítulo debes recordar:

- SMTP es el protocolo utilizado para enviar correo electrónico.
- POP3 descarga el correo al dispositivo del usuario.
- IMAP mantiene el correo sincronizado entre varios dispositivos.
- El servidor SMTP consulta DNS para localizar el servidor del dominio de destino.
- Los registros MX indican qué servidor recibe el correo de un dominio.
- Tras resolver el registro MX mediante un registro A o AAAA, el servidor SMTP entrega el mensaje al servidor de destino.
- El destinatario accede posteriormente al buzón mediante IMAP o POP3.

---

# 📖 Resumen final

El correo electrónico es un servicio distribuido en el que intervienen distintos protocolos especializados. **SMTP** se encarga del envío de mensajes entre clientes y servidores, así como entre servidores de correo. Para localizar el servidor responsable del dominio de destino, se utiliza **DNS** mediante los **registros MX**, que posteriormente se resuelven a una dirección IP utilizando registros **A** o **AAAA**. Finalmente, el destinatario accede a su buzón mediante **IMAP** o **POP3**, dependiendo del método de acceso configurado. Comprender el recorrido completo de un mensaje permite entender cómo colaboran los distintos servicios de red para hacer posible uno de los sistemas de comunicación más utilizados de Internet.
