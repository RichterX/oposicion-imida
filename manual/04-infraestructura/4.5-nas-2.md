En NAS destacan:


------------------------------------------------------------------------

# 4. SMB

> **Server Message Block**

es un protocolo de red utilizado para compartir recursos, especialmente
archivos e impresoras.

En NAS se utiliza principalmente para:

``` text
File sharing
```

------------------------------------------------------------------------

# 5. Evolución de SMB

Históricamente han existido distintas versiones:

``` text
SMB 1
SMB 2
SMB 2.x
SMB 3.x
```

Las versiones modernas ofrecen mejoras importantes de:

``` text
Performance
Security
Reliability
Features
```

------------------------------------------------------------------------

# 6. SMB1

SMB1 es una versión antigua.

En entornos modernos:

``` text
SMB1
```

se considera obsoleta y, cuando es posible, debe evitarse.

------------------------------------------------------------------------

# 7. ¿Por qué evitar SMB1?

Entre otros motivos:

``` text
Legacy design
Security weaknesses
Older protocol behavior
```

Por ello las infraestructuras modernas prefieren:

``` text
SMB 2+
```

y especialmente versiones modernas de:

``` text
SMB 3.x
```

------------------------------------------------------------------------

# 8. SMB2

SMB2 introdujo mejoras importantes respecto a SMB1:

``` text
Fewer protocol operations
Improved performance
Better scalability
```

------------------------------------------------------------------------

# 9. SMB3

SMB3 añadió capacidades orientadas a entornos empresariales, incluyendo
mecanismos relacionados con:

``` text
Encryption
Multichannel
Direct
Availability
```

según versión y plataforma.

------------------------------------------------------------------------

# 10. SMB Multichannel

> **SMB Multichannel**

permite utilizar múltiples conexiones de red para una sesión SMB cuando
el cliente y servidor lo soportan.

Puede mejorar:

``` text
Throughput
Redundancy
```

------------------------------------------------------------------------

# 11. SMB Direct

> **SMB Direct**

utiliza tecnologías como:

``` text
RDMA
```

para reducir determinadas cargas y latencias en entornos compatibles.

Es una característica avanzada, especialmente relevante en
infraestructuras empresariales.

------------------------------------------------------------------------

# 12. SMB encryption

SMB moderno puede proporcionar:

``` text
Encryption
```

para proteger los datos en tránsito.

Esto es especialmente importante cuando:

``` text
Traffic crosses untrusted networks
```

o cuando las políticas de seguridad lo exigen.

------------------------------------------------------------------------

# 13. SMB signing

SMB también puede utilizar:

> **SMB signing**

para proporcionar integridad y autenticidad del tráfico en determinados
escenarios.

No debemos confundir:

``` text
Signing
```

con:

``` text
Encryption
```

------------------------------------------------------------------------

# 14. Signing vs encryption

``` text
Signing
→ protege integridad/autenticidad del tráfico

Encryption
→ protege confidencialidad del tráfico
```

------------------------------------------------------------------------

# 15. SMB authentication

SMB puede integrarse con mecanismos de autenticación como:

``` text
Kerberos
NTLM
```

según entorno y configuración.

------------------------------------------------------------------------

# 16. Active Directory

------------------------------------------------------------------------

# 17. Authentication vs Authorization

Una diferencia clásica de examen:

> **Authentication = quién eres.**

> **Authorization = qué puedes hacer.**

------------------------------------------------------------------------

# 18. Ejemplo

``` text
Pedro
↓
Authentication
↓
"Soy Pedro"
```

Después:

``` text
Authorization
↓
"Pedro puede leer Projects"
```

# 19. Kerberos

> **Kerberos**

es un protocolo de autenticación basado en tickets.

En un dominio Active Directory:

``` text
User
↓
Kerberos
↓
Ticket
↓
Service
```

------------------------------------------------------------------------

# 20. Ventaja conceptual

El cliente no necesita enviar continuamente la contraseña al servicio.

Utiliza:

``` text
Tickets
```

para demostrar su identidad.

------------------------------------------------------------------------

# 21. NTLM

> **NTLM**

es otro mecanismo histórico de autenticación de Microsoft.

En entornos modernos se prefiere:

``` text
Kerberos
```

cuando es posible.

------------------------------------------------------------------------

# 22. LDAP

> **LDAP (Lightweight Directory Access Protocol)**

permite acceder y consultar servicios de directorio.

Puede utilizarse para:

``` text
Users
Groups
Directory information
```

------------------------------------------------------------------------

# 23. LDAP vs Active Directory

No son exactamente lo mismo.

``` text
LDAP
→ protocolo de acceso a directorios
```

``` text
Active Directory
→ servicio/directorio empresarial de Microsoft
```

Active Directory soporta LDAP, entre otros protocolos y mecanismos.

``` text

Deny rules
Inheritance
Protocol
```

universal.

# 43. Principle of Least Privilege

``` text
Accidental modification

Security risk
```

# 47. NFS export

En NFS se habla habitualmente de:

> **Export**

El NAS exporta un directorio para que determinados clientes puedan
montarlo.

------------------------------------------------------------------------

# 48. Ejemplo

Servidor:

``` text
NAS
```

``` text
/export/projects
```

El cliente puede montarlo en:

``` text
/mnt/projects
```

------------------------------------------------------------------------

# 49. Mount

Un montaje relaciona:

``` text
Remote filesystem
```

con:

``` text
Local directory
```

Ejemplo:

``` text
NAS:/export/projects
        ↓
     /mnt/projects
```

------------------------------------------------------------------------

# 50. Resultado

Para el usuario Linux:

``` text
/mnt/projects
```

parece un directorio normal.

Pero los datos están realmente en:

``` text
NAS
```

# 59. Root Squash

Una característica importante de NFS tradicional:

> **root_squash**

puede impedir que el usuario root del cliente tenga privilegios
equivalentes a root sobre el servidor.

Conceptualmente:

``` text
Client root
↓
mapped identity
↓
restricted privileges
```

------------------------------------------------------------------------

# 60. ¿Por qué?

Porque:

``` text
root
```

en un cliente no debería obtener automáticamente:

``` text
root privileges
```

sobre el NAS.

Es una medida de seguridad importante.

# 75. File locking

Cuando dos clientes acceden simultáneamente al mismo archivo, pueden
aparecer conflictos.

El:

> **File locking**

permite coordinar accesos.

------------------------------------------------------------------------

# 76. Ejemplo

``` text
↓

```

``` text

↓
```

# 79. Mandatory locking
