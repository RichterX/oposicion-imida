# 14. VMware: conceptos que NO debemos confundir

Esta sección es especialmente importante.

---

## 14.1 ESXi vs vCenter

```text
ESXi
→ Ejecuta VMs

vCenter
→ Gestiona centralizadamente hosts y recursos
```

---

## 14.2 Host vs Cluster

```text
Host
→ servidor ESXi individual

Cluster
→ conjunto lógico de hosts
```

---

## 14.3 VM vs Template

```text
VM
→ workload operativo

Template
→ imagen/configuración base para despliegues
```

---

## 14.4 Datastore vs VMDK

```text
Datastore
→ espacio de almacenamiento gestionado por vSphere

VMDK
→ disco virtual de una VM
```

---

## 14.5 vNIC vs vmnic

```text
vNIC
→ NIC virtual de una VM

vmnic
→ NIC física del host ESXi
```

---

## 14.6 VMkernel vs vNIC

```text
VMkernel
→ interfaces utilizadas por servicios del host

vNIC
→ interfaz virtual de una VM
```

---

# 15. HA vs DRS

Una de las parejas más importantes.

```text
HA
→ Availability
```

```text
DRS
→ Resource scheduling / placement
```

### Regla mental

```text
HA
→ "¿Qué hacemos si falla?"

DRS
→ "¿Dónde debería ejecutarse?"
```

---

# 16. HA vs vMotion

```text
HA
→ recuperación

vMotion
→ migración
```

---

# 17. DRS vs vMotion

```text
DRS
→ decide/recomienda colocación según configuración

vMotion
→ mecanismo de migración de una VM en ejecución
```

DRS puede utilizar vMotion.

---

# 18. vMotion vs Storage vMotion

```text
vMotion
→ Compute / host

Storage vMotion
→ Storage / datastore
```

---

# 19. Snapshot vs Backup

```text
Snapshot
→ estado/delta temporal asociado a una VM

Backup
→ copia destinada a recuperación
```

### Nunca memorices:

```text
Snapshot = Backup
```

porque es una trampa clásica.

---

# 20. Backup vs Replication

```text
Backup
→ puntos de recuperación

Replication
→ copia del workload hacia otro sistema/destino
```

Una replicación no sustituye automáticamente una estrategia de backup.

---

# 21. HA vs DR

```text
HA
→ determinados fallos de infraestructura local

DR
→ recuperación ante desastres de mayor alcance
```

---

# 22. Reservation vs Limit vs Shares

```text
Reservation
→ reserva / garantía

→ máximo

→ prioridad relativa
```


# 25. Event vs Task


# 27. VMFS vs NFS

# 28. Standard Switch vs Distributed Switch

# 29. vNIC vs Port Group

# 57. 🧪 Preguntas de razonamiento

Estas son más importantes que las puramente memorísticas.

---

## Caso 1

```text
ESXi01
CPU usage: 30 %

VM01
CPU Ready: alto
```

¿Es posible que exista un problema de CPU?

### Respuesta

Sí.

El host puede tener:

```text
CPU usage global moderado
```

y aun así existir:

```text
Contention
```

en determinadas cargas.

---

## Caso 2

```text
Datastore
Free: 50 %

Latency: 100 ms
```

¿Hay necesariamente un problema de capacidad?

### Respuesta

No.

Hay:

```text
capacidad disponible
```

pero:

```text
performance problem
```

puede existir.

---

## Caso 3

```text
Datastore
Free: 5 %

Latency: normal
```

¿Está todo bien?

### Respuesta

No necesariamente.

El rendimiento actual puede ser normal, pero existe:

```text
Capacity risk
```

---

## Caso 4

```text
Replication ✓
Backup ❌
```

¿Tenemos una estrategia completa de protección?

### Respuesta

No necesariamente.

La replicación no sustituye automáticamente a:

```text
Backup
Retention
Recovery points
```

---

## Caso 5

```text
Backup ✓
Restore test ❌
```

¿Tenemos una recuperación validada?

### Respuesta

No.

Debemos realizar:

```text
Restore testing
```

---

## Caso 6

```text
RPO = 15 min
RTO = 4 h
```

¿Cuál es la diferencia?

### Respuesta

```text
RPO
→ cuánto dato podemos perder

RTO
→ cuánto tiempo podemos tardar
```

---

## Caso 7

```text
Script
+
Administrator
+
100 VMs
```

¿Qué riesgo existe?

### Respuesta

Un error del script puede afectar:

```text
100 VMs
```

con un:

```text
Blast Radius
```

muy elevado.

---

## Caso 8

```text
Script
→ 1 VM
→ validate
→ 5 VMs
→ validate
→ 100 VMs
```

¿Qué concepto estamos aplicando?

### Respuesta

```text
Canary / Progressive rollout
```

### "vmnic es una NIC virtual"

❌ Es física.

❌ Es virtual.
