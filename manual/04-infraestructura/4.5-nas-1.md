# 1. ¿Qué es NAS?

NAS significa:

> **Network Attached Storage**

Es un sistema de almacenamiento conectado a una red que proporciona
principalmente **acceso a archivos** a otros equipos.

Modelo básico:

``` text
Cliente
   │
   │ Red
   ▼
  NAS
   │
   ▼
Storage
```

La característica esencial es:

``` text
NAS
↓
File-level storage
```

El cliente trabaja normalmente con:

``` text
Files
Folders
Directories
Shares
```

y no necesita conocer cómo están organizados físicamente los discos.

------------------------------------------------------------------------

Imaginemos:

``` text
NAS
└── Company
    ├── Finance
    ├── HR
    ├── Projects
    └── Public
```

``` text
\\NAS\Company
```

El usuario ve:

``` text
Archivos
Carpetas
```

``` text
Filesystem
```

------------------------------------------------------------------------

# 7. La red como cuello de botella

Supongamos:

``` text
Storage backend
→ 2 GB/s
```

pero:

``` text
Network
→ 1 Gb/s
```

El cliente no podrá aprovechar los 2 GB/s del backend.

Recordemos:

``` text
1 Byte = 8 bits
```

Por tanto:

``` text
1 Gb/s ≈ 125 MB/s
```

antes de overheads.

  Característica          File                       Block

  Filesystem              Normalmente lado storage   Normalmente lado host
  Ejemplo                 NAS                        SAN
  Protocolos habituales   SMB/NFS                    FC/iSCSI

# 16. Storage Pool

Un:

> **Storage Pool**

es una agrupación lógica de recursos físicos de almacenamiento.

Ejemplo:

``` text
Disk 1
Disk 2
Disk 3
Disk 4
   │
   ▼
Storage Pool
```

El pool permite abstraer los recursos físicos.

------------------------------------------------------------------------

# 17. Pool no es RAID

No debemos confundir:

``` text
Storage Pool
```

con:

``` text
RAID
```

Conceptualmente:

``` text
RAID
→ distribución/protección

Pool
→ agrupación lógica de capacidad
```

Pueden utilizarse conjuntamente.

------------------------------------------------------------------------

Sobre un pool pueden crearse:

``` text

ZFS
```




# 22. Volume vs Share

No son necesariamente lo mismo.

``` text

→ espacio lógico de almacenamiento
```

``` text
Share
→ recurso presentado a clientes
```

Un volumen puede contener varios shares, según la plataforma.


# 24. NFS

> **Network File System**

es un protocolo de compartición de archivos muy habitual en:

``` text

Unix
```

Ejemplo conceptual:

``` text

```

``` text

```

------------------------------------------------------------------------

# 25. SMB y NFS

  Característica    SMB             NFS
  ----------------- --------------- ---------------
  Tipo              File protocol   File protocol
  Uso tradicional   Windows         Unix/Linux
  NAS               Muy común       Muy común
  Multiplataforma   Sí              Sí

No debemos memorizar:

``` text
SMB = exclusivamente Windows
NFS = exclusivamente Linux
```

porque ambas tecnologías tienen implementaciones para diferentes
sistemas.

# 35. Snapshots

Un:

> **Snapshot**

representa un estado lógico de los datos en un momento determinado.

Ejemplo:

``` text
10:00 → Snapshot A
12:00 → Snapshot B
14:00 → Snapshot C
```

Puede permitir recuperar versiones anteriores según la implementación.

------------------------------------------------------------------------

# 36. Snapshot no es backup

Esta diferencia es fundamental:

``` text
Snapshot
≠
Backup
```

Si todos los snapshots están dentro del mismo NAS y el NAS desaparece:

``` text
NAS destroyed
↓
Snapshots may be lost
```

------------------------------------------------------------------------

# 37. Snapshot y ransomware

Los snapshots pueden ser útiles frente a:

``` text
Accidental deletion
Ransomware
Corruption
```

pero no deben considerarse una protección completa por sí solos.

------------------------------------------------------------------------

# 38. Replication

``` text

```

o:

``` text
Another site
```

según la plataforma.

------------------------------------------------------------------------

# 39. Replication vs backup

``` text
Replication
→ mantiene una copia sincronizada o casi sincronizada

Backup
→ mantiene copias destinadas a recuperación
```

La replicación puede propagar determinados errores o borrados, por lo
que no sustituye automáticamente al backup.

# 95. 🏆 Las 20 reglas de oro

``` text
1. NAS = Network Attached Storage.
2. Su modelo tradicional es file-level storage.
3. NAS utiliza una red.
4. SMB es un protocolo fundamental.
5. NFS es otro protocolo fundamental.
6. NAS puede utilizar RAID.
7. RAID no es backup.
8. Storage Pool no es RAID.
9. Volume no es Share.
10. Filesystem organiza archivos.
11. Share presenta recursos a clientes.
12. NAS puede integrarse con Active Directory.
13. ACL controla acceso.
14. Quotas limitan consumo.
15. Snapshots representan estados puntuales.
16. Snapshot no equivale automáticamente a backup.
17. Replication no equivale automáticamente a backup.
18. NAS puede utilizarse como destino de backup.
19. Algunos NAS pueden proporcionar también block storage.
20. NAS y SAN se diferencian tradicionalmente por file-level vs block-level.
```

# 103. 🎓 Pregunta de razonamiento

> Una empresa tiene un NAS con RAID 6 y snapshots. ¿Está completamente
> protegida contra ransomware?

No.

Porque:

``` text
RAID
→ redundancia
```

y:

``` text
Snapshot
→ recuperación puntual
```

pero ambos pueden residir dentro del mismo sistema afectado.

Se recomienda una estrategia de backup apropiada, idealmente con copias
aisladas/inmutables cuando el riesgo lo justifique.
