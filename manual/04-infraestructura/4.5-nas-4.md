# 9. Administración desde Linux

En Linux podemos trabajar principalmente con:

``` text
mount
/etc/fstab
NFS
SMB/CIFS
systemd
```

------------------------------------------------------------------------

# 10. Montaje NFS

Ejemplo conceptual:

``` bash
mount NAS:/export/projects /mnt/projects
```

La sintaxis concreta puede variar según la versión y distribución.

------------------------------------------------------------------------

# 11. Montaje SMB desde Linux

Linux puede utilizar:

``` text
CIFS
```

para montar recursos SMB.

Ejemplo conceptual:

``` bash
mount -t cifs //NAS/Projects /mnt/projects
```

------------------------------------------------------------------------

# 12. CIFS

> **CIFS**

es un término históricamente asociado a SMB y aparece habitualmente en
Linux para el cliente SMB.

En sistemas modernos:

``` text
SMB2/SMB3
```

son preferibles frente a protocolos legacy.

------------------------------------------------------------------------

# 13. Montaje temporal

Un:

``` bash
mount
```

manual normalmente no garantiza que el recurso se monte después de
reiniciar.

Para persistencia debemos utilizar mecanismos de configuración.

------------------------------------------------------------------------

# 14. /etc/fstab

En Linux:

``` text
/etc/fstab
```

permite definir sistemas de archivos que pueden montarse
automáticamente.

Ejemplo conceptual:

``` text
NAS:/export/projects /mnt/projects nfs defaults 0 0
```

------------------------------------------------------------------------

# 15. Cuidado con fstab

Un error en:

``` text
/etc/fstab
```

puede provocar:

``` text
Boot problems
Mount failures
Delayed boot
```

Por eso conviene validar cuidadosamente los cambios.

------------------------------------------------------------------------

# 16. systemd

En sistemas Linux modernos:

``` text
systemd
```

gestiona muchos servicios y puede participar en la gestión de montajes.



# 60. Capacity planning

Antes de comprar un NAS debemos estimar:

``` text
Current data
Annual growth
Retention
Snapshots
Backup
Replication
Free space
```

------------------------------------------------------------------------

# 61. Ejemplo

Tenemos:

``` text
Current = 30 TB
Growth = 5 TB/year
Planning horizon = 3 years
```

Necesitamos aproximadamente:

``` text
30 + 15 = 45 TB
```

antes de añadir:

``` text
RAID overhead
Snapshots
Free space
Backup
```

------------------------------------------------------------------------

# 62. No dimensionar al límite

No deberíamos diseñar:

``` text
45 TB requirement
45 TB usable
```

y asumir que está resuelto.

Necesitamos margen.

------------------------------------------------------------------------

# 63. Performance planning

Debemos estimar:

``` text
Users

IOPS
Throughput
Latency
Network bandwidth
```

------------------------------------------------------------------------

# 64. Ejemplo

Una empresa necesita:

``` text
500 MB/s
```

pero dispone de:

``` text
1 GbE
```

Recordemos:

``` text
1 Gb/s ≈ 125 MB/s
```

por lo que ese enlace no será suficiente para conseguir 500 MB/s de
throughput de red.

# 71. RAID rebuild y disponibilidad

Si falla un disco:

``` text

↓
Replacement
↓
Rebuild
```

------------------------------------------------------------------------

# 72. Hot spare

Un:

``` text
Hot spare
```

puede reducir el tiempo hasta comenzar la reconstrucción.

------------------------------------------------------------------------

# 73. Multiple failures

El diseño debe considerar:

``` text
How many disks can fail?
```

Por ejemplo:

``` text
RAID 5
→ one disk failure

RAID 6
→ two disk failures
```

------------------------------------------------------------------------

# 74. RAID 10

RAID 10 combina:

``` text
Mirroring
+
Striping
```

y puede proporcionar buen rendimiento y redundancia, con el coste de una
menor capacidad utilizable respecto a un RAID puramente orientado a
capacidad.

------------------------------------------------------------------------

# 75. RAID choice

``` text
Capacity
Performance
Fault tolerance
Rebuild time
Budget
Workload
```
