# 1. ¿Qué es una SAN?

> **SAN = Storage Area Network**

Es una infraestructura especializada que proporciona acceso a
almacenamiento, normalmente mediante **block storage**, a servidores.

Modelo:

``` text
HOST
  ↓
SAN
  ↓
STORAGE
```

El host recibe dispositivos de bloques y posteriormente decide cómo
utilizarlos.

------------------------------------------------------------------------

# 2. SAN vs NAS

Una de las diferencias fundamentales:

``` text
SAN
↓
Block storage
```

``` text
NAS
↓
File storage
```

Conceptualmente:

``` text
SAN:
"Te doy bloques."

NAS:
"Te doy archivos."
```

# 6. La identidad FC

Debes diferenciar:

``` text
WWNN
WWPN
FCID
```

## WWNN

``` text
World Wide Node Name
```

Identifica conceptualmente un nodo Fibre Channel.

## WWPN

``` text
World Wide Port Name
```

Identifica un puerto Fibre Channel.

## FCID

``` text
Fibre Channel ID
```

Es una dirección utilizada dentro del fabric.

------------------------------------------------------------------------

# 7. Regla rápida

``` text
WWPN
→ ¿Qué puerto eres?

FCID
→ ¿Qué dirección tienes dentro del fabric?
```

------------------------------------------------------------------------

# 8. Puertos FC

``` text
N_Port
F_Port
E_Port
```

## N_Port

Puerto de un dispositivo final.

Ejemplo:

``` text
HBA
```

## F_Port

Puerto del switch que conecta un dispositivo final.

## E_Port

Puerto utilizado para conectar switches.


# 68. IOPS y tamaño de bloque

La misma cantidad de IOPS puede generar diferentes niveles de
throughput.

Ejemplo:

``` text
1000 IOPS × 4 KB
≈ 4 MB/s
```

Mientras:

``` text
1000 IOPS × 1 MB
≈ 1000 MB/s
```

------------------------------------------------------------------------

# 69. Sequential vs Random

``` text

→ acceso consecutivo

Random
→ acceso disperso
```

Una carga de backup puede favorecer:

``` text
Sequential throughput
```

``` text
Random I/O
High IOPS
Low latency
```

# 70. Queue Depth



  --------------------- --------------------------------
  Fallo de disco        RAID
  Fallo de HBA/path     Multipath
  Fallo de switch       Dual Fabric

# 93. 🧠 Una última historia para recordarlo

Imagina que una empresa tiene un almacén gigante.

Los servidores son trabajadores:

``` text
HOSTS
```

La SAN son las carreteras privadas:

``` text
SAN
```

Las LUN son almacenes concretos:

``` text
LUNs
```

Zoning decide:

``` text
"Este trabajador puede llegar a este almacén."
```

LUN masking decide:

``` text
"Este trabajador puede ver este almacén concreto."
```

Multipath construye:

``` text
Varias carreteras alternativas.
```

RAID protege:

``` text
Los edificios frente al fallo de determinados discos.
```

Replication mantiene:

``` text
Otro almacén en otra ubicación.
```

Backup conserva:

``` text
Versiones anteriores.
```

DR define:

``` text
Qué hacemos si desaparece todo el recinto.
```

Y entonces la SAN deja de ser una sopa de siglas y se convierte en una
infraestructura con una lógica bastante razonable.
