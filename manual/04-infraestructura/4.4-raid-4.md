# 6. RAID como capa

La idea importante es:

> **RAID es una capa de almacenamiento, no toda la arquitectura de almacenamiento.**

---

# 7. Servidor físico + RAID

Supongamos:

```text
Server01
```

con:

```text
8 × 2 TB
RAID 10
```

El sistema operativo puede ver:

```text
Logical Disk
```

por ejemplo:

```text
Disk 0
```

sin necesidad de conocer todos los detalles físicos del array.

---

# 8. Abstracción

Tenemos:

```text
Physical disks
```

pero presentamos:

```text
Logical storage
```

Esto es una abstracción.

---

# 9. Ventaja de la abstracción

El sistema operativo puede trabajar con:

```text
Logical disk
```

mientras la controladora gestiona:

```text
RAID
Parity
Mirroring
Disk failures
Rebuild
```

---

# 10. HBA

Una:

> **HBA (Host Bus Adapter)**

es un adaptador que conecta un servidor con un sistema de almacenamiento o bus de almacenamiento.

Puede encontrarse en tecnologías como:

```text
Fibre Channel
SAS
```

---

# 11. HBA vs RAID Controller

No debemos confundir:

```text
HBA
```

con:

```text
RAID Controller
```

Una HBA proporciona principalmente:

```text
Connectivity
```

mientras una controladora RAID puede proporcionar:

```text
RAID management
Parity
Mirroring
Caching
```

---

# 12. HBA en modo passthrough

Algunos controladores o adaptadores pueden funcionar en modos donde los discos se presentan al sistema operativo sin que la controladora construya un RAID hardware tradicional.

Esto permite utilizar:

```text
Software-defined storage
```

o:

```text
Software RAID
```

según plataforma.

---

# 13. IT Mode

En algunos ecosistemas SAS se habla de:

> **IT Mode**

para referirse a una configuración orientada a presentar los discos directamente al sistema operativo o software de almacenamiento.

No debe confundirse con:

```text
Hardware RAID
```

---

# 14. SAS

> **Serial Attached SCSI**

es una tecnología de almacenamiento empresarial.

Características generales:

```text
Enterprise-oriented
Reliable
Dual-port capable in many implementations
High availability options
```

---

# 15. SATA

> **Serial ATA**

es una interfaz ampliamente utilizada para almacenamiento.

Es frecuente en:

```text
HDD
SSD
```

especialmente en sistemas donde el coste y capacidad son importantes.

---

# 16. SAS vs SATA

| Característica | SAS | SATA |
|---|---|---|
| Orientación | Empresarial | General |
| Dual-port | Habitual en entornos enterprise | Generalmente no |
| Robustez empresarial | Alta | Variable |
| Coste | Mayor | Menor |
| Uso | Servidores/storage | PCs/servidores/storage |

No significa:

```text
SAS siempre más rápido
```

ni:

```text
SATA siempre peor
```

La comparación depende del dispositivo y workload.

---

# 17. Velocidad de interfaz

No debemos confundir:

```text
Interface bandwidth
```

con:

```text
Actual storage performance
```

---

# 18. Ejemplo

```text
X GB/s
```

pero el disco puede ofrecer:

```text

```

siendo:

```text

```

El cuello de botella puede estar en:

```text
Media
Controller
Interface
```

# 19. NVMe

> **NVMe (Non-Volatile Memory Express)**

es un protocolo diseñado para aprovechar medios de memoria no volátil de alta velocidad, especialmente SSD, sobre PCIe.

Conceptualmente:


mientras:

```text

↓

```

# 21. Ventaja de NVMe

NVMe está diseñado para ofrecer:

```text
Low latency
High parallelism
High IOPS
```

---

# 22. NVMe y RAID

```text

```

pero la arquitectura depende de:


# 23. RAID tradicional vs NVMe architectures

En plataformas modernas pueden existir:

```text
Software RAID

```


# 24. PCIe

NVMe utiliza:

```text
PCI Express
```

Esto permite:

```text
Más bandwidth
Menor latencia
Más paralelismo
```

# 27. El cuello de botella

Una regla importante:

> **El rendimiento de una cadena está condicionado por sus componentes y por el workload, no solo por el disco más rápido.**

# 28. Storage latency

La latencia puede acumularse en:

```text
Application
+
OS
+
Controller
+
Network
+
Storage
```

---

# 29. Latencia de disco

En HDD:

```text
Mechanical movement
```

puede producir mayor latencia.

En SSD:

```text
Electronic access
```

reduce considerablemente la latencia.

---

# 30. Latencia RAID

Un RAID con paridad puede introducir:

```text
Additional operations
```

especialmente en:

```text
Small random writes
```

---

# 31. Latencia de red

En SAN/NAS:

```text
Network latency
```

también forma parte de la experiencia final.

---

# 32. IOPS

Recordatorio:

```text
IOPS = I/O operations per second
```

---

# 33. Throughput

```text
Throughput = amount of data transferred per unit of time
```

---

# 34. Latency

```text
Latency = time required to complete an operation
```

---

# 35. No confundir

```text
IOPS
≠
Throughput
≠
Latency
```

---

# 36. Ejemplo

Una aplicación puede necesitar:

```text
100.000 IOPS
```

pero transferir pequeños bloques.

Otra puede necesitar:

```text
1 GB/s
```

con operaciones grandes.

Son workloads diferentes.

---

# 37. Block size

El:

> **Block size**

afecta al rendimiento.

Por ejemplo:

```text
4 KB
```

produce un patrón de I/O diferente a:

```text
1 MB
```

---

# 38. IOPS vs throughput

Conceptualmente:

```text
Throughput ≈ IOPS × I/O size
```

Por ejemplo:

```text
10.000 IOPS × 4 KB
```

produce mucho menos throughput que:

```text
10.000 IOPS × 256 KB
```

---

# 39. Read/write ratio

Debemos conocer:

```text
70 % read
30 % write
```

o:

```text
20 % read
80 % write
```

porque RAID puede comportarse de forma diferente.

---

# 40. Queue depth

La:

```text
Queue Depth
```

# 41. Demasiada cola

# 50. RPO y RTO

Dos conceptos fundamentales:

> **RPO - Recovery Point Objective**

indica cuánta pérdida de datos es aceptable en términos temporales.

> **RTO - Recovery Time Objective**

indica cuánto tiempo puede tardarse en recuperar el servicio.

---

# 51. RAID y RTO

RAID puede reducir:

```text
Downtime caused by disk failure
```

porque permite mantener disponibilidad durante determinados fallos.

---

# 52. RAID y RPO

RAID no sustituye:

```text
Backup
```

por lo que no proporciona por sí mismo un RPO histórico.

---

# 53. Ejemplo

Una base de datos tiene:

```text
RAID 10
```

y:

```text
Backup every 1 hour
```

El RAID protege frente a determinados fallos físicos.

El backup determina parte del:

```text
RPO
```

---

# 54. RAID y alta disponibilidad

```text

```


```text

```

# 55. RAID no convierte un servidor en HA


```text

1 CPU architecture
1 PSU
1 network path
```

# 57. Multipath

> **Multipathing**

consiste en proporcionar múltiples caminos entre:

```text
Host
```

y:

```text
Storage
```

---

# 58. Ejemplo

Sin multipath:

```text
Server
   │
   ▼
Path A
   │
   ▼
Storage
```

Si:

```text
Path A ❌
```

se pierde conectividad.

---

# 59. Con multipath

```text
          ┌── Path A ──┐
Server ───┤            ├── Storage
          └── Path B ──┘
```

Si:

```text
Path A ❌
```

puede continuar:

```text
Path B
```

---

# 60. Multipath no es RAID

Importante:

```text
Multipath
→ redundancia de conectividad
```

```text
RAID
→ redundancia de almacenamiento
```

---

# 61. RAID + Multipath

```text

   │
   ├── Path A
   └── Path B
        │
        ▼
    Controller
        │
        ▼
       RAID
        │
        ▼
      Disks
```

# 211. 🏆 Las 25 reglas de oro del capítulo

```text
1. RAID = Redundant Array of Independent Disks.
2. RAID 0 = Striping.
3. RAID 1 = Mirroring.
4. RAID 5 = Single parity.
5. RAID 6 = Double parity.
6. RAID 10 = Mirroring + Striping.
7. RAID 5 tolera un fallo.
8. RAID 6 tolera dos fallos.
9. RAID 10 depende del patrón de fallo.
10. RAID no es backup.
11. Hot Spare no es backup.
12. Degraded no significa Failed.
13. Rebuild restaura redundancia.
14. Controller gestiona el RAID hardware.
15. Backplane proporciona conectividad física.
16. HBA proporciona conectividad de almacenamiento.
17. SMART monitoriza indicadores del dispositivo.
18. Multipath proporciona caminos redundantes.
19. NAS suele proporcionar file storage.
20. SAN suele proporcionar block storage.
21. LUN es una unidad lógica de almacenamiento.
22. IOPS no es throughput.
23. Throughput no es latency.
24. Capacity planning debe considerar crecimiento.
25. RAID es solo una capa de resiliencia.
```
