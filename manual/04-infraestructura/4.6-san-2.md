# 1. Fibre Channel: visión general

Fibre Channel:

``` text
FC
```

es una tecnología de conectividad utilizada habitualmente en SAN
empresariales.

La arquitectura clásica:

``` text
HOST
 │
 HBA
 │
 ▼
FC SWITCH
 │
 ▼
STORAGE ARRAY
```

------------------------------------------------------------------------

# 2. ¿Por qué Fibre Channel?

FC fue diseñado para proporcionar:

``` text
High performance
Low latency
Dedicated storage networking
Reliability
```

en infraestructuras de almacenamiento.

------------------------------------------------------------------------

# 3. Fibre Channel no es simplemente "un cable"

Una SAN FC está formada por:

``` text
Hosts
HBAs
Switches
Fabrics
Storage ports
Cables
Optics
```

------------------------------------------------------------------------

# 4. HBA

Recordemos:

> **HBA = Host Bus Adapter**

En FC:

``` text
Server
↓
FC HBA
↓
FC Fabric
```

------------------------------------------------------------------------

# 5. Puertos de un HBA

Un HBA puede disponer de:

``` text
Port 1
Port 2
```

Cada puerto puede tener una identidad propia.

------------------------------------------------------------------------

# 6. WWN

> **WWN = World Wide Name**

Es un identificador único utilizado en Fibre Channel.

------------------------------------------------------------------------

# 7. WWPN

> **WWPN = World Wide Port Name**

Identifica un puerto Fibre Channel.

Conceptualmente:

``` text
HBA
├── Port A → WWPN A
└── Port B → WWPN B
```

------------------------------------------------------------------------

# 8. WWNN

> **WWNN = World Wide Node Name**

Identifica el nodo Fibre Channel.

Podemos pensar:

``` text
Node
└── Ports
```

------------------------------------------------------------------------

# 9. Diferencia WWNN / WWPN

``` text
WWNN
→ identidad del nodo

WWPN
→ identidad del puerto
```

------------------------------------------------------------------------

# 10. ¿Cuál se utiliza mucho en zoning?

En entornos FC es muy habitual utilizar:

``` text
WWPN
```

para identificar puertos concretos.

------------------------------------------------------------------------

# 11. Ejemplo

Tenemos:

``` text
ESXi01
```

con:

``` text
HBA1
```

y:

``` text
WWPN:
10:00:00:00:00:01:01:01
```

El switch puede utilizar esa identidad para configurar zoning.

------------------------------------------------------------------------

# 12. N_Port

> **N_Port**

es un puerto Fibre Channel de un dispositivo final.

Ejemplos:

``` text
Host HBA
Storage port
```

------------------------------------------------------------------------

# 13. F_Port

> **F_Port**

es un puerto del switch que conecta un dispositivo final.

Conceptualmente:

``` text
N_Port
   │
   │
F_Port
   │
FC Switch
```

------------------------------------------------------------------------

# 14. E_Port

> **E_Port**

se utiliza para conectar:

``` text
FC Switch
```

con:

``` text
FC Switch
```

------------------------------------------------------------------------

# 15. E_Port y fabric

``` text
Switch A
   │
 E_Port
   │
   │ ISL
   │
 E_Port
   │
Switch B
```

------------------------------------------------------------------------

# 16. ISL

> **ISL = Inter-Switch Link**

es el enlace entre switches Fibre Channel.

------------------------------------------------------------------------

# 17. Fabric

Un:

> **Fabric**

es el conjunto lógico de switches Fibre Channel interconectados.

------------------------------------------------------------------------

# 18. Ejemplo de fabric

``` text
          Switch A
         /        \
      Host        Switch B
                   │
                Storage
```

Los switches forman parte de un mismo fabric.

------------------------------------------------------------------------

# 19. Fabric ID

Los fabrics pueden identificarse lógicamente mediante:

``` text
Fabric identifiers
```

La implementación concreta depende del fabricante.

------------------------------------------------------------------------

# 20. Single fabric

Una arquitectura sencilla:

``` text
Host
 │
 ▼
FC Switch
 │
 ▼
Storage
```

------------------------------------------------------------------------

# 21. Problema

Si falla:

``` text
FC Switch
```

se pierde el acceso por ese fabric.

------------------------------------------------------------------------

# 22. Dual fabric

Una arquitectura empresarial:

``` text
             HOST
           /      \
        HBA A     HBA B
          │         │
          ▼         ▼
       Fabric A   Fabric B
          │         │
          ▼         ▼
       Storage Controllers
```

------------------------------------------------------------------------

# 23. Ventaja

Si:

``` text
Fabric A
```

falla:

``` text
Fabric B
```

puede continuar proporcionando acceso.

------------------------------------------------------------------------

# 24. Importante

Los dos fabrics deben mantenerse:

``` text
Independent
```

para evitar que un único fallo afecte a ambos.

------------------------------------------------------------------------

# 25. Single points of failure

Debemos evitar:

``` text
Single HBA
Single switch
Single cable
Single storage controller
Single power supply
```

cuando los requisitos exigen alta disponibilidad.

------------------------------------------------------------------------

# 26. Zoning

Uno de los conceptos más importantes:

> **Zoning**

controla qué dispositivos pueden comunicarse dentro del fabric.

------------------------------------------------------------------------

# 27. ¿Qué problema resuelve zoning?

Supongamos:

``` text
20 hosts
10 storage arrays
```

No queremos necesariamente:

``` text
Every host
↔
Every storage port
```

------------------------------------------------------------------------

# 28. Zoning reduce visibilidad

Podemos definir:

``` text
Host A
↔
Storage A
```

y:

``` text
Host B
↔
Storage B
```

------------------------------------------------------------------------

# 29. Zoning no presenta LUN

Esto es importantísimo:

``` text
Zoning
≠
LUN presentation
```

------------------------------------------------------------------------

# 30. Zoning

Controla:

``` text
Who can communicate
```

------------------------------------------------------------------------

# 31. LUN masking

Controla:

``` text
Who can see which LUN
```

------------------------------------------------------------------------

# 32. Cadena completa

``` text
Zoning
↓
Connectivity
↓
LUN masking
↓
LUN visibility
↓
Host rescan
↓
Block device
```

------------------------------------------------------------------------

# 33. Ejemplo

``` text
ESXi01
  │
  │ FC
  ▼
Fabric
  │
  ▼
Storage
  │
  └── LUN 10
```

Zoning permite:

``` text
ESXi01 ↔ Storage Port
```

LUN masking permite:

``` text
ESXi01 → LUN 10
```

# 34. Single initiator zoning

# 35. Ejemplo

# 36. Segunda zona

------------------------------------------------------------------------

# 37. Ventajas

Puede reducir:

``` text
Unnecessary communication
Fabric noise

Failure impact
```

según diseño.

# 38. WWPN zoning

``` text
Host WWPN
+
Storage WWPN
```

------------------------------------------------------------------------

# 39. Ejemplo

``` text
Zone_ESXi01:

10:00:00:00:01:01:01:01
```

------------------------------------------------------------------------

# 40. Port-based zoning

Algunas plataformas permiten zoning basado en:

``` text
Physical switch ports
```

------------------------------------------------------------------------

# 41. WWPN vs port zoning

``` text
WWPN zoning
→ identidad del dispositivo

Port zoning
→ puerto físico del switch
```

------------------------------------------------------------------------

# 42. Ventaja de WWPN

Si el dispositivo se mueve a otro puerto físico del switch:

``` text
WWPN
```

puede mantener su identidad lógica.

------------------------------------------------------------------------

# 43. Riesgo

La configuración exacta depende del fabricante.

En un examen debemos entender:

``` text
WWPN = identidad lógica del puerto FC
```

------------------------------------------------------------------------

# 44. VSAN

En determinados switches Fibre Channel, especialmente en arquitecturas
empresariales, podemos encontrar:

> **VSAN = Virtual Storage Area Network**

------------------------------------------------------------------------

# 45. ¿Qué hace VSAN?

Permite dividir lógicamente un switch/fabric en dominios separados.

Conceptualmente:

``` text
Physical switch
│
├── VSAN 10
│
└── VSAN 20
```

------------------------------------------------------------------------

# 46. Ventaja

Proporciona:

``` text
Logical isolation
Segmentation
Separate fabrics
```

sin necesidad de que cada dominio tenga hardware completamente
independiente.

------------------------------------------------------------------------

# 47. VSAN y VLAN

Conceptualmente:

``` text
Ethernet
→ VLAN

Fibre Channel
→ VSAN
```

No son exactamente la misma tecnología, pero sirven como analogía
conceptual de segmentación lógica.

------------------------------------------------------------------------

# 48. NPIV

> **NPIV = N_Port ID Virtualization**

permite que un único puerto físico Fibre Channel tenga múltiples
identidades virtuales.

------------------------------------------------------------------------

# 49. Problema que resuelve NPIV

Supongamos:

``` text
One physical HBA port
```

queremos presentar varias identidades:

``` text
Virtual Port A
Virtual Port B
Virtual Port C
```

NPIV permite esta virtualización.

------------------------------------------------------------------------

# 50. NPIV y virtualización

Es especialmente útil en:

``` text
Virtualized environments
```

porque múltiples máquinas o entidades lógicas pueden disponer de
identidades FC diferenciadas.

------------------------------------------------------------------------

# 51. Concepto

``` text
Physical HBA Port
       │
      NPIV
   ┌───┼───┐
   │   │   │
 WWPN WWPN WWPN
```

------------------------------------------------------------------------

# 52. NPIV y zoning

Cada identidad virtual puede participar en:

``` text
Zoning
```

como un puerto FC independiente desde el punto de vista lógico.

------------------------------------------------------------------------

# 53. iSCSI

Pasamos ahora a la segunda gran tecnología:

``` text
iSCSI
```

------------------------------------------------------------------------

# 54. iSCSI

> **Internet Small Computer Systems Interface**

transporta comandos SCSI mediante:

``` text
TCP/IP
```

------------------------------------------------------------------------

# 55. Arquitectura

``` text
HOST
 │
iSCSI Initiator
 │
 ▼
Ethernet
 │
 ▼
iSCSI Target
 │
 ▼
LUN
```

------------------------------------------------------------------------

# 56. Initiator

El:

``` text
Initiator
```

está normalmente en el host.

Puede ser:

``` text
Software initiator
```

o:

``` text
Hardware iSCSI adapter
```

según arquitectura.

------------------------------------------------------------------------

# 57. Target

El:

``` text
Target
```

está normalmente en:

``` text
Storage array
```

o dispositivo que proporciona el servicio iSCSI.

------------------------------------------------------------------------

# 58. IQN

> **IQN = iSCSI Qualified Name**

identifica lógicamente entidades iSCSI.

------------------------------------------------------------------------

# 59. Ejemplo IQN

``` text
iqn.2026-08.example:storage01
```

La sintaxis exacta sigue las reglas del estándar.

------------------------------------------------------------------------

# 60. IQN del initiator

Un host puede tener:

``` text
Initiator IQN
```

------------------------------------------------------------------------

# 61. IQN del target

El almacenamiento puede tener:

``` text
Target IQN
```

------------------------------------------------------------------------

# 62. Sesión iSCSI

Conceptualmente:

``` text
Initiator
↓
Login
↓
Target

iSCSI Session
```

------------------------------------------------------------------------

# 63. TCP 3260

El puerto estándar habitual de iSCSI es:


# 64. Discovery

``` text
iSCSI targets
```

# 65. Static discovery

``` text

```

------------------------------------------------------------------------

# 66. SendTargets

Un target puede proporcionar una lista de targets mediante:

``` text
SendTargets
```

El initiator consulta el portal de discovery y obtiene información sobre
los targets disponibles.

------------------------------------------------------------------------

# 67. iSNS

Existe también:

> **iSNS = Internet Storage Name Service**

que puede ayudar al descubrimiento y gestión de dispositivos iSCSI.

------------------------------------------------------------------------

# 68. Portal

> **Portal**

un target.

Ejemplo conceptual:

``` text

```

------------------------------------------------------------------------

# 69. Target portal




# 71. iSCSI multipath

``` text
Redundancy
```

``` text
Load balancing
```

según implementación.

# 72. VLAN de almacenamiento

# 73. Ejemplo

# 76. ¿Siempre?

# 125. 🏆 Reglas de oro

``` text
1. WWPN identifica un puerto FC.
2. WWNN identifica un nodo FC.
3. N_Port pertenece a un dispositivo final.
4. F_Port conecta un dispositivo final al switch.
5. E_Port conecta switches FC.
6. ISL conecta switches.
7. Fabric es la estructura lógica de switches interconectados.
```

# 139. 🧠 Frase clave

> **En una SAN Fibre Channel, primero debemos conseguir conectividad
> mediante el fabric y zoning; después controlar la visibilidad del
> almacenamiento mediante LUN masking.**

En iSCSI:

> **Primero establecemos conectividad IP y sesión iSCSI; después
> presentamos y descubrimos las LUN.**
