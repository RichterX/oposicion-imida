# 1. ¿Qué es una SAN?

> **SAN = Storage Area Network**

Una SAN es una red especializada o dedicada que proporciona acceso a
almacenamiento, normalmente a nivel de bloque, desde servidores.

Conceptualmente:

``` text
SERVER
   │
   │ Block protocol
   ▼
  SAN
   │
   ▼
STORAGE ARRAY
   │
   ▼
DISKS
```

------------------------------------------------------------------------

# 2. La idea fundamental

En un NAS:

``` text
Client
↓
SMB / NFS
↓
Files
```

En una SAN:

``` text
Server
↓
Block protocol
↓
Block device
```

------------------------------------------------------------------------

# 3. NAS vs SAN

La diferencia que debes recordar para el examen:

``` text
NAS
→ File-level storage
```

``` text
SAN
→ Block-level storage
```

------------------------------------------------------------------------

# 4. File-level storage

En un NAS el servidor de almacenamiento presenta normalmente:

``` text
Files
Directories
Shares
```

Ejemplo:

``` text
\\NAS\Projects
```

------------------------------------------------------------------------

# 5. Block-level storage

En una SAN el almacenamiento se presenta al servidor como:

``` text
Block device
```

El servidor puede utilizar ese dispositivo para crear:

``` text
Filesystem
```

o para otras estructuras de almacenamiento.

------------------------------------------------------------------------

# 6. Diferencia conceptual

NAS:

``` text
Application
↓
File
↓
SMB/NFS
↓
NAS
```

SAN:

``` text
Application
↓
Filesystem
↓
Block device
↓
SAN
↓
Storage array
```

------------------------------------------------------------------------

# 7. ¿Quién gestiona el filesystem?

Esta es una diferencia fundamental.

En NAS:

``` text
NAS
↓
Filesystem
↓
Files
```

El almacenamiento gestiona el filesystem que presenta el servicio.

En SAN:

``` text
Server
↓
Filesystem
↓
LUN / Block device
```

Normalmente el host es quien crea y administra el filesystem sobre el
dispositivo de bloques.

------------------------------------------------------------------------

# 8. Ejemplo

Tenemos:

``` text
Server A
```

y una cabina:

``` text
Storage Array
```

La cabina presenta:

``` text
100 GB LUN
```

al servidor.

El servidor puede ver:

``` text
Disk
```

y posteriormente crear:

``` text
NTFS
```

o:

``` text
VMFS
```

según el uso.

# 19. LUN

Uno de los conceptos más importantes:

> **LUN = Logical Unit Number**

En la práctica, una LUN identifica una unidad lógica de almacenamiento
que puede ser presentada a un host.

------------------------------------------------------------------------

# 20. LUN como disco lógico

Desde el punto de vista del host:

``` text
LUN
```

puede aparecer como:

``` text
Disk
```

Por ejemplo:

``` text
Disk 1
```

------------------------------------------------------------------------

# 21. LUN no es un disco físico

Esto es una trampa clásica.

``` text
LUN
≠
Physical disk
```

Una LUN es una unidad lógica.

------------------------------------------------------------------------

# 22. Ejemplo

Una cabina puede tener:

``` text
24 physical disks
```

y crear:

``` text
Storage Pool
```

sobre ellos.

Después:

``` text
Pool
↓
Volume
↓
LUN
```

El host verá:

``` text
Block device
```

------------------------------------------------------------------------

# 23. Relación conceptual

``` text
Physical disks
       ↓
      RAID
       ↓
Storage Pool
       ↓
Logical Volume
       ↓
      LUN
       ↓
     Host
```

La nomenclatura exacta depende del fabricante.

------------------------------------------------------------------------

# 24. LUN masking

> **LUN masking**

es el mecanismo mediante el cual se controla qué hosts pueden ver
determinadas LUN.

------------------------------------------------------------------------

# 25. Ejemplo

Tenemos:

``` text
Host A
Host B
```

y:

``` text
LUN 1 → Finance
LUN 2 → VMware
```

Podemos configurar:

``` text
Host A → LUN 1
Host B → LUN 2
```

------------------------------------------------------------------------

# 26. ¿Por qué?

Para evitar:

``` text
Unauthorized access
Accidental access
Data corruption
```

# 27. Host groups

y presentar almacenamiento a todo el grupo.

# 31. Zoning

En Fibre Channel:

> **Zoning**

controla qué dispositivos pueden comunicarse dentro del fabric.

Conceptualmente:

``` text
Host HBA
↓
FC Switch
↓
Storage port
```

El zoning determina qué miembros pueden establecer comunicación.

------------------------------------------------------------------------

# 32. LUN masking

Una vez que existe conectividad:

``` text
Host
↓
Storage
```

el:

``` text
LUN masking
```

controla qué LUN puede ver cada host.

------------------------------------------------------------------------

# 33. Diferencia

``` text
Zoning
→ controla conectividad

LUN masking
→ controla visibilidad de LUN
```

------------------------------------------------------------------------

# 34. Ejemplo

``` text
Zoning
↓
Host A puede hablar con Storage Port A
```

Después:

``` text
LUN masking
↓
Host A puede ver LUN 10
```

# 35. Fibre Channel

Uno de los principales protocolos/tecnologías SAN:

> **Fibre Channel (FC)**

------------------------------------------------------------------------

# 36. ¿Qué es Fibre Channel?

Fibre Channel es una tecnología de red de alta velocidad diseñada para
transportar almacenamiento y otros tipos de tráfico, siendo
especialmente conocida por su uso en SAN.

------------------------------------------------------------------------

# 37. FC no significa fibra obligatoriamente

Aunque el nombre pueda inducir a error:

``` text
Fibre Channel
```

puede funcionar sobre diferentes medios físicos, incluyendo:

``` text
Fiber optic
Copper
```

según tecnología y distancia.

------------------------------------------------------------------------

# 38. FC fabric

Una SAN Fibre Channel puede construirse alrededor de:

``` text
FC switches
```

que forman un:

> **Fabric**

------------------------------------------------------------------------

# 39. Arquitectura FC básica

``` text
        HOST
          │
         HBA
          │
          ▼
     FC SWITCH
          │
          ▼
       STORAGE
```

------------------------------------------------------------------------

# 40. Arquitectura redundante

En producción se busca evitar un único fabric.

``` text
             HOST
           /      \
        HBA A     HBA B
         │          │
         ▼          ▼
      FC Switch A  FC Switch B
         │          │
         ▼          ▼
      Storage Controller
```

------------------------------------------------------------------------

# 41. Dual fabric

Podemos tener:

``` text
Fabric A
Fabric B
```

separados.

------------------------------------------------------------------------

# 42. ¿Por qué dos fabrics?

Para evitar:

``` text
Single Point of Failure
```

Si:

``` text
Fabric A
```

falla:

``` text
Fabric B
```

puede mantener conectividad, si el diseño está correctamente
implementado.

------------------------------------------------------------------------

# 43. HBA

> **HBA = Host Bus Adapter**

Es un adaptador utilizado por el host para conectarse a determinados
tipos de redes de almacenamiento, especialmente Fibre Channel.

------------------------------------------------------------------------

# 44. HBA Fibre Channel

Un servidor puede tener:

``` text
HBA 1
HBA 2
```

------------------------------------------------------------------------

# 45. HBA vs NIC

Conceptualmente:

``` text
NIC
→ conectividad de red general

FC HBA
→ conectividad Fibre Channel
```

Existen tecnologías convergentes que combinan funciones, pero para el
modelo clásico de examen conviene mantener esta distinción.

------------------------------------------------------------------------

# 46. WWN

> **WWN = World Wide Name**

# 47. WWPN

------------------------------------------------------------------------

# 48. WWNN

> **WWNN = World Wide Node Name**

------------------------------------------------------------------------

# 49. Port vs node


# 50. Ejemplo

``` text
HBA
├── Port A
└── Port B
```


# 51. WWPN como identidad del puerto

``` text
Host HBA port
```

mediante:

``` text
WWPN
```

# 52. Zoning mediante WWPN


# 53. Ejemplo

# 55. ¿Por qué evitar zonas enormes?

# 58. F_Port

# 59. E_Port


# 60. Fabric

``` text

```

podemos formar un:

``` text
Fabric
```

------------------------------------------------------------------------

# 61. ISL

> **ISL = Inter-Switch Link**

es un enlace entre switches.

Conceptualmente:

``` text
Switch A
   │
  ISL
   │
Switch B
```

------------------------------------------------------------------------

# 62. FC switch

Un switch Fibre Channel proporciona conectividad dentro de la SAN.

No debemos confundir:

``` text
Ethernet switch
```

con:

``` text
FC switch
```

aunque ambos sean dispositivos de switching.

# 135. 🏆 Reglas de oro

``` text
1. SAN significa Storage Area Network.
2. SAN proporciona normalmente block-level storage.
3. NAS proporciona normalmente file-level storage.
4. Una LUN es una unidad lógica de almacenamiento.
5. Una LUN no es un disco físico.
6. El host suele gestionar el filesystem sobre el almacenamiento SAN.
7. Initiator inicia la comunicación.
8. Target proporciona el servicio de almacenamiento.
9. Fibre Channel es una tecnología SAN.
10. iSCSI transporta SCSI sobre TCP/IP.
11. FC utiliza WWN/WWPN para identificar entidades.
12. iSCSI utiliza IQN.
13. Zoning controla conectividad dentro de un fabric FC.
14. LUN masking controla visibilidad de LUN.
15. HBA proporciona conectividad SAN especializada.
16. Multipath proporciona múltiples caminos.
17. MPIO gestiona múltiples rutas en Windows.
18. ALUA puede distinguir rutas optimizadas y no optimizadas.
19. VMFS es un filesystem de VMware para datastores.
20. Una SAN puede proporcionar almacenamiento compartido a varios hosts.
```
