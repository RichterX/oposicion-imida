# 1. ¿Qué es un CPD?

**CPD** significa **Centro de Procesamiento de Datos**.

También podemos encontrar:

- Centro de Datos.
- Data Center.
- Datacenter.

Un CPD es una instalación específicamente diseñada para **alojar, alimentar, refrigerar, conectar, proteger y mantener equipos informáticos y de comunicaciones**.

No debemos imaginarlo simplemente como:

> "Una habitación llena de servidores."

Esta definición se queda muy corta.

Un CPD es un **sistema completo de infraestructura** cuyo objetivo es proporcionar un entorno controlado donde los servicios tecnológicos puedan funcionar de forma segura, fiable y continua.

De forma simplificada:

```text
                         🏢 CPD
                           │
             ┌─────────────┼─────────────┐
             │             │             │
          CÓMPUTO      ALMACENAMIENTO    RED
             │             │             │
         Servidores      RAID/NAS/SAN   Switches
         VMware
             │
             └─────────────┬─────────────┘
                           │
                    INFRAESTRUCTURA
                           │
          ┌────────────────┼────────────────┐
          │                │                │
      ELECTRICIDAD    CLIMATIZACIÓN    SEGURIDAD
          │                │                │
       UPS/SAI         Refrigeración    Accesos
       Generador       Humedad          Incendios
       PDU
```

Por tanto:

> **Los servidores son solamente una parte del CPD.**

---

# 2. ¿Por qué son necesarios los CPD?

Las organizaciones dependen de sus sistemas informáticos para prestar servicios.

Una aplicación empresarial puede depender de:

```text
Usuarios
   ↓
Red
   ↓
Servidor de aplicaciones
   ↓
Base de datos
   ↓
Almacenamiento
```

Pero toda esta infraestructura necesita además:

```text
Electricidad
Climatización
Conectividad
Seguridad
Mantenimiento
```

Si cualquiera de los elementos críticos falla, el servicio puede verse afectado.

Por ejemplo:

```text
Base de datos funcionando
        ↓
Red caída
        ↓
Aplicación inaccesible
```

O:

```text
Servidor funcionando
        ↓
Fallo eléctrico
        ↓
Servidor apagado
```

Por eso un CPD debe contemplar **toda la cadena de infraestructura necesaria para proporcionar el servicio**.

---

# 3. Objetivos de un CPD

Un CPD debe proporcionar un entorno que permita mantener los servicios informáticos de manera:

- **Fiable**
- **Disponible**
- **Segura**
- **Continua**
- **Escalable**
- **Mantenible**

Estos conceptos están estrechamente relacionados y aparecerán a lo largo de todo el capítulo.

---

# 4. Disponibilidad

La **disponibilidad** representa la capacidad de un sistema para permanecer operativo y accesible durante el tiempo requerido.

De forma sencilla:

```text
Disponibilidad
      ↓
¿Cuánto tiempo está disponible el servicio?
```

Podemos tener un servidor perfectamente operativo, pero si otro elemento crítico de la infraestructura falla, el servicio puede quedar inaccesible.

Por ejemplo:

```text
              Servidor
                 │
                 ▼
              Switch
                 │
                 ▼
               Red
                 │
                 ▼
              Usuario
```

Si el servidor funciona pero el switch falla:

```text
Servidor ✅
Switch   ❌
Red      ❌
Servicio ❌
```

La disponibilidad debe analizarse **de extremo a extremo**.

No basta con que un único componente funcione.

---

# 5. Redundancia

La **redundancia** consiste en disponer de componentes, sistemas o caminos alternativos para reducir el impacto de un fallo.

## 5.1. Ejemplo sin redundancia

```text
Red eléctrica
      │
      ▼
    UPS
      │
      ▼
  Servidor
```

Si el UPS falla:

```text
UPS ❌
 ↓
Servidor
 ↓
Servicio afectado
```

Existe un único elemento cuya caída puede interrumpir el servicio.

## 5.2. Ejemplo con redundancia

Podemos introducir dos sistemas de alimentación:

```text
             Red eléctrica
              /                      /                     UPS A         UPS B
             \           /
              \         /
               Servidor
```

Si falla uno de los sistemas:

```text
UPS A ❌
UPS B ✅
   ↓
Servidor continúa funcionando
```

La redundancia puede aplicarse a numerosos componentes:

```text
Fuentes de alimentación
          ↓
       Redundantes

Conexiones de red
          ↓
       Redundantes

Discos
          ↓
         RAID

Servidores
          ↓
        Cluster

Conexiones
          ↓
     Caminos alternativos
```

> **La redundancia busca evitar que un único fallo provoque una interrupción del servicio.**

---

# 6. Punto único de fallo (SPOF)

Un **Single Point of Failure (SPOF)**, o **punto único de fallo**, es un componente cuya avería puede provocar la interrupción de un servicio porque no existe una alternativa adecuada.

Ejemplo:

```text
Internet
   │
   ▼
Router
   │
   ▼
Servidor
```

Si el router falla:

```text
Router ❌
   ↓
Servidor aislado
   ↓
Servicio inaccesible
```

El router constituye un posible **SPOF**.

Una arquitectura redundante puede reducir este riesgo:

```text
             ┌─────────┐
          ┌──┤ Router A│
          │  └─────────┘
Internet ─┤
          │  ┌─────────┐
          └──┤ Router B│
             └────┬────┘
                  │
             ┌────┴────┐
             │ Servidor│
             └─────────┘
```

### Concepto clave

> **Eliminar o reducir los puntos únicos de fallo es uno de los objetivos fundamentales del diseño de infraestructuras críticas.**

---

# 7. Tolerancia a fallos

La **tolerancia a fallos** es la capacidad de un sistema para continuar funcionando, total o parcialmente, cuando determinados componentes fallan.

Es importante distinguir:

```text
REDUNDANCIA
     ↓
Tenemos una alternativa
```

frente a:

```text
TOLERANCIA A FALLOS
     ↓
El sistema puede continuar funcionando
     ↓
a pesar del fallo
```

Por ejemplo:

```text
Fuente A ─────┐
              ├── Servidor
Fuente B ─────┘
```

Si falla una fuente:

```text
Fuente A ❌
Fuente B ✅
     ↓
Servidor continúa funcionando
```

En este caso:

- Existe **redundancia**.
- El sistema presenta **tolerancia frente al fallo** de una fuente.

### ⚠️ Importante

No debemos considerar ambos conceptos como sinónimos.

La redundancia es un **mecanismo o característica de diseño**.

La tolerancia a fallos es la **capacidad resultante del sistema para seguir funcionando ante determinados fallos**.

---

# 8. El CPD como sistema de sistemas

Un CPD no pertenece exclusivamente al ámbito de los sistemas informáticos.

Intervienen diferentes áreas.

## 8.1. Infraestructura informática

Incluye:

- Servidores.
- Sistemas de almacenamiento.
- Equipos de red.
- Sistemas de virtualización.
- Sistemas de backup.
- Equipamiento de seguridad.

## 8.2. Infraestructura eléctrica

Podemos encontrar:

- Cuadros eléctricos.
- Sistemas de distribución eléctrica.
- UPS/SAI.
- Generadores.
- PDUs.
- Fuentes de alimentación redundantes.

## 8.3. Climatización

Los equipos electrónicos generan calor durante su funcionamiento.

Por ello necesitamos:

- Sistemas de refrigeración.
- Control de temperatura.
- Control de humedad.
- Distribución adecuada del aire.

> Un servidor puede estar perfectamente configurado a nivel de software y aun así apagarse porque el entorno físico no mantiene unas condiciones adecuadas.

## 8.4. Seguridad física

El propio CPD debe estar protegido frente a:

- Accesos no autorizados.
- Incendios.
- Inundaciones.
- Manipulación accidental.
- Robo.
- Otros riesgos físicos.

## 8.5. Comunicaciones

Los servidores necesitan comunicarse entre sí y con otros sistemas:

```text
Servidor
   ↓
Switch
   ↓
Red
   ↓
Usuarios / otros sistemas / Internet
```

Por tanto, la infraestructura de red constituye otra pieza fundamental del CPD.

# 9. Principales elementos de un CPD

## 9.1. Cómputo

Los servidores físicos proporcionan capacidad de procesamiento.

```text
Servidor
├── CPU
├── RAM
├── Almacenamiento
├── NIC
└── Fuentes de alimentación
```

### CPU

Ejecuta instrucciones y procesa datos.

### RAM

Proporciona memoria de trabajo para los procesos que se están ejecutando.

### Almacenamiento

Permite conservar sistemas, aplicaciones y datos.

### NIC

**Network Interface Card**.

Permite conectar el servidor a la red.

### Fuentes de alimentación

Proporcionan la energía eléctrica necesaria para el funcionamiento del servidor.

---

# 10. Almacenamiento

Los sistemas de almacenamiento proporcionan capacidad para conservar información.

En este bloque estudiaremos posteriormente:

```text
DAS
NAS
SAN
RAID
```

Aunque están relacionados, **no son conceptos equivalentes**.

De forma muy simplificada:

```text
RAID
 ↓
Organización de discos

NAS
 ↓
Almacenamiento accesible por red a nivel de archivos

SAN
 ↓
Red especializada de almacenamiento
```

Esta diferencia será fundamental en los capítulos posteriores.

---

# 11. Red

Un CPD puede contener numerosos equipos de comunicaciones.

Entre ellos:

```text
Switches
Routers
Firewalls
Load Balancers
```

Estos elementos permiten conectar:

- Servidores.
- Sistemas de almacenamiento.
- Usuarios.
- Otros CPD.
- Redes externas.
- Internet.

La red también puede diseñarse con redundancia:

```text
Servidor
  │  │
  │  └──────── Switch B
  │
  └─────────── Switch A
```

De esta manera se intenta evitar que un único enlace o dispositivo provoque una interrupción.

---

# 12. Alimentación eléctrica

Los equipos de un CPD necesitan una alimentación eléctrica estable y fiable.

Una arquitectura simplificada puede ser:

```text
Red eléctrica
      │
      ▼
   UPS / SAI
      │
      ▼
     PDU
      │
      ▼
Equipamiento
```

En instalaciones críticas pueden existir además **generadores eléctricos**.

```text
        ┌──────────────┐
        │ Red eléctrica│
        └──────┬───────┘
               │
               ▼
             UPS
               │
               ▼
          Equipamiento
               ▲
               │
          Generador
```

La finalidad es reducir el riesgo de que un fallo eléctrico provoque una interrupción del servicio.

> Los conceptos **UPS/SAI, PDU y generador** se estudiarán con mayor profundidad posteriormente.

---

# 13. Refrigeración

Los equipos informáticos generan calor.

Si este calor no se elimina adecuadamente, la temperatura puede aumentar hasta alcanzar niveles perjudiciales para los equipos.

Un sistema de climatización debe permitir:

- Extraer calor.
- Mantener una temperatura adecuada.
- Controlar la humedad.
- Distribuir correctamente el aire.

Conceptualmente:

```text
Equipos
  ↓
Generan calor
  ↓
Aire caliente
  ↓
Sistema de refrigeración
  ↓
Eliminación del calor
```

La refrigeración no es un elemento accesorio.

> **La gestión térmica es una parte fundamental de la infraestructura de un CPD.**

---

# 14. Seguridad física

La seguridad de un CPD no se limita a firewalls, antivirus o contraseñas.

También es necesario proteger físicamente las instalaciones.

Podemos encontrar:

### Control de acceso

```text
Tarjeta
Biometría
PIN
Personal autorizado
```

### Videovigilancia

Cámaras para controlar las instalaciones y registrar accesos o incidentes.

### Protección contra incendios

Puede incluir:

- Detección de humo.
- Sistemas de alarma.
- Sistemas de extinción.

### Detección ambiental

Por ejemplo:

- Temperatura.
- Humedad.
- Humo.
- Agua.
- Apertura de puertas.

La seguridad física busca proteger tanto los equipos como la información y los servicios que dependen de ellos.

# 15. Disponibilidad, redundancia y SPOF

Estos conceptos están muy relacionados.

| Concepto | Significado |
|---|---|
| **Disponibilidad** | Capacidad de permanecer operativo y accesible |
| **Redundancia** | Existencia de alternativas ante un fallo |
| **SPOF** | Elemento cuyo fallo puede provocar una interrupción |
| **Tolerancia a fallos** | Capacidad de continuar funcionando ante determinados fallos |

Podemos visualizar la relación:

```text
              ALTA DISPONIBILIDAD
                      ▲
                      │
             ┌────────┴────────┐
             │                 │
        Redundancia       Menos SPOF
             │                 │
             └────────┬────────┘
                      │
              Tolerancia
               a fallos
```

# 16. Escalabilidad

Una infraestructura profesional debe poder aumentar su capacidad cuando las necesidades crecen.

Existen dos conceptos fundamentales.

## 16.1. Escalabilidad vertical

Consiste en aumentar los recursos de un sistema existente.

```text
Servidor
   │
   ├── 16 GB RAM
   │
   ▼
   64 GB RAM
```

También podemos aumentar:

- CPU.
- RAM.
- Almacenamiento.
- Capacidad de red.

### Idea clave

```text
UN SISTEMA
    ↓
MÁS RECURSOS
```

---

## 16.2. Escalabilidad horizontal

Consiste en añadir más sistemas.

```text
Servidor 1
Servidor 2
Servidor 3
Servidor 4
```

En lugar de hacer un único servidor cada vez más potente, añadimos más servidores y distribuimos la carga.

### Idea clave

```text
MÁS SISTEMAS
     ↓
MÁS CAPACIDAD
```

La escalabilidad horizontal será especialmente importante al estudiar:

- Virtualización.
- Clusters.
- Alta disponibilidad.
- Balanceadores.

---

# 17. Mantenibilidad

La **mantenibilidad** es la facilidad con la que una infraestructura puede mantenerse, repararse o sustituirse minimizando las interrupciones.

Por ejemplo:

```text
Fuente A ✅
Fuente B ✅
```

Podemos retirar una:

```text
Fuente A ❌
Fuente B ✅
```

y el servidor puede continuar funcionando mientras se sustituye la fuente averiada.

Esto permite realizar determinadas tareas de mantenimiento sin detener necesariamente el servicio.

> Una infraestructura bien diseñada no solamente debe funcionar. También debe poder mantenerse y repararse.

---

# 18. El CPD como conjunto de capas

Podemos pensar en un CPD como una serie de capas:

```text
┌──────────────────────────────┐
│          SERVICIOS           │
├──────────────────────────────┤
│       APLICACIONES           │
├──────────────────────────────┤
│       SERVIDORES / VM        │
├──────────────────────────────┤
│   ALMACENAMIENTO / RED       │
├──────────────────────────────┤
│ ELECTRICIDAD / REFRIGERACIÓN │
├──────────────────────────────┤
│      INFRAESTRUCTURA FÍSICA  │
└──────────────────────────────┘
```

Un fallo en una capa inferior puede afectar a todas las superiores.

Por ejemplo:

```text
Fallo eléctrico
      ↓
Servidor apagado
      ↓
Aplicación detenida
      ↓
Servicio inaccesible
```

Por eso el diseño del CPD debe considerar **toda la cadena de dependencias**.

---

# 19. Ejemplo práctico

Imaginemos una aplicación empresarial:

```text
                 Usuarios
                    │
                    ▼
              Load Balancer
                /                      /                   Servidor A   Servidor B
               \         /
                \       /
                Base de datos
                     │
                     ▼
                Almacenamiento
```

Pero físicamente necesitamos además:

```text
             🏢 CPD
               │
      ┌────────┼────────┐
      │        │        │
  Electricidad Red    Cooling
      │        │        │
     UPS     Switches  HVAC
      │
  Generador
```

Si diseñamos todos estos componentes sin redundancia, podríamos terminar con:

```text
Servidor A ✅
Servidor B ✅
Base de datos ✅
Almacenamiento ✅

             ↓

Único switch ❌

             ↓

TODO INACCESIBLE
```

Por eso la arquitectura debe buscar evitar los **puntos únicos de fallo**.

# 🎓 Resumen

Un **Centro de Procesamiento de Datos (CPD)** es una instalación diseñada para alojar y mantener infraestructura tecnológica bajo condiciones controladas.

No está formado únicamente por servidores.

Incluye:

```text
🖥️ Cómputo
💾 Almacenamiento
🌐 Red
⚡ Electricidad
❄️ Climatización
🔐 Seguridad
```

El diseño debe buscar:

```text
Alta disponibilidad
       ↓
Redundancia
       ↓
Menos SPOF
       ↓
Tolerancia a fallos
       ↓
Mantenimiento sencillo
```

También debemos distinguir:

```text
Escalabilidad vertical
↓
Más recursos en un sistema

Escalabilidad horizontal
↓
Más sistemas
```

La idea fundamental:

> **Un CPD no se diseña únicamente para que funcione. Se diseña para que continúe funcionando, pueda mantenerse y pueda recuperarse cuando algo falle.**

# ⚠️ Puntos que pueden confundirse

### Redundancia ≠ disponibilidad

La redundancia es un mecanismo de diseño que puede contribuir a aumentar la disponibilidad.

```text
Redundancia
     ↓
Alternativas
     ↓
Menor impacto de fallos
     ↓
Mayor disponibilidad potencial
```

### Redundancia ≠ tolerancia a fallos

```text
Redundancia
↓
Tengo una alternativa

Tolerancia a fallos
↓
Puedo seguir funcionando
```

### Escalabilidad vertical ≠ horizontal

```text
VERTICAL
1 servidor
   ↓
más CPU/RAM/discos

HORIZONTAL
1 servidor
   ↓
2 servidores
   ↓
3 servidores
   ↓
...
```

### CPD ≠ sala de servidores

Un CPD incluye:

```text
Servidores
+
Almacenamiento
+
Red
+
Electricidad
+
Climatización
+
Seguridad
+
Infraestructura física
```

¿El servicio continúa?
       ↓

# 📖 Resumen final

Un **Centro de Procesamiento de Datos (CPD)** es una instalación diseñada para alojar y mantener infraestructura tecnológica bajo condiciones controladas.

Su objetivo no es únicamente proporcionar capacidad de procesamiento, sino garantizar que los servicios puedan mantenerse:

- Disponibles.
- Fiables.
- Seguros.
- Continuos.
- Escalables.
- Mantenibles.

El diseño de un CPD debe prestar especial atención a los fallos.

Por ello aparecen conceptos como:

```text
Redundancia
SPOF
Tolerancia a fallos
Disponibilidad
Mantenibilidad
```

Y debemos distinguir:

```text
Escalabilidad vertical
↓
Más recursos en un sistema

Escalabilidad horizontal
↓
Más sistemas
```

La idea fundamental que debemos conservar es:

> **Un CPD no se diseña únicamente para que funcione. Se diseña para que continúe funcionando, pueda mantenerse y pueda recuperarse cuando algo falle.**
