La controladora RAID es el componente encargado de gestionar el array.

Puede encargarse de:

```text
RAID calculations
Disk management
Parity
Mirroring
Caching
Rebuild
Monitoring
Error handling
```

# 3. Componentes de una controladora

Dependiendo del modelo podemos encontrar:

```text
Processor
Cache
Firmware
Ports
Battery / capacitor
Management interface
```

---

# 4. Procesador de la controladora

Una controladora hardware puede disponer de un procesador dedicado para realizar:

```text
Parity calculations
RAID management
I/O scheduling
```

Esto reduce parte de la carga que tendría que gestionar el sistema operativo.

---

# 5. Cache

La controladora puede disponer de memoria caché.

Podemos encontrar:

```text
Read cache
Write cache
```

---

# 6. Read cache

La:

> **Read Cache**

mantiene temporalmente datos que pueden volver a solicitarse.

Objetivo:

```text
Reducir accesos al almacenamiento
```

---

# 7. Write cache

La:

> **Write Cache**

almacena temporalmente escrituras pendientes.

Puede mejorar:

```text
Write performance
```

---

# 8. Riesgo de write cache

Si una controladora confirma:

```text
WRITE OK
```

antes de que el dato haya llegado al almacenamiento persistente y después se pierde la alimentación:

```text
Power loss
↓
Cache loss
↓
Potential data loss
```

Por eso la protección de caché es importante.

---

# 9. BBU

Una:

> **Battery Backup Unit**

puede mantener protegida la memoria caché durante una pérdida de alimentación.

---

# 10. Flash-backed cache

Controladoras modernas pueden utilizar:

```text
Flash
+
Supercapacitor
```

para conservar datos pendientes de escritura.

La implementación depende del fabricante.

---

# 11. Write-back

Con:

```text
Write-back
```

el controlador puede confirmar la operación antes de que el dato se haya escrito definitivamente al medio, si la política de caché lo permite.

Ventaja:

```text
Performance ↑
```

Pero requiere:

```text
Cache protection
```

para mantener seguridad de datos.

---

# 12. Write-through

Con:

```text
Write-through
```

la escritura se confirma de acuerdo con una política más conservadora respecto al almacenamiento persistente.

Generalmente:

```text
Performance ↓
```

pero:

```text
Cache dependency ↓
```

---

# 13. No activar write-back a ciegas

Una mala práctica sería:

```text
Write-back
+
No cache protection
```

porque una pérdida de energía puede provocar:

```text
Data loss
```

o:

```text
Filesystem corruption
```

según el escenario.

---

# 14. Backplane

El:

> **Backplane**

es la infraestructura física donde se conectan los discos en determinados servidores.

Puede proporcionar:

```text
Physical connectivity
Power
Data paths
Hot-swap bays
```

---

# 15. Hot-swap bays

Un servidor puede tener bahías que permitan:

```text
Insert disk
Remove disk
```

sin apagar el servidor.

Pero:

> La posibilidad física de retirar un disco no garantiza por sí sola que cualquier operación sea segura.

---

# 16. Hot Swap

Para realizar hot swap correctamente necesitamos que:

```text
Server
+
Backplane
+
Controller
+
Disk
+
OS / firmware
```

sean compatibles con la operación.

# 19. Fault LED

Puede indicar:

```text

```

El significado exacto depende del servidor.

# 20. Estados de un disco

Una plataforma puede utilizar estados como:

```text
Online
Healthy
Ready
Hot Spare
Failed
Predictive Failure
Rebuilding
Unconfigured
```

Los nombres exactos dependen del fabricante.

---

# 21. Online

Un disco:

```text
Online
```

forma parte activa de un array y funciona correctamente.

---

# 22. Failed

Un disco:

```text
Failed
```

ha sido marcado como no disponible para el array.

---

# 23. Predictive Failure

Un disco puede estar marcado como:

```text
Predictive Failure
```

cuando existen indicios de que podría fallar.

---

# 24. Hot Spare

Un disco:

```text
Hot Spare
```

está reservado para sustitución/rebuild.

---

# 25. Unconfigured

Puede significar que el disco:

```text
No pertenece actualmente a un array configurado
```

pero la interpretación exacta depende del controlador.

---

# 26. Estados del array

También debemos diferenciar:

```text
Healthy
Degraded
Rebuilding
Failed
```

---

# 27. Healthy

```text
Redundancy intact
```

---

# 28. Degraded

```text
Redundancy reduced
```

pero el array puede seguir operativo.

---

# 29. Rebuilding

```text
Replacement disk
↓
Data reconstruction
```

---

# 30. Failed

```text
Tolerance exceeded
```

y el array ya no puede proporcionar correctamente los datos.

---

# 31. Disk state vs Array state

Muy importante:

```text
Disk = Failed
```

no significa necesariamente:

```text
Array = Failed
```

Ejemplo:

```text
RAID 6
D1 ❌
```

puede producir:

```text
Disk = Failed
Array = Degraded
```

```text
8. Verify health
9. Check logs
```

# 40. Consistency Check

Una:

> **Consistency Check**

comprueba la coherencia de los datos/paridad según el nivel RAID.

---

# 41. ¿Es un rebuild?

No.

```text
Rebuild
→ reconstruye datos perdidos
```

```text
Consistency Check
→ comprueba coherencia
```

---

# 42. Patrol Read

Una:

> **Patrol Read**

puede recorrer los discos para detectar errores de lectura.

Objetivo:

```text

```

---

# 43. ¿Por qué Patrol Read es útil?

Supongamos:

```text
RAID 5
```

y todavía está:

```text
Healthy
```

Pero existe un sector difícil de leer.

Si lo detectamos antes:

```text
Preventive action
```

puede ser posible.



Esto es extremadamente importante.

Si los discos contienen un array válido:

```text

```

Pero:

```text
Clear Foreign Configuration
```

puede eliminar la información de configuración necesaria.

# 170. 📚 Mini-glosario

| Término | Significado |
|---|---|
| RAID Controller | Controladora que gestiona un array RAID |

| BBU | Battery Backup Unit |
| Cache | Memoria temporal para I/O |
| Write-back | Política de escritura con confirmación anticipada bajo determinadas condiciones |
| Write-through | Política más conservadora de escritura |
| Hot Swap | Sustitución en caliente |
| Hot Spare | Disco reservado para sustitución/rebuild |
| Rebuild | Reconstrucción de datos/redundancia |
| Degraded | Array operativo con redundancia reducida |
| Failed | Array fuera de su tolerancia |
| SMART | Sistema de monitorización de salud del dispositivo |
| Patrol Read | Lectura preventiva de discos |
| Consistency Check | Comprobación de coherencia |
| Foreign Configuration | Configuración RAID detectada pero no importada a la controladora |
| Backplane | Conectividad física de las bahías |
| Common Cause Failure | Fallo común que afecta a varios componentes |
| Predictive Failure | Indicio de posible fallo futuro |
| RMA | Return Merchandise Authorization |
