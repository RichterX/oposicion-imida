# 1. Antes de SAN: ¿qué es SCSI?

Para entender:

``` text
iSCSI
```

y muchas arquitecturas SAN, necesitamos conocer:

> **SCSI = Small Computer System Interface**

SCSI define un conjunto de comandos y modelos de comunicación utilizados
para interactuar con dispositivos de almacenamiento.

------------------------------------------------------------------------

# 2. SCSI no es solamente un cable

Históricamente SCSI podía referirse a:

``` text
Interface
Protocol
Command set
```

En SAN modernas nos interesa especialmente:

``` text
SCSI command set
```

------------------------------------------------------------------------

# 3. Ejemplos de comandos SCSI

Podemos encontrar operaciones conceptuales como:

``` text
READ
WRITE
INQUIRY
TEST UNIT READY
```

------------------------------------------------------------------------

# 4. READ

El host puede solicitar:

``` text
READ
```

para obtener datos del dispositivo.

Conceptualmente:

``` text
Host
↓
READ
↓

↓
Data
```

------------------------------------------------------------------------

# 5. WRITE

Para escribir:

``` text
WRITE
```

``` text

↓
WRITE
↓
Storage
```

------------------------------------------------------------------------

# 6. INQUIRY

Un comando:

``` text
INQUIRY
```

puede utilizarse para obtener información sobre un dispositivo SCSI.

Por ejemplo:

``` text
Vendor
Product
Device information
```

------------------------------------------------------------------------

# 7. TEST UNIT READY

Permite comprobar conceptualmente si una unidad está preparada para
operaciones.

``` text
TEST UNIT READY
↓
Storage
↓
Ready / Not Ready
```



Estamos transportando comandos de almacenamiento.

# 24. Payload

# 25. CRC


------------------------------------------------------------------------

# 26. FCID

Una vez que un dispositivo se registra en el fabric, puede obtener un:

> **FCID = Fibre Channel ID**

El FCID identifica una dirección dentro del fabric.

------------------------------------------------------------------------

# 27. FCID no es WWPN

Esto es importante:

``` text
WWPN
→ identidad persistente del puerto

FCID
→ dirección asignada dentro del fabric
```

------------------------------------------------------------------------

# 28. Ejemplo

Un HBA puede tener:

``` text
WWPN:
10:00:00:00:01:01:01:01
```

y recibir:

``` text
FCID:
0x010203
```

La asignación del FCID pertenece al contexto del fabric.

------------------------------------------------------------------------

# 29. ¿Por qué existe FCID?

Porque el fabric necesita una dirección operativa para:

``` text
Routing
Communication
Frames
```

------------------------------------------------------------------------

# 30. Fabric Login

Cuando un dispositivo Fibre Channel se conecta al fabric debe realizar
un proceso de registro.

Uno de los conceptos fundamentales:

> **FLOGI = Fabric Login**

------------------------------------------------------------------------

# 31. FLOGI

El:

``` text
N_Port
↓
FLOGI
↓
Fabric
```

permite al dispositivo registrarse en el fabric.

------------------------------------------------------------------------

# 32. ¿Qué ocurre conceptualmente?

``` text
HBA
↓
FC Switch
↓
FLOGI
↓
Fabric assigns FCID
↓
Device becomes registered
```

------------------------------------------------------------------------

# 33. FLOGI y WWPN

Durante el proceso se intercambia información que permite identificar al
dispositivo.

El fabric aprende información sobre:

``` text
WWPN
WWNN
FCID
```

según el proceso y plataforma.

------------------------------------------------------------------------

# 34. PLOGI

Otro concepto importante:

> **PLOGI = Port Login**

Se utiliza para establecer una relación lógica entre puertos Fibre
Channel.

------------------------------------------------------------------------

# 35. FLOGI vs PLOGI

``` text
FLOGI
→ Login en el fabric

PLOGI
→ Login entre puertos
```

# 37. Name Server

El fabric mantiene servicios para registrar dispositivos.

> **Name Server**

Puede almacenar información sobre dispositivos registrados en el fabric.

------------------------------------------------------------------------

# 38. ¿Qué puede conocer?

Conceptualmente:

``` text
WWPN
WWNN
FCID
Port information
```

# 39. ¿Por qué es útil?

------------------------------------------------------------------------

# 42. RSCN

> **RSCN = Registered State Change Notification**

Es un mecanismo mediante el cual el fabric puede notificar cambios de
estado a dispositivos interesados.

------------------------------------------------------------------------

# 43. Ejemplo

Si aparece:

``` text
New storage port
```

o:

``` text
Port disappears
```

puede producirse un cambio de estado que genere notificaciones.

------------------------------------------------------------------------

# 44. ¿Por qué importa?

Porque permite que los dispositivos conozcan cambios relevantes del
fabric sin tener que descubrir continuamente todo desde cero.

------------------------------------------------------------------------

las implementaciones, pero este modelo es excelente para comprender la
secuencia.

# 140. 🏆 Reglas de oro

``` text
1. SCSI define comandos de almacenamiento.
2. iSCSI transporta SCSI sobre TCP/IP.
3. Fibre Channel puede transportar tráfico SCSI.
4. FC-0 corresponde a la capa física.
5. FC-1 se relaciona con codificación.
6. FC-2 se relaciona con frames y funciones de transporte.
7. FC-4 relaciona FC con protocolos superiores.
8. FLOGI significa Fabric Login.
9. PLOGI significa Port Login.
10. FCID es una dirección dentro del fabric.
11. WWPN identifica un puerto FC.
12. Name Server mantiene información de dispositivos registrados.
13. RSCN notifica cambios de estado registrados.
14. IQN identifica entidades iSCSI.
15. Una sesión iSCSI se establece entre initiator y target.
16. CHAP proporciona autenticación.
17. Multipath utiliza múltiples caminos.
18. ALUA distingue estados de acceso a LUN.
19. VMFS es un filesystem utilizado por VMware.
20. VAAI permite determinadas operaciones de offload.
21. SIOC permite controlar determinadas prioridades de I/O.
22. NAA ayuda a identificar dispositivos de almacenamiento.
23. Rescan permite detectar cambios.
24. Dos paths no garantizan redundancia si comparten un SPOF.
25. El troubleshooting debe hacerse por capas.
```


❌

❌

## Trampa 9

## Trampa 10


❌
