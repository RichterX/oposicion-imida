# 🎯 MISIÓN 11 · EL PROYECTO QUE NADIE SABE GESTIONAR

## Bloque 06 · Gestión TIC

> **Tipo:** misión integradora  
> **Dificultad:** 🟠 Media-Alta  
> **Objetivo:** aplicar conjuntamente ITIL, Scrum, PRINCE2 e ISO/IEC 20000.
>
> **Importante:** esta misión no pretende que memorices definiciones aisladas. Tendrás que decidir **qué marco, concepto, práctica o mecanismo corresponde a cada situación**.

---

# 🧭 1. SITUACIÓN

El IMIDA dispone de varias aplicaciones internas utilizadas por investigadores, técnicos y personal administrativo.

Actualmente existe un problema generalizado:

- Los usuarios comunican las incidencias por correo, teléfono y mensajes informales.
- No existe un catálogo de servicios claramente definido.
- Algunas incidencias se resuelven rápidamente, mientras que otras permanecen semanas sin seguimiento.
- Los cambios en las aplicaciones se realizan sin un procedimiento uniforme.
- No existen acuerdos de nivel de servicio formalizados para los principales servicios.
- La dirección no dispone de indicadores homogéneos sobre disponibilidad, incidencias o cumplimiento.
- Cada equipo técnico trabaja de una manera diferente.
- Los proyectos de desarrollo suelen sufrir retrasos.
- En algunos proyectos no está claro quién tiene autoridad para tomar determinadas decisiones.
- Cuando aparece un problema recurrente, normalmente se resuelve el incidente concreto, pero no siempre se investiga su causa.

La dirección decide lanzar un proyecto denominado:

> **PROYECTO NEXUS**

Su objetivo es implantar una plataforma corporativa para:

```text
gestionar servicios TIC
+
registrar incidencias
+
gestionar peticiones
+
controlar cambios
+
consultar indicadores
+
gestionar niveles de servicio
```

Además, la organización quiere establecer un sistema formal de gestión de servicios que pueda mantenerse y mejorarse con el tiempo.

El proyecto tendrá una duración aproximada de un año.

El desarrollo de la nueva plataforma será realizado por un equipo interno utilizando un enfoque ágil.

La dirección quiere evitar que el proyecto termine convirtiéndose simplemente en:

> "otro programa que registra tickets".

Quiere que exista un modelo real de gestión de servicios.
